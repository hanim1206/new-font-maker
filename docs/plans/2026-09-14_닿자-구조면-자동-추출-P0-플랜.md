# 닿자 구조면 자동 추출 P0 플랜

## 목적

완성 글자에서 첫닿자 영역과 기준면을 즉석 추출한다. 결과는 기존 `/font-guide-lab?font=...` 화면에 첫닿 후보선과 선택 영역 색면으로 표시한다. 레거시 `첫닿윗선·밑선·왼선·오른선` 숫자를 복구하거나 다른 문맥에 재사용하지 않는다.

입력 identity는 `font file SHA + 축 + 첫닿자 + 선택 홀자 + 실제 받침 + glyph path SHA`다. 결과는 분석용 `ExternalObservation`이며 생산 LayoutProfile·JamoMaster·프리셋·OTF로 자동 승격하지 않는다.

상태: D0·G0·G1·교정 G2·G3 완료. 기존 G2의 전체 `inkBounds` 색면은 무효 기록으로만 남기고, 역할 단면 v2 계약과 `initial-component-matcher-v3`를 승인본으로 사용한다.

병렬 작업 경계: G0·G1 추출기 작업은 홀자 v9와 분리했고, 홀자 작업 종료 뒤 G2에서 공용 `FontGuideLab` UI와 Reference API cache identity만 연결했다. 홀자 extractor와 생산값은 수정하지 않았다.

## 먼저 분리할 값

`영역 경계`와 `구조면`을 같은 값으로 부르지 않는다.

- `inkBounds`: 선택된 첫닿 잉크의 실제 상·하·좌·우 원시 극값. 역할 단면과 같다고 가정하지 않는다.
- `axisFaces`: 선택된 첫닿 안에서 실제로 보이는 선택 전 축평행 면 후보와 유한 구간. 없는 직선 면은 만들지 않는다.
- `roleFaces`: 구조 클래스와 문맥 결속으로 판정한 `첫윗단면·첫밑단면·첫왼단면·첫오른단면`. 상·하는 첫닿 전체 극값, 좌·우는 첫 구조획 양끝을 쓴다.
- `selectionArea`: 네 `roleFaces`가 모두 관측됐을 때만 파생하는 반투명 영역 색면. 원시 bbox나 탐색용 ROI를 대신 표시하지 않는다.
- `componentGroup`: 첫닿으로 판정된 외곽 island와 내부 counter 묶음. contour 번호는 현재 path 안의 근거일 뿐 글자별 규칙으로 저장하지 않는다.

각 좌표와 면은 독립적으로 `candidate | abstained`다. 영역 경계가 보여도 평평한 면이 없을 수 있고, 첫닿과 다른 자소가 붙어 분리가 불확실하면 전체 그룹을 자동 포기할 수 있다.

## P0 범위

- 폰트: SHA가 고정된 Noto Sans KR, 나눔고딕.
- 첫닿자: 현대 첫닿자 19자 전체.
- 문맥: 오른쪽 `ㅏ`, 아래 `ㅗ`, 섞임 `ㅘ` × 받침 없음/`ㄱ`의 6문맥.
- 글자 수: 폰트당 `19 × 6 = 114`, 합계 228.
- 화면: 기존 Font Guide Lab 유지.
- 제외: 나머지 18홀자, ㄱ 외 받침, 임의 업로드 폰트, 생산값 반영.

6문맥은 탐색 방향 계약을 공유하지만 좌표를 공유하지 않는다. 모든 완성 글자의 실제 path를 따로 계산한다.

## 추출 원칙

먼저 홀자 v9 구조를 찾아 첫닿이 아닌 잉크의 방향을 안다.

- 오른쪽 홀자: 바깥기둥 왼쪽의 잉크를 찾는다. 받침이 있으면 왼쪽 잉크의 가장 큰 수직 공백으로 위 첫닿과 아래 받침을 나눈다.
- 아래 홀자: 주 보 위쪽에서 첫닿 island를 모은다. 보와 줄기 위상을 만족하는 홀자 잉크는 제외한다.
- 섞임 홀자: 바탕 보 위·왼쪽에서 시작하고, 바탕 줄기·오른 기둥과 연결된 홀자 구조를 제외한다.
- 겹닿자와 분리 획: ㄲ·ㄸ·ㅃ·ㅆ·ㅉ·ㅊ·ㅎ처럼 island가 여러 개여도 한 첫닿 그룹으로 묶는다.
- ㅁ·ㅂ·ㅇ·ㅎ의 내부 빈 공간은 containment로 바깥 island에 귀속한다.
- 글자·첫닿·폰트 ID, contour 번호, 절대 좌표 예외는 금지한다.

첫닿 그룹이 결정되면 Bézier 실제 극값으로 원시 `inkBounds`를 계산하고, 그 그룹 안에서만 축평행 가시 면 후보를 찾는다. 다음 역할 구조 클래스로 좌우 단면을 판정한다.

- `full-component`: ㄴ·ㅅ·ㅆ·ㅇ. 전체 잉크 좌우 극값.
- `first-main-horizontal`: ㄱ·ㄷ·ㄹ·ㅁ·ㅂ·ㅈ·ㅋ·ㅌ·ㅍ. 첫 본체 가로줄기 양끝.
- `paired-first-main-horizontal`: ㄲ·ㄸ·ㅃ·ㅉ. 같은 상단 층의 병렬 첫 본체 가로줄기 묶음 양끝.
- `marked-body-horizontal`: ㅊ·ㅎ. 짧은 윗 모자를 제외한 본체 가로줄기 양끝.

홀자나 받침 면이 후보에 섞이거나 역할 단면 근거가 유일하지 않으면 생성률과 무관하게 실패다. 레거시 숫자는 결과 비교에만 쓰며 선택 입력으로 넣지 않는다.

## 데이터 계약 초안

```ts
interface InitialComponentObservation {
  character: string
  initialJamo: string
  medialJamo: string
  finalJamo: string | null
  componentGroup: Candidate<ComponentEvidence>
  inkBounds: {
    top: Candidate<BoundObservation>
    bottom: Candidate<BoundObservation>
    left: Candidate<BoundObservation>
    right: Candidate<BoundObservation>
  }
  axisFaces: readonly AxisFaceObservation[]
  roleFaces: {
    top: Candidate<RoleFaceObservation>
    bottom: Candidate<RoleFaceObservation>
    left: Candidate<RoleFaceObservation>
    right: Candidate<RoleFaceObservation>
  }
  selectionArea: Candidate<DerivedArea>
}
```

`selectionArea`는 관측 원본이 아니라 네 역할 단면의 파생값이다. UI 색면은 `derivedFrom` 네 역할 ID를 표시하고 저장·승인도 원시 `inkBounds`·`axisFaces`와 분리한다.

## 실행 게이트

### D0 — 역할·응답 계약

Python·TypeScript에 `componentGroup`, `inkBounds`, `axisFaces`, `selectionArea` 계약을 같은 이름으로 정의한다. 곡선 극값과 평평한 면, 관측값과 파생 색면을 parser와 UI에서도 구분한다.

완료 조건:

- 19첫닿 × 6문맥 요청 identity를 결정적으로 만든다.
- 네 경계와 각 구조면이 독립 포기 가능하다.
- 거친 ROI와 레거시 기준값이 응답에 들어가지 않는다.
- schema·parser 단위 테스트 통과.

재완료: 2026-09-14. v1의 `selectionArea=네 inkBounds` 정의를 무효화하고 `initial-component-p0-contract.v2.json`을 Python·TypeScript 단일 계약으로 추가했다. `componentGroup`·원시 `inkBounds`·선택 전 `axisFaces`·판정된 네 `roleFaces`·파생 `selectionArea`를 분리했다. parser는 역할 구조 클래스·선택 규칙·근거 가로면 양끝·네 역할 단면 파생값을 검증하고 레거시 값·ROI 유입을 거부한다. 계약은 `initial-component-matcher-v3`, 역할 정의 `initial-component-role-v2`, 홀자 앵커 `geometric-role-matcher-v9`를 고정한다.

### G0 — Noto 19첫닿 전체

Noto 114글자를 계산한다. 첫닿 형태군별 contact sheet에서 그룹 누락, 홀자·받침 오염, 겹닿 분리 실패를 먼저 본다.

완료 조건:

- crash·NaN·identity·근거 위반 0건.
- 후보 그룹의 홀자·받침 오염 0건.
- 형태군별 usable 영역 후보율 80% 이상. 미달군은 지원 표시하지 않는다.
- 에이전트가 114글자 화면을 전수 확인한다.

완료: 2026-09-14. `initial-component-matcher-v2`의 contour grouping 결과는 유지한다. v3 역할 판정으로 고정 Noto 114자의 네 `roleFaces` 456/456과 역할 색면 114/114를 다시 계산했다. `ㄹ·ㄷ·ㅌ` 첫오른단면, 병렬 첫획, ㅊ·ㅎ 모자 제외 규칙을 fixture와 회귀 테스트로 고정했다. 글자별 contour·좌표 예외와 레거시 기준값은 넣지 않았다.

### G1 — 나눔고딕 holdout

코드 조정 없이 나눔고딕 114글자를 계산한다. composite·merged contour, 둥근 모서리, 좁은 받침 간격을 검사한다. 조정이 필요하면 새 버전으로 두 폰트를 모두 다시 계산한다.

완료 조건은 G0와 같고, 두 폰트 차이를 같은 수치로 억지 통일하지 않는다.

완료: 2026-09-14. `initial-component-matcher-v2`의 나눔고딕 component grouping과 합쳐진 contour 29건 근거는 유지한다. v3 역할 판정으로 나눔고딕 114자의 네 `roleFaces` 456/456과 역할 색면 114/114를 다시 계산했다. Noto와 같은 네 역할 구조 클래스만 사용했고 폰트·글자·좌표 예외는 없다. 두 v2 fixture를 새 파일로 동결했다.

### G2 — 기존 화면·캐시 통합

Font Guide Lab 카드에 첫닿 `inkBounds` 후보선, 실제 `axisFaces`, 파생 `selectionArea` 색면을 추가한다. 레거시 첫닿·받침선은 계속 숨긴다. 홀자 후보선과 겹칠 때 레이어·범례·hover 출처를 구분한다.

캐시 identity에 component extractor·schema 버전을 넣고 늦은 응답이 현재 글자를 덮어쓰지 않게 한다.

기존 완료 판정 무효: 2026-09-14. v1 UI가 전체 `inkBounds`를 첫닿 영역으로 표시해 승인된 좌우 역할을 무시했다.

교정 완료: 2026-09-14. 읽기 전용 API·parser·브라우저 cache를 v2 계약으로 올리고 Font Guide Lab에 `첫윗단면·첫밑단면·첫왼단면·첫오른단면`, 네 역할 단면 파생 색면, 선택 전 원시 면 후보를 구분해 표시한다. `ㄹ`의 오른쪽 역할값은 Noto `라`에서 전체 잉크 오른쪽 592.2가 아니라 첫 가로줄기 꺾임 493.14다. 레거시 Noto 첫윗·첫밑선 228값은 평가기에서만 비교했고 최대 차이 0.499 unit이다. extractor·응답에는 레거시 값이 들어가지 않는다. Python 역할 추출·fixture 13개, Reference API 14개, TypeScript 11개, 관련 Playwright 2개, targeted ESLint, 전체 build가 통과했다. 사용자가 실제 링크에서 역할 단면과 색면 교정을 확인해 G2를 승인했다.

### G3 — 사용자 검증

에이전트 전수검사 뒤 형태군·문맥별 위험 표본만 같은 화면에 묶는다. 사용자가 확인한 글자만 기록한다. 다 별로면 개별 글자 예외를 추가하지 않고 component grouping·탐색 방향을 다시 연다.

완료: 2026-09-14. 사용자가 실제 Font Guide Lab에서 교정된 역할 단면과 파생 색면을 확인하고 승인했다. 특히 `ㄹ` 첫오른단면이 아래 긴 가로줄기·전체 bbox가 아니라 첫 가로줄기의 첫 바깥 꺾임을 따르는 화면을 확인했다.
