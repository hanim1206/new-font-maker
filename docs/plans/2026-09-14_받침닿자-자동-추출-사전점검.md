# 받침닿자 자동 추출 사전점검

## 결론

받침 27자 추출은 새 세션에서 시작해도 된다. 홀자 v9와 첫닿 v3의 승인 계약을 입력으로만 읽고, 받침 전용 계약·추출기·fixture·테스트를 새 파일로 만들면 작업이 분리된다. 현재 작업공간에 미커밋 변경이 많으므로 새 worktree보다 같은 작업공간을 쓰되 공용 API와 Font Guide Lab 수정은 추출 검증 뒤 별도 통합 단계로 미룬다.

이번 문서는 구현 확정안이 아니라 시작 전 검토안이다. 특히 받침왼단면·받침오른단면을 받침 전체 외곽으로 볼지 특정 구조획 양끝으로 볼지는 코드 작성 전에 사용자와 먼저 확정한다.

## 앞선 추출에서 범한 오류

### 역할 의미보다 측정 가능한 도형을 먼저 잡음

첫닿 v1은 `selectionArea`를 네 `inkBounds`에서 만들었다. 하지만 사용자가 말한 첫왼단면·첫오른단면은 전체 외접면이 아니라 첫 구조획 양끝이었다. `ㄹ` 오른쪽을 아래 장가로획 끝까지 넓힌 뒤 테스트와 UI 통과를 완료로 잘못 기록했다.

홀자에서도 초기 역할표에 복수 기둥·복수 보·쌍줄기 구조가 빠졌다. 역할 계약이 불완전한 상태에서 scorer부터 확장해 뒤늦게 D1을 다시 열었다.

보완: 받침은 추출 코드보다 용어와 역할 계약을 먼저 동결한다. 원시 `inkBounds`, 선택 전 `axisFaces`, 판정된 `roleFaces`, 네 역할 단면에서 파생한 `selectionArea`를 처음부터 분리한다.

### 비슷한 선을 같은 역할로 오인함

홀자 v4는 Noto `표`에서 홀자 보 대신 초성 `ㅍ` 가운데 가로획을 골랐다. v6은 `뫠`에서 바탕 줄기 대신 초성 세로면을 골랐다. v7은 `규·귝`에서 오른 줄기 대신 주 보 오른끝면을 골랐고 같은 오염이 76문맥에 있었다. v8은 `풔·풕`에서 혼합 홀자 바탕 보·줄기 대신 초성 `ㅍ`을 골랐고 같은 실패가 11문맥에 있었다.

보완: 위치·길이·방향만으로 후보를 승인하지 않는다. 알려진 완성 글자 identity, 첫닿·홀자 역할, 받침의 하단 위상, 연결 방향, 이웃 요소와의 내부 결속, 선택 요소와 제외 요소를 함께 증명해야 한다. ROI는 탐색 범위일 뿐 역할 근거가 아니다.

### contour 하나를 역할 하나처럼 다룸

나눔고딕처럼 자소끼리 합쳐진 contour와 둥근 혼합 구조에서 누락·과도한 포기·이웃 자소 오염이 반복됐다. 반대로 곡면을 직선 면으로 억지 축약하면 실제 윤곽과 다른 값이 생긴다.

보완: `contour = 자소` 가정 금지. 하나의 contour 안에서도 경계 segment·곡선 구간을 역할별로 분리하고, 여러 contour를 하나의 받침 그룹이나 겹받침 구성원으로 묶을 수 있어야 한다. 축평행 면이 없으면 국소 접선 근거를 명시하거나 자동 포기한다.

### 후보율과 테스트 통과를 역할 정확도로 착각함

홀자 v4·v6·v7·v8은 수치 검사, 계약 검사, 후보율 또는 에이전트 contact sheet 검사를 통과한 뒤 사용자 화면에서 체계적 오염이 발견됐다. 첫닿도 schema·parser·UI 테스트가 잘못된 bbox 의미를 그대로 고정했다.

보완: 테스트를 세 층으로 나눈다.

- 형식: schema, identity, NaN, cache, provenance
- 구조 불변식: 받침이 홀자·첫닿을 침범하지 않음, 겹받침 구성원 순서·결속, 선택 경계가 실제 contour에 접촉
- 의미 검증: 구조군별 위험 표본과 사용자 확인

후보 개수와 100% 생성률은 정확도 증거로 사용하지 않는다. 한 오염이 발견되면 같은 역할·구조군·문맥 전체를 무효화하고 전수 재계산한다.

### 사용자 확인을 너무 늦게 받음

여러 버전을 전체 batch와 UI까지 연결한 뒤 위험 표본에서 역할 오류가 발견됐다. 수정 비용과 캐시·보고서 폐기 범위가 커졌다.

보완: 받침 단일자·쌍자·겹받침 각 대표군의 D0 역할 그림을 먼저 확인한다. Noto 소규모 대표 결과도 full batch 전에 같은 화면으로 확인한다. 사용자 확인 전 `완료`, `정확`, `지원`으로 기록하지 않는다.

### 문맥과 지원 범위를 축약함

레거시 키가 선택 홀자를 포함하지 않아 `고` 값을 `구`에 재사용했다. 프리셋 r2는 가로·세로 문맥축을 반대로 연결했다. 현재 자동 추출 API는 Noto Sans KR·나눔고딕만 검증됐지만 다른 카탈로그 폰트 버튼도 클릭 가능해 범용 자동화처럼 보인다.

보완: 받침 관측 identity는 `font SHA + axes + codepoint/path SHA + 첫닿자 + 홀자 + 실제 받침 + context ID + extractor/schema version`을 전부 가진다. `candidate`와 `verified`를 분리하고, 미검증 폰트도 후보 실행을 허용한다면 화면에 `미검증`을 명시한다. 실행 자체를 막는다면 버튼에 `받침 추출 미지원` 상태를 먼저 표시한다. 조용히 빈 화면으로 만들지 않는다.

### 공용 UI를 의미 확정 전에 연결함

첫닿 G2는 bbox 의미가 틀린 상태로 API·cache·UI까지 연결돼 완료 판정을 취소했다. 공용 파일은 홀자 세션과 충돌 위험도 컸다.

보완: 받침 계약·추출기·두 폰트 fixture·검증 보고서가 동결되기 전 `server.py`, `FontGuideLabPage`, 브라우저 cache를 수정하지 않는다. 통합 시 extractor·schema·role version을 cache identity에 모두 넣고 늦은 응답이 현재 선택을 덮지 않는 테스트를 추가한다.

## 받침 추출 시작 전 확정할 의미

- UI 용어는 `받침윗단면·받침밑단면·받침왼단면·받침오른단면`으로 고정한다.
- 상·하는 받침 전체 그룹의 실제 바깥 극값을 기본 후보로 삼는다.
- 좌·우는 전체 그룹 외곽인지 지정 구조획 양끝인지 사용자 결정을 먼저 받는다. 첫닿 규칙을 복사하지 않는다.
- 겹받침 11종은 하나의 bbox로만 저장하지 않는다. 왼구성원·오른구성원과 각 contour/segment 근거를 보존하고, 색면만 승인된 네 역할 단면에서 파생한다.
- 단일 받침, 된받침, 겹받침의 구조군을 먼저 선언한다. 글자별 contour ID·폰트별 좌표·레거시 수치 예외는 금지한다.
- 받침 없음은 후보 0이 정상이며 숨은 값을 만들지 않는다.

## 권장 게이트

### D0 — 받침 역할 계약

27종 역할표, 겹받침 구성원 모델, 네 단면 의미, 포기 사유, provenance를 JSON·Python·TypeScript에서 같은 이름으로 정의한다. extractor 구현 전 parser의 거부 테스트를 먼저 만든다.

### G0 — Noto 구조 대표

첫닿 `ㄱ`, 대표 홀자 `ㅏ·ㅗ·ㅘ`, 받침 27종의 81글자를 계산한다. 단일·된·겹받침별 component grouping과 네 단면을 확인한다. 구조군 하나라도 의미가 틀리면 full batch로 넘어가지 않는다.

### G1 — 나눔고딕 holdout

코드 조정 없이 같은 81글자를 계산한다. merged contour, 둥근 모서리, 겹받침 결합을 본다. 수정이 필요하면 새 matcher 버전으로 Noto와 나눔을 모두 다시 계산한다.

### G2 — 첫닿 문맥 전체

두 폰트에서 `19첫닿 × 3대표 홀자 × 27받침 = 폰트당 1,539글자`, 합계 3,078글자를 계산한다. 후보율이 아니라 역할 오염·구성원 순서·실제 경계 접촉·provenance를 구조군별로 검사한다. 이 범위 밖 홀자와 미검증 폰트까지 지원한다고 표현하지 않는다.

### G3 — 추가 폰트 일반화

돋움을 첫 추가 holdout으로 같은 G0 81글자에 돌린다. 폰트별 예외 없이 통과하면 범위를 넓힌다. 실패해도 후보 자체는 `unverified`로 볼 수 있게 하는 방식을 우선 검토한다. Noto·나눔 통과만으로 `모든 폰트 자동 추출 완료`라고 부르지 않는다.

### G4 — API·캐시·Font Guide Lab 통합

D0~G3 계약이 안정된 뒤 공용 화면을 수정한다. 원시 면, 역할 단면, 파생 색면, 검증 상태를 분리한다. 레거시 받침선과 수치는 정답 비교기에만 두고 extractor 응답과 색면에는 넣지 않는다.

### G5 — 사용자 검증

단일·된·겹받침, 합쳐진 contour, 곡면, 좁은 간격, 세 홀자 문맥의 위험 표본을 같은 화면에 묶는다. 사용자가 실제 윤곽 접촉과 역할을 확인한 범위만 승인한다.

## 새 세션 작업 경계

새 세션은 D0부터 시작한다. 현재 홀자 v9와 첫닿 v3 파일은 읽기 전용 기준이다.

허용:

- `final-component-p0-contract.v1.json`
- `final_component_contract.py`
- `final_component_extractor.py`
- 받침 전용 fixture·평가기·테스트
- 이 사전점검 문서를 발전시킨 받침 P0 플랜

초기 금지:

- 홀자 extractor v9 수정
- 첫닿 extractor v3 수정
- 기존 홀자·첫닿 fixture 재작성
- `server.py`, Font Guide Lab 공용 UI, browser cache 수정
- 레거시 받침 좌표를 extractor 입력으로 사용
- 생산 프리셋·JamoMaster·LayoutProfile 자동 반영

공용 파일 통합은 G0~G3 검증 뒤 한 세션에서 합친다. 새 세션이 같은 작업공간의 기존 미커밋 파일을 삭제·reset·정리하면 안 된다.

## 새 세션 전달문

> 받침닿자 자동 추출 사전점검 문서를 기준으로 D0부터 진행. 홀자 v9·첫닿 v3는 읽기 전용 입력으로 사용하고 수정 금지. 먼저 받침 27종의 역할 용어, 단일·된·겹받침 구조군, 네 역할 단면과 구성원 provenance 계약을 고정. 첫닿 규칙이나 전체 bbox를 받침 좌우 의미로 복사하지 말 것. G0 Noto 81글자, G1 나눔고딕 81글자, G2 두 폰트 3,078글자, G3 돋움 holdout 순서. 후보율·테스트 통과만으로 정확 판정 금지. 글자·폰트·contour 번호·레거시 좌표 예외 금지. G0~G3까지 extractor·fixture·평가기·테스트만 만들고 server·Font Guide Lab·cache는 수정하지 말 것. 단계 완료마다 옵시디언 받침 P0 문서 갱신.
