# 속공간 지키기 — 참고 폰트 역추론

- **이번에 비교하는 것**: 손잡이 값(하한선 · 가로줄기 몫 · 바닥 · 자소 사이)을 사람 눈으로 하나씩 고르는 지금 대, 참고 폰트(노토 가변)의 100 · 900을 같은 자로 재서 숫자로 역추론하는 것
- **이번 승인으로 바뀌는 것**: 굵기 손잡이 값이 "참고 폰트 두 굵기 → 우리 손잡이 값" 셈에서 나온다. 사용자 눈 검증은 세 번뿐 — 자 확인 · 900 완성본 월드컵 · 굵기 막대 훑기. 재는 자와 맞추는 셈은 폰트 이름을 박지 않아 다른 폰트 분석에도 쓴다
- **바뀌지 않는 것**: 굵기 400 · 기본 네모꼴의 모든 글자, 저장된 굵기 값과 획 데이터, 자동 보정 끈 글자, 제품 화면(실효 스타일 입구가 dev에 들어온 뒤에만 붙인다)

## 왜

굵기 900에서 모든 획을 같은 배율(×1.95)로 굵게 하니 빽빽한 자소(ㅃ · ㄹ)가 검은 덩어리가 된다. 앞 작업에서 하한선(B′)과 가로줄기 몫(×1.5)을 눈으로 골랐지만, 손잡이를 하나씩 켠 덜 된 글자로 물으니 "너무 굵다 / 너무 얇다" 사이라 고를 수 없었다(10-01 뒤집힘). 노토에는 100~900 실물이 있고 우리도 같은 굵기로 추출할 수 있으니, "노토가 400 → 900에서 한 일"을 숫자로 재서 손잡이 값을 역추론하는 쪽이 빠르고, 같은 셈을 나중에 다른 폰트에도 쓴다.

## 단계

판단할 변수는 늘 하나. 숫자 통과선을 넘은 것만 사용자 눈으로 간다.

1. **같은 자** — 노토와 우리 폰트를 같은 윤곽 프로브(`measure_weight_offsets.py` 계열)로 잰다. 특징: 가로 · 세로줄기 절대 두께, 자소 상자 밀림, 속공간 폭, 검기. 폰트 이름 안 박음.
   - **눈 ①** (한 번): 노토 900 위에 잰 선을 겹친 그림 — "자가 제자리를 짚었나" 예/아니오.
2. **오차 하나** — 표본 글자마다 노토와의 차이를 항목별 가중 합으로 점수 하나. 막힘 개수는 0 목표가 아니라 **노토 900을 같은 자로 잰 값과의 상대 지표**로 바꾼다(지금 기준이면 노토 900의 ㅃ · ㅈ · ㅅ도 막힘이라).
3. **자동 맞추기** — 손잡이(가로 몫 · 하한선 · 바닥 · 바깥 분배 · 자소 사이 임시판)를 격자로 훑어 점수 최소 값을 찾는다. 먼저 400 → 900 끝에서.
   - **눈 ②**: 900 완성본 이상형 월드컵, 노토 900을 옆에 두고. **첫 판 = 숫자로 맞춘 것 대 앞서 눈으로 고른 것(B′ + ×1.5)** — 노토를 따를지 취향을 남길지 이 한 판으로 정한다.
4. **패턴** — 400 · 900에서 나온 값을 굵기의 함수로 놓고, 100으로 바깥을 확인한다. 중간 굵기(300 · 500 · 700)는 맞추는 데 쓰지 않고 예측 검증용으로 남긴다. 다른 폰트에 다시 쓰는 부분이 여기다.
5. **숫자 통과선** — 남긴 글자 · 중간 굵기에서 오차가 기준 아래일 때만 다음으로.
   - **눈 ③**: 제품 화면에서 굵기 막대를 돌려 본다 — "튀는 굵기가 있나".

**질문을 띄우기 전 거름망**: 후보 차이 10u 이상이거나 검기 1%p 이상일 때만 묻는다(그 아래는 AI가 정함) · 네모붓 폰트 스크린샷으로 먼저 확인 · 한 번에 후보 둘, 질문 하나.

**미결정**
- 네모꼴 보정(세로줄기만 얇게, 폰트 전체 하나)과 합칠지 — 역추론 뒤에 본다.
- 자소 단위 배율은 한 글자 안 굵기를 들쑥날쑥하게 한다(뷁 ㅂ 1.00 · ㅞ 0.72) — 바닥 값을 역추론에서 얻는다(가설: 노토처럼 0.94~1.0으로 모인다).
