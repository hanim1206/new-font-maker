# 카카오 로그인

- **이번에 비교하는 것**: 로그인 없이 바로 만들고, 저장 · 불러오기 · 다운로드 때만 로그인을 받는 흐름이 베타 코드 로그인과 부딪치지 않는지.
- **이번 승인으로 바뀌는 것**: 들어오자마자 뜨던 코드 입력 화면이 없어진다. 로그인 창은 카카오 버튼이 주인이고, 베타 코드는 그 아래 작은 링크로 남는다. 새 카카오 계정은 폰트 1개.
- **바뀌지 않는 것**: 베타 계정(코드 = 이메일·비번), 베타 계정의 폰트 3개, 편집 화면, 계정 저장 방식(`accountFontSync`), 약관 내용.

뒤집는 결정: 9/25 "제품 주소 전체 앞에 게이트"(베타 코드 로그인 플랜)를 거둔다. 9/24 "스스로 가입은 막는다"는 카카오에 한해 연다.

## 계약 (D0 안)

- **처음 열면**: 로그인 없이 지금 `VITE_AUTH_GATE=off`일 때처럼 이 기기 폰트(`LOCAL_OWNER`)로 바로 편집한다. 만든 글자는 브라우저에만 있다(처리방침 2항과 같다).
- **로그인을 받는 때**: ① 상단 폰트 이름 자리의 `로그인` ② 내 폰트 불러오기(대시보드) ③ 다운로드 누르기 직전. 다운로드는 로그인 없이는 안 된다(약관 4조 3항).
- **로그인 창**: `카카오로 시작하기` 버튼 하나 + 아래 작은 `베타 초대 코드가 있어요` → 지금 코드 입력칸. 처음 카카오로 들어오면 약관 · 처리방침 · 홍보 활용 · 만 14세 이상 동의를 받는다.
- **로그인 직후**: 이 기기에서 만들던 폰트를 계정 폰트로 올린다(`uploadPendingCopy`). 카카오는 페이지를 떠났다 돌아오지만 브라우저 사본은 남아 있다. 계정에 이미 폰트가 있고 한도가 찼으면 "덮어쓸까요 / 이 기기에만 둘까요"를 묻는다.
- **폰트 한도**: 서버 트리거(`limit_font_projects_per_user`)가 계정 종류로 나눈다 — 카카오 가입(`auth.users.raw_app_meta_data->>'provider' = 'kakao'`) 1개, 그 밖(베타 이메일) 3개. 화면의 `FONT_LIMIT`도 같은 값을 쓴다.
- **카톡 안 브라우저**: 카톡 안 브라우저와 사파리는 저장 공간이 따로라 로그인 없이 나가면 작업을 잃는다. 사용자 에이전트에 `KAKAOTALK`이 있으면 위에 얇은 띠 — "로그인하면 어디서든 이어서 만들 수 있어요 [카카오로 저장] [사파리로 열기]". 사파리로 열기는 `kakaotalk://web/openExternal?url=…`, 만들던 글자는 넘어가지 않는다고 적는다.
- **처음 알림**: 로그인 안 한 사람이 글자를 처음 고친 뒤 한 번만 "저장하려면 로그인" 알림. 닫으면 다시 안 띄운다(브라우저에 기록).
- **탈퇴**: 계정 페이지(`/account`) 맨 아래 작은 `탈퇴하기` → 확인 창("30일 뒤 계정과 폰트가 지워져요. 그 전엔 이메일로 되살릴 수 있어요") → 서버 함수(security definer)가 탈퇴 표(`withdrawals`: user_id · 신청 시각)에 적고 로그아웃. 다음 로그인 때 탈퇴 표에 있으면 바로 로그아웃하고 "탈퇴한 계정이에요" 안내(약관 9조). 카카오 `연결 끊기`는 30일 뒤 지울 때 관리자 키로 부른다. 30일 지난 계정은 관리자 계정 화면에 `지울 차례`로 뜨고, 기존 `삭제`로 지운다(처리방침 4항 "운영자가 확인해 지웁니다"). 베타 계정도 같은 길.
- **카카오 버튼**: 카카오 디자인 가이드(노랑 #FEE500 · 말풍선 기호 · "카카오 로그인" 문구)를 따른다. 우리 단추 규칙(`Button`) 밖이라 `style-guard` 예외를 한 곳만 둔다.
- **처음 가입 동의**: 카카오에서 돌아온 첫 로그인에만 약관 · 처리방침 · 홍보 활용 · 만 14세 이상 네 칸(전체 동의 하나로 묶을 수 있음). 동의 시각을 계정에 남긴다. 안 하면 로그아웃.
- **실패 문구**: 카카오 계정에 이메일이 없거나 동의를 거부하면 Supabase가 오류로 돌려보낸다 → "카카오 계정에 이메일이 있어야 가입할 수 있어요" 한 줄.
- **돌아올 자리**: `redirectTo`에 누른 화면 주소를 넣어, 다운로드 직전에 로그인했으면 다운로드 화면으로 돌아온다.
- **Supabase 설정**: Kakao 공급자 켜기(Client ID = REST API 키, Secret = 클라이언트 시크릿). `Allow new users to sign up`을 켜야 카카오 가입이 된다. 그러면 익명 키로 이메일 가입도 열리므로, **이메일 가입은 서버에서 막는다** — Before User Created 훅이나 `auth.users` 트리거로 provider가 `email`이고 관리자 발급이 아닌 가입을 거절. 베타 계정 발급(`scripts/beta-accounts.mjs`, `service_role`)은 그대로 된다.
- **주소**: Site URL `https://hangulkangul.com`, Redirect URLs에 운영 · `hangul-mus.vercel.app` · 로컬.

## 진행 기록

**2026-10-07** 플랜 작성. 구현 없음.
- 사실: 지금은 `main.tsx`의 `gate()`가 로그인 안 된 사람에게 `BetaLoginPage`만 보인다. 게이트를 끈 길(`authGateMode() === 'off'` → `LOCAL_OWNER`)이 이미 있다. 폰트 한도는 `FONT_LIMIT = 3`(`accountFont.ts`)과 서버 트리거 3개(`20260925190000_font_projects_three_per_user.sql`) 두 곳.
- 사실: 사용자 결정 — 카톡 안 작업 지키기는 "띠 + 처음 알림". 게스트 계정은 출시 뒤.
- 사실: 사용자 결정 — 베타는 "코드 문 유지", 로그인은 다운로드 직전(들어올 때 X).
- 가설: Supabase Kakao 공급자는 이메일 동의가 있어야 계정을 만든다(이메일 필수 동의 = 비즈 앱 전환). 콘솔에서 확인 전.
- 사실: 탈퇴 기능은 아직 코드에 없다(`탈퇴` · `withdraw` 검색 0건, 약관 · 처리방침 문구만). 관리자 계정 화면에 정지 · 삭제는 있다.
- 미결정: 이메일 가입 막기를 훅으로 할지 트리거로 할지. 로그인 직후 한도가 찼을 때 문구.
