# 적용 범위 D0 계약

플랜의 A~E가 기대는 계약이다. 여기 없는 것은 구현이 정한다. 이 문서가 바뀌면 플랜 진행 기록에 한 줄 남긴다.

## 1. 범위 규칙식

```ts
/** 배치 Δ 하나가 닿는 글자 집합. 조건은 AND, 각 조건 안의 목록은 OR. */
interface ScopeRule {
  /** 홀자 계열. 없으면 안 따진다. */
  medialFamily?: ('right' | 'bottom' | 'mixed')[]
  /** 받침 유무. 없으면 안 따진다. */
  hasFinal?: boolean
  /** 부품별 자모 목록. 없으면 안 따진다. */
  initial?: string[]
  medial?: string[]
  /** 받침 자모 목록. `null`은 **받침 없음**이다. */
  final?: (string | null)[]
}
```

- **글자 판정**: 다섯 조건을 모두 만족하면 닿는다. `{}`는 11,172자 전부다.
- **넓이** = 닿는 글자 수. 세는 것은 한 번 하고 규칙식 키로 메모한다.
- **겹침**: 글자 하나에 여러 규칙이 닿으면 **넓은 것부터 좁은 것 순으로 더한다**. 같은 수면 `medialFamily → hasFinal → initial → medial → final` 순으로 조건이 먼저 붙은 쪽을 넓게 본다(결정적이어야 한다). 변 고정(`{ at }`)은 지금처럼 좁은 층이 값을 교체한다.
- **사용자가 만들 수 없는 것**: 조건이 하나도 없는 규칙(`{}`). 전체는 기본값 자리라 사용자 저장소에 새로 안 생긴다. 옛 저장분만 그 자리에 남는다.
- **저장 단위**: 자모를 여럿 골라 적용하면 **자모마다 규칙 하나씩** 쌓는다(`ㄱ·ㅋ` → `…|i=ㄱ`과 `…|i=ㅋ`). 지금 화면이 칩마다 `×`로 따로 지우기 때문이다. 목록 하나(`i=ㄱㅋ`)로 합쳐 한 박스로 보일지는 옵션 박스(플랜 B)에서 정한다 — 규칙식 자체는 목록을 받는다.
- **저장 키**: 규칙식을 정규화한 문자열(각 목록은 자모 순으로 정렬, 빈 조건은 빼고, 키 순서 고정). 같은 뜻이면 같은 키여야 한다. 받침 `없음`은 키에서 `0`으로 적는다(`n=0ㄱㄲ`).
- **받침 목록에 `없음`이 든다**(9/21). 표에서 `없` 열과 받침 열을 같이 끌면 나오는 모양이라 담을 자리가 있어야 한다. 목록이 `없음` 하나면 `hasFinal: false`로, 받침 자모 27개 전부면 `hasFinal: true`로 정규화가 접는다.

## 2. 옛 저장분 이전

한 번 읽고 새 모양으로 바꿔 쓴다. 읽기 전용 호환이 아니라 **이전**이다.

| 옛 | 새 |
|---|---|
| `all` | `{}` (읽기 전용 표시) |
| `layers['right-final']` | `{ medialFamily: ['right'], hasFinal: true }` |
| `jamo['right-final']['CH:ㄱ']` | `{ medialFamily: ['right'], hasFinal: true, initial: ['ㄱ'] }` |

`contextId`의 여섯 값은 `<계열>` 또는 `<계열>-final`이다. `JU:ㅘ`처럼 섞임홀자는 `medial: ['ㅘ']` 하나로 간다(가로부·세로부를 안 쪼갠다).

## 3. 이름 자동 생성

조건을 넓은 것부터 붙여 한 줄로 만든다. 사용자가 고쳐 쓰지 않는다(스토어에 이름을 저장하지 않는다).

- 계열+받침만: `오른쪽 홀자 · 받침` (지금 `LAYOUT_CONTEXT_LABEL` 그대로)
- 자모가 붙으면 뒤에 ` · <부품> <자모 목록>`: `오른쪽 홀자 · 받침 · 첫닿자 ㄱ·ㅋ`
- 자모가 넷 이상: `ㄱ 외 3`
- 부품이 둘 이상이면 부품마다 한 마디씩, `첫닿자 ㄱ · 받침 ㄴ`
- 조건 없음: `전체`

## 4. 옵션 박스

- **생김**: 범위를 고르는 순간(스택 맨 위 `옵션 추가`·범위 고르기 화면의 `이 범위로`). Δ가 아직 없으면 둘째 줄이 `아직 고친 것 없음`이다(점선은 9/22에 뺐다).
- **보이는 옵션**: 지금 고치는 글자에 **닿는 옵션만** 선다(9/22). 같은 칸이라도 `각`을 고칠 때 `첫닿자 ㅁ` 옵션은 안 보인다 — 이 글자에서 안 보이는 값을 고르고 저장하게 되기 때문이다. 옛 `전체`는 어디서나 보이고, 이 화면에서 방금 만든 빈 슬롯은 거르지 않는다. 켠 옵션이 이 글자에 안 닿게 되면 기본으로 돌아간다.
- **저장할 자리는 둘**(9/22): 보선을 옮기면 하단 바가 `복원(정사각 아이콘 + 바뀐 수) | 선택 옵션에 저장 | 신규 옵션에 저장`이 된다. **주 버튼은 신규**(파랑)고 선택 옵션은 보조(회색)다 — 보선을 끌 때의 뜻은 대개 `이 자모가 이상하다`고, 넓은 범위에 잘못 저장하는 쪽이 더 비싸다. 두 버튼 다 아랫줄에 저장될 범위와 글자 수를 적는다(`이 레이아웃 · 4,617자` / `첫닿자 ㅂ · 243자`). `선택 옵션에 저장`은 라디오로 켠 옵션(기본 `이 레이아웃`)에 저장한다 — 어느 옵션인지는 라디오가 말하므로 버튼에 이름을 안 적는다(읽어 주는 말에는 있다). `신규 옵션에 저장`은 옮긴 값을 든 채 범위 고르기 화면을 열고 — 방금 옮긴 부품의 지금 글자 자모 하나가 골라져 있고 그대로 확정할 수 있다 — 확정하면 그 범위에 바로 저장하고 그 옵션을 켠다. 같은 범위의 옵션이 이미 있으면 거기에 더해진다. 취소하면 옮긴 값은 그대로 남는다.
- **사라짐**: Δ가 0인 박스는 범위가 바뀌거나 글자를 떠나면 사라진다. 저장은 `pruned`가 지금 하는 그대로다.
- **순서**: **좁은 것이 위**(9/22 뒤집힘 — 닿는 글자 수 오름차순). 좁힌 범위가 위에 쌓이고 `이 레이아웃`은 `기본` 머리글 아래, 옛 `전체`는 그 아래 맨 끝. Δ를 더하는 순서(§1 겹침, 넓은 것부터)는 그대로고 화면만 뒤집는다.
- **이름**: 좁힌 축마다 부품 색 알약 하나(`첫닿자 ㅂ·ㅃ` × `받침 ㄹ`), 바로 옆에 닿는 글자 수. 읽어 주는 말(`aria-label`)은 §3 이름 그대로다. 좁힌 축이 없으면 `이 레이아웃`.
- **둘째 줄**: 부품 점 + 고친 자리 수(`첫닿자 3 · 받침 2`). 값은 `title`과 읽어 주는 말에만 싣는다.
- **고르기**: 줄 전체를 누르면 켜지고 앞머리 라디오(파란 체크 원)가 그걸 말한다. 켠 줄만 옅은 파란 면이 깔리고 **연필(범위 고치기)과 `×`는 켠 줄에만** 선다.
- **생김새**: 카드가 아니라 줄이다. 테두리·그림자·점선 없이 면과 여백으로 가르고, 강조는 파랑 하나. `옵션 추가`는 회색 면 버튼, `기본`은 글 옆으로 가는 선 하나가 붙은 머리글.
- **접힘**: 넷 이상이면 기본 접힘, 켠 박스는 접혀도 보인다.
- **머리 그림**: 그 규칙의 몬드리안. 자모 조건이 붙은 부품은 **전부** 꽉 찬 칸, 나머지는 같은 색 테두리 칸. 계열 조건이 둘 이상이면 첫 계열로 그린다.
- **`×`**: 그 규칙 하나만 지운다. Undo가 스냅샷으로 되돌린다(지금과 같다).

## 5. 상단 두 줄

- `내 문장`(위) · `닿는 글자`(아래). **글자 크기와 칸 높이가 같다.** 줄 높이는 고정이라 범위가 바뀌어도 아래가 안 밀린다.
- `닿는 글자`는 **다섯 장**을 보이고 옆으로 밀어 더 본다(지금 표본 카드의 묶음 이어 붙이기를 그대로 쓴다).
- 글자를 누르면 그 글자를 연다. 두 줄 다 같은 동작.
- 적용 직후 `내 문장`에서 방금 범위에 든 글자를 표시한다. 다음 편집이 시작되면 지운다.
- **획 편집에도 같은 줄이 선다**(9/21). 범위는 고치는 자모가 든 글자 전부고 레이아웃을 안 가린다(`모든 ㅁ 글자`). 줄이 한쪽에만 있으면 `획 고치기`로 오갈 때 캔버스가 44px 튄다.

## 6. 범위 고르기 화면

9/21에 다시 잡았다. 아래가 지금 계약이고, 뒤집힌 것은 그 자리에 적어 둔다.

- `NotoCorpusMatrix`에 `variant: 'picker'`를 더한다. `lab`·`viewer`의 동작은 안 바뀐다.
- **표는 행 홀자 × 열 받침 한 장**이다. 첫 열이 `없`(받침 없음)이라 발치의 받침 세그먼트(`전부 · 있음 · 없음`)는 없앴다. — **뒤집힘**: 9/21 오전 계약의 `행 홀자 × 열 첫닿자 + 받침 세그먼트`.
- **첫닿자는 표 위 한 줄**이다(19개, 가로로 민다). 시트 탭 줄은 없앴다. 누르면 표가 그 자모로 다시 그려질 뿐 범위는 안 바뀐다. 범위에 든 자모는 진하게 두고, 줄 머리에 `전부` 또는 `N개`를 적는다(시트로 접힌 축의 뜻).
- **범위 = 사각 하나.** 지나간 행·열의 곱이다. 칸 하나도 사각 하나고, 머리(행·열)는 그 줄 통째 = 한 축이 전부인 사각이다. **새로 집으면 갈아치운다**(더하지 않는다). 표 밖 축(첫닿자)의 조건은 그대로 남는다.
  - **뒤집힘**: `칸 누르기는 크게 보기`와 `머리 토글·쓸기`. 크게 보기는 없앴다 — 표의 켠 칸이 이미 표본이고, 칸에 Δ를 안 얹으니 크게 볼 이유가 없다.
  - 손가락은 표를 미는 데 먼저 쓴다. 탭은 그 자리 하나를 집고, **220ms 꾹 누른 뒤** 끌어야 사각이 된다. 마우스는 누르는 즉시 끈다.
- 하단 표본 줄(`멈` + 표본 여섯 + `외 N자`)은 없앴다. 수는 머리에 있다.
- 칸은 프로젝트 획으로 그리되 **보이는 칸만** 그리고(`CellGlyph`), **Δ는 안 얹는다**(9/21). 588칸을 한 번에 그리면 열 때 1.3초·조작 한 번에 1.1초라 사각 끌기가 안 된다 — 보이는 칸만 + `memo`면 115ms·33ms다. Δ가 10~20u라 26px 칸에서는 안 보이고, 칸이 답하는 질문은 `이 범위에 어떤 글자가 들었나`다. Δ는 상단 `닿는 글자` 줄이 답한다.
- **생김새**: 칸은 정사각 26px, 칸 사이는 선이 아니라 5px 여백(간격 31px). 켜짐은 **검정 글자 + 머리에 2px 바**, 꺼짐은 흐린 회색. 주황 강조와 그룹 머리 줄(`첫닿자 · 19`, `세로/가로/혼합`)은 없앴고 묶음 경계는 1px 옅은 선 하나다. 추천 칩은 짧은 이름(`구조군 ㅁ`)에 높이 27px 회색이고 켠 것만 검정이다.
- 28열이 390px에 다 안 들어가 표는 가로로 민다(칸에 글자를 그리기로 한 값이다).
- **추천 칩은 표를 켜 줄 뿐이다.** 누르면 그 칩의 규칙으로 **갈아치운다**(합치지 않는다). 같은 칩을 다시 누르면 꺼지고 바로 앞 규칙으로 돌아간다.
- 머리의 닿는 글자 수와 이름은 고르는 동안 계속 갱신한다.
- `취소`는 열기 전 규칙으로 되돌린다. `이 범위로`가 확정한다.

## 7. 추천 칩

한 번에 넷까지, 이 순서로 고른다.

1. **구조군** — 잡은 부품과 문맥으로 기준을 고른다(`criterionFor`): 첫닿자면 계열 + 받침 유무로 넷 중 하나, 받침이면 `finalHorizontalMixed`/`finalVertical`. 같은 그룹 번호의 자모 전부. 홀자를 잡았으면 이 칩은 없다(구조군은 닿자 표라서).
2. **rail 역할** — 잡은 rail의 역할을 가진 홀자 전부(`바깥기둥 있는 홀자`). 역할 이름은 `ROLE_LABEL`을 쓴다.
3. **속공간** — 잡은 부품 자모의 `inkSpaceGroup`이 같은 자모 전부.
4. **높이** — 잡은 부품 자모의 `height`가 같은 자모 전부(`2줄`·`3줄`).

## 8. 구조군 JSON

`src/data/jamoLiteratureGroups.json` 하나가 출처다.

```ts
interface JamoLiteratureGroup {
  initialHorizontal?: number            // 가로모임 받친글자 · 첫닿자
  initialHorizontalNoFinal?: number     // 가로모임 민글자 · 첫닿자
  initialVertical?: number              // 세로모임 받친글자 · 첫닿자
  initialVerticalNoFinal?: number       // 세로모임 민글자 · 첫닿자
  finalHorizontalMixed?: number         // 가로·섞임모임 · 받침닿자
  finalVertical?: number                // 세로모임 · 받침닿자
  height?: string                       // 문헌_높이 (`2줄` · `3줄`)
  inkSpaceGroup?: string                // 문헌_속공간_그룹 (`S1`…)
}
type JamoLiteratureGroups = Record<string, JamoLiteratureGroup> // 30자모(첫닿자 19 + 겹받침 11)
```

- **기준은 여섯이다.** 같은 자모라도 홀자 자리와 **받침 유무**로 묶음이 갈린다(민글자 ㅋ은 혼자, 받친글자 ㅋ은 ㄷㅁㅇㅈ과 한 묶음). 옵시디언 노트에는 받친글자 넷뿐이라, 민글자 둘은 랩 상수에서 왔다.
- 자리가 없는 칸은 비어 있다 — 겹받침에는 첫닿자 기준이, ㄸ·ㅃ·ㅉ에는 받침 기준이 없다. 없으면 구조군 칩을 안 만든다.
- 섞임(`mixed`) 첫닿자 기준은 표에 없다. 가로모임 것을 쓴다(받침은 `가로·섞임`이 둘을 같이 덮는다).
- `ReferenceGroupLabPage.tsx`의 상수 배열은 이 JSON에서 만든다(그룹 번호 → 자모 목록).
- 거울은 `npm run jamo:groups:docs` → 옵시디언 `자모 데이터/자모 구조군 표.md` 한 장. **JSON → 볼트 한 방향**이고, 사용자가 `문서화해`라고 할 때만 돌린다. 자모별 노트 30장은 안 건드린다.

## 안 바뀌는 것

Δ의 뜻과 단위(em), 변 고정 `{ at }`의 교체 규칙, 사용자 저장소와 프리셋 오버라이드의 분리(앱은 프리셋에 안 쓴다), 적용 전 세션 편집(복원·Undo), 획 편집·문장 보정(`/`) 화면, `NotoCorpusMatrix`의 `lab`·`viewer` 동작.
