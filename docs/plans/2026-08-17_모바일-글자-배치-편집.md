# 모바일 레이아웃 편집

사용자 화면에서도 `글자 배치` 대신 `레이아웃`을 기본 명칭으로 사용한다.

트랙패드가 아직 나타나지 않은 초기 글자 선택 상태를 자소 편집과 레이아웃 편집의 공통 진입점으로 사용한다. 별도 상단 버튼이나 선행 화면을 추가하지 않는다.

- 자소를 선택하면 자소 전체 → 획 → 점 편집으로 들어가고 트랙패드가 나타난다.
- 레이아웃 진입 표시를 선택하면 같은 글자 위에 파트 영역, 분할선, 패딩을 표시한다.
- 분할선이나 패딩을 선택한 뒤에만 레이아웃 전용 조절 UI가 나타난다.
- 뒤로 가면 레이아웃 요소 선택을 먼저 해제하고 초기 글자 선택 상태로 돌아간다.
- `레이아웃` 진입점은 트랙패드가 열린 자소·획·점 편집 상태에서도 같은 위치에 유지한다. 실제 드래그 중에만 미확정 변경을 보호하기 위해 잠시 비활성화한다.

초기 화면에서 자소 선택 영역과 모든 레이아웃 핸들을 동시에 강하게 표시하지 않는다. 글자 주변에 작지만 명확한 `레이아웃` 진입 표시를 두고, 진입한 뒤에만 분할선과 패딩을 펼쳐 선택 충돌과 시각적 복잡도를 줄인다.

배치 변경은 현재 글자 하나가 아니라 **같은 레이아웃 유형 전체에 귀속**된다. 예를 들어 `가로모음 + 받침` 배치를 수정하면 그 구조를 사용하는 모든 글자에 함께 반영한다.

- 조정할 파트 영역, 분할선, 여백을 글자 화면에서 선택
- 선택된 배치 요소의 실제 이동은 하단 트랙패드에서 조작
- 현재 글자를 유지해 배치 변화 즉시 확인
- `가로모음 + 받침 전체에 적용`처럼 적용 범위를 편집 화면에 상시 표시
- 영향을 받는 대표 글자를 함께 보여줘 전체 변화를 예측하게 함
- 레이아웃 편집을 닫으면 초기 글자 선택 상태로 복귀
- 자소 편집과 배치 편집의 변경을 같은 히스토리에서 추적

레이아웃 편집은 같은 레이아웃 유형의 분할선과 패딩을 바꾸는 기능이다. 자소 기본형이나 자소 계보의 `현재 레이아웃 보정`과 데이터 귀속을 분리한다.

## 다음 논의

- 패딩·분할선·전체 비율의 모바일 조작 우선순위
- 배치 변경이 영향을 주는 대표 글자 표시 방식

## 구현 기록

2026-08-18 첫 단계로 `레이아웃` 진입점을 추가했다. 진입하면 현재 글자를 유지한 채 파트 영역과 같은 구조 전체 적용 범위를 보여주고, 뒤로 가면 트랙패드가 없는 초기 상태로 돌아간다. 이후 트랙패드가 열린 편집 상태에서도 진입점을 계속 표시하도록 확장했다. 실제 드래그 중에는 전환을 막는다. 아직 분할선·패딩 선택과 실제 값 조절은 연결하지 않았다. 빌드, 단위 테스트, 모바일 브라우저 전환 테스트를 통과했다.

## 파트 사이 갭 모델 기술 검토

레이아웃 편집의 주 조작 대상을 바깥 패딩과 파트별 오버라이드 대신 파트 사이의 `갭`으로 바꾸는 방향을 우선안으로 검토한다. 사용자는 글자 안에서 실제로 벌리고 싶은 사이를 직접 고른다.

예를 들어 `밤`의 ㅂ–ㅏ 사이 갭을 선택해 값을 늘릴 수 있다.

- 기본값은 ㅂ과 ㅏ가 모두 조절 대상으로 활성화된 상태다. 양쪽에서 절반씩 공간을 내어 갭 중심을 유지한다.
- ㅂ을 비활성화하면 ㅂ의 오른쪽 경계는 유지하고 활성 상태인 ㅏ의 왼쪽 경계만 움직인다.
- ㅏ를 비활성화하면 ㅏ의 왼쪽 경계는 유지하고 활성 상태인 ㅂ의 오른쪽 경계만 움직인다.
- 두 파트를 동시에 비활성화할 수는 없다. 최소 한쪽은 조절 대상으로 남긴다.

갭은 레이아웃 스키마의 1급 데이터로 두는 편이 안전하다. 각 갭은 축, 경계 양쪽의 파트 묶음, 크기, 공간을 어느 쪽에서 낼지를 가진다.

```ts
interface LayoutGap {
  id: string
  axis: 'x' | 'y'
  before: Part[]
  after: Part[]
  size: number
  anchor: 'before' | 'center' | 'after'
}
```

`anchor`는 화면에 노출하지 않는 내부 계산 값이다. `before`는 앞쪽 비활성, `after`는 뒤쪽 비활성, `center`는 양쪽 활성에 대응한다. 파트 활성 상태와 갭 경계 이동량은 스키마와 히스토리에 함께 저장한다.

계산 순서는 `Split으로 기본 영역 계산 → 갭으로 맞닿은 경계 축소 → 광학 보정 적용`으로 둔다. 갭이 Split 자체를 움직이지 않게 해야 파트 비율 변경과 사이 간격 변경의 역할이 섞이지 않는다.

현재 `partOverrides`에는 실제 파트 사이 간격과 광학적 크기·위치 보정이 섞여 있어 기존 값을 갭으로 완전히 자동 변환할 수 없다. 첫 전환에서는 기존 렌더링을 유지한 채 새 갭을 추가 적용하고, 기본 프리셋별로 기존 안쪽 오버라이드를 사람이 검토해 갭과 광학 보정으로 나누는 마이그레이션이 필요하다. 새 모바일 UI에서는 기존 파트별 오버라이드를 직접 노출하지 않는다.

글자 바깥 여백은 갭과 역할이 다르므로 데이터에서 제거하지 않는다. 단독 자소와 캔버스 가장자리 안전 여백에 필요하다. 모바일 레이아웃 MVP에서는 고정 기본값으로 두거나 별도 고급 설정으로 미루고, 주 편집 화면에는 파트 사이 갭만 노출한다.

혼합중성은 사각형 둘의 단순 경계가 아니라 T자 형태가 생긴다. 박스 좌표에서 자동 추론하지 않고 레이아웃 타입별 인접 관계를 명시한다. 예를 들어 혼합중성+종성은 `CH–JU_V`, `CH–JU_H`, `JU_H–JO`, `JU_V–JO`처럼 실제로 맞닿는 구간만 선택 가능하게 한다.

첫 기술 구현 범위는 세로모음 레이아웃의 좌우 갭 하나로 제한한다. `가·밤` 계열에서 갭 선택, 양쪽 활성, 한쪽 비활성, 최소 파트 크기 제한, 실행 취소를 검증한 뒤 상하 구조와 혼합중성으로 확장한다.

아직 결정하지 않은 항목은 갭 크기를 절대 정규화 값으로 저장할지, 해당 축 길이에 대한 비율로 저장할지와 기존 프리셋의 파트 오버라이드를 어디까지 광학 보정으로 유지할지다.

2026-08-18 첫 기술 범위를 구현했다. 세로중성 레이아웃과 세로중성+받침 레이아웃에서 초성–중성 사이 세로 갭을 선택하고 0.5% 단위로 좁히거나 넓힌다. 갭 크기와 조절 대상은 레이아웃 스키마에 저장하고 같은 레이아웃 유형 전체에 적용하며, 히스토리와 즉시 취소를 지원한다. 최소 파트 크기는 10%로 제한했다.

구현은 기존 프리셋을 보존하기 위해 갭 기본값을 0으로 두고 `Split → Gap → 기존 partOverrides` 순서로 계산한다. 32개 단위 테스트, 레이아웃 관련 모바일 브라우저 테스트 3개, 320×568 최소 화면 검증과 빌드를 통과했다. 상하 갭, 혼합중성, 기존 오버라이드 마이그레이션은 아직 구현하지 않았다.

### 갭 조작 UI

첫 구현의 고정 버튼은 제거했다. 화면에서는 `고정`이나 `잠금` 개념을 사용하지 않고 조절 대상의 활성·비활성만 보여준다.

- 갭을 선택하면 인접한 두 파트가 모두 활성 상태로 표시된다.
- 파트를 탭하면 해당 파트가 조절 대상에서 해제되고 다른 활성 파트 쪽 경계만 움직인다.
- 비활성 파트를 다시 탭하면 양쪽 활성 상태로 돌아간다.
- 최소 한쪽은 항상 활성 상태로 유지한다.
- 활성 상태는 색만으로 표시하지 않고 외곽선, `활성 · 제외` 문구와 `aria-pressed`를 함께 사용한다.

갭 경계 직접 드래그를 기본 조작으로 사용한다. 양쪽이 활성 상태면 갭 중심을 유지하며 두 경계를 같은 거리로 움직인다. 한쪽이 비활성 상태면 현재 경계를 유지하고 활성 파트 쪽만 움직인다. 드래그 중에는 현재 갭 값과 영향을 받는 파트 크기를 실시간으로 표시하고, 손을 떼면 변경 한 건으로 저장한다.

직접 드래그만으로 0.5% 단위를 맞추기 어려우므로 갭 선택 후 하단에는 기존 트랙패드의 납작한 1축 버전을 보조 입력기로 둔다. 좌우 이동만 받고, 왼쪽은 좁히기, 오른쪽은 넓히기로 일관되게 동작한다. 직접 드래그는 큰 조절, 납작한 트랙패드는 미세 보정을 담당하며 같은 임시 값과 히스토리 경계를 공유한다.

세로중성 좌우 갭에서 파트 활성 전환, 경계 직접 드래그, 납작한 1축 트랙패드까지 검증한 뒤 다른 레이아웃으로 확장한다.

2026-08-18 직접 조작 UI를 구현했다. 갭 경계를 드래그하면 캔버스 폭 기준으로 크게 조절되고, 하단의 납작한 1축 트랙패드는 낮은 감도의 미세 조절과 좌우 방향키를 지원한다. 두 입력은 같은 실시간 프리뷰와 손을 뗄 때 한 건 저장 규칙을 사용한다.

빌드, 32개 단위 테스트, 변경 파일 린트, 레이아웃 모바일 브라우저 테스트 3개와 320×568 최소 화면 검증을 통과했다. 상하 갭과 혼합중성은 아직 지원하지 않는다.

활성 대상을 바꿀 때 기존 갭을 새 기준으로 재분배해 파트 너비가 초기 위치처럼 튀는 문제가 확인됐다. 갭을 양쪽 경계 이동량으로 따로 저장하도록 수정해, 활성 상태 변경은 현재 보이는 경계를 그대로 유지하고 이후 변화가 적용될 쪽만 바꾼다. 이전 `size + anchor` 데이터도 같은 경계 이동량으로 변환해 읽는다.

갭은 0 아래의 음수 값도 허용한다. 음수는 파트 사이 중첩을 뜻하며 현재 최소값은 -25%다. 화면에는 `-0.5% · 중첩`처럼 의미를 함께 표시하고 겹치는 영역은 별도 패턴으로 강조한다. 한쪽이 비활성 상태면 중첩 역시 활성 파트 쪽 경계만 넘어간다. 관련 단위 테스트는 35개로 늘었고 모바일 브라우저에서 경계 유지, 음수 중첩, 실행 취소를 검증했다.

2026-08-18 파트 선택 표현을 활성 모델로 교체했다. 갭을 선택하면 양쪽 파트가 기본 활성 상태이며, 한쪽을 탭하면 해당 파트가 제외된다. 화면에서 자물쇠와 `고정` 문구를 제거하고 `활성 · 제외` 상태로 표시한다. 양쪽 활성은 전체 갭을 함께 조절하고, 한쪽 제외는 활성 파트 쪽만 조절한다.
