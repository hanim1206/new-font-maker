# OTF 경량화 — CFF 서브루틴

- **이번에 비교하는 것**: 지금 OTF(CFF, 서브루틴 없음)와, 같은 윤곽에 서브루틴을 붙인 OTF.
- **이번 승인으로 바뀌는 것**: 추출 마지막에 CFF 서브루틴 단계를 하나 붙인다. 파일 크기와 추출 시간이 바뀐다.
- **바뀌지 않는 것**: 글자 모양(한 점도 안 바뀐다), 획 → 윤곽 → 합치기 과정, 글리프 수 · 이름 · 메트릭, 곡선 다시 맞추기(다음 플랜).

출처: 9/29 논의. 곡선 · 붓 굵기 기능이 들어오면 파일이 커지니 변환 비용을 줄이자. 먼저 일반 고딕 용량을 재고 거기에 맞춘다.

## 지금 상태 (사실)

한글 11,172자 윤곽만 잰 값. 측정은 fontTools, 우리 폰트는 `npm run font:sample`(기본 스토어 상태).

| 폰트 | 파일 | 한글 윤곽 | 글자당 | 비고 |
|---|---|---|---|---|
| 나눔고딕 | 2.05MB | 1.37MB | 122B | 컴포넌트 79% |
| Apple SD 산돌고딕 Neo | 약 3.1MB | 1.70MB | 152B | CFF, 서브루틴 없음 |
| 노토 산스 KR | 10.4MB(가변) | 2.27MB | 203B | |
| IBM Plex Sans KR | 2.80MB | 2.45MB | 220B | |
| 고운돋움 | 7.23MB | 6.77MB | 606B | 곡선 많음 |
| **우리 기본** | **3.61MB** | **3.39MB** | **304B** | 곡선 0%, 글자당 점 92개 |

- 컴포넌트 안 쓰는 고딕의 기준선은 **글자당 150–220B, 파일 2–3MB**.
- 우리는 곡선을 전부 직선으로 쪼개고(`strokeToOutline.ts` 구간당 8–48개), Clipper2 합치기도 다각형이라 `RLINETO`만 나온다. 추출은 Node 기준 14.8초, 메인 스레드.
- `cffsubr`(fontTools, AFDKO `tx`)를 파일에 한 번 돌리면 **3.61MB → 1.82MB (−50%)**. 무손실.
- 같은 윤곽 고리를 통째로 재사용하는 단순한 방식은 −12%(0.44MB)에 그친다. 고리 5만 725개 중 고유 3만 1,490개. 합치기가 고리를 조금씩 바꿔 놓아서, 고리 단위보다 짧은 명령 조각 단위로 찾아야 한다.
- 사용자 다운로드 폴더의 옛 추출본: 납작체 8.8MB, 초딩무스 6.9MB, 삐뚤 3.4MB.

## 계약 (D0에서 정할 것)

- **어디서 돌리나**: 브라우저 안(Worker)에서. 서버 왕복은 로그인 · 네트워크가 끼니 뺀다.
- **어떻게 만드나** — D0에서 하나를 고른다. 비교 기준은 절감률 · 번들 크기 · 추출 시간.
  - (가) AFDKO `tx` 또는 `compreffor`를 WASM으로 빌드해 쓴다. 검증된 결과지만 번들이 무겁다.
  - (나) compreffor 방식(접미사 배열 + 탐욕 선택)을 TS로 옮긴다. 가볍지만 직접 검증해야 한다.
- **규칙**: 전역 서브루틴만 쓴다(FD 하나). CFF 한도는 지킨다(서브루틴 수 · 호출 깊이 10). `validateOpenTypeForIOS`를 그대로 통과해야 한다.
- **목표**: 기본 폰트 **2.0MB 이하**, 추가 시간은 데스크톱 추출의 30% 이하, 아이폰에서 메모리 때문에 죽지 않는다.
