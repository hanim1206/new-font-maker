# 피드백 보드 스킬

보드: `/Users/hanim/Documents/Obsidian Vault/개인 프로젝트/폰트메이커/피드백 보드.base`
노트: 같은 폴더 `피드백/NN_짧은-제목.md` (NN은 두 자리, 다음 번호는 `ls`로 가장 큰 번호 + 1)

## 발동

첫 줄이 `피드백:`일 때만. 예외는 `구현: NN`(번호 있을 때 → 시작 동작). 그 외 대화에서 버그 얘기가 나와도 노트를 만들지 않는다. 필요하면 "피드백에 넣을까?" 한 줄만 묻는다.

## 동작

| 말 | 동작 |
|---|---|
| `피드백: <자연어>` | 추가. 노트 만들고 속성 추측해 채운 뒤 한 줄로 되묻는다 |
| `피드백: NN 시작` · `구현: NN` | `status` → `🔨 진행`. 묶음 제안(아래) |
| `피드백: NN 끝` | `status` → `✅ 완료`, `done` 오늘, `## 해결`에 불릿(커밋 해시 포함) |
| `피드백: NN 보류` | `status` → `⏸️ 보류`, 해결에 왜 한 줄 |
| `피드백: NN 재오픈` | `status` → `🔨 진행`, `reopened` +1, `confirmed` false, 해결에 왜 한 줄 |
| `피드백: NN 확인` | `confirmed` → true (사용자가 직접 써 보고 됐다고 한 것 = G3) |
| `피드백: 정리` | 이번 세션에서 바뀐 항목만 한 줄씩. 남은 🔴🔴는 개수만 |

여러 항목을 한 줄에 말하면 각각 노트로. 번호 없이 제목으로 말하면 `grep -l`로 찾는다.

## 노트 형식

```markdown
---
area: 피드백
id: 29
title: "짧은 제목"
priority: "🔴 P0"
rank: 1
status: "⏳ 대기"
kind: "🐛 이슈"
part: "편집 · 획"
summary: "사용자 원문 한 줄"
confirmed: false
source: "2026-09-25 금"
created: 2026-09-25
related: []
plan:
reopened: 0
---

# 29 짧은 제목

**항목** 사용자 원문

**AI 근거** 왜 이 우선순위인지 한 줄

## 해결
```

속성 값은 정해진 것만 쓴다.

- `priority` ↔ `rank`: `🔴🔴 베타 전`=0 · `🔴 P0`=1 · `🟡 P1`=2 · `⚪ P2`=3
- `status`: `⏳ 대기` `🔨 진행` `✅ 완료` `⏸️ 보류`
- `kind`: `🐛 이슈` `✨ 개선` `🔍 검토`
- `part`: `영역 · 세부`. 영역은 `입력` `생성 엔진` `편집` `출력` `공통 기반` `출시·운영`. 세부는 기존 노트에서 쓴 말을 먼저 찾아 쓴다(`grep -h '^part:' 피드백/*.md | sort -u`)
- `related`: 다른 피드백 노트 위키링크 목록 `["[[28_아이폰-드래그-멈춤]]"]`
- `plan`: 이 항목이 플랜으로 커지면 `docs/plans/` 파일명. 플랜 문서 맨 위에도 `feedback: [29]` 한 줄을 둔다
- `done`: 완료한 날. 완료 전엔 키 자체를 안 넣는다
- `project:` 속성은 넣지 않는다(작업 대시보드가 전 문서를 잡아 버린다)

`## 해결` 불릿은 날짜순, 사실 / 결정(나·AI) / 커밋 해시. QA에서 써 본 결과도 같은 노트의 이 절에 불릿으로 쓴다. 별도 노트를 만들지 않는다.

## 추가할 때 추측하는 법

- `kind`: 안 된다·멈춘다·틀리다 → 🐛, 있으면 좋겠다·바꾸자 → ✨, 맞는지 봐 달라·결정 → 🔍
- `priority`: 베타 테스터가 막히는 것 → 🔴🔴, 자주 밟는 오동작 → 🔴, 나머지 ✨는 🟡, 먼 것 ⚪
- `part`: 화면 이름·기능 이름으로. 모르면 `공통 기반`
- `related`: 같은 `part`의 열린 노트 제목과 겹치는 말이 있으면 넣는다

만든 뒤 답은 한 줄: `29 짧은-제목 · 🐛 · 🔴 P0 · 편집 · 획. 맞아?` 사용자가 고치면 속성만 고친다.

## 시작할 때 묶음 제안

`시작` 또는 `구현: NN`이면 먼저 이걸 돌린다.

```bash
cd "/Users/hanim/Documents/Obsidian Vault/개인 프로젝트/폰트메이커/피드백"
grep -l "^part: \"<같은 영역>" *.md | xargs grep -L "✅ 완료"
```

같은 `part`의 열린 항목 + `related`에 적힌 것을 표로 보여 주고 "같이 갈까" 묻는다. 최대 셋. 사용자가 고른 것만 🔨로 같이 바꾸고 서로 `related`에 넣는다. 안 고른 건 건드리지 않는다.

## 세션 시작 규칙

`피드백:` 세션이 아니어도 코드를 고치는 세션이면 처음에 🔨 항목을 한 번 본다.

```bash
grep -l "🔨 진행" "/Users/hanim/Documents/Obsidian Vault/개인 프로젝트/폰트메이커/피드백/"*.md
```

그게 지금 하는 일이다. 진행 중 플랜은 그 노트의 `plan` 속성이 가리킨다.

## 하지 않는 것

- 키워드 없이 노트 생성·수정
- `confirmed`를 AI가 true로 바꾸기(사용자가 `확인`이라고 했을 때만)
- 원칙·결정 문서 수정(그건 `마무리` 규칙)
- 완료한 노트 본문 다시 쓰기(해결에 불릿만 붙인다)
