## 지금 상태 (사실, 코드 조사)

- Supabase 이메일·비번 로그인이 `src/stores/authStore.ts`에 있지만, 부르는 곳은 죽은 옛 편집기(`src/components/AuthForm.tsx` 등)뿐이다. `src-next`에는 로그인이 없다.
- `font_projects` 테이블의 `user_id`는 빈 값이 허용된다(`src/types/database.ts:80`). 로그인 안 한 상태의 `list()`는 걸러 내지 않고 전부 조회한다(`fontProjectService.ts`). 행 단위 권한(RLS)이 켜져 있는지는 레포에 마이그레이션이 없어 모른다.
- 레포 마이그레이션은 버전 되돌림을 막는 트리거 하나뿐이다.

## 계약 (D0 안)

- **코드 모양**: `K7QM-4XPA-9TRD`처럼 4자 세 묶음. 헷갈리는 글자(0 O 1 I L)는 뺀다. 입력할 때 대소문자, 하이픈, 공백은 봐준다.
- **코드 → 계정**: 앞 묶음이 계정 이름, 코드 전체가 비번이다. 앱은 `k7qm@beta.<도메인>`으로 로그인한다. 코드와 이메일을 잇는 표가 필요 없다. 친구는 이메일을 보지 않는다.
- **계정 만들기**: 로컬에서만 도는 `scripts/beta-accounts.mjs`. `service_role` 키로 `admin.createUser`(메일 인증 완료로)를 호출하고, `이름 · 코드` 목록을 파일로 떨군다. 이 키와 목록은 커밋하지 않는다(`.gitignore`). `VITE_` 환경변수에 넣지 않는다.
- **가입 막기**: Supabase 대시보드에서 `Allow new users to sign up`을 끈다. 앱에는 가입 화면이 없다.
- **권한**: `font_projects`에 RLS를 켜고, 본인 행만 읽고 쓰는 정책을 마이그레이션으로 둔다(26번이 저장을 붙이기 전에 먼저).
- **로그인 유지**: Supabase 기본값(브라우저에 세션을 두고 자동 갱신). 로그아웃은 메뉴 깊은 곳에만 둔다.
- **코드를 잊으면**: 카톡으로 나에게 묻는다. 같은 계정에 새 코드를 발급하면(비번 교체) 폰트는 그대로 남는다.
- **화면**: 제품 주소 전체 앞에 게이트. 로그인 안 됐으면 코드 입력칸 하나 + `들어가기`. 틀리면 "코드를 다시 확인해 주세요" 한 줄.
