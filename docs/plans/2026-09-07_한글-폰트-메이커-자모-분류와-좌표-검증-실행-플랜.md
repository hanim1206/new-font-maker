# 한글 폰트 메이커 자모 분류와 좌표 검증 실행 플랜

> 분류로 좌표 근거를 만들고 → 이론 프레임을 세우고 → 실제 폰트로 검증하고 → 채택값을 자산화하고 → 필요한 자모만 예외 처리한다.

## 목표

이용제의 닿자 분류를 출발점으로, `자모 × 조합문맥` 단위의 재사용 가능한 PartFrame·Guide 규칙과 자모 원자 데이터를 만든다. 결과물은 연구 노트가 아니라 Font Maker 엔진 규칙으로 옮길 수 있는 데이터 자산이다.

## 핵심 원칙

1. **이용제 분류는 분류 근거만 제공한다.** 같은 그룹에 속한 자모가 기본 규칙을 공유할 후보라는 뜻이다. 논문은 좌표·크기·오프셋 수치를 제공하지 않는다.
2. **분류값 / 이론값 / 관찰값 / 채택값을 분리한다.** 논문 근거, 그리드 가설, 무료폰트 관찰, Font Maker 적용값을 한 값으로 섞지 않는다.
3. **자모만이 아니라 `자모 × 조합문맥`을 기록 단위로 본다.** 예: `ㄱ × 가로모임 초성`과 `ㄱ × 세로모임 초성`은 다른 geometry를 가질 수 있다.
4. **그룹 기본값을 먼저 만들고 상속한다.** 개별 자모 좌표 하드코딩 금지. 반복 검증된 차이만 자모별 override로 둔다.
5. **무료폰트는 규칙 발명 도구가 아니라 검증 게이트다.** 이론값을 대체하지 않고, 반복 관찰된 차이를 확인하는 근거로 쓴다.
6. **근거와 결정은 추적 가능해야 한다.** 채택값마다 출처, 샘플, 판단 이유, 검토 상태를 남긴다.

## 데이터 흐름

```text
이용제 분류값
  → 그룹별 이론값
  → 무료폰트 관찰값
  → 비교·판단
  → 채택값
  → 그룹 기본값 상속 + 자모별 override
```

## 권장 데이터 구조

```yaml
jamo: ㄱ
context: initial-vertical

classification:
  source: lee-yongje
  height-class: 2-line
  inner-space-group: IS-01
  context-group: IV-01

geometry:
  theoretical:
    part-frame: initial-vertical-base
    guide-binding: { top: guide-1, bottom: guide-3 }
  observed:
    samples: []
    summary: null
  adopted:
    part-frame: initial-vertical-base
    guide-binding: { top: guide-1, bottom: guide-3 }
    optical-offset: { x: 0, y: 0 }
    confidence: unverified

override: null
```

`classification`은 논문 근거다. `geometry.theoretical`부터 Font Maker 설계값이다. `observed`와 `adopted`는 절대 덮어쓰지 않는다.

## 1. 이용제 분류 전체 데이터화

### 시작 폴더 구조

1단계 시작에는 하위 분류를 만들지 않는다. 분류법이 검증되기 전 폴더 구조가 가설을 고정하지 않게 `자모 데이터` 폴더 하나만 만든다. 필요한 노트와 하위 폴더는 실제 전사·검토가 시작되어 반복되는 단위가 확인된 뒤 추가한다.

```text
한글 폰트 메이커/
└── 자모 데이터/
```

첫 노트를 만들 때도 원본 분류와 프로젝트 해석을 같은 값으로 쓰지 않는다. 좌표값은 2단계 전까지 입력하지 않는다.

**목적**  
좌표 설계 전에 자모가 어떤 이유로 같은 규칙을 공유하거나 분리해야 하는지 구조화한다.

**입력**

- 이용제 논문의 높이, 속공간, 닿자-홀자 위치 관계, 최종 조합 그룹
- 초성·종성, 가로·세로·섞임 모임꼴 등 프로젝트 조합문맥 정의
- 자모 목록과 자모 원자 데이터 스키마

**작업**

1. 논문 분류를 출처 보존 형태로 전사한다.
2. 각 자모에 `height-class`, `inner-space-group`, `context-group`을 기록한다.
3. 문맥별 그룹을 독립적으로 기록한다. 다른 문맥의 같은 그룹 번호를 같은 규칙으로 가정하지 않는다.
4. 논문 직접값과 프로젝트가 만든 예시 음절을 구분한다.

**산출물**

- 이용제 분류 원본 표
- `자모 × 조합문맥` 분류 매트릭스
- 대표 자모 seed 데이터: `ㄱ ㄴ ㅁ ㅂ ㅅ ㅈ ㅎ` 등

**완료 기준**

- 모든 대상 문맥에 분류 필드가 정의됨
- 분류 출처와 프로젝트 해석이 분리됨
- 좌표·비율·오프셋 값이 이 단계 데이터에 섞이지 않음

---

## 2. 그룹별 이론 PartFrame / Guide binding 설정

**목적**  
분류 그룹마다 공유 가능한 기본 배치 규칙을 만들고, 개별 자모가 상속할 초기 geometry를 정한다.

**입력**

- 1단계 분류 매트릭스
- Font Maker 5선 시스템, 기준선, PartFrame 모델
- 조합문맥별 사용 가능 공간 정의

**작업**

1. 문맥별 그룹에 PartFrame ID를 부여한다. 예: `IV-01`.
2. 각 PartFrame의 상·하·좌·우 bound와 Guide binding을 정의한다.
3. 이론값은 그리드와 조합 구조에서만 계산한다. 무료폰트 수치를 복사하지 않는다.
4. 그룹 기본값과 자모별 값의 책임 범위를 문서화한다.

**산출물**

- 그룹별 PartFrame 사전
- Guide binding 표
- 문맥별 기본 geometry 이론값

**완료 기준**

- 모든 분류 그룹이 기본 PartFrame 또는 미결정 상태를 가짐
- 기본값이 자모 단위가 아닌 그룹 단위로 정의됨
- 값마다 `theoretical` 상태와 산정 근거가 기록됨

---

## 3. 무료폰트 시각 보정 게이트

**목적**  
이론상 분리·공유한 규칙이 실제 한글 서체에서도 반복되는지 검증하고 보정 후보를 수집한다.

**입력**

- 2단계 이론 PartFrame·Guide binding
- 비교 가능한 무료 한글 폰트 샘플
- 문맥별 테스트 음절 세트

**작업**

1. 같은 `자모 × 조합문맥` 조건을 여러 폰트에서 비교한다.
2. 위치, 크기, 여백, 속공간, 판독성 문제를 측정·기록한다.
3. 표본마다 측정 방식과 화면 조건을 통일한다.
4. 단일 서체 취향, 장식적 스타일, 불명확한 관찰은 채택 후보로 승격하지 않는다.

**산출물**

- 폰트별 관찰 기록
- 문맥별 비교 시트와 스크린샷 링크
- 보정 후보 목록

**완료 기준**

- 관찰값마다 폰트명, 버전, 대상 음절, 문맥, 측정값이 있음
- 그룹 공통 경향과 자모 단독 현상이 구분됨
- 관찰 데이터가 `observed` 영역에만 저장됨

---

## 4. 관찰값과 이론값 비교

**목적**  
관찰된 차이가 그룹 기본값 조정, 자모별 override, 보류 중 무엇인지 판정한다.

**입력**

- 그룹별 이론값
- 무료폰트 관찰값과 시각 검토 메모
- 테스트 음절 렌더링 결과

**작업**

1. 이론값과 관찰값의 차이를 수치·시각 양쪽에서 비교한다.
2. 차이가 여러 서체와 음절에서 반복되는지 확인한다.
3. 원인을 아래 세 가지로 분류한다.
   - 그룹 전체 경향: 기본값 조정 후보
   - 특정 자모 특성: override 후보
   - 근거 부족 또는 서체 특수성: 보류
4. 판단 이유와 반대 사례를 기록한다.

**산출물**

- 이론값 대비 관찰값 비교표
- 그룹 조정안 / override 후보 / 보류 목록
- 채택 판단 로그

**완료 기준**

- 모든 변경 후보에 판단 유형과 근거가 있음
- 관찰값 하나만으로 그룹 기본값을 바꾸지 않음
- 미해결 항목이 `unverified` 또는 `deferred` 상태로 남음

---

## 5. 채택값을 자모 원자 데이터에 기록

**목적**  
검증된 판단을 Font Maker가 읽을 수 있는 안정적인 원자 데이터로 축적한다.

**입력**

- 4단계 채택 판단 로그
- 그룹 PartFrame·Guide binding
- 자모 원자 데이터 스키마

**작업**

1. 채택한 그룹 기본값을 `adopted` 영역에 기록한다.
2. 각 값에 근거, 관찰 표본 수, 신뢰도, 검토일을 붙인다.
3. 분류값·이론값·관찰값 원본을 보존한다.
4. 테스트 렌더링으로 저장값이 의도한 문맥에 적용되는지 확인한다.

**산출물**

- 업데이트된 자모 원자 데이터
- 그룹 기본값 라이브러리
- 적용 테스트 결과

**완료 기준**

- 모든 채택값이 출처와 결정 근거를 가짐
- 데이터만으로 값의 생성 경로를 역추적 가능함
- 엔진 테스트에서 문맥별 올바른 기본값이 적용됨

---

## 6. 예외 자모만 override

**목적**  
그룹 규칙은 유지하면서, 구조적·시각적으로 필요한 자모만 최소 보정한다.

**입력**

- 그룹 기본값
- 4단계 override 후보
- 자모별 렌더링 검토 결과

**작업**

1. 자모가 그룹 기본값을 상속한 결과부터 검토한다.
2. 기본값으로 해결되지 않는 반복 문제만 override로 등록한다.
3. override 범위를 `자모 × 조합문맥 × 속성`까지 최소화한다.
4. override 이유, 영향 범위, 재검토 조건을 기록한다.

**산출물**

- 최소화된 override 목록
- override 적용 전후 비교
- 예외 관리 규칙

**완료 기준**

- 모든 override에 상속값으로 해결되지 않는 이유가 있음
- override가 다른 문맥·자모로 불필요하게 확산되지 않음
- 그룹 기본값 변경과 자모 예외가 데이터에서 명확히 분리됨

## 최종 상태

새 자모는 다음 흐름으로 처리한다.

```text
새 자모
  → 기존 분류 그룹 확인
  → 그룹 기본 PartFrame·Guide binding 상속
  → 문맥별 렌더링 검토
  → 필요할 때만 optical override 추가
```

이 구조에서 전역 규칙은 강하게 유지하고, 개별 디자인 판단은 근거 있는 예외로 관리한다.

## 2026-09-08 보완 — 문헌 소속을 폰트 검증에 쓰는 방법

> 아래는 실행 가설이다. 현재 `자모 데이터`의 30개 닿자 파일은 확정 데이터나 엔진 입력이 아니라 만들어 가는 문헌 전사 초안이다. 원문 대조와 시각 검증 전에는 값·그룹·좌표 어느 것도 채택값으로 취급하지 않는다.

### 먼저 고정할 구분

문헌의 그룹 번호는 하나의 최종 그룹 ID가 아니다. 자모는 문맥마다 여러 그룹에 속한다. 예를 들어 한 닿자의 `문헌_최종_가로_첫닿자`와 `문헌_최종_세로_받침닿자`는 서로 다른 분류 가족에서의 소속이다. 같은 숫자 `1`도 다른 열에서는 같은 규칙을 뜻하지 않는다.

현재 `자모-문헌분류-v1`의 독립 필드는 이 다중 소속을 원문에 가깝게 보존하는 기준 원본이다. 이를 `최종_그룹` 한 값이나 숫자를 이어 붙인 결합 ID로 중복 저장하지 않는다. Obsidian Base와 비교표는 각 필드에서 다음 소속을 파생해 보여 준다.

```text
분류 가족: 문헌_최종_가로_첫닿자
그룹: 1
대상: ㄱ
```

엔진 후보를 만들 때만 별도 프로젝트 데이터에 `문헌 필드 → 프로젝트 문맥 → 후보 규칙` 연결을 둔다. 이 연결은 문헌 전사가 아니라 검증 대상 가설이다.

### 세 층과 책임

| 층 | 저장하는 것 | 폰트 대조에서의 쓰임 |
| --- | --- | --- |
| 문헌 전사 | 높이·속공간·위치·최종 조합별 소속, 원문 대조 상태 | 비교 대상을 같은 분류 가족·같은 그룹으로 묶는 표본 선택 기준 |
| 프로젝트 가설 | 문헌 문맥과 Font Maker 문맥의 대응, 테스트 음절, 예상되는 공간 관계 | 무엇을 비교하고 어떤 차이를 그룹 규칙 후보로 볼지 정의 |
| 관찰·판정 | 폰트 파일·버전·해시, 음절, 측정·이미지, 반대 사례, 판정 | 그룹 경계 유지·분할·보류와 PartFrame 후보 채택 근거 |

문헌 전사값은 좌표를 만들지 않고, 관찰값은 문헌 전사값을 고치지 않는다. 채택한 PartFrame·Guide·override도 세 층 밖의 별도 설계 데이터다.

### 실제 폰트 대조 흐름

```text
문헌 필드의 문맥별 소속
  → 프로젝트 문맥 대응 가설
  → 같은 문맥에서 자모만 바꾼 테스트 음절 묶음
  → 여러 폰트의 원본 좌표·윤곽·여백 관찰
  → 그룹 경계 판단
  → PartFrame 기본값 또는 자모 override 후보
  → 렌더링 결과 재검증
```

1. **전사 완성**: 닿자별 문헌 필드를 채우되 `원문_대조: false`를 유지한다. 대상은 모든 자모가 아니라 이 논문이 다루는 닿자 역할과 겹받침이다. 홀자는 별도 문헌·별도 스키마가 필요하다.
2. **문맥 대응 표**: 문헌의 `가로·세로·섞임`을 앱의 layout ID와 이름만 보고 같다고 놓지 않는다. 논문 예시 음절, 역할, 받침 유무를 근거로 한 대응표를 만들고 상태를 `proposed`로 둔다.
3. **그룹 가설 카드**: `문헌 필드 × 그룹`마다 대상 자모, 대응 문맥, 고정할 다른 자모, 비교 음절, 관찰할 공간 관계를 적는다. 여기까지는 좌표나 프리셋을 채택하지 않는다.
4. **폰트 관찰**: 같은 가로폭·baseline·UPM 기준에서 여러 무료폰트의 완성 글자를 본다. 글리프마다 ink bounds에 맞춰 확대·가운데 정렬하지 않고 원래 advance를 유지한다. 글리프 윤곽에는 자모 경계가 보통 따로 없으므로, 처음부터 자동 자모별 box 추출을 전제하지 않는다. 완성 글자의 여백, 이웃 자모와 최소 간격, 속공간, 판독성, 그룹 안팎의 반복 차이를 기록한다.
5. **판정**: 여러 폰트와 여러 예시에서 같은 차이가 반복되면 그룹 기본값 후보다. 특정 자모만 반복되면 override 후보다. 그룹 안에서도 일관되지 않거나 서체 스타일에만 묶이면 그룹을 분할하거나 보류한다.
6. **설계·재검증**: 판정 뒤에만 PartFrame·Guide 후보를 만든다. 후보 렌더링을 같은 음절·좌표 기준으로 다시 대조하고, 관찰 폰트의 숫자를 복사하지 않은 채 공간 관계와 판독성을 확인한다.

무료폰트는 두 번 쓰인다. 첫 관찰은 문헌 그룹이 시각적으로 유효한 표본 층인지 확인한다. 두 번째 대조는 만든 PartFrame 규칙의 결과가 그 관찰과 어긋나지 않는지 확인한다. 어느 단계도 폰트 좌표를 Font Maker 기본값으로 복사하는 근거가 아니다.

### 그룹 가설 카드 최소 형식

```yaml
# 그룹 가설 카드의 안정 식별자다.
# 문헌 분류 가족과 그룹을 함께 넣어, 다른 필드의 같은 그룹 번호와 충돌하지 않게 한다.
id: lee-final-horizontal-initial-g1

# 이 가설의 출발점인 문헌 분류 소속이다. 엔진 규칙이나 채택값이 아니다.
source-membership:
  # 자모 문헌분류 파일에서 읽을 YAML 필드명이다.
  # 그룹 번호는 이 필드 안에서만 의미가 있다.
  field: 문헌_최종_가로_첫닿자

  # 위 문헌 필드에서 비교할 그룹 번호다.
  group: 1

  # 현재 문헌 전사에서 이 그룹에 속하는 비교 대상 자모의 파생 목록이다.
  # 자모 파일이 기준 원본이며, 이 목록은 가설 실행 시점의 표본을 고정한다.
  jamos: [ㄱ]

# 문헌 문맥을 Font Maker 조합 문맥으로 해석하는 프로젝트 가설이다.
context-mapping:
  # 대응 검토 상태다. proposed는 아직 확정되지 않은 대응임을 뜻한다.
  status: proposed

  # 대응이 확인되면 Font Maker의 LayoutType 또는 별도 문맥 ID를 기록한다.
  # null은 이름만 보고 대응하지 않았고 아직 검토가 필요하다는 뜻이다.
  font-maker-context: null

# 같은 조건으로 반복 비교할 테스트 음절 또는 fixture ID 목록이다.
# 대상 자모 외의 홀자·받침·스타일 조건을 고정한 사례만 넣는다.
fixtures: []

# 실제 폰트에서 관찰할 항목이다. 좌표 채택값이 아니라 검증 질문 목록이다.
observe:
  # 대상 자모 잉크와 이웃 자모 잉크 사이의 최소 간격을 본다.
  - target-ink-to-neighbor-clearance
  # 대상 자모의 안쪽 공간이 전체 점유 공간에서 차지하는 시각적 비율을 본다.
  - inner-space-proportion
  # 붙음·막힘·형태 혼동 등 판독성 문제가 생기는지 본다.
  - reading-risk

# 폰트별 관찰 레코드, 비교 이미지, 측정표의 링크 또는 ID 목록이다.
# 실제 관찰값은 카드에 직접 복사하지 않고 별도 근거 레코드에 보존한다.
evidence: []

# 가설 판정 상태다. unverified는 아직 충분한 폰트 관찰이 없다는 뜻이다.
# 이후 supported, split-needed, jamo-override, rejected, deferred 중 하나로 판정한다.
decision: unverified
```

`jamos`는 문헌 원본의 반복 저장이 아니라 그 시점 비교 표본을 고정한 파생 목록이다. 원본과 다르면 원본을 바꾸지 않고 카드 생성 규칙 또는 전사 오류를 먼저 확인한다.

### 실행 순서 수정

기존 1~3단계 사이에 아래를 넣는다.

1. 문헌 전사 초안을 `자모-문헌분류-v1`의 목표 형식으로 점진적으로 맞춘다. 기존 본문 표는 전사 근거로 보존한다.
2. 문헌 분류 가족별 소속을 Base에서 파생해 전체 매트릭스로 검토한다.
3. 문헌 문맥과 앱 문맥의 대응 가설, 그룹 가설 카드, 테스트 음절·측정 규칙을 만든다.
4. 폰트 관찰로 그룹 경계가 유효한지 먼저 판단한다.
5. 살아남은 그룹만 PartFrame·Guide 기본값 후보로 올린 뒤 결과를 재대조한다.

따라서 현재 다음 단위의 우선순위는 `문헌 전사 초안 → 문맥 대응표 → 그룹 가설 카드 → 실제 폰트 관찰`이다. 그룹 기본 좌표와 엔진 입력은 이 관찰·판정 뒤 단계다.

## 2026-09-08 보완 — 대화 중 보정값의 저장과 승격

> 현재 권장안이다. 문헌 분류, 연구 중 판단, 앱이 사용하는 채택값의 기준 원본을 분리한다.

React 컴포넌트에 자모별 그룹값이나 보정값을 직접 적지 않는다. React는 문맥 해석, 상속 계산, SVG 표시만 담당하고 데이터는 구조화된 입력으로 받는다.

대화에서 새 개념이나 시각 보정 후보가 나오면 먼저 Obsidian에 기록한다. 이 단계에서는 관찰 사실, 해석, 후보 수치, 반대 사례, 상태를 함께 남긴다. 현재 `자모-문헌분류-v1` 파일은 문헌 원본층이므로 프로젝트 가설이나 보정값을 추가하지 않는다.

보정값은 곧바로 모든 자모에 복사하지 않는다. 저장 단위는 다음처럼 나눈다.

- `문헌 자모 소속`: 현재 자모 파일의 문맥별 그룹 번호
- `그룹 기본 후보`: `문헌 필드 × 그룹`이 공유할 개념과 보정값
- `자모별 예외 후보`: 그룹 기본값으로 설명되지 않는 `자모 × 문맥 × 속성`만 저장
- `관찰 기록`: 특정 폰트·음절·날짜에서 확인한 측정값과 시각 판단

대화 중 특정 자모에서 차이를 발견해도 처음부터 자모 override로 확정하지 않는다. 관찰로 기록한 뒤 여러 그룹 구성원에서 반복되면 그룹 기본 후보로, 해당 자모에서만 반복되면 자모별 예외 후보로 판정한다.

```text
대화·랩 관찰
  → Obsidian 관찰/가설
  → 그룹 기본값 또는 자모 예외 판정
  → 사용자 승인
  → 검증된 repo JSON snapshot
  → React 랩과 생성 엔진이 읽음
```

repo의 JSON snapshot은 Obsidian 원본에서 생성하며 손으로 중복 편집하지 않는다. 후보와 보류값은 연구 화면에서만 보이고 production 기본값에는 들어가지 않는다. 사용자가 승인한 단위만 versioned fixture로 승격하고 타입 검사·스키마 검증·렌더링 테스트를 붙인다.
