# 레이아웃 모드를 사용자 네모꼴로

- **이번에 비교하는 것**: 네모꼴을 바꿨을 때 레이아웃 모드(둘째 줄 `닿는 글자` 카드 + 캔버스 + 보선)가 기준 네모꼴(850)에 남을지, 문장 줄처럼 사용자 네모꼴을 따를지.
- **이번 승인으로 바뀌는 것**: 카드 · 캔버스 · 부품 상자 · 보선 · Noto 고스트가 전부 사용자 네모꼴 안에 그려진다. 문장 줄 = 카드 = 캔버스가 같은 글자가 된다.
- **바뀌지 않는 것**: 저장 형식. 레이아웃 Δ · 모델 상자 · 스냅 후보는 그대로 기준 네모꼴 em이다. 획 두께는 그대로(원칙: 두께 고정). 글로벌 스타일 공간, OTF, 검수 격자.

앞 플랜 `2026-09-22_네모꼴이-글자까지-줄이게.md`가 문장 줄과 OTF까지 했고, 레이아웃 모드는 거기서 `미결정`으로 남겼다. 사용자 지적(09-22): "그거 반영되면 둘째 줄 예시 글자 카드에도 반영돼야 하는 거 아님?"

## 이번에 판단할 변수 하나

**네모꼴 옮기기를 어디에 넣나.**

- **A. 상자 층에서 한 번(추천)** — 문장 줄과 같은 길. 편집기의 숫자 상태(rail 값 · Δ · 스냅 후보 · `tryPlace` 검사)는 전부 기준 em 그대로 두고, 상자를 옮긴 **뒤에** 앱 획을 맞춘다(`renderMedialPart` · `renderComponentPart`에 `padding`을 넘겨 slot · faces를 `mapFacesToDesignBody`로 옮기고 `fitPartStrokes`). 캔버스는 보선 · 상자 · Δ 띠의 x · y만 같은 식으로 옮겨 그리고, 고스트는 `designBodySvgTransform`. 끌기는 픽셀 → 사용자 네모꼴 → 역변환 → 기준 em. 카드는 같은 함수를 부르므로 따로 할 게 없다.
- **B. SVG `<g transform>` 하나로 그림째 눌러 그리기** — 코드 한 줄이지만 획 두께가 같이 눌려 문장 줄 · OTF와 다른 글자가 된다. 원칙 위반이라 탈락.

A로 가면 캔버스의 글자는 `contextPlacementOf`가 문장에 내놓는 상자와 같은 상자에서 나온다. 확인 질문은 하나: **보선을 끌 때 손가락과 보선이 1:1로 따라오는 게 맞나** (사용자 네모꼴이 좁으면 기준 em 한 칸이 화면에서 짧아진다 → 픽셀을 그대로 따라오게 역변환한다. 대안은 없다고 본다).

## 손대는 곳

| 파일 | 무엇 |
|---|---|
| `src/services/designBodyPlacement.ts` | 역변환 `unmapPointFromDesignBody` 추가(끌기용). 단위 테스트: 왕복이 점 하나까지 같다. |
| `src-next/notoMedialFitView.ts` · `notoComponentFitView.ts` | `render*Part(…, padding?)`: slot · faces를 옮긴 뒤 잉크. 돌려주는 `slot` · `faces` · `inkBox`도 옮긴 값. 기준 네모꼴이면 전과 점 하나까지 같다. |
| `src-next/propagationCardView.ts` · `TouchedGlyphRow.tsx` | `padding`을 받아 넘긴다. `propagation-card-view.test.ts`에 네모꼴 케이스. |
| `src-next/GlyphLayoutEditor.tsx` | `useEffectiveGlobalStyle(layoutType).padding` 읽기. `GhostCanvas`에 좌표 옮기기 함수 하나(`toBody`)와 그 역을 넘겨 보선 · 상자 · Δ 띠 · 기준 보선(`measured`)을 옮겨 그리고 끌기는 역변환. 고스트에 transform. |
| `tests/e2e/workspace-jamo-layout.spec.ts` | 네모꼴 `600 × 850`에서 카드 글자 폭이 문장 글자와 같은 비율로 좁고, 캔버스 잉크 상자와 보선이 사용자 네모꼴 안에 있고, 보선을 끌면 Δ가 기준 em으로 저장돼 `850`으로 되돌려도 같은 자리인 것. |

주의: `GlyphLayoutEditor.tsx`와 `CalibrationSentenceEditor.tsx`에 다른 세션의 스냅 작업이 미커밋으로 얹혀 있다. 그쪽 커밋을 기다리거나 내 헝크만 골라 스테이징한다(`feedback_stage_by_path`).
