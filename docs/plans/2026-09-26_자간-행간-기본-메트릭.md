# 자간 · 행간 기본 메트릭

- **이번에 비교하는 것**: 지금 OTF(글자 폭 = 몸통 그대로 840, 좌우 여백 0, 줄 높이 1.0em)와 노토 비율로 맞춘 OTF(글자 폭 920 · 왼 50 · 오른 30, 공백 220, 줄 높이 1.448em). 정할 변수 하나: **몸통 폭을 바꿨을 때 좌우 여백이 따라 줄어드는지(A · 노토 비율) 그대로인지(B · 여백 고정)**. 기본 몸통에선 둘 다 920으로 같다. 추천은 A — 글자를 좁히면 자간도 같이 좁아야 밀도가 유지된다.
- **이번 승인으로 바뀌는 것**: 추출기의 글자 폭 · 원점 · 공백 폭 · 세로 메트릭(hhea · win). 메트릭 함수를 한 파일(`src/services/fontMetrics.ts`)로 모아 추출기가 쓴다. 화면은 없다.
- **바뀌지 않는 것**: 획 모양 · 몸통 기본값(840 × 910) · 전역 `letterSpacing`의 뜻(더하는 값) · 추출 대기 · 완료 페이지. **문장 줄의 글자 피치**(`CalibrationSentenceEditor.tsx` 2380행 부근)와 프로젝트 `metrics` 저장값은 다른 세션이 그 파일을 만지는 중이라 이번엔 손대지 않는다 — 같은 함수로 바꾸는 한 줄은 그 세션 뒤 후속.

## 지금 상태 (사실, 09-26 다운로드된 `test1 2.otf`를 fontTools로 잼)

| | 지금 OTF | 노토 (`.reference-fonts/NotoSansKR.ttf`) |
|---|---|---|
| 한글 글자 폭 | 840 (= 몸통 폭) | 920 (11,172자 전부) |
| `가` 잉크 x | 39 ~ 839 → 오른 여백 1 | 79 ~ 884 → 왼 79 · 오른 36 (여섯 레이아웃 합집합은 43 ~ 893) |
| 공백 | 494 (500 × 몸통/0.85) | 220 |
| hhea | 880 / −120 / 0 → 줄 높이 1.0em | 1160 / −288 / 0 → 1.448em |
| OS/2 typo · win | 880/−120/0 · 잉크 끝(898/148) | 880/−120/0 · 1160/288 |
| 문장부호 | 없음 (시스템 폰트로 대체) | 쉼표 · 마침표 231 |

- 폭은 `fontExportUtils.ts:181~184` — `originX = padding.left`로 잉크를 왼쪽 끝에 붙이고 `advance = 몸통 폭 + letterSpacing`. 그래서 글자끼리 닿는다.
- 세로는 `fontExportUtils.ts:27~28` 상수(880 / −120)를 hhea · typo에 그대로 넣고, win만 `windowsClipMetrics`가 잉크 끝까지 넓힌다(`fontGenerator.ts:575`).
- 문장 줄(앱)은 `hangulAdvance = 몸통 폭`으로 OTF와 같은 피치. 자막 템플릿의 내 획 그림은 `AppGlyph` 1em 피치라 둘 다와 다르다.
- **가설**: 09-26 G0 기록 "진짜 폰트 자간이 훨씬 넓다"는 측정과 반대다(OTF가 더 좁다). 대체 폰트가 그려졌거나 착시. G0에서 같은 화면을 다시 본다.

## 계약 (D0)

- **글자 폭**: 노토 비율 `왼 50 : 몸통 840 : 오른 30`. A면 `advance = 몸통 폭 × 920/840`, 원점은 `padding.left − 몸통 폭 × 50/840`. B면 `advance = 몸통 폭 + 80`, 원점은 `padding.left − 50`. 둘 다 `+ UPM × letterSpacing`. 레이아웃별 여백 오버라이드가 있으면 그 레이아웃만 폭이 달라진다(지금도 그렇다).
- **공백**: 220 고정. 몸통을 따라 움직이지 않는다.
- **세로**: hhea `1160 / −288 / 0`, typo `880 / −120 / 0` 유지, win은 `max(1160, 잉크 위) / max(288, 잉크 아래)`. `USE_TYPO_METRICS`는 노토처럼 안 켠다 — 맥(hhea) · 윈도(win) 둘 다 1.448em. 몸통 높이를 바꿔도 줄 높이는 안 변한다.
- **한 파일**: `src/services/fontMetrics.ts`에 `hangulAdvance(padding, letterSpacing)` · `hangulOriginX(padding)` · `SPACE_ADVANCE` · `LINE_METRICS`. 추출기(`fontExportUtils` · `fontGenerator`)만 이걸 쓴다. 후속에서 문장 줄과 `calibrationProjectStore.metrics`(hangulAdvance 1000 · spaceAdvance 500 · lineHeight 1200)가 같은 함수를 부른다.
- **테스트**: 메트릭 숫자를 테스트에 박지 않고 상수를 참조한다(굵기 곡선 때와 같은 규칙).

## 미결정

- 행간을 몸통 높이에 따라 움직일지. 이번엔 노토 상수 고정.
- 문장부호 · 숫자 · 라틴 글리프가 없어 자막 템플릿의 쉼표가 다른 폰트로 그려진다. 이 플랜 밖 — 별도 플랜.
- 레이아웃별 여백 오버라이드로 글자마다 폭이 달라지는 것. 노토는 전부 920. 그대로 둘지, 몸통 폭의 최댓값으로 통일할지.
- 프로젝트 `metrics` 저장값(hangulAdvance 1000 등)을 언제 버릴지 — 문장 줄이 같은 함수로 바뀌는 후속에서.
