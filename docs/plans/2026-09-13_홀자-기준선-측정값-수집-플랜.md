# 홀자 기준선·측정값 수집 플랜

## 목표

홀자(중성)의 구조상 기둥과 보를 문맥별 배치선, 자모 원형 구조, 현재 윤곽의 관측값으로 분리해 수집한다. 목적은 외부 폰트 모사가 아니라, 홀자 프리셋·가독성 검사·역할 기반 일괄 편집에 쓸 수 있는 비교 가능한 근거를 만드는 일이다.

이 문서에서 `기둥선`은 긴 세로 구조상 바깥기둥의 기준 x 위치, `보선`은 가로 구조상 보의 기준 y 위치다. `ㅗ·ㅜ`의 짧은기둥도 사라진 것으로 취급하지 않고 `바탕 세로줄기`, `ㅛ·ㅠ`의 두 짧은기둥은 `왼쪽·오른쪽 세로줄기`로 구분한다. 각 짧은 세로줄기는 가로 위치용 바깥 면과 진행 방향 끝면을 보선과 별도로 가진다. `ㅑ·ㅕ`처럼 서로 다른 높이의 보가 있으면 `upperBeam`, `lowerBeam` 역할을 나눈다.

## 범위와 원칙

- 수집 대상은 현대 홀자 21자와 이들이 들어간 완성 글자 문맥이다.
- 외부 폰트 관측선과 생성 마스터의 구조선은 다른 값이다. 외부 관측의 `outerPillarFace`·`beamFace`는 실제 윤곽의 선택한 바깥 면에, 생성 마스터의 `pillarAxis`·`beamAxis`는 로컬 구조축에 결속한다. 한 ID에 면 끝과 중심축을 섞지 않는다.
- 생성용 5선 네모꼴·Layout Grid Rail과 외부 폰트 분석 Rail은 다른 층이다. 이름이 같거나 가까운 위치여도 자동으로 합치지 않는다.
- 외부 폰트 관측 원본은 폰트의 shared-baseline 절대좌표와 파일 SHA·축·첫닿자·홀자·글리프·문맥을 함께 저장한다. 후보 PartFrame으로 바꾼 정규화 ratio는 비교용 파생값이다.
- 생산용 홀자 구조 Rail은 JamoMaster의 로컬 좌표 또는 로컬 Rail 사이 비율로 저장한다. JU PartFrame 안의 절대 위치는 해석값이다.
- 현재 윤곽·완성 글자에서 얻은 경계와 거리값은 `DerivedMetrics`다. 원본 설계값으로 중복 저장하지 않는다.

## 문서 책임과 실행 순서

이 문서는 홀자 측정값의 의미와 소유권을 정하는 상위 계약이다. 실제 자동 추출 구현과 정확도 게이트는 [2026-09-13_홀자-기준선-자동-추출-P0-플랜](./2026-09-13_홀자-기준선-자동-추출-P0-플랜.md), 생성용 자소 내부 구조는 [2026-09-13_자모-구조-메타데이터-수집-플랜](./2026-09-13_자모-구조-메타데이터-수집-플랜.md)에서 관리한다. 같은 설명을 세 문서에 복제하지 않는다.

전체 자모 구조 메타데이터 입력은 P0 선행 조건이 아니다. P0 전에 필요한 것은 관측 역할 ID·홀자별 역할 존재 여부·좌표계·provenance·후보/검토 상태의 최소 계약뿐이다. 추출기가 생산 `JamoMaster`나 `LayoutProfile` 좌표를 읽어 후보를 고르면 순환 추론이 되므로 금지한다.

```text
문서·최소 데이터 계약 정합화
  → P0 G0: 14글자 gold·ROI 승인
  → 순수 추출기와 G1
  → 첫닿자 holdout·캐시·두 번째 폰트
  → 검증 결과로 구조 어휘와 관찰 메타데이터 보강
  → 21홀자·전체 받침·임의 폰트 확장 검토
```

P0의 승인 관측값도 `ExternalObservation`에만 남는다. 반복 패턴이 확인되면 생성 규칙 후보의 근거로 연결할 수 있지만 `pillarAxis`, `beamAxis`, ContextPreset을 자동 생성하지 않는다.

## 수집할 기준선과 구조 메트릭

### 구조 기준선 후보

| 항목 | 축 | 뜻 | 적용 |
| --- | --- | --- | --- |
| `outerPillarFace` / 관측 긴 기둥선 | x | 오른쪽에 놓인 긴 바깥기둥의 우측 외곽면. 기둥 중심축이나 초성 쪽 좌측면이 아니다. 좌측면이 필요한 초성↔홀자 간격은 별도 파생 지표로 측정한다. | 외부 관측, 세로·혼합형 중 긴 기둥이 있는 홀자 |
| `basePillarFace`, `leftStemFace`, `rightStemFace` / 관측 짧은 세로줄기 면 | x | `ㅗ·ㅜ` 계열의 짧은 세로줄기 오른면. 단일 줄기는 `base`, `ㅛ·ㅠ`의 두 줄기는 `left/right`로 나눈다. `basePillarFace`는 현재 저장 호환 ID이며 화면 용어는 `바탕 세로줄기`다. | 외부 관측, `ㅗ·ㅛ·ㅜ·ㅠ`와 이를 포함한 혼합형 |
| `baseStemTipFace`, `leftStemTipFace`, `rightStemTipFace` / 관측 짧은 세로줄기 끝면 | y | `ㅗ·ㅛ`는 위끝, `ㅜ·ㅠ`는 아래끝의 실제 외곽 면. 보선만으로 알 수 없는 돌출 범위와 이웃 자소 충돌을 판정한다. | 외부 관측, 짧은 세로줄기가 있는 가로·혼합형 |
| `pillarAxis` / 생성 기둥축 | x | JamoMaster 로컬 구조의 기둥 중심축. `outerPillarFace`와 같은 필드가 아니다. | 생성 마스터, 기둥이 있는 홀자 |
| `beamFace[]`·`beamAxis[]` / 보선 | y | 각 가로 보의 관측 면 또는 생성 구조축. `primaryBeam`, `upperBeam`, `lowerBeam` 등 역할 ID를 각각 가진다. | 보가 있는 세로·가로·혼합형 홀자 |
| `glyphLeft`, `glyphRight` | x | 완성 글자 전체 ink bounds의 좌·우 경계. 홀자 전용 Rail 아님. | 모든 완성 글자, 분석 오버레이만 |
| `pillarToGlyphLeft`, `pillarToGlyphRight` | x 거리 | 기둥선과 글리프 외곽의 관계. 조합 뒤 계산한다. | 기둥선이 있는 사례 |
| `beamStartToGlyphLeft`, `beamEndToGlyphRight` | x 거리 | 보의 양끝과 글리프 외곽의 관계. 조합 뒤 계산한다. | 해당 보가 있는 사례 |

외부 관측의 기둥·보·짧은 세로줄기는 scalar 기준선만 저장하지 않는다. 선택한 면 위치와 실제 외곽으로 드러난 유한 구간을 같은 요소 후보로 묶는다.

| 외부 관측 요소 | 면 위치 | 가시 구간 |
| --- | --- | --- |
| 세로 기둥·짧은 세로줄기 | 선택한 왼면 또는 오른면 x | y 방향 `visibleSpans[]` |
| 가로 보 | 선택한 윗면 또는 아랫면 y | x 방향 `visibleSpans[]` |

가시 구간은 접합이나 이웃 자소 겹침으로 여러 조각이 될 수 있다. 따라서 `top/bottom`, `left/right` 한 쌍으로 숨은 구간을 메우지 않는다. 요소의 전체 외접 높이·너비와 실제 노출 길이는 각각 `extent`, `visibleLength`로 파생한다.

기울거나 휜 면은 원칙적으로 단일 x/y 후보를 자동 포기한다. 사용자가 시작 방향을 명시한 검토 사례만 예외로 두고, 시작점의 국소 접선과 허용 편차 안의 짧은 지지 구간을 기록한다. provenance에 `start-side-local-tangent`, 시작 방향, anchor, 허용 편차를 남기며 이 값을 전체 보 높이·길이로 해석하지 않는다.

`glyphLeft/right`는 `가·고·과` 같은 완성 글자 결과를 읽는 값이다. 홀자가 실제 왼선·오른선을 만들었다는 판정은 자동 사실이 아니다. 필요하면 `edgeContribution: observed | reviewed | none`과 근거를 관측 기록으로 남긴다. 생산 `LayoutProfile`에 글리프 외곽선을 홀자 고정값으로 넣지 않는다.

`*StemTipFace`는 완성 글자에서 실제 바깥면으로 노출된 경우만 raw 기준선 후보다. 줄기 contour가 이웃 첫닿·받침 잉크 안에 묻히면 숨은 `componentTip` 좌표를 증거로 남기되 후보는 `occluded-by-neighbor-overlap`으로 자동 포기한다. 첫 접촉면과 겹침 깊이는 `DerivedMetrics.contactFace`, `overlapDepth`로 계산한다. 숨은 끝을 보이는 접촉면처럼 저장하거나 접촉면으로 덮어쓰지 않는다.

### 생성 구조 메트릭

아래 값은 JamoMaster 로컬 생성 구조다. 외부 관측의 `visibleSpans[]`와 다른 소유 계층이다. 각 기둥·보는 역할 ID를 가져야 하며 `ㅑ`의 두 짧은 보를 합친 하나의 길이로 저장하지 않는다.

| 항목 | 단위 | 뜻 |
| --- | --- | --- |
| `pillarTop`, `pillarBottom` | JamoMaster 로컬 y 비율 | 선택 기둥의 구조상 시작·끝 위치 |
| `pillarLength` | y 비율 차 | `pillarBottom - pillarTop` 파생값 |
| `shortStemStart`, `shortStemEnd` | JamoMaster 로컬 y 비율 | 짧은 세로줄기의 접합 쪽 시작과 진행 방향 끝. `ㅛ·ㅠ`는 왼쪽·오른쪽을 별도 요소로 둔다. |
| `shortStemLength` | y 비율 차 | 각 짧은 세로줄기의 start/end에서 계산한 파생값 |
| `beamStart`, `beamEnd` | JamoMaster 로컬 x 비율 | 각 보의 좌·우 구조 끝. 방향과 무관하게 작은 x를 start로 둔다. |
| `beamLength` | x 비율 차 | `beamEnd - beamStart` 파생값 |
| `beamAttachX`, `beamAttachY` | JamoMaster 로컬 비율 | 보와 기둥이 만나는 구조점. 분리되어 있으면 `not-applicable`. |
| `beamCount`, `pillarCount`, `shortStemCount` | 구조 태그에서 계산 | 독립 원본 수치 아님. 현재 선택된 역할 요소 수에서 계산. |

형태상 필요한 곳에서만 `strokeFace`, `strokeAxis`, `structuralCenter` 중 위치 방식을 택한다. 외부 폰트 분석에서의 면 끝, 생성 마스터의 중심선, 광학 중심을 하나의 숫자로 섞지 않는다.

## 홀자 유형별 적용

| 유형 | 대상 | 기둥선 | 보선 | top/bottom | start/end/length | 글리프 왼·오른선 관계 |
| --- | --- | --- | --- | --- | --- | --- |
| 세로형 | `ㅏ ㅑ ㅓ ㅕ ㅐ ㅒ ㅔ ㅖ ㅣ` | `ㅣ` 포함 세로줄기에 적용 | `ㅏ·ㅑ·ㅓ·ㅕ·ㅐ·ㅒ·ㅔ·ㅖ`의 가로 보마다 적용. `ㅣ`는 없음. | 기둥 있을 때 적용 | 보 있을 때 보마다 적용 | 조합 문맥에서만 파생. 오른쪽 홀자·왼쪽 홀자 여부와 첫닿 폭을 함께 본다. |
| 가로형 | `ㅗ ㅛ ㅜ ㅠ ㅡ` | 긴 기둥은 없다. `ㅗ·ㅜ`는 짧은 세로줄기 1개, `ㅛ·ㅠ`는 2개, `ㅡ`는 0개다. 각 줄기의 x 면과 방향 끝 y를 적용한다. | 주 가로 보에 적용 | 짧은 세로줄기마다 적용. `ㅡ`만 `not-applicable` | 보와 짧은 세로줄기 각각 적용 | 완성 글자의 좌·우 여백, 보 길이, 세로줄기 돌출과 이웃 자소 충돌을 파생 비교한다. |
| 혼합형 | `ㅘ ㅙ ㅚ ㅝ ㅞ ㅟ ㅢ` | 가로 바탕의 짧은 세로줄기와 오른쪽 긴 기둥을 구분해 적용. `ㅢ`의 바탕 `ㅡ`에는 짧은 세로줄기가 없다. | 구성 요소의 보를 역할별로 적용 | 긴 기둥과 짧은 세로줄기에 각각 적용 | 각 구조 요소마다 적용 | 혼합 배치·받침 유무에서 별도 관찰한다. 구성요소 수치를 단순 합산하지 않는다. |

분류는 수집 UI의 기본 필터다. 실제 적용 여부는 자모의 구조 태그가 결정한다. 존재하지 않는 구조에 `0`을 넣지 않고 `not-applicable`을 저장한다.

## 데이터 소유권

| 층 | 저장할 것 | 저장하지 않을 것 |
| --- | --- | --- |
| `LayoutProfile` / JU PartFrame | 문맥별 중성 슬롯의 위치·크기, part 사이 최소 간격 같은 배치 제약 | 홀자 내부 기둥·보 좌표, 외부 폰트 절대좌표, 특정 윤곽 ink bounds |
| `JamoMaster` local grid | `pillarAxis`, `primaryBeam`, `upperBeam` 등 구조 요소의 역할·연결·로컬 Rail과 원형 형태 | 완성 글자에서 측정한 x/y, 문맥별 배치 수치, glyph bounds |
| `ContextPreset` | 세로·가로·섞임·받침 유무에서 반복 확인된 로컬 구조 Rail 또는 JU PartFrame의 명시적 보정, 필요한 `not-applicable`/구조 override | 모든 관측값의 자동 승격, 다른 문맥 결과의 복제 |
| `ExternalObservation` | 파일 SHA·축·글리프·문맥별 구조 요소의 선택 면 위치, 복수 가시 구간, contour·segment 근거, 성분별 후보·자동 포기·검토 상태 | 숨은 전체 획을 복원한 값, 생산 LayoutProfile·JamoMaster에 자동 반영한 값 |
| `DerivedMetrics` | 후보 PartFrame으로 투영한 ratio, 해석된 길이·glyph bounds와 거리·충돌·여백·분포 | 편집 뒤 재계산돼야 할 값을 진실값처럼 영속 원본화한 것 |

관계는 아래 순서다.

```text
ExternalObservation raw 좌표
  → 후보 비교에만 사용

JamoMaster local 구조 Rail
  → LayoutProfile의 JU PartFrame 투영
  → ContextPreset 보정·예외
  → 조합된 현재 윤곽
  → DerivedMetrics: 길이·외곽 관계·여백·충돌
```

### 권장 표현

```yaml
jamo: ㅏ
role: JU
structure:
  pillars:
    - id: pillarAxis
      elementRef: main-vertical
      positionMode: structuralCenter
  beams:
    - id: primaryBeamAxis
      elementRef: right-horizontal
      positionMode: structuralCenter

localGuide:
  pillarAxis:
    axis: x
    position: { kind: between, from: partLeft, to: partRight, ratio: 0.72 }
  primaryBeamAxis:
    axis: y
    position: { kind: between, from: partTop, to: partBottom, ratio: 0.50 }

externalObservation:
  coordinateFrame: shared-baseline
  elementId: outerPillar
  orientation: vertical
  face:
    side: right
    position: { status: candidate, value: 745 }
  visibleSpans:
    status: candidate
    value:
      - { from: 53, to: 420 }
      - { from: 489, to: 957 }
  evidence: { contourId: 0, segmentIds: [1] }

derivedMetrics:
  pillar:
    topRatio: 0.14
    bottomRatio: 0.88
    lengthRatio: 0.74
  beams:
    - id: primaryBeam
      startRatio: 0.72
      endRatio: 0.96
      lengthRatio: 0.24
  glyphRelation:
    glyphLeft: 0.09
    glyphRight: 0.94
    pillarToGlyphRight: 0.22
```

예시는 필드 경계만 보인다. 숫자는 샘플값이며 기본 설계값이 아니다. `derivedMetrics`는 현재 `PartFrame`과 윤곽에서 다시 계산한다.

## 외부 폰트 관측값 규칙

### 즉석 조합 후보 추출과 캐시

수집의 주 흐름은 사람이 닿자별 값을 처음부터 입력하는 방식이 아니다. 사용자가 `폰트 → 첫닿자 → 홀자 → 받침`을 고르면 앱은 그 값으로 완성 글자를 조합하고, 해당 폰트 outline에서 선택 홀자의 역할선 후보를 계산한다. 후보는 같은 글자 윤곽 위에 바로 보인다. 수동 입력은 자동 추출이 실패하거나 구조 해석이 모호할 때의 보정 수단으로 둔다.

좌표·윤곽 계약, 후보/자동 포기 상태, gold·holdout, 캐시, 구현 단계와 사용자 검증 게이트는 [2026-09-13_홀자-기준선-자동-추출-P0-플랜](./2026-09-13_홀자-기준선-자동-추출-P0-플랜.md)에서 따로 관리한다.

외부 폰트 분석값은 설계값이 아닌 관측값이다. 파일별·글리프별·문맥별로 아래 provenance를 함께 저장한다.

```yaml
source: external-font-observation
font: { family: Noto Sans KR, fileHash: "..." }
glyph: 과
context: mixed-with-final
method: manual | inferred
confidence: low | medium | high
review: pending | accepted-for-analysis | rejected
```

관측 좌표는 `coordinateFrame: shared-baseline`과 value를 빠뜨리지 않는다. 후보 JU PartFrame으로 계산한 `ratio`·inset·overflow는 `derivedComparison`에 따로 두며, 원본 관측값을 덮어쓰지 않는다.

- 자동 추론은 후보만 만든다. 외부 관측값을 `LayoutProfile`, `JamoMaster`, `ContextPreset`에 자동 기록하지 않는다.
- 생산 설계값 승격은 통제 사례 반복 관찰 → 수동 시각 검토 → 명시적 사용자 승인 → 해당 층에 새 값 작성 순서로만 한다.
- 같은 폰트 안에서 일치한 값도 다른 폰트·다른 문맥의 불변 규칙으로 일반화하지 않는다.
- 윤곽의 붓끝 돌출·optical correction은 기둥·보의 구조 anchor가 아니다. 필요하면 별도 overflow/광학 관측값으로 둔다.

## 최소 수집 세트

처음부터 21자 전체·모든 조합을 채우지 않는다. 아래만으로 필드와 측정 방식부터 검증한다.

1. `ㅏ`, `ㅓ`, `ㅣ` — 세로형: 오른쪽/왼쪽 보, 보 없음.
2. `ㅗ`, `ㅜ`, `ㅡ` — 가로형: 위·아래 보, 단일 보.
3. `ㅘ`, `ㅝ`, `ㅢ` — 혼합형: 기둥+보, 복합 구성.
4. 각 대표 홀자는 첫닿 `ㄱ`과 결합하고, 받침 없음/`ㄱ` 받침 쌍으로 관찰한다.

최소 필드:

- 구조: `vowelType`, `pillar[]`, `beam[]`, `positionMode`, `not-applicable`.
- 정규화 측정: `pillarTop/bottom`, 보별 `y`, `start/end`; 길이는 파생.
- 조합 파생: `glyphLeft/right`, 기둥·보와 외곽의 정규화 거리, 충돌/최소 여백.
- 관측: 폰트·글리프·문맥·방법·신뢰도·검토 상태.

### 1. 통합 기준선 랩에 홀자 관측 추가

- 관측값이 없는 Rail은 기본 숫자가 아니라 `미측정`으로 표시한다.

캔버스는 닿자 랩처럼 같은 완성 글자 안에 홀자 PartFrame과 역할선을 겹쳐 보여 준다. 다만 표시층을 섞지 않는다.

- `JU PartFrame`: 반투명 배경 영역. 해당 문맥에서 홀자가 배치될 슬롯이다.
- `outerPillarFace`·`beamFace`: 외부 폰트의 실제 윤곽에 붙는 관측선. 점선, 관측 상태·신뢰도와 함께 표시한다.

- `glyphLeft/right`, overflow, 충돌: 완성 글자 결과값. 옅은 보조선 또는 경고색으로만 표시한다.

- 세로·가로·혼합형 × 받침 유무에서 `LayoutProfile` 해석값과 실제 윤곽을 비교한다.

### 5. 가독성·충돌 검사 연결

- 기둥과 첫닿·받침 사이 최소 여백, 보 끝과 이웃 요소 사이 충돌을 `DerivedMetrics`로 계산한다.

완료 기준: 가독성 경고가 구조·문맥·현재 윤곽 중 어느 층에서 나온 것인지 표시한다.

### 6. 전체 확장·프리셋 승인

| 일괄 편집 범위 추론 | JamoMaster의 `pillarAxis`·보 역할 태그 + ContextPreset provenance | 예: 모든 `upperBeamAxis` 또는 세로형 `pillarAxis`를 선택한다. 선택 범위는 현재 역할·문맥에서 시작하고, 사용자가 확장한다. |
| 분석 오버레이 | DerivedMetrics의 glyph bounds·관계값 | 완성 글자 외곽과 역할선을 겹쳐 비교한다. 오버레이 값을 설계 Rail로 역기록하지 않는다. |
