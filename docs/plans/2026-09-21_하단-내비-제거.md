# 하단 내비 제거

- **이번에 비교하는 것**: 셸 하단 내비(홈 · 자소 · 검수 · 출력)를 둘지, 없애고 화면 이동을 머리 `…` 메뉴로 옮길지.
- **이번 승인으로 바뀌는 것**: 하단 내비가 사라지고 `…` 메뉴 맨 위에 `자소` · `검수`가 생긴다. `…`는 도구가 없는 화면에서도 켜진다. 셸 아래 58px가 빈다.
- **바뀌지 않는 것**: 화면과 주소, `…` 메뉴의 도구 넷(자소 원형 · OTF 추출 · 형태 규칙 · 네모꼴·획 스타일), 왼쪽 위 `문장 보정` 링크.

[홈을 자소 탭으로](./2026-09-21_홈을-자소-탭으로.md)에서 이어진 결정. `/`가 자소 탭으로 넘어가면서 `홈`은 중복, `자소`는 자기 자신, `출력`은 `…`의 `OTF 추출`과 중복이 됐고 남는 건 `검수` 하나였다.

## 게이트

| G2 전수 | `tsc -b` · eslint · 셸 · 자소 · 검수 e2e 전부. 내비 위치에 기대던 단언은 화면 바닥 기준으로 바꿈. |
| G3 사용자 검증 | 사용자가 셸을 한 바퀴 돌아 보고 판정. |

## 진행 기록

### 2026-09-21
- **사실**: `WorkspaceChrome.tsx`에서 `primaryNav` 삭제, `…` 메뉴에 `menuNav`(자소 · 검수) 추가, `…`는 늘 켜짐. `WorkspaceArea`는 `'jamo' | 'review'`. CSS에서 내비 규칙과 넓은 화면용 옆 내비 규칙 삭제, `.shell`이 `safe-area-inset-bottom`을 맡음.
- **사실 (검증)**: `tsc -b` 0, eslint 0, e2e 5개 파일(`shape-workspace-shell` · `workspace-jamo-editor` · `workspace-jamo-layout` · `review-viewer` · `layout-preview-propagation`) + `home-redirect` 44/44. 처음 돌릴 때 `J-02 4×4 점유 면`이 한 번 떨어졌다가 혼자 돌리면 통과 — 병렬 부하로 보인다(가설).
- **사실**: 다른 세션의 미커밋 작업과 같은 파일에서 만났다. 그쪽이 하단 내비에 넣던 `홈` 링크 · `출력` 버튼(`workspace-nav-output`)은 내비와 함께 사라졌고, 그 e2e는 같은 이름 창 흐름을 `…` 메뉴의 `OTF 추출`로 보도록 고쳤다. `FontExportDialog` · `fontExportStore`는 그대로 쓰인다. 고치기 전 그쪽 diff는 스크래치패드에 패치로 떠 두었다. 화면 명세의 `화면 이동` 줄은 그쪽 세션이 같은 내용으로 이미 고쳤다.
- **가설**: 자소 편집은 캔버스가 폭에 매여 있어 빈 58px가 아래 여백으로만 남는다. 세로 예산 플랜에서 쓸 자리.
- **미결정**: 자소 편집 말고는 출력 입구가 없다(검수 · 자소 원형 · 조합별 결과). 필요하면 `OTF 추출`을 셸 메뉴로 올린다.
