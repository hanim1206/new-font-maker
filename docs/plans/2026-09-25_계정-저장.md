# 계정 저장

- **이번에 비교하는 것**: 친구가 폰트를 만들다 닫고, 다른 기기에서 같은 코드로 들어와도 하던 폰트가 그대로 보이는지.
- **이번 승인으로 바뀌는 것**: 편집 내용이 계정(서버)에 자동 저장되고, 들어올 때 서버에서 불러온다. 브라우저 저장은 계정 이름표가 붙은 임시 사본이 된다. 계정당 폰트 1개를 DB가 막는다.
- **바뀌지 않는 것**: 편집 화면과 동작, 추출, 로그인 게이트가 꺼진 개발 서버(지금처럼 브라우저에만), 화면 설정(고스트 켜기 등)은 브라우저에만.

## 지금 상태 (사실, 코드 조사)

- 폰트는 브라우저 키 다섯에 흩어져 있다: `font-maker-jamo-data` · `font-maker-layout-schemas` · `font-maker-global-style` · `font-maker-shape-system-v1` · `noto-layout-delta-v1`.
- 앞의 넷은 `FontData` v1.4(`src/types/database.ts:69`)에 이미 칸이 있고, 옛 버전 변환은 `parseAndMigrateFontData`(`fontDataMigration.ts:121`)가 한다. **레이아웃 조정 `noto-layout-delta-v1`은 칸이 없다.**
- `fontProjectService`(list/get/create/update/remove)는 있지만 지금 앱에서 부르는 곳이 없다. `font_projects`에는 RLS가 켜져 있다(베타 코드 로그인 플랜).
- 레포 마이그레이션 `protect_font_data_version`(버전 되돌림 막기)이 main Supabase에 적용됐는지는 모른다.

## 계약 (D0 안)

- **저장 단위**: 폰트 전체를 `FontData` JSON 한 덩어리로 `font_projects` 한 줄에. `layoutDelta`를 넣고 버전 `1.5.0`. 1.4 이하는 불러올 때 `layoutDelta` 빈 값으로 올린다. 되돌리기 기록·파생 윤곽·캐시는 넣지 않는다.
- **모으기 · 채우기**: 스토어 다섯 → `FontData`(`collectFontData`), `FontData` → 스토어 다섯(`applyFontData`). 한 곳에만 둔다.
- **불러오기**: 로그인 뒤 편집 화면을 열기 전에 내 폰트 한 줄을 읽어 채운다. 읽는 동안은 빈 화면 대신 불러오는 중 표시.
- **자동 저장**: 스토어가 바뀌고 편집이 2초 멈추면 올린다. 올리는 중에 또 바뀌면 끝난 뒤 한 번 더. 실패하면 브라우저 사본은 남기고 저장 상태를 `실패`로(지금 있는 `[data-save-state]`·토스트 틀), 다음 변경이나 30초 뒤 재시도. 탭을 닫을 때 못 올린 게 있으면 브라우저 확인창.
- **서버가 이긴다**: 둘이 다르면 서버 값을 쓴다. 두 기기에서 동시에 고치면 나중 저장이 이긴다(베타에서는 합치지 않는다).
- **브라우저 사본 이름표**: 사본에 `owner`(계정 id)를 적는다.
  - 계정에 폰트가 없고, 사본의 주인이 없거나 나일 때만 사본을 계정으로 올린다.
  - 다른 계정 이름표의 사본은 올리지 않고 서버 값으로 덮는다.
  - 로그아웃하면 사본을 지운다.
- **계정당 1개**: `font_projects`에 `user_id` 기준 개수 제한(마이그레이션, 트리거나 부분 유니크). 한도는 숫자 하나라 유료 때 올린다. 폐기·보관함은 이 플랜 밖.
- **크기**: G0에서 실제 JSON 크기를 잰다. 브라우저 사본이 localStorage 5MB 가까이 가면 IndexedDB로 옮기는 걸 별도 항목으로 남긴다.

## 이 플랜에 없는 것

- 폐기 · 보관함 · 여러 폰트 목록, 버전 기록(되돌리기 서버 저장).
- 로그인 없이 만들고 추출할 때 가입(카톡 로그인 플랜). 이름표 없는 사본이 가입 때 올라가는 규칙은 이 플랜의 규칙을 그대로 쓴다. Supabase 익명 로그인은 그때 비교.
- 두 기기 동시 편집 합치기.

## 진행 기록

**2026-09-25** 플랜 작성. 구현 없음.
- 사실(사용자 결정): 저장은 JSON 통으로, 자동 저장 기본, 브라우저 사본에 계정 이름표 · 로그아웃 때 지움 · 비어 있는 계정에만 올림.
- 사실: 폰트 데이터는 비밀 정보가 아니라 localStorage 평문 보관이 괜찮다. 브라우저 안 암호화는 열쇠도 같은 곳에 있어 막는 게 없다. 진짜 위험은 공용 기기에서 주인이 섞이는 것이고 이름표로 막는다.
- 가설: 폰트 JSON은 localStorage 한도 안에 든다(G0에서 잰다).
- 미결정: 자동 저장 간격 2초 · 재시도 30초는 쓰다가 조정. 계정당 1개를 트리거로 할지 유니크 인덱스로 할지(유니크가 단순하지만 보관함을 붙이면 부분 유니크로 바꿔야 함).
