# 고정 Δ — 상자 변을 한 자리에 맞추기

- **이번에 비교하는 것**: 배치 Δ가 더하기뿐이라 "노·도·로의 닿자 윗변을 한 선에" 같은 의도가 안 되는 지금과, 변 하나를 자리(em 값)에 고정하는 Δ 종류를 더한 것.
- **이번 승인으로 바뀌는 것**: Δ 종류가 `더하기 | 고정` 둘이 된다. 캔버스에서 기준선에 탁 걸렸을 때 `이 자리에 맞추기`를 누르면 그 변이 고정 Δ가 되고, 범위 안 글자가 전부 그 자리에 모인다. 합산 규칙에 "고정은 값을 교체"가 생긴다.
- **바뀌지 않는 것**: 저장 키·층·범위, 카드 목록, 프리셋 모델의 보정항(끄지 않는다), 중심 rail Δ(더하기만), 획·두께, production 값.

출처: 9/21 논의. "자모 높이를 기준선에 딱 맞추고 싶은데 보정값 때문에 안 된다" → 보정을 끄는 대신 그 변만 덮는다. 사용자가 고르는 건 의도(맞추기/옮기기)지 메커니즘(어느 보정항을 끌지)이 아니다. 원칙 "미세 보정은 엔진이 먼저".

## 지금 상태

**사실**
- `ContextBoxDelta.faces[part][side]`는 숫자(em 더하기). `addContextBoxDelta`가 층을 더하고, `resolveContextBoxes`의 `place`가 예측 변 + Δ로 상자를 만든다. 홀자 변은 `fitContextMedial` 안에서 slot에 먼저 들어간다.
- 예측 변은 글자마다 다르다(층 대표값 + 자모 효과 + 쌍 셀). 그래서 같은 더하기 Δ를 줘도 글자마다 결과 자리가 다르다.
- 캔버스 드래그는 이미 실측선·다른 rail·격자에 걸린다(`snapRail`, `SnapHit { kind, label, value }`). 걸린 자리의 em 값이 있다.
- 편집 카드는 `rail.value - rail.original`만 뽑는다(`propagationEditOf`). "자리"라는 개념이 없다.

## 하려는 것

1. 저장: 변 Δ 값을 `number | { at: number }`로. `at`은 em 절대 자리. 중심 rail(`medial`)은 그대로 숫자.
2. 합산(`addContextBoxDelta`): 넓은 층 → 좁은 층 순서로 걸으며, 더하기면 `+`, 고정이면 **교체**(그 전 값은 버림). 고정 뒤 더하기는 `at + n`.
3. 적용(`place`, 홀자 slot): `at`이면 예측 변 대신 그 값. 순서·간격 위반(윗변이 밑변 아래, 홀자와 겹침)은 지금처럼 그 글자만 자동 예외.
4. 편집: 변 rail을 끌다 탁 걸리면(실측선·다른 rail·격자 어느 것이든) 스냅 표지 옆에 `이 자리에 맞추기`. 누르면 그 rail의 편집이 고정으로 바뀌고 Δ 줄이 `첫닿자 윗변 = 718`로. 다시 끌면 더하기로 돌아간다. 범위 칩·카드·적용은 그대로.
5. 표본 카드: 고정이면 범위 안 글자가 전부 같은 자리에 모이는 게 보여야 한다(이게 이 기능의 존재 이유).
6. 카드 목록 요약 줄에 `= 718` 항목. 위 카드의 같은 변이 아래 고정에 덮이면 그 항목을 흐리게.

판단 변수 하나 = **Δ 종류 둘(더하기/고정)**. 상대 고정("각 글자의 홀자 윗선에"), 중심 rail 고정, 프리셋 보정 끄기 스위치는 이 플랜 밖이다.

## 미결정

1. `이 자리에 맞추기` 버튼 자리 — 스냅 표지 옆 캔버스 위(추천, 걸린 순간 보임) vs Δ 줄의 항목을 눌러 전환.
2. 고정 뒤 다시 끌면 — 더하기로 돌아감(추천, 단순) vs 고정 자리를 끌어 옮김.
3. 격자에 걸린 자리도 고정 후보인지 — 예(추천, "1/4 선에 맞춰" 같은 의도) vs 실측선·rail만.

사실
- 타입 `FaceDelta = number | { at }`, `FacesDelta`(`src/services/contextBoxResolver.ts`). `addFaceDelta`: 뒤(좁은 층)가 고정이면 교체, 앞이 고정이고 뒤가 더하기면 `at + n`. `faceWithDelta`·`facesOffsets`(지금 변 기준 오프셋으로 풀기). 닿자는 `withDelta`, 홀자는 slot 변 기준으로 풀어 기존 아핀(`applySlotFacesDelta`)에 넘긴다 — 두께 고정 그대로. `hasContextBoxDelta`·저장소 `pruned`는 고정을 0 자리여도 남긴다. 중심 rail(`medial`)은 숫자 그대로.
- 편집: `GlyphLayoutEditor`에 세션 상태 `fixedRails`. 변 rail(닿자 `c*`, 홀자 `s*`)을 잡으면 캔버스 위 가운데에 `이 자리에 맞추기`(탁 걸린 자리면 주황), 누르면 `윗변 = 718 · 고정` 표지. 그 rail을 다시 옮기거나 복원·적용하면 풀린다. `propagationEditOf({ fixed })`가 그 변을 `{ at: 지금 값 }`으로 뽑는다(Δ 0이어도). Δ 줄은 `= 718`, 오버라이드 카드 요약도 `첫닿자 윗변 = 718`.
- 플랜과 다른 점 하나: 버튼을 "탁 걸렸을 때만"이 아니라 **변 rail을 잡으면 늘** 보이게 했다. 방향키로 옮기는 사람은 스냅이 없어서. 걸린 자리면 색으로 알린다.
- G0(Playwright): 노 첫닿자 윗변 -20u → 카드 8장의 닿자 윗변이 제각각(더하기) → 맞추기 → 전부 같은 자리(서로 1e-6, 라벨과 0.5u 안) → 다시 옮기면 더하기(`-21u`)로 복귀 → 다시 맞추기 → `이 레이아웃에 적용` → 저장 `layers.bottom.faces.CH.top = { at }`, 카드 요약 `= 자리`, 로를 열면 ㄹ 윗변이 그 자리에서 시작.
- G1(단위): `addFaceDelta` 네 경우, `이 레이아웃 +10` 위 `ㄴ = 0`(ㄴ만 고정, 다른 닿자 +10), 고정 위 같은 층 더하기는 `at` 이동, 노·로 첫닿자 윗변 고정 → 둘 다 0.12(더하기는 예측 차이 그대로), 홀자 ㅗ 윗변 고정 → slot.y 0.5, 고정 rail은 Δ 0이어도 `{ at }`, 중심 rail의 고정 표시는 무시. Undo/Redo는 스냅샷이 JSON 통째라 그대로(레이아웃 e2e 통과로 확인).
- G2: 임시 스윕 — 11,172자에 `CH.top = {at:0.12}` + `JU.bottom = {at:0.86}` 얹어 칸 해석: 전부 `complete`, 첫닿자 윗변 전부 0.12, 예외 0(획 없이 푼 상자 기준). `tsc -b` 0, 바뀐 파일 eslint 0, `npm test` 919 통과 · 2 실패(기존 digest·해시), e2e 레이아웃 19 + 자소 편집 3 통과. 옛 저장분(숫자만)은 타입이 그대로 받아 호환.
- 라벨의 자리 수는 1u 반올림이고 실제 `at`은 모델 예측 + k/1000이라 소수가 남는다. 저장은 실제 값.
