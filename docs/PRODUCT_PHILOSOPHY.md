# 제품 철학

이 문서는 한글 폰트 메이커의 장기적인 제품 방향과 판단 기준을 프로젝트에 남기는 메모리다. 대화에서 나온 아이디어나 결정이 숨은 맥락에만 머물지 않도록 계속 갱신한다.

## 지향점

한글 폰트 메이커는 결과 폰트의 형태만 조절하는 도구에 머물지 않는다. 붓, 압력, 도구의 성격을 벡터 획 스타일로 번역하여 사용자가 글자를 만드는 행위와 재료의 느낌까지 설계할 수 있게 하는 도구를 지향한다.

## 제품 판단 원칙

사용자가 제안한 아이디어에 무조건 동의하거나 곧바로 확정안으로 취급하지 않는다. 다음 관점에서 비판적으로 검토하고, 판단 근거와 남은 불확실성을 함께 기록한다.

- 프로젝트 철학과 핵심 사용 흐름에 맞는가
- 사용자가 이해하고 다뤄야 할 복잡도를 감당할 수 있는가
- 구현과 유지보수의 기술 비용이 가치에 비례하는가
- 같은 입력에서 결과를 예측할 수 있는가
- 적용한 변경을 쉽게 되돌리거나 비교할 수 있는가
- MVP에 필요한 범위와 후속 단계로 미룰 범위는 무엇인가

## 현재 브러시 모델

아래 항목은 1차 제품 범위에 관해 합의한 결정이다. 구현 가능성이나 출력 품질까지 검증된 사실을 뜻하지는 않는다.

- MVP의 붓촉 모양은 `원형`과 `납작형`이다.
- 납작형 붓촉은 모서리가 없는 타원형으로 정의한다. aspect ratio로 납작한 정도를 조절하고, 좌·우 방향을 포함한 각도를 조절한다.
- MVP의 방향 모드는 `고정 방향`만 제공한다.
- 브러시 스타일은 폰트 전체에 일괄 적용한다.
- 기존 자모 중심 편집 흐름에서는 자소 캐러셀과 하단 드로어를 사용한다. 신규 샘플 문장 기반 역추론형 흐름에는 자모 교체 스와이퍼를 가져오지 않고, 보정 문장과 선택한 완성 글자를 계속 문맥으로 유지한다. 기존 트랙패드의 제스처와 시각 피드백만 편집 부품으로 재사용한다.
- 원형 붓촉에서는 의미가 없는 aspect ratio와 각도 조절을 노출하지 않는다.
- 납작형 각도는 가로축을 `0°`로 삼아 `-90°`부터 `+90°`까지 조절하며 기본값은 `0°`다.
- 납작함의 수치는 조작 중에만 표시하고, 원형으로 전환해도 마지막 납작형 설정은 기억한다.
- 별도의 브러시 크기는 두지 않는다. 전체 획 굵기와 붓촉의 납작한 정도를 서로 다른 역할로 유지한다.
- 사용자는 대표 글자 미리보기와 변경 전·현재 비교를 통해 전체 적용 결과를 확인하고, 저장 이력으로 되돌릴 수 있어야 한다. 조절 중에는 결과를 즉시 미리보되 손을 떼는 시점에 한 번의 변경으로 저장한다.
- 편집 히스토리와 변경 전·현재 비교는 기존 전체 화면 흐름을 유지한다. 압력, 끝맺음, 세리프처럼 조절 항목이 늘어날 때만 별도 전체 화면 편집기를 다시 검토한다.

아래 항목은 후속 가설로 남긴다.

- `획 따라가기`는 급커브와 교차부의 품질을 먼저 기술 실험한 뒤 도입 여부를 판단한다.
- 개별 획 오버라이드는 필요성과 UX 비용을 확인한 뒤 검토한다.
- 압력, 속도, 끝맺음, 세리프는 시간에 따른 입력과 획 방향의 의미를 정의한 뒤 별도 단계에서 다룬다.

## 알려진 위험과 미결정 사항

- SVG 기본 `stroke`만으로는 고정각 납작 붓촉을 충분히 표현하기 어려울 수 있다. 별도의 custom stroke-to-contours 또는 outline expansion이 필요할 가능성이 있다.
- 후속 후보인 `획 따라가기`는 급커브와 획 교차부에서 윤곽이 뒤틀리거나 불안정해질 수 있다.
- 브러시 옵션을 한꺼번에 노출하면 사용자가 결과를 예측하기 어렵고 편집 UI가 복잡해질 수 있다. 단계적 노출, 프리셋, 고급 설정 분리가 필요한지는 검증해야 한다.
- 현재 원형 중심선 모델은 SVG와 OTF가 같은 배치·두께·linecap·linejoin·문맥 안전 계산을 사용한다. CFF 1 출력 직전에는 닫힌 경로의 중복 시작점을 제거하고 획 컨투어를 Boolean union하여 교차부의 흰 구멍을 없앤다. 이 처리로 `ㅁ·ㅂ·ㅙ`의 꼭짓점과 교차부, `ㅇ·ㅁ·ㅎ`의 의도된 내부 공간을 브라우저와 macOS CoreText의 실제 OTF 렌더링에서 검증했다. 납작 붓촉을 도입할 때는 custom stroke-to-contours를 양쪽에서 공유해야 일치를 유지할 수 있다.

## 샘플 문장 기반 편집 원칙

- 제품의 기준 흐름은 `보정 문장 → 완성 글자 직접 편집 → 편집 의도 분류 → 관련 글자 자동 전파`다.
- 사용자는 초성·중성·종성 카드나 레이아웃 편집 화면에서 적용 범위를 선택하지 않는다.
- 완성 글자의 자모 전체 이동·크기 변경은 레이아웃 패턴 변화로, 점·획 변경은 자모 형태 변화로 기록한다.
- 기존 모바일 편집기의 트랙패드, 포인트·베지어 조작, 스냅, SVG 렌더러, 히스토리는 독립 부품으로만 차용한다. 기존 페이지 라우팅과 자모 교체 스와이퍼는 신규 흐름에 포함하지 않는다.

### 검증된 구현 상태 — 2026-08-20

- 보정 문장은 글자별 카드가 아니라 연속된 글줄로 조판한다. 각 글자는 개별 선택할 수 있지만 줄바꿈은 글자 중간이 아닌 어절 경계에서 일어난다. 현재 한글은 레이아웃별 Design Body 가로폭을 advance로 사용한다. 스페이스는 기본 Body 폭 850에서 500 unit을 기준으로 글로벌 Body 가로 변화율을 따르며, 문장부호는 0.5em advance를 사용한다. 선택용 터치 영역은 글자 간격을 바꾸지 않는다.
- 신규 흐름의 기본 Font Space는 UPM 1000, Major Grid 8×8, Minor Grid 25 unit, Snap 5 unit이다. Grid 표시는 안내선이고 실제 편집 스냅은 별도 값에서 계산한다.
- 기본 Design Body는 EM 안쪽 75 unit inset의 850×850 영역이며 편집 화면에는 약한 안내선으로만 표시한다.
- Font Space 1000×1000은 고정하고, 폰트 전체 Design Body와 레이아웃별 Design Body 보정은 네 방향 inset으로 저장한다. 보정 화면의 네모꼴 설정과 SVG·폰트 출력은 같은 `globalPadding` 및 `paddingOverrides`를 사용한다.
- Design Body 비율이 바뀌면 내부 분할선, 파트 여백, 간격과 자모 슬롯도 기본 850×850 Body를 기준으로 같은 x/y 비율만큼 변환한다. 바깥 Body만 줄여 특정 슬롯이나 돌출 획이 과도하게 압축되지 않게 한다.
- Design Body와 advance는 조판 폭을 정하지만 Ink Bounds를 다시 맞추는 클리핑 경계가 아니다. 완성 글자 편집기에서 이동·확대한 레이아웃과 돌출 획은 예시 문장과 폰트 출력에서도 같은 형태를 유지한다.
- 한글 Advance Width는 실제 잉크 경계에서 자동 산출하지 않고 레이아웃별 Design Body 가로폭을 사용한다. 예시 문장과 폰트 출력이 같은 advance를 사용하며, 글리프 좌표는 Design Body의 왼쪽을 출력 원점으로 옮긴다. 글자별 잉크 기반 가변폭과 커닝은 side bearing과 조판 리듬을 함께 정의한 뒤 후속 검토한다.
- OTF 출력은 화면과 같은 Design Body 좌표·문맥별 안전 보정·linecap·linejoin 계산을 사용한다. 글리프 Y 좌표는 ascender 880, descender -120 기준으로 변환하고 실제 잉크는 해당 레이아웃의 advance 경계 안에 유지한다. 한글 이름은 원문을 보존하되 설치 충돌을 막는 고유 ASCII/PostScript 식별자를 함께 생성하며, 완성형 11,172자와 호환 자모 51자를 포함한다. 좌표·메트릭·수록 범위와 CFF 겹침 제거·닫힌 경로 시작점 정규화를 전체 OTF 생성 및 실제 렌더링으로 검증했다.
- 신규 보정 화면의 추출 버튼은 별도 프로젝트 저장본을 다시 불러오지 않고 현재 확정된 자모 마스터·레이아웃 프로필·Design Body 값을 직접 OTF 생성기에 전달한다. 진행 중인 제스처의 미확정 미리보기 값은 출력에 포함하지 않는다.
- 완성 글자의 컴포넌트·획·점·베지어 핸들을 구분해 선택할 수 있다. 컴포넌트 이동·크기 변경은 레이아웃 프로필로, 획·점·핸들 변경은 자모 마스터로 분류한다.
- 글자의 자모를 처음 누르면 해당 자모 자체가 아니라 초성·중성·종성 레이아웃 영역을 선택한다. 큰 편집 글자와 보정 문장에 동일 영역의 전파 범위를 표시하고, 같은 획을 다시 누르면 영역 강조를 닫고 자모의 획·점 편집으로 전환한다.
- 사용자의 원본 편집과 그 편집에서 결정적으로 분류한 적용 규칙을 별도 기록하며, 레이아웃 프로필은 기본 레이아웃 템플릿과 분리해 저장한다.
- Undo/Redo는 레이아웃 프로필과 자모 마스터 양쪽에 동일하게 적용한다.
- 자모 마스터는 캔버스 여백이나 조합 위치를 저장하지 않는다. 다만 현재 기본 자모는 실제 종횡비가 소실된 구형 `slot-normalized` 좌표이므로 레이아웃 슬롯의 x/y 크기에 각각 맞춘다.
- 실제 잉크 경계를 기준으로 고유 비율을 보존해 만든 신규 `ink-normalized` 마스터만 조합 슬롯 안에서 x/y를 같은 비율로 확대·축소한다. 두 좌표 모드를 구분하지 않고 기존 자모에 균일 스케일을 적용하면 세로중성의 높이가 가로폭에 종속되는 오류가 생긴다.
- 과거 `ㅏ·ㅗ·ㅜ` 자모 데이터에 있던 위치용 padding은 레이아웃 계산의 조합 배치 프로필로 이관했다. 화면 렌더링, 편집 선택선, 폰트 출력은 동일한 좌표 모드와 배치 변환을 사용한다.
- 초성이 `ㄷ·ㅁ·ㅂ` 계열처럼 닫힌 몸체형 하단면을 가진 경우 위쪽 가로중성 `ㅗ·ㅛ`의 세로획이 초성 하단 획을 관통하지 않는다. 초성과 중성의 기존 가로폭은 바꾸지 않으며, `ㄱ·ㄴ·ㄹ`처럼 열린 구조에는 이 세로 제한을 적용하지 않는다. 이 형태 규칙은 화면과 폰트 출력이 공유하는 레이아웃 계산 단계에 적용한다.
- 신규 보정 화면에서 레이아웃 슬롯은 배치 안내선이며 획 편집의 클리핑 경계가 아니다. 점·획·베지어 핸들은 슬롯 밖으로 이동할 수 있고, 기존 editor-v2의 명시적 `0–1` 편집 경계는 변경하지 않는다.
- 슬롯 밖 자유 편집 중에도 서로 다른 컴포넌트의 실제 곡선과 획 두께 사이에는 Minor Grid 1칸(기본 25 unit)의 최소 잉크 간격을 유지한다. 같은 자모 내부에서 획이 접합·교차하는 것은 검사하지 않는다.
- 자모 획 편집에서는 선택한 글자가 다른 문맥의 충돌 때문에 멈추지 않고 자기 문맥의 충돌에만 제한된다. 자모 마스터에는 사용자가 만든 전체 변화량을 공통 목표로 저장하고, 다른 완성 글자는 실제 잉크 여유에 따라 그 변화량을 0–100% 사이에서 독립적으로 적용한다. 여유 있는 글자는 끝까지 뻗고 충돌하는 글자만 최소 간격 직전에서 안전 보정되며, 완성 자소 복사본을 저장하지 않는다.
- 문맥별 안전 보정은 화면 렌더링과 폰트 출력에서 같은 계산을 사용하고, 보정 문장에는 안전 보정된 글자를 별도 색으로 표시한다. 이미 최소 간격보다 가까운 기존 상태에서는 현재보다 간격을 악화시키는 편집만 막고, 간격을 유지하거나 벌리는 탈출 편집은 허용한다. 다른 컴포넌트까지 자동으로 이동시키는 확장형 Collision Solver는 후속 범위다.
- 모바일 제스처가 `pointercancel`로 종료되어도 마지막 미리보기 값을 한 번의 편집으로 확정한다. 분석용 복사는 클릭 순간의 자모·레이아웃·보정 프로젝트 저장소를 직접 읽고, 현재 문장에 사용된 값뿐 아니라 편집 이력에 포함된 모든 변경 자모·레이아웃의 최종값과 변경 요약을 함께 기록한다.
- 사용자가 문장 보정으로 만든 첫 번째 스타일은 신규 보정 흐름의 기본값으로 사용한다. 5 unit 그리드에 맞춰 레이아웃 수치를 정돈하고 원형 자소의 중심과 베지어 핸들을 대칭화하되, 기울어진 혼합중성과 슬롯 밖 획처럼 반복 편집으로 드러난 의도적 비대칭은 유지한다. 슬롯 밖 끝획은 글자 폭을 깨지 않는 범위로 제한한다.

## 결정 기록 방식

논의와 구현 결과는 다음 상태를 구분해 기록한다.

- **사실**: 코드, 사용자 검증, 기술 실험 등으로 확인된 내용
- **가설**: 가치나 구현 가능성을 검증해야 하는 제안
- **미결정**: 대안과 위험이 남아 선택하지 않은 사항

현재 이 문서에서 사실로 볼 수 있는 것은 프로젝트가 정규화된 벡터 획 데이터를 사용하며, OTF 출력 과정에서 원형 중심선 획을 채워진 윤곽선으로 변환한다는 점이다. 원형 획의 화면·OTF 공통 좌표, 교차 획의 CFF 겹침 제거, 닫힌 경로 꼭짓점, 폰트 전체 적용은 실제 생성 파일과 브라우저·macOS CoreText 렌더링으로 검증했다. 고정각 납작형의 출력 품질과 구현 가능성은 아직 검증된 사실이 아니다. `획 따라가기`와 개별 획 오버라이드는 후속 가설이며, 그 구현 방식은 미결정이다.

제품 결정, 프로토타입 결과, 사용자 검증 또는 기술 제약이 새로 확인되면 관련 항목의 상태와 근거를 갱신한다. 오래된 가설을 확정 사실처럼 남겨두지 않는다.
