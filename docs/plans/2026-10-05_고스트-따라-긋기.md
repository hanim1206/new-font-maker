# 그린 획에 역할 붙이기 (고스트 따라 긋기 + 자유 그리기)

- **이번에 비교하는 것**: 그린 획을 프리셋 획에 **대응시키는 점수의 문턱 `τ`**. 문턱 위면 그 프리셋 획의 역할(id · 채널 · 방향 · 닫힘)을 승계하고, 아래면 "자유 획"으로 남긴다. 같은 손그림 묶음에서 `τ`마다 맞게 인식한 비율과 잘못 붙인 비율을 잰다.
- **이번 승인으로 바뀌는 것**: 편집기(잠긴 자소)에 `펜` 도구 하나 — 고스트를 깔거나 끄고 그린다. 그린 뒤 자모 단위로 세 상태 중 하나를 보여 준다: **인식됨 / 일부 자유 / 자유**. 자유 획이 있으면 "이 자모는 전체 스타일 · 문맥 조정이 일부만 적용돼요"를 알린다.
- **바뀌지 않는 것**: 생성 엔진 · 보선 · 프리셋 · 저장 스키마 · 내보내기. 인식된 획은 좌표만 바꿔 끼우고, 자유 획은 지금도 되는 "이름 없는 획"으로 저장한다(새 타입 없음).

## 왜

엔진은 획의 **이름(id) · 순서 · 방향 · 채널**로 판단하고 모양은 안 본다(앞 플랜 점검표). 따라 긋기만 허용하면 입문자에게 쉽지만 프리셋과 많이 다른 글자는 못 만든다. 자유도를 주되, 그린 획이 **어느 프리셋 획인지 알아볼 수 있으면 역할을 붙이고**, 알아볼 수 없으면 자유 획으로 두고 그 대가(아래)를 알려 준다. 100% 자유에서 시작해도 같은 판정을 거친다 — 고스트는 판정을 쉽게 하는 안내일 뿐이다.

자유 획으로 남으면 지금 엔진에서 이렇게 된다(코드 조사, 10-05).

| 되는 것 | 안 되는 것 |
|---|---|
| 그린 대로 렌더 · 두께 · 끝 모양 · 내보내기 | 홀자 줄기를 보선에 붙이기(ㅏ 곁줄기가 기둥을 안 따라감) |
| 자모 칸은 획 범위로 계산(초성 · 종성은 대체로 괜찮음) | 얇은 칸 넓히기(ㅣ · ㅡ의 휨이 납작해짐) |
| 굵기 · 끝모양 전체 스타일 | 섞임홀자 채널(ㅘ의 '오'가 세로부 칸에 들어감) |
| | 문맥 오버라이드 · 문맥 틈 보정(자모 단위로 초기화) |

그래서 **홀자는 인식이 거의 필수**이고, 닿자는 자유 획이어도 크게 안 망가진다. 알림 문구는 이 차이를 담는다.

## D0 계약 초안

- **한 값**: 대응 점수 문턱 `τ`. 점수는 그린 획 ↔ 프리셋 획 쌍마다 0–1: 현 각도 차(가로 · 세로 · 삐침 · 내림, `strokeGrammar.shapeOf`와 같은 기준) · 중심 위치 차 · 길이 비 · 닫힘 일치의 가중합. 자모 안에서 1:1 최적 대응(헝가리안)을 구하고, 쌍 점수가 `τ` 미만이면 둘 다 짝 없음. 후보 `τ` 0.5 · 0.65 · 0.8.
- **인식된 획**: 프리셋 획에서 `id` · `closed` · `thickness` · `linecap/linejoin` · 채널을 승계하고 `points`만 `fitPenStroke` 결과로. 시작점이 프리셋 끝점에 더 가까우면 점 순서를 뒤집는다. 닫힌 프리셋 획은 시작 · 끝이 두께 안이면 닫고, 아니면 자유 획.
- **자유 획**: `pen-<자모>-<n>` id, 채널은 자모의 기본 채널(섞임홀자는 획 범위가 가로부 칸에 더 겹치면 가로부). 두께는 자모 공통값.
- **획 수가 다를 때**: 그린 획이 프리셋보다 많으면 남는 것은 자유 획. 적으면 빠진 프리셋 획을 고스트로 남겨 "더 긋기 / 이대로 두기"를 묻는다. "이대로"면 그 자모는 **일부 자유**.
- **자모 상태와 안내**: 인식됨(전부 짝) / 일부 자유 / 자유(짝 0). 홀자가 일부 자유 이상이면 경고 톤("기둥 · 보선이 안 따라가요"), 닿자는 안내 톤("문맥 조정은 적용 안 돼요").
- **오버라이드**: 펜 도구에 들어갈 때 그 자모의 문맥 오버라이드 · 계열 획 · 문맥 보정이 있으면 "N개가 초기화돼요" 안내 후 비운다.
- **고스트**: 기본 켬. 끄면 빈 상자. 어느 쪽이든 판정은 같다.
- **칸**: 그리는 상자는 그 자모의 기본 칸 비율. `frame` 없는 자모는 첫 획 저장 때 지금 규칙대로 굳힌다.
- **안 하는 것**: 자유 획을 보선에 붙이는 새 로직(그건 별도 플랜 — 자유 획에서 기둥을 각도로 뽑는 것), 압력 → 두께, 획 자동 분리 · 합치기.
- **미결정**: 점수 가중치(G0에서 `τ`와 함께 고정값으로 시작), 홀자 자유 획을 아예 막을지(질문 2).

| G3 사용자 | 아이패드에서 자모 하나를 자유롭게 긋고 안내 문구 → 문장 미리보기 | 사용자 확인 — "무엇이 안 되는지 알겠다" |

## 확인 질문

1. 점수의 재료: **각도 · 위치 · 길이 · 닫힘**(추천) / 거기에 꺾임 수까지 / 모양 거리(프레셰)까지 — 뒤로 갈수록 정확하지만 G0 전에 못 가늠.
2. 홀자 자유 획: **허용하되 경고**(추천) / 홀자는 인식 안 되면 저장 막기.
3. 오버라이드: **들어갈 때 안내하고 비운다**(추천) / 유지.

## 진행 기록

**2026-10-05**
- 사실: 엔진은 `label`을 안 읽고 id · 첫/끝 점 · 획 범위로 판단한다(앞 플랜 점검표). 인식된 획은 좌표만 바꿔 끼우면 보선 · 채널 · 닫힘이 그대로 돈다. 자유 획은 지금도 "이름 없는 획"으로 렌더되고 보선 · 얇은 칸 · 채널 · 문맥 보정만 빠진다.
- 사실: 편집기 `선 추가`(`CalibrationSentenceEditor.tsx` `addStroke`)가 `onCommitJamo(before, after, …)`로 자모를 통째 바꾸는 길이 있어 같은 경로로 들어갈 수 있다. 현 각도 분류는 `strokeGrammar.shapeOf`(±10°)가 이미 있다.
- 뒤집힘: 첫 판은 "따라 긋기만"이었다(AI). 사용자 — 자유도를 주되 역할을 추출하고, 못 알아보면 전체 스타일 적용이 어렵다고 알린다. 그래서 `τ` 문턱으로 선을 긋는 지금 판으로.
- 가설: 각도 · 위치 · 길이 · 닫힘만으로 닿자 대부분은 맞는다. ㅅ/ㅈ의 삐침 · 내림, ㅁ/ㅂ의 닫힘 여부가 어려운 자리다.
- 미결정: 위 확인 질문 셋.
