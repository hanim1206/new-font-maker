# 그리드 점유 기반 면 생성

그리드 시스템 2는 기존 중심선 획을 그리드에 스냅하거나 끝만 같은 각도로 자르는 스타일이 아니다. 사용자가 먼저 형태 그리드의 가로·세로 레일, 간격, 획 채널과 대각선 계열을 정하고 글자 면은 그 경계 안에서만 생성한다.

글자는 래스터 칸을 칠하지 않고 인접한 레일 사이의 벡터 영역을 점유한다. 직선은 선택한 채널을 채우고, 꺾임은 채널의 접속 규칙으로 만든다. 곡선은 자유 베지어가 아니라 그리드 간격에서 계산할 수 있는 반지름과 접선 조합만 제안한다. 절단도 자유 각도가 아니라 그리드 교점에서 나오는 대각선 계열만 사용한다.

폰트 전체에는 공통 형태 그리드를 두고 10개 한글 레이아웃은 초성·중성·종성 영역이 어떤 레일 구간을 쓰는지만 보정한다. 레이아웃마다 완전히 다른 그리드를 만들면 자모 정체성이 깨질 수 있으므로 공통 규격과 레이아웃별 배치 오버라이드를 분리한다.

편집 흐름은 `형태 그리드 설정 → 레이아웃 선택 → 자모가 점유할 채널 선택 → 규격 곡률 제안 선택 → 허용된 대각선으로 끝면 절단 → 문장 비교`로 잡는다. 사용자의 기존 중심선은 참고 골격과 변환 전 원본으로 남기되 Grid 2의 최종 면은 중심선 sweep가 아니라 채널 점유 정보에서 다시 생성한다.

첫 프로토타입은 10개 레이아웃 전체가 아니라 `초성 단독`의 `ㄱ·ㄴ·ㄷ·ㅁ·ㅇ`으로 제한한다. 가로·세로 레일을 직접 움직이고, 레일 사이 한 채널을 채우며, 한 종류의 규격 곡률과 한 대각선 계열만 사용해 조형 일관성을 먼저 본다.

현재 구현한 25-unit 스냅 Grid 2는 기술 실험으로만 남기고 이 개념의 완성으로 보지 않는다.

첫 상호작용 실험실은 앱 안의 별도 전체 화면으로 만들었다. 공통 6×6 레일, 칸 점유, `ㅇ`의 내부 공간을 포함한 벡터 외곽선 합성, 부분 곡률, 교점 기준 절단, Undo/Redo와 재접속 복원을 `ㄱ·ㄴ·ㄷ·ㅁ·ㅇ`에 한정해 확인한다. 아직 기존 10개 레이아웃이나 전체 OTF에는 이 점유 데이터를 연결하지 않는다.

그리드 편집 모드에서는 반복 슬라이더를 없애고 캔버스의 레일을 직접 드래그한다. 기본 25 unit 단위로 딱 맞춰 움직이며 하단에는 선택 레일 위치와 스냅 단위의 숫자 입력만 둔다. 가로·세로 레일 추가와 선택 레일 삭제도 구현했다. 추가할 때는 기존 칸의 점유 상태를 새 칸에 이어받고, 삭제할 때는 맞닿은 두 칸 중 하나라도 채워져 있으면 병합한 칸을 채워 잉크가 갑자기 사라지지 않게 한다. 최소 간격과 최대 레일 수를 두어 모바일 조작과 윤곽 품질이 무너지지 않게 한다.

절단각은 독립적인 각도 슬라이더로 풀지 않는다. 절단 모드에서 사용자가 그리드 교점 하나를 누르고 다른 행과 열의 교점까지 이어 기준선을 그린다. 이 선에서 각도만 가져와 별도 깊이로 자르지 않고 선 자체를 실제 절단 경계로 쓴다. 선이 확정되면 캔버스의 양쪽 면 자체가 선택 영역이 된다. 한쪽 면에 호버하거나 포커스를 두면 그쪽에서 사라질 실제 글자 면이 흐려지고, 클릭하면 해당 면을 삭제한다. 삭제 완료 뒤 캔버스를 다시 누르면 교점 그리드가 곧바로 다시 나타나 같은 흐름을 반복한다. 별도의 위·아래 삭제 버튼, 기준선 다시 그리기 버튼, 더 작은 면을 자동으로 추측하는 규칙은 두지 않는다. 기준선과 글자별 적용 절단은 좌표값이 아니라 두 교점의 인덱스로 저장하므로 레일을 움직이면 경계가 자동으로 다시 계산되고, 레일을 추가·삭제해도 선택했던 교점 위치를 가능한 한 이어간다. 여러 절단선과 자유 베지어 핸들은 다음 범위로 남긴다.

첫 교점을 고른 뒤 다른 교점에 호버하거나 키보드 포커스를 두면 두 점 사이의 임시 기준선이 따라온다. 다른 행과 열에 있어 선택 가능한 대각선은 주황색 점선, 같은 행이나 열이라 선택할 수 없는 후보는 붉은 짧은 점선으로 구분한다. 두 번째 점을 탐색하는 동안에는 이전 확정 기준선을 숨겨 현재 후보와 혼동하지 않게 한다.

실제 사용 검증에서 기준선보다 훨씬 많은 면이 잘리는 원인은 각도만 가져오고 절단 깊이를 글자 경계의 최대 18%로 별도 계산한 데 있었다. 이 계산을 제거하고 두 교점의 무한 직선으로 면을 나누는 방식으로 수정했다. 화면의 기준선과 실제 절단 경계가 일치하며 위쪽·아래쪽 삭제를 전환할 수 있다.

곡률도 글자 전체 꼭짓점에 고정 반지름을 일괄 적용하지 않는다. 곡률 모드에서 실제 외곽선의 적용 가능한 꼭짓점만 표시하고, 사용자가 꼭짓점과 들어오는 경계의 시작 교점, 나가는 경계의 끝 교점을 차례로 골라 곡선이 차지할 면적을 직접 정한다. 저장 단위도 `대상 꼭짓점 + 들어오는 경계 끝점 + 나가는 경계 끝점`으로 바꿨다. 레일 추가·삭제 시 교점 인덱스를 함께 보정하며, 점유 변경으로 해당 꼭짓점이 사라진 데이터는 렌더링에서 적용하지 않는다.

결과를 확정하기 전에 바뀌는 면적을 직접 보여준다. 절단선 양쪽의 캔버스 면에 호버하거나 키보드 포커스를 두면 선택한 반평면을 옅게 표시하고 실제 글자에서 사라질 부분은 더 진한 위험색으로 표시한다. 곡률 모서리와 범위 후보에 호버하거나 포커스를 두면 직각 윤곽과 예상 곡선 윤곽 사이에서 사라지는 정확한 쐐기 면적과 곡선을 함께 표시한다. 모서리를 선택한 뒤에는 호버가 없는 모바일에서도 같은 미리보기를 고정해 다음 시작점·끝점 선택의 맥락을 유지한다. 이 동작은 실제 브라우저 호버와 390px 모바일 화면에서 검증했다.

실험실 하단에는 모바일에서도 항상 보이는 `전체 초기화` 버튼을 추가했다. 초기화도 한 번의 편집 이력으로 남으므로 실행 취소할 수 있다.

절단 교점은 전체 레일 교차점을 한꺼번에 보여주지 않는다. 처음에는 현재 글자 외곽의 모서리만 표시하고 첫 점을 고른 뒤에만 다른 행과 열에 있는 외곽선 교점을 펼친다. 직선 구간의 중간 교점은 호버·포커스로 계속 선택할 수 있어 절단 자유도는 유지한다. 다른 도구나 자모 탭으로 이동하면 진행 중이던 첫 점과 호버 미리보기를 초기화한다. 이 흐름은 데스크톱 절단 순환과 390px 모바일 화면을 포함한 브라우저 자동화로 검증했다.

## 구현 완료 — 곡률 선택 단축

`모서리 → 시작점 → 끝점` 3회 선택을 `모서리 선택 → 2차원 곡률 핸들 조절·확정`의 2단계로 교체했다. 핸들의 두 축은 인접한 두 경계 교점에 각각 스냅되므로 비대칭 곡률 데이터도 그대로 유지한다. 데스크톱에서는 호버로 쐐기 면적을 미리 보고 드래그를 놓는 순간 저장하며, 390px 화면에서는 모서리 탭 뒤 조절 영역을 한 번 더 탭해 적용한다. 별도 설정이나 프리셋은 추가하지 않았다. 드래그 중 미리보기, 두 번째 조작의 저장, 기존 절단 순환과 모바일 가로폭을 브라우저 자동화로 검증했다.

핸들 점을 정확히 누를 필요도 없게 했다. 모서리부터 가능한 최대 곡률까지의 전체 쐐기 칸을 터치 영역으로 쓰고, 칸 안을 누르면 가장 가까운 두 경계 교점으로 스냅한다. 390px 화면에서 실제 점과 떨어진 칸 중앙을 눌러 적용되는 것까지 검증했다.

채우기는 곡률의 국소 복구 역할도 한다. 곡률이 닿은 점유 칸을 누르면 칸을 비우지 않고 그 곡률을 제거해 직각 면으로 다시 채운다. 복원한 뒤 같은 칸을 다시 눌러야 기존처럼 빈다. 데스크톱과 390px 탭, 실행 취소 이력을 자동화로 검증했다.

## 이전 구현 — 국소 절단과 각도 스탬프

이전 절단은 선택한 선의 반평면을 글자 전체에 적용해 다른 획까지 함께 지운다. 현재 MVP는 의미론적 획을 임의로 추측하지 않고, 선택한 점유 칸 안의 글자 면에만 적용한다. 호버·포커스 중에는 실제 삭제 면을 먼저 보여준다. 첫 꺾임이나 분기 전까지의 채널 인식은 후속 범위다.

첫 절단이 적용되면 그 기준선의 각도와 삭제 방향을 스탬프로 유지한다. 데스크톱에서는 같은 각도의 선이 커서를 따라다니고, 점유 칸을 클릭할 때마다 그 칸에만 절단을 누적한다. 모바일에서는 같은 칸 탭 흐름으로 연속 적용한다. 빈 캔버스를 누르거나 도구를 바꾸면 스탬프를 끝내고 교점 선택으로 돌아간다. 여러 절단은 `localCuts[]`로 누적하고 최초 두 교점의 기준선을 공유해 레일 이동 뒤에도 같은 각도를 유지한다. 기존 전역 절단 저장본은 읽기 호환을 유지했다. 데스크톱 호버·반복 클릭과 390px 연속 탭을 브라우저 자동화로 검증했다.

## 구현 완료 — 각도 스탬프 철회와 외곽선 사선화

버그와 상태 복잡도가 큰 각도 복사 스탬프를 현재 도구 흐름에서 제거했다. 기존 `cut`·`localCuts[]`는 이전 저장본의 표시 호환으로만 남긴다.

래퍼런스의 사선은 무한한 선의 한쪽 면을 지우는 절단보다, 두 그리드 교점 사이의 직각 외곽선 구간을 하나의 사선 변으로 교체한 형태에 가깝다. 따라서 후속안은 `절단선 선택 → 삭제 방향 선택`을 제거하고, `외곽 모서리나 구간 선택 → 다른 외곽 교점으로 사선 연결`만 남긴다. 삭제할 면은 폐곡선의 안쪽으로 자동 결정되므로 방향을 묻지 않는다.

데스크톱은 `모서리 누름 → 쐐기 면으로 드래그 → 놓아서 적용`을 한 제스처로 이어간다. 짧게 눌렀다 놓으면 적용하지 않고 범위 선택 상태에 남아 두 번째 클릭을 받을 수 있으며, 모바일은 `모서리 탭 → 쐐기 면 탭`의 두 단계를 유지한다. 호버와 첫 탭 후에는 글자 전체가 아니라 교체될 외곽 구간과 결과 사선만 미리 보여준다. 현재는 볼록 외곽 모서리만 허용하고, 내부 공간·오목 모서리·다른 외곽을 가로지르는 선택은 후속으로 남긴다. 도구나 자모를 바꾸면 진행 중인 선택을 초기화하며, 데스크톱 단일 드래그·단일 실행 취소·390px 탭을 브라우저 자동화로 검증했다.

## 논의 중 — 편집 패널 축소

모바일에서 곡률 상태 카드, 비활성 버튼, `전체 곡률 해제`, 공통 레일·스냅·곡률·사선 요약 카드가 캔버스보다 많은 세로 공간을 차지한다. 직접 조작 흐름에서는 `선택 취소`와 `이 모서리 곡률 해제`를 빈 캔버스 탭·도구 전환·채우기로 대체할 수 있고, 공통 요약은 조작을 만들지 않는 피동 정보다. 따라서 상단의 짧은 문맥 안내만 남기고 곡률 옵션 패널과 2×2 요약 카드를 제거하는 안을 검토한다. 레일 도구의 수치 입력, 실행 취소·다시 실행, 하단 `전체 초기화`는 유지한다. 아직 구현하지 않은 제안이다.

J-02 실제 검토에서도 면 채우기 중 하단 `정밀 조절` 패널은 캔버스에 이미 보이는 점유 상태와 채우기·비우기 안내를 반복해 작업 영역만 줄였다. 면 채우기에는 별도의 수치가 없으므로 이 모드에서는 패널을 숨기고, 레일 편집의 수치 입력에는 정밀 조절 패널을 유지한다. 2026-08-24 J-02에 이 구분을 반영하고 390px 화면에서 면 도구의 패널 제거와 선택 도구의 패널 복귀를 확인했다.

## 구현 완료 — 채우기 연속 드래그

채우기는 첫 칸에서 `채우기`나 `비우기` 방향을 결정하고, 손이 지나간 모든 칸에 같은 상태를 연속으로 적용한다. 같은 칸을 왕복해도 한 제스처 안에서 두 번 토글하지 않고, 손을 떼면 전체 드래그를 하나의 편집 이력으로 저장한다. 곡률·사선이 닿은 칸에서 시작하면 직각 복원 방향으로 동작한다. 데스크톱과 390px 화면에서 세 칸 연속 채우기와 단일 실행 취소를 브라우저 자동화로 검증했다.

## 2026-09-16 결정 — 메인 앱 통합 방향

아방가르드한 볼드 조형을 만들려면 선 외에 면이 필요하다는 판단에서 랩을 다시 보고 메인 앱에 어떻게 녹일지 정했다.

현재 상태를 보면 이미 반은 들어와 있다. `src/types`의 `JamoConstructionElement`가 `GridCenterlineElement`(선)와 `GridAreaElement`(면)를 함께 담고, 면은 `filledCells`와 `boundaryTreatments`(곡률·사선)로 저장된다. `ShapeWorkspacePage`에는 셀 점유 도구까지 있다. 비어 있는 건 곡률·사선을 잉크로 그리는 부분과 그 편집 도구다. 랩의 단면(`localCuts`)은 메인 타입에 없다.

핵심 구조는 잉크 층이 합류점이라는 것이다. 선이든 면이든 나중에 들어올 Noto 윤곽이든 전부 `InkRegion[]`로 환원된 뒤 union → 미리보기 → 폰트 출력을 같이 탄다. 면은 선의 대체가 아니라 세 번째 재료이고, 한 자모 안에 선과 면이 섞여도 된다.

결정한 것.

- 굵기 축과 면: 면은 굵기 축을 무시한다. 면의 굵기는 레일과 칸으로만 만든다. 외곽 offset으로 굵기에 반응하는 방식은 면이 선을 흉내 내기 시작해 경계가 흐려지므로 넣지 않는다. 필요해지면 면 단위 옵션으로 나중에 검토한다.
- 단면(cut): 보류. 1차는 사선까지만. 사선으로 부족한 사례가 쌓이면 재검토한다.
- 순서: Noto 윤곽 렌더 경로(Y-2)와 같이 간다. 둘 다 `shapeGlyphInkResolver`를 손대는 작업이라 `outline` 종류 추가와 `area`의 곡률·사선 렌더를 한 번에 잡는다. 랩의 `getGrid2ShapePath`·clip polygon·Q 곡률 로직을 `gridAreaToInkRegions`로 이식한다.
- 편집 도구(곡률·사선)는 엔진 뒤에. 랩에서 검증한 `모서리 클릭 → 핸들 끌기` UX를 재사용하되 목업부터 만든다. `ShapeWorkspacePage`의 "곡률·사선이 있는 면은 편집 불가" 가드는 엔진이 붙은 뒤 푼다.
- 검증: 레일을 옮길 때 면과 곡률이 문맥별로 따라오는지(`jamoContextVariants`) 확인한다.
