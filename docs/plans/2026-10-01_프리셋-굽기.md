# 프리셋 굽기

- **이번에 비교하는 것**: 사용자가 제품 에디터로 만든 원본 폰트 대 그 폰트를 구운 v2로 새로 만든 폰트. 둘은 같아야 한다.
- **이번 승인으로 바뀌는 것**: v2를 만드는 길(관리자 대푯값 편집기 → 제품 에디터 + 굽기), 관리자의 `v2로 굽기` 단추, v2 폰트가 구운 파일을 읽는 구조
- **바뀌지 않는 것**: 기존 폰트(계속 v1), 새 폰트의 기본(출시 한 줄 전까지 v1), 원본 폰트 자체, 노토 모델 파일

## 왜

관리자 `프리셋` 편집기는 레이아웃 대푯값만 고친다. 획 모양 · 자모별 조정 · 짧은기둥 가로 자리는 못 고친다. 제품 에디터는 이걸 다 하고, 사용자가 이미 손에 익었다. 그래서 프리셋은 제품 에디터로 만들고, 완성한 폰트를 프리셋으로 지정하는 단계(굽기)만 새로 만든다(10-01 사용자 결정).

## D0 계약 초안

- **굽는 것**: 폰트 데이터 통째. 자소 획, 레이아웃 Δ, 전역 스타일, 네모꼴(여백). 계정 정보는 싣지 않고 폰트 이름과 구운 날짜만 적는다.
- **파일**: `public/house-preset/basic-gothic-v2.font.json`. 지금 있는 대푯값 파일(`basic-gothic-v2.json`, 노토 복사)은 그대로 둔다.
- **굽는 곳**: 관리자 계정 폰트 카드의 `v2로 굽기`. 개발 서버 전용이고 문지기는 지금 저장 API와 같다(이 맥 · 전용 헤더 · 같은 출처). 배포본에는 쓰기가 없다. 레포 파일을 덮으므로 누르면 한 번 확인한다.
- **새 v2 폰트가 받는 방식**은 둘로 나뉜다.
  - 자소 획 · 전역 스타일 · 네모꼴은 **시작값**이다. 폰트를 만들 때 복사해 넣는다. 지금 기본 획이 들어가는 것과 같은 방식이다.
  - 레이아웃 Δ는 **프리셋 층**이다. 복사하지 않고 모델 입구(`notoModel.ts`)가 v2 모델에 실어 주고, 칸 풀기가 사용자 Δ보다 먼저 얹는다. 화면 · 카드 · 문장 · OTF가 모두 이 입구를 지나므로 다른 곳은 안 고친다.
- **사용자 쪽에서 보이는 것**: 새 v2 폰트의 오버라이드 카드는 비어 있다. 사용자가 조정을 얹었다가 지우면 노토 자리가 아니라 프리셋 자리로 돌아온다(원칙 `프리셋 오버라이드와 사용자 오버라이드는 저장 따로`).
- **다시 굽기**: 출시 전에는 몇 번이든 덮어쓴다. 출시(`DEFAULT_FONT_PRESET` 한 줄) 뒤에는 v2 파일을 얼리고, 고친 프리셋은 v3로 옆에 둔다(원칙 `레거시 동결`). v2 폰트를 원본으로 다시 구울 때는 프리셋 층과 사용자 Δ를 합쳐 적는다.
- **관리자 대푯값 편집기**: 얼린다. 지우지 않고 더 손보지도 않는다. v1 · v2 비교 줄은 구운 v2를 보여 준다.
- **미결정**
  - 줄기 마스터는 폰트 데이터에 없고 이 기기에만 남는다(줄기 마스터 플랜 D0 미결정). 구운 프리셋에는 획 모양만 실린다. 새 v2 폰트에서 전파가 어떻게 보이는지는 G0에서 본다.
  - 저장 형태가 `노토 모델 + 우리 Δ`다. 09-29의 "노토에 맞춘 뒤 오차로 만들지 않는다"와 닿는다. 레이아웃 전체 Δ를 대푯값 절대값으로 접어 넣으면 피할 수 있는데, 홀자 Δ와 대푯값의 대응을 아직 안 쟀다. 다음 플랜 후보로 둔다.

## 진행 기록

- 2026-10-01 · 플랜 작성. 코드 변경 없음.
  - **사실 (결정, 사용자)**: v2는 관리자 대푯값 편집기가 아니라 제품 에디터로 만들고 굽는다. [하우스 레이아웃 프리셋 편집기](./2026-09-29_하우스-레이아웃-프리셋-편집기.md)의 "관리자에서 직접 집도"를 뒤집는다.
  - **사실**: 폰트 데이터는 자소 획 · 레이아웃 Δ · 전역 스타일 · 네모꼴을 담는다. 줄기 마스터는 안 담긴다(`stemMasterStore`는 이 기기 전용). 새 폰트는 브라우저 사본을 비운 뒤 코드의 기본값으로 시작한다(`fontSwitch.ts` → `startAccountFont`). 레이아웃 Δ를 읽는 곳은 여섯 군데지만 칸 풀기는 모두 모델 묶음을 받는다.
  - **사실**: 관리자 편집기의 지금 상태를 쟀다. 닿자 네 변, 기둥 가로 자리, 곁줄기 · 걸침 · 보 높이는 여섯 레이아웃 모두 끌 수 있다. 짧은기둥 가로 자리와 ㅔ ㅖ ㅞ 안 기둥 가로 자리는 숨는다. ㅐ 안 기둥은 뜨는데 ㅔ만 안 뜨는 까닭은 확인하지 않았다.
  - **가설**: 레이아웃 Δ를 모델 묶음에 실으면 소비처를 안 고쳐도 된다. G0에서 확인한다.
  - **주의**: 원본 폰트는 로그인한 계정에서 만든다. 확인용 서버(`dev:nogate`)는 브라우저에만 저장한다.
