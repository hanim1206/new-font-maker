### 검증된 Shape System 구현 상태 — 2026-08-24

- Shape System V2는 역할별 7개 construction, 선택적 공통 layout grid, 선택적 문맥 preset catalog를 한 strict 원본으로 저장한다. Shape V1과 FontData 1.3을 읽으면 layout grid와 catalog를 추측하지 않고 명시적인 `null` 상태로 V2/FontData 1.4에 올린다. 파생 grid·윤곽·provenance·history는 저장하지 않는다.
- 새 프로젝트의 Shape 구조는 화면의 `추천 기본 구조로 시작`을 사용자가 눌렀을 때만 만든다. 현재 starter는 7개 역할 grid와 STANDALONE·CH의 `ㄱ` 중심선 마스터만 제공하며 공통 layout grid나 67개 자소를 자동 생성하지 않는다. 기존 저장값이나 Grid Lab 숫자에서 묵시적으로 seed하지 않는다.
- J-03 조합 화면은 `ㄱ·가·고·과·각·곡·곽`의 정확한 역할·문맥을 해석하고, 현재 자소·현재 문맥의 안쪽 왼쪽·오른쪽·위·아래 코어 Rail override를 실제 Shape 최종 잉크로 미리 본다. 카드 관찰만으로 variant를 만들지 않으며, 편집을 명시적으로 시작한 뒤 `pointerup`에서 command 한 건을 저장한다. `pointercancel`은 원본으로 돌아가고, 기본값 복원은 선택한 sparse override만 제거한다.
- Shape 편집 Undo/Redo는 before/after 원본 transaction을 사용하며 세션 history만 유지한다. 로컬 저장 완료를 표시하기 전에는 디바운스된 Shape write를 명시적으로 flush한다. 프로젝트 apply는 layout·jamo·style·Shape와 두 history를 먼저 검증하고, 지연 저장 실패가 발생하면 메모리와 저장 원본을 함께 복원한다.
- 위 J-03 수직 흐름은 390px 화면에서 `starter 생성 → 캔버스 Rail 직접 드래그 → cancel 무변 → pointerup 1회 저장 → Undo → Redo → reload 복원`으로 검증했다. 드래그 중에는 같은 final ink를 다시 해석해 미리보기만 바꾸고 저장하지 않는다. 아직 Rail 추가·삭제, 셀 채우기, 참조 재연결, 곡률·사선, 전체 폰트 Shape 출력은 연결하지 않았다.
- J-02의 단일 원자 셀 면 생성·이동은 stable element/cell ID, draft, pointerup 1회 저장, cancel 무변, Undo exact 복원을 확인한 기술 조각이다. 2026-08-24 사용자 검토에서 전체 그리드 점유 편집이라는 제품 의도와 다르다고 판정했으므로 완성된 `면 채우기`로 취급하거나 이 흐름을 확장하지 않는다. 다음 조각은 현재 part grid의 모든 원자 셀을 직접 채우고 비우며 하나의 면 요소가 여러 `filledCells`를 소유하는 방식으로 교체한다.

### 원도 5선 네모꼴 P0 구현 예정 계약 — 2026-08-28

> 상태: 기술 계약 및 시각 기본값 승인 대기. 아직 구현되거나 검증된 사실이 아니다. 단일 기준 문서는 [`docs/specs/FIVE_GUIDE_SQUARE_LAYOUT_P0_SPEC.md`](specs/FIVE_GUIDE_SQUARE_LAYOUT_P0_SPEC.md)다.

- P0는 신규 5선 네모꼴 프로젝트만 대상으로 한다. 고정 Canonical Design Body와 `square-upm` 메트릭을 사용하며, 기존 프로젝트는 현재 `layout-design-body` 메트릭과 출력 결과를 유지한다.
- 5선은 고정 상단 기준선·typography baseline과 가변 배치선 3선으로 구분한다. 원도의 `밑선`은 baseline이며 현 출력 메트릭에서 `fontY=0`, glyph-normalized Y `.880`으로 고정한다. Canonical Design Body 아래 경계 `.925`는 필요하면 보조 표시로 사용하지만 5선 role에 포함하지 않는다. Layout Grid V2의 안정 Rail ID에 role을 명시적으로 결속하고, 숫자 위치만 보고 기존 Layout Grid V1의 role을 추론하지 않는다.
- 구조 마이그레이션은 Layout Grid V2, Shape V3, FontData 1.5로 원본을 올리되 기존 프로젝트의 role binding은 `null`로 둔다. P0에는 기존 프로젝트의 5선 연결·advance 변환·Design Body 변환을 포함하지 않는다.
- provisional 배치선과 between 비율은 비영속 비교 보드에서만 사용한다. 사용자 시각 승인 전에는 production starter나 복구 기본값으로 등록하지 않는다.
- 대표 자소의 중심선·면·hole은 하나의 `FinalGlyphInk`를 만들고, 화면과 prototype OTF는 그 결과를 각각의 출력 좌표로만 투영한다.

### 시각 보정의 근거와 승인 단위 — 2026-08-28

- 기존 코드의 레이아웃 숫자는 동작을 재현하는 기술 기준일 뿐, 새 서체의 시각 기본값으로 자동 승격하지 않는다.
- 배치·간격·두께 같은 시각 보정은 한 번에 질문 하나만 다룬다. 대상 자모와 문맥, 고정 변수, 판단 제외 범위를 먼저 고정한다.
- 후보를 만들기 전 보유한 무료폰트의 실제 윤곽을 같은 좌표계로 비교한다. 폰트 파일·굵기·라이선스·출처·해시와 측정 한계를 함께 남기고, 스타일 경계용 서체는 중립 기준 집계와 구분한다.
- Reference Group Lab의 기준선 조율값은 분석용 로컬 데이터다. 넓은 `가로·세로·섞임 × 받침 유무` 값은 비교 기준일 뿐이며, 실제 윤곽 위에 표시하는 첫닿·받침선은 `file SHA + 축 + 첫닿자 + 선택 홀자 + 실제 받침` 조합과 일치해야 한다. `고`에서 조율한 첫닿선을 `구`에 재사용하는 식의 문맥 축약은 금지하고, 정확한 조합값이 없으면 미측정으로 숨긴다. 생산용 layout grid·자모 마스터·OTF 기본값으로 자동 승격하거나 seed하지 않는다.
- 홀자 외부 관측은 첫닿 조율값과 별도 저장소에 `file SHA + 축 + 홀자 + 받침 유무 + 역할` raw 좌표로 보관한다. 관측 기둥·보의 외곽면과 생성용 JamoMaster 축을 같은 값으로 저장하지 않는다. 화면의 후보 JU 슬롯 배경은 비교 전용이며 production LayoutProfile로 저장하지 않는다.
- 홀자 외부 관측의 기둥·보·짧은 세로줄기는 무한 기준선 하나로 축약하지 않는다. 선택한 외곽 면 위치와 실제로 보이는 유한 구간들을 같은 구조 요소 후보로 묶는다. 접합·겹침으로 가린 구간은 복원해서 채우지 않으며 전체 외접 높이·너비와 실제 노출 길이를 다른 파생값으로 계산한다. 외부 관측의 가시 구간과 JamoMaster의 로컬 `top/bottom`·`left/right` 구조 끝은 계속 분리한다.
- 외부 폰트에서 여러 홀자 구조면이 하나의 합쳐진 contour에 들어갈 수 있으므로 `contour 하나=역할 하나`로 가정하지 않는다. 전체 contour 역할 탐색이 실패하면 실제로 바깥에 노출된 축평행 segment 묶음을 유한 면 후보로 사용하고, 같은 contour 안의 기둥과 보를 서로 다른 역할로 허용한다. 이 fallback은 medium confidence를 넘지 않으며 `ㅘ` 아랫보는 먼저 찾은 짧은 세로줄기 끝과 접하는 면만 허용한다. 고정 나눔고딕 G4 위험 표본 24글자에서 후보 60개·자동 포기 4개를 agent가 전수 확인했고 역할 오선택은 0개였으며, 사용자가 같은 화면을 확인했다.
- 반복 구조는 상대 위치와 접합 관계로 분리한다. `ㅐ·ㅔ·ㅒ·ㅖ·ㅙ·ㅞ`의 안쪽·바깥쪽 긴 기둥, `ㅑ·ㅒ·ㅕ·ㅖ`의 위·아랫보, `ㅛ·ㅠ`의 좌우 짧은 세로줄기를 글자별 contour 번호 없이 각각 고른다. 고정 Noto Sans KR·나눔고딕의 ㄱ 대표 56글자에서 v4 후보 180/192개를 전수 확인해 역할 오선택 0개를 기록했다. 나눔고딕의 둥근 혼합 바탕보 12개는 평평한 국소 지지 구간이 부족해 좌표를 만들지 않고 `non-scalar-face`로 남겼다.
- 첫닿자 19자 전체로 넓힌 P1 G2의 v4 검증 판정은 사용자 화면 검토에서 폐기됐다. Noto `표`에서 `ㅛ primaryBeam` 대신 초성 `ㅍ`의 가운데 가로획을 고른 역할 오염이 확인됐다. 구조 순서·후보율만으로 역할 정확도를 증명할 수 없으며, `ㅛ·ㅠ` 주 보는 좌우 줄기와의 방향성 접합을 함께 증명해야 한다. 수정 버전의 전체 재검증 전에는 G2를 통과로 기록하지 않는다.
- `geometric-role-matcher-v6`의 agent 판정은 사용자 화면 검토로 무효화됐다. 나눔고딕 `궥·뛔·뛕`의 휜 혼합 바탕보와 `뚀`의 명백한 ㅛ 구조를 자동 포기했고, `뫠`에서는 기반 줄기 대신 초성의 세로면을 고른 사실이 후속 구조 검사에서 확인됐다. 후보율과 구조 순서만으로 역할 정확도를 선언하지 않으며 P1 G2·G4는 문맥별 탐색 방향을 적용한 다음 버전의 전체 재검증 전까지 열린 상태다.
- 홀자 자동 추출은 완성 글자를 무방향으로 훑지 않는다. 요청에서 이미 아는 홀자와 조합 문맥을 검색 계약으로 사용한다. 세로형은 오른쪽 외곽에서 안쪽으로 `바깥기둥 → 안기둥 → 방향이 맞는 부착 보`를 찾고, 가로형은 초성 아래의 긴 보에서 시작해 `ㅗ·ㅛ`의 위쪽 줄기와 `ㅜ·ㅠ`의 아래쪽 줄기를 접합으로 검증한다. 혼합형은 초성 아래 왼쪽의 기반 보를 먼저 찾고 방향성 기반 줄기를 결속한 뒤 오른쪽 외곽부터 세로부를 찾는다. 받침은 단순히 아래에 있다는 이유로 고르지 않고 이 홀자 위상을 만족하지 못하면 제외한다.
- `geometric-role-matcher-v7`은 사용자 화면 검토로 무효화됐다. Noto `규·귝`에서 `ㅠ rightStem`이 실제 오른쪽 짧은 세로줄기 대신 주 가로보의 오른쪽 끝면을 골랐고, 후속 전수 감사에서 같은 오염이 `ㅛ·ㅠ × 19초성 × 받침 없음/ㄱ` 76문맥 모두에 있었음이 확인됐다. 후보 누락 0건과 기존 구조·방향·스캔 계약 통과는 역할 정확도 증명이 아니었다. v7은 프리셋 입력과 생산 사용에서 차단한다.
- `geometric-role-matcher-v8`도 사용자 화면 검토로 무효화됐다. `ㅛ·ㅠ` 끝면 오염 76건은 막았지만 Noto `풔·풕`에서 `ㅝ` 바탕 보·줄기 대신 초성 `ㅍ` 중간 보와 오른쪽 끝면을 골랐다. 전체 혼합 바탕 구조 감사에서 같은 실패가 `뒥·뤄·뤼·뤽·퉈·튀·튁·풔·풕·퓌·퓍` 11문맥에 반복됐다. 오선택 줄기 면은 선택 보의 오른끝과 같아 내부 여유가 0이었고 정상 대안은 최소 184.529 unit 안쪽에 있었다. 접합만으로는 역할을 증명할 수 없으며 혼합 바탕 줄기는 선택 보 내부에 결속되어야 한다. v8과 그 P1 G4 완료 판정은 프리셋 입력·생산 사용에서 차단한다.
- `geometric-role-matcher-v9`는 혼합 바탕 줄기가 선택 보 양끝에서 보 폭의 8% 이상 안쪽에 있어야 같은 홀자 구조로 인정한다. 이 규칙은 글자·첫닿·폰트·좌표 예외 없이 Noto의 오염 11문맥·22요소만 교정했고 나눔고딕 출력은 바꾸지 않았다. 두 고정 폰트 1,064글자·3,648요소 전수 계산과 변경 영향권 `ㅙ·ㅚ·ㅝ·ㅞ·ㅟ` 380카드·1,520후보의 에이전트 화면검사에서 계약 위반과 역할 오선택은 0건이었다. API·parser·cache 교체 뒤 사용자가 실제 Noto `풔·풕` 화면을 확인해 P1 G4를 닫았다. 이 승인은 고정 범위 분석 관측에만 적용하며 생산값 자동 승격은 계속 금지한다.
- Noto 단일 출처 `기본 고딕 01` 작업의 v8 관찰 manifest는 승인 입력에서 차단한다. v9 manifest는 `ㄱ × 14개 P1 홀자 × 받침 없음/ㄱ` 28자의 좌표·reference mode·anchor·가시 구간이 기존 사용자 확인값과 같은 digest일 때만 그 관찰 승인 상태를 승계한다. `/preset-candidate-lab`은 계속 읽기 전용이고 localStorage나 제품 프리셋을 바꾸지 않으며, 후보 artifact도 별도 사용자 승인 전에는 생산 프리셋이 아니다.
- `기본 고딕 01`의 r1·r2·r3은 모두 폐기 이력이다. r3은 문맥축은 바로잡았지만 초성·홀자·종성을 한 글자 안에서 공동 배치하지 않았고, 외부 윤곽의 가시 외곽 구간과 앱 중심선 구간을 같은 의미로 비교했다. 후보 화면과 컴파일러가 서로 다른 linecap을 사용한 문제도 있었다. 따라서 낮은 RMSE는 올바른 글자 조합의 증거가 아니며 제품값이나 검수 후보로 재사용하지 않는다.
- 새 프리셋 입력은 `joint-component-input-v1`으로 초성 v3 114건, 홀자 42건, 종성 v1 81건을 같은 Noto SHA와 shared-baseline 좌표계에서 결속한다. 초성·종성의 대표 `ㅏ·ㅗ·ㅘ` 값을 다른 홀자에 적용할 때는 정확 관측으로 위장하지 않고 `structure-context-projection`으로 표시한다. `/preset-candidate-lab`은 별도 보조 보드 없이 상단 19초성 선택과 `선택 초성 × 21홀자 × 무받침/ㄱ` 단일 보드를 사용한다. 무받침은 공동 layout fit 입력 준비 상태이고, 종성은 별도 사용자 시각 검증이 끝날 때까지 받침 포함 후보 생성을 차단한다. 전역 후보 스타일은 `linecap=square`, `linejoin=round`, 둥근 붓촉으로 고정하며 화면과 컴파일러가 같은 계약을 사용해야 한다.
- 사용자 캡처의 글자·초성·폰트 ID를 runtime 예외 조건이나 좌표표로 넣지 않는다. 캡처는 같은 홀자를 `19초성 × 받침 없음/ㄱ × 고정 2폰트`로 다시 검사하는 회귀 입력이다. 허용되는 일반화 단위는 홀자 역할 위상, 부착 방향, 구조 순서, 실제 윤곽에서 정규화한 비율뿐이다.
- P1 G3도 별도 화면을 만들지 않는다. 기존 `/font-guide-lab?font=...`의 21홀자 버튼 모두가 고정 Noto Sans KR·나눔고딕의 현재 API 후보를 요청한다. 추출 의미가 바뀌면 extractor·browser cache identity를 함께 올리며, 기존 7홀자의 요소 근거와 analysis gold 자체는 v3 동결 기록을 유지한다. 국소 접선 후보는 글리프에 가려지지 않는 시작점 표식을 함께 보여 줘야 한다.
- 레거시 첫닿·받침 기준선과 자소 영역 색면은 문맥을 축약한 숫자로 복구하지 않는다. 홀자 P1 G4 뒤 별도 닿자 자동 추출 단계에서 `file SHA + 축 + 첫닿자 + 선택 홀자 + 실제 받침`별 유한 구조면을 먼저 검증하고, 선택 영역 색면도 승인된 상·하·좌·우 관측면에서 파생한다. 초성 19자를 먼저 다룬 뒤 종성 27자로 확장하며 같은 Font Guide Lab 화면을 유지한다.
- 첫닿 자동 추출에서 `componentGroup`, 상·하·좌·우 원시 `inkBounds`, 선택 전 평평한 `axisFaces`, 역할 판정을 마친 `roleFaces`, 네 역할 단면의 파생 `selectionArea`를 분리한다. `첫윗단면·첫밑단면`은 첫닿 전체 잉크 극값, `첫왼단면·첫오른단면`은 초성 구조 클래스가 정한 첫 구조획 양끝이다. 곡선 닿자는 축 평행 면이 없어도 해당 역할 클래스가 전체 잉크 극값을 쓰는 경우 역할 단면을 관측할 수 있다. 탐색용 ROI·레거시 기준 숫자·원시 bbox를 선택 색면으로 보여 주지 않는다. P0는 고정 두 폰트의 현대 첫닿 19자와 `ㅏ·ㅗ·ㅘ × 받침 없음/ㄱ` 6문맥으로 제한한다.
- 받침 자동 추출 D0는 현대 받침 27종을 `단일 14종·된받침 2종·겹받침 11종`으로 나눈다. `받침윗단면·받침밑단면·받침왼단면·받침오른단면`은 역할 판정을 마친 받침 전체 그룹의 실제 잉크 외곽 극값을 사용한다. 첫닿의 첫 구조획 좌우 규칙을 받침에 복사하지 않는다. 된받침과 겹받침은 왼·오른 구성원 경계 fragment와 contour·segment 구간, 실제 접촉 관계를 별도 provenance로 보존하고 하나의 bbox만으로 승인하지 않는다. 자동 응답은 `candidate | abstained`만 만들며 `verified | rejected`는 후보 artifact와 identity를 참조한 별도 사용자 화면 검증 기록에서만 만든다. 이 결정은 역할·응답 계약 승인이지 G0 추출 정확도 승인이 아니다.
- 첫닿 P0 `initial-component-matcher-v2`의 component grouping과 나눔고딕 합쳐진 contour 29건 분리는 유지한다. 사용자 검토에서 v2가 `selectionArea`를 전체 `inkBounds`로 파생해 승인된 첫닿 좌우 역할을 무시한 사실이 확인되어 v2 UI·G2 완료 판정을 무효화했다. `initial-component-matcher-v3`는 `full-component`, `first-main-horizontal`, `paired-first-main-horizontal`, `marked-body-horizontal` 역할 구조 클래스에서 네 `roleFaces`를 고른다. `ㄹ·ㄷ·ㅌ` 오른단면은 첫 가로획의 첫 바깥 꺾임, `ㄸ`은 병렬 첫 구조의 오른쪽 꺾임, `ㅊ·ㅎ`은 윗 모자를 제외한 본체 가로획 양끝을 쓴다. 고정 Noto Sans KR·나눔고딕 228글자에서 역할 단면 912/912와 역할 색면 228/228을 계산했고 fixture·parser·API·cache·Font Guide Lab 화면을 v2 계약으로 교체했다. 레거시 Noto 첫윗·첫밑선 228값은 평가기에서만 비교하며 최대 차이는 0.499 unit이다. 글자·폰트·contour 번호·레거시 좌표 예외는 없다. 사용자가 실제 Font Guide Lab에서 `ㄹ`의 첫오른단면과 역할 색면 교정을 확인해 P0 G2·G3를 승인했다. 생산값에는 자동 승격하지 않는다.
- 홀자의 `outerPillarFace`는 오른쪽에 놓인 긴 바깥기둥의 우측 외곽면이다. 기둥 중심축이나 초성 쪽 좌측면을 대신하지 않는다. 좌측면이 필요한 초성↔홀자 잉크 간격은 별도 파생 지표로 측정한다.
- 곡선 구조면은 전체를 단일 x/y로 대표하지 않는다. 시작 방향이 자소 구조 역할로 승인되면 글자별 허용 목록이 아니라 해당 홀자 역할 전체에 적용하고, 시작점의 국소 접선과 허용 편차 안의 짧은 지지 구간을 provenance와 함께 기록한다. 현재 `ㅘ lowerBeam`은 모든 첫닿자와 받침 없음/ㄱ 문맥에서 왼쪽 시작 기준을 쓴다. 이 후보를 전체 보 높이·길이로 해석하지 않으며 방향 규칙이 없는 비정형 면은 자동 포기한다.
- `start-side-local-tangent`는 배치용 시작 앵커 제약이다. G2는 이 앵커로 현재 자모의 슬롯·Split·Padding을 이동하거나 스케일할 수 있지만, 직선 획을 자동으로 휘게 하거나 외부 폰트의 곡선을 추론·복사하지 않는다. 현재 자모 경로가 곡선이면 그 곡선을 유지하고 직선이면 직선을 유지한다. 곡률 보정은 공간 승인 뒤 별도 형태 단계에서 시작점·끝점·접선 또는 제어점 근거와 새 사용자 승인을 갖춰 수행한다.
- 가로 홀자를 `보만 있는 구조`로 축약하지 않는다. `ㅗ·ㅜ`는 짧은 세로줄기 1개, `ㅛ·ㅠ`는 좌우 세로줄기 2개, `ㅡ`만 세로줄기가 없다. 외부 관측은 각 짧은 세로줄기의 가로 위치용 바깥 면과 진행 방향 끝면을 보선과 별도 역할로 기록한다. 획 전체 폭·길이·접합은 실제 윤곽이나 JamoMaster 구조에서 파생하며 기준선 한 값에 합치지 않는다.
- 반복 구조를 대표선 하나로 축약하지 않는다. `ㅐ·ㅔ`는 안쪽·바깥쪽 긴 기둥과 보, `ㅒ·ㅖ`는 두 긴 기둥과 두 보를 각각 독립 역할로 기록한다. `ㅛ·ㅠ`의 두 짧은 세로줄기도 좌우 역할과 끝면을 따로 가진다. 한 요소가 가려지거나 검출되지 않아도 다른 요소의 관측 후보를 함께 버리거나 숨은 값을 복제하지 않는다.
- 자소 contour 끝이 이웃 자소 잉크 안에 묻히면 `숨은 컴포넌트 끝`, `보이는 접촉면`, `겹침 깊이`를 구분한다. 숨은 끝은 provenance가 있는 분석 근거일 뿐 바깥면 기준선으로 채택하지 않는다. 접촉면과 겹침 깊이는 완성 글자 관계에서 계산한 `DerivedMetrics`로 두며 JamoMaster 끝 좌표나 LayoutProfile Rail로 자동 승격하지 않는다.
- 기준선 조율 입력은 임의의 `0–1000` 제한이 아니라 분석 SVG viewBox 범위를 따른다. 글리프의 실제 받침 끝이 EM을 넘으면 그 좌표를 보존한다. 홀자 기둥선은 가로팔의 bbox 끝이 아니라 긴 세로 구조면의 바깥 끝을 사용한다.
- 첫닿 좌우선은 잉크 전체의 좌우 bbox가 아니라 첫 구조획의 폭을 나타낸다. `ㄱ`의 왼선은 위 가로획 시작점이며, 오른선은 그 획이 꺾여 내려가는 상부 구조의 우측 외곽이다. 가로 막대 사각형의 내부 접합 끝이나 분리된 아래 삐침·갈고리를 쓰지 않는다. 첫닿윗·밑선은 계속 첫닿 전체 외곽을 사용한다.
- 첫닿 좌우선의 기준 구조획이 가로획인 자소는 그 가로획의 양 끝을 쓴다. `ㅈ·ㅊ·ㅋ·ㅌ·ㅍ·ㅎ`처럼 대각선·세로 돌기·아래 분리획이 더 넓어도 그 외곽을 좌우선으로 쓰지 않는다. `ㅎ·ㅊ`의 분리된 짧은 윗 모자 획은 기준 구조획이 아니며, 모자 아래 본체 가로획을 쓴다. `ㅃ·ㅉ`처럼 같은 높이의 병렬 본체 가로획은 두 획 묶음의 좌우 외곽을 쓰되, 오른선은 오른쪽 본체 가로획이 처음 꺾이는 바깥면에서 멈춘다.
- `ㄹ·ㄷ·ㅌ`의 첫닿오른선은 첫 가로획이 아래로 꺾이는 첫 바깥면이다. 아래 장가로획이나 마지막 획의 끝은 쓰지 않는다. `ㄸ`은 같은 높이 두 첫 구조의 오른쪽 꺾임을 쓴다. 이 규칙은 여섯 문맥 모두에 직접 측정해 적용한다.
- 기준선값은 역할·구조 단위·외곽면 판정을 거친 뒤에만 저장한다. 내부 접합점·counter·인접 자소 윤곽·정의상 제외한 장식은 후보에서 탈락한다. 저장 전 대상 카드에서 선이 선택 윤곽 외곽에 닿고, 빈틈이나 윤곽 침범이 없는지 확인한다. 받침 좌우선은 받침이 있는 세 문맥을 모두 확인한다.
- 기준선 여섯 문맥은 화면 카드 배치나 SVG 배열 순서로 대응시키지 않는다. 저장·추출·재검증은 `initial-horizontal` → `initial-horizontal-final` → `initial-mixed` → `initial-mixed-final` → `initial-vertical` → `initial-vertical-final`의 안정 문맥 ID와 카드에 표시된 글자를 함께 확인한다. 둘 중 하나라도 다르면 값을 저장하지 않는다.
- 서체 간 위치·크기 비교는 공통 UPM·원점·ascender/descender·baseline을 명시하고 각 글리프의 원래 advance를 유지한다. 개별 ink bounds에 맞춘 확대나 가운데 정렬로 차이를 숨기지 않으며, 모든 비교 셀에 같은 기준선을 표시한다.
- 특정 변수만 격리하는 보조 비교에서는 원본 좌표본을 함께 남기고 변환식·고정값·미승인 범위를 명시한 경우에만 comparison-only 정규화본을 추가한다. 이 정규화본은 production 자소나 5선의 승인값으로 승격하지 않으며, 선행 크기·위치 조건이 미승인인 동안 후속 간격 판정을 보류한다.
- 사용자 확인물은 실제 글자 윤곽, 현재값, 복수 후보, 후보 도출 근거, 남은 미결정을 한 HTML에 담는다. 막대나 슬롯 수치만으로 시각 승인을 요청하지 않는다.
- 사용자가 고른 단위만 versioned fixture와 후속 구현의 입력으로 승격한다. 승인 전 후보는 비영속이며 production starter·복구 기본값·전체 자모 규칙에 반영하지 않는다.

### 검증된 구현 상태 — 2026-08-20

- 보정 문장은 글자별 카드가 아니라 연속된 글줄로 조판한다. 각 글자는 개별 선택할 수 있지만 줄바꿈은 글자 중간이 아닌 어절 경계에서 일어난다. 현재 한글은 레이아웃별 Design Body 가로폭을 advance로 사용한다. 스페이스는 기본 Body 폭 850에서 500 unit을 기준으로 글로벌 Body 가로 변화율을 따르며, 문장부호는 0.5em advance를 사용한다. 선택용 터치 영역은 글자 간격을 바꾸지 않는다.
- 신규 흐름의 기본 Font Space는 UPM 1000, Major Grid 8×8, Minor Grid 25 unit, Snap 5 unit이다. Grid 표시는 안내선이고 실제 편집 스냅은 별도 값에서 계산한다.
- 기본 Design Body는 EM 안쪽 75 unit inset의 850×850 영역이며 편집 화면에는 약한 안내선으로만 표시한다.
- Font Space 1000×1000은 고정하고, 폰트 전체 Design Body와 레이아웃별 Design Body 보정은 네 방향 inset으로 저장한다. 보정 화면의 네모꼴 설정과 SVG·폰트 출력은 같은 `globalPadding` 및 `paddingOverrides`를 사용한다.
- Design Body 비율이 바뀌면 내부 분할선, 파트 여백, 간격과 자모 슬롯도 기본 850×850 Body를 기준으로 같은 x/y 비율만큼 변환한다. 바깥 Body만 줄여 특정 슬롯이나 돌출 획이 과도하게 압축되지 않게 한다.
- Design Body와 advance는 조판 폭을 정하지만 Ink Bounds를 다시 맞추는 클리핑 경계가 아니다. 완성 글자 편집기에서 이동·확대한 레이아웃과 돌출 획은 예시 문장과 폰트 출력에서도 같은 형태를 유지한다.
- 한글 Advance Width는 실제 잉크 경계에서 자동 산출하지 않고 레이아웃별 Design Body 가로폭을 사용한다. 예시 문장과 폰트 출력이 같은 advance를 사용하며, 글리프 좌표는 Design Body의 왼쪽을 출력 원점으로 옮긴다. 글자별 잉크 기반 가변폭과 커닝은 side bearing과 조판 리듬을 함께 정의한 뒤 후속 검토한다.
- OTF 출력은 화면과 같은 Design Body 좌표·문맥별 안전 보정·linecap·linejoin 계산을 사용한다. 글리프 Y 좌표는 ascender 880, descender -120 기준으로 변환하고 실제 잉크는 해당 레이아웃의 advance 경계 안에 유지한다. 한글 이름은 원문을 보존하되 설치 충돌을 막는 고유 ASCII/PostScript 식별자를 함께 생성하며, 완성형 11,172자와 호환 자모 51자를 포함한다. 좌표·메트릭·수록 범위와 CFF 겹침 제거·닫힌 경로 시작점 정규화를 전체 OTF 생성 및 실제 렌더링으로 검증했다.
- 신규 보정 화면의 추출 버튼은 별도 프로젝트 저장본을 다시 불러오지 않고 현재 확정된 자모 마스터·레이아웃 프로필·Design Body 값을 직접 OTF 생성기에 전달한다. 진행 중인 제스처의 미확정 미리보기 값은 출력에 포함하지 않는다.
- 상단의 설정 버튼 하나가 하단 `글로벌 스타일` 조절판을 열고, 그 안에서 `글자 네모꼴`과 `획 스타일`을 전환한다. 기존 네모꼴 팝업은 이 하단 조절판 구조로 통합했다. 획 스타일 탭에서는 이전 편집의 선택 획·꼭짓점·레이아웃 강조를 숨겨 윤곽만 비교한다. `원형·납작형·네모형` 대표 글자를 바로 비교하고, 납작함 슬라이더와 좌우 각도 패드로 폰트 전체 설정을 미리 본다. 제스처 종료 시 한 번의 이력으로 저장하며 Undo/Redo와 로컬 재접속 복원이 적용된다. 화면과 같은 네모형 설정으로 전체 OTF 생성·다운로드까지 검증했다.
- 기존 `면적형` 실험은 중심선의 열린 끝에 절단각을 적용하는 `절단형 끝처리`로 역할을 축소했다. 점 반복형은 화면·OTF 공통 생성 경로까지 기술 검증했지만 교차부와 형태 규칙의 조형 품질 문제가 남아 제품 UI에서 보류한다.
- `그리드 시스템 2`는 기존 중심선에 획 폭과 절단각을 입히는 스타일이 아니라, 사용자가 먼저 형태 레일을 정하고 레일 사이의 칸을 점유하여 글자 면을 만드는 별도 생성 규칙으로 정의한다. 곡률과 절단도 자유 수치가 아니라 형태 그리드의 교점에서만 정한다. 첫 상호작용 프로토타입은 별도 전체 화면 실험실에서 `ㄱ·ㄴ·ㄷ·ㅁ·ㅇ`만 다룬다. 기본 6×6 공통 레일을 캔버스에서 직접 드래그하고 기본 25 unit 단위로 스냅하며, 하단에는 반복 슬라이더 대신 선택 레일 위치와 스냅 단위의 숫자 입력만 둔다. 가로·세로 레일을 추가하면 기존 점유 칸을 분할하고 삭제하면 맞닿은 두 칸을 병합한다. 칸 채우기, 점유 면의 단일 벡터 외곽선 합성, `ㅇ`의 내부 공간을 제공한다. 곡률은 글자 전체에 고정 반경으로 적용하지 않고 사용자가 외곽 모서리와 들어오는 선의 시작 교점, 나가는 선의 끝 교점을 차례로 골라 해당 구간에만 적용한다. 모서리·범위 후보에 호버하거나 키보드 포커스를 두면 직각과 예상 곡선 사이의 쐐기 면적과 곡선을 미리 표시하고, 모서리를 선택한 뒤에는 모바일에서도 미리보기를 고정한다. 절단은 교점 두 개를 잇는 선에서 각도만 빌려 별도 깊이로 자르지 않는다. 처음에는 글자 외곽 모서리만 표시하고, 첫 교점을 고른 뒤에만 외곽선 위의 유효한 레일 교점을 펼친다. 직선 구간의 중간 교점은 숨겨져 있어도 호버·포커스로 선택할 수 있다. 첫 교점을 선택한 뒤 다른 교점에 호버하거나 포커스를 두면 두 점 사이의 임시선을 표시하며 유효한 대각선과 선택 불가능한 같은 행·열을 색과 점선 간격으로 구분한다. 도구나 자모 탭을 벗어나면 진행 중인 첫 교점과 호버 미리보기를 초기화한다. 선택한 선 자체가 실제 절단 경계다. 선을 확정한 뒤 캔버스의 양쪽 면을 직접 선택 영역으로 사용하며, 한쪽 면에 호버하거나 포커스를 두면 그쪽에서 사라질 실제 글자 면을 흐리게 표시하고 클릭하면 그대로 삭제한다. 삭제 완료 후 캔버스를 다시 누르면 별도 버튼 없이 교점 그리드가 다시 열려 같은 순환을 반복한다. 별도의 위·아래 삭제 버튼, 기준선 다시 그리기 버튼, 면적 자동 추측은 두지 않는다. 기준선·절단·곡률은 교점 인덱스로 저장하여 레일 이동 시 형태가 다시 계산되고 레일 추가·삭제 시 선택 위치를 함께 보정한다. Undo/Redo와 재접속 복원도 제공하며 모바일에서도 보이는 전체 초기화 버튼 역시 한 번의 실행 취소 가능한 변경으로 처리한다. 원본 중심선은 변경하지 않고 Grid 2 실험 데이터를 분리해 저장한다. 기존의 25-unit 스냅·75-unit 획·35° 절단 렌더러는 화면·OTF 공통 출력 기술을 검증한 선행 실험으로 남아 있으나, 새 형태 그리드 데이터는 아직 10개 레이아웃과 전체 OTF에 전파하지 않는다. 대표 자모에서 레일 점유 방식의 조형 타당성을 먼저 검토한 뒤 출력 파이프라인 연결 범위를 결정한다.
- Grid 2 곡률의 최신 구현은 위 기록의 세 점 순차 선택을 대체한다. `모서리 선택 → 2차원 곡률 핸들 조절·확정`의 두 단계만 사용하고, 핸들의 가로·세로 축을 인접한 두 경계 교점에 각각 투영하여 비대칭 범위를 함께 저장한다. 데스크톱 호버·드래그와 390px 화면의 탭 적용을 같은 상태 전이로 검증했다.
- 곡률 범위는 핸들 점 자체만 터치 대상으로 삼지 않는다. 선택한 모서리와 가능한 최대 범위 사이의 전체 쐐기 칸을 조작 영역으로 사용하고, 칸 안을 누르면 가장 가까운 두 경계 교점으로 스냅한다.
- Grid 2에서 곡률이나 사선이 닿은 점유 칸을 채우기 도구로 누르면, 첫 조작은 칸을 비우지 않고 해당 국소 편집을 제거해 직각 면을 복원한다. 복원된 칸을 다시 누를 때부터 기존 칸 비우기로 동작한다. 이 복구는 하나의 실행 취소 가능한 변경으로 저장하며 데스크톱과 390px 탭으로 검증했다.
- Grid 2 채우기는 첫 칸에서 결정한 `채우기`나 `비우기`를 드래그가 지나간 모든 칸에 같게 적용한다. 같은 칸을 왕복해도 한 제스처 안에서 두 번 토글하지 않고, 손을 떼는 시점에 전체 드래그를 하나의 실행 취소 가능한 변경으로 저장한다. 데스크톱과 390px 화면의 세 칸 연속 드래그로 검증했다.
- Grid 2의 최신 사선 구현은 무한한 기준선과 삭제 방향을 사용하던 절단과 각도 복사 스탬프를 대체한다. 외곽의 볼록 모서리를 고른 뒤 쐐기 면을 끌거나 눌러 두 직각 경계 구간을 하나의 사선 변으로 치환한다. 삭제 방향은 폐곡선의 안쪽에서 자동 결정된다. 데스크톱은 `모서리 누름 → 쐐기 면으로 드래그 → 놓아서 적용`하는 한 번의 제스처와 짧은 클릭 후 재선택을 함께 지원하고, 390px 화면은 `모서리 탭 → 쐐기 면 탭`을 유지한다. 도구나 자모를 바꾸면 진행 중인 선택을 초기화하며, 기존 `cut`·`localCuts[]`는 이전 저장본의 표시 호환으로만 유지한다. 오목 모서리·내부 공간·다른 외곽을 가로지르는 사선은 후속 범위다.
- 완성 글자의 컴포넌트·획·점·베지어 핸들을 구분해 선택할 수 있다. 컴포넌트 이동·크기 변경은 레이아웃 프로필로, 획·점·핸들 변경은 자모 마스터로 분류한다.
- 글자의 자모를 처음 누르면 해당 자모 자체가 아니라 초성·중성·종성 레이아웃 영역을 선택한다. 큰 편집 글자와 보정 문장에 동일 영역의 전파 범위를 표시하고, 같은 획을 다시 누르면 영역 강조를 닫고 자모의 획·점 편집으로 전환한다.
- 사용자의 원본 편집과 그 편집에서 결정적으로 분류한 적용 규칙을 별도 기록하며, 레이아웃 프로필은 기본 레이아웃 템플릿과 분리해 저장한다.
- 형태 규칙 데이터는 획의 모든 특징을 선제적으로 분류하지 않는다. 규칙 대상을 다시 찾기 위한 최소 기하 정보만 기본값으로 두고, 사용자가 형태의 예절과 일괄 적용 범위를 검토해 추가한다. 위치·방향처럼 좌표에서 다시 계산할 수 있는 값은 중복 저장하지 않는다.
- 형태 규칙 패널은 별도 복제 자모가 아니라 실제 보정 에디터에서 현재 선택한 자모 마스터를 직접 읽는다. 여러 획의 주방향·경로 시작과 끝·연결 관계는 현재 좌표에서 다시 계산하고, 사용자가 확인한 필순과 형태 예절·적용 범위만 획 ID에 연결해 저장한다.
- Undo/Redo는 레이아웃 프로필과 자모 마스터 양쪽에 동일하게 적용한다.
- 자모 마스터는 캔버스 여백이나 조합 위치를 저장하지 않는다. 다만 현재 기본 자모는 실제 종횡비가 소실된 구형 `slot-normalized` 좌표이므로 레이아웃 슬롯의 x/y 크기에 각각 맞춘다.
- 프리셋 공동 입력 검수판은 수치 상태표만 두지 않는다. 같은 글자 카드 안에서 외부 폰트 실제 윤곽과 추출 영역, 현재 앱 기준값, 새 후보 캔버스를 나란히 비교한다. 새 후보가 아직 생성되지 않았으면 입력 영역만 표시하고 형태를 임의로 그리지 않는다.
- 실제 잉크 경계를 기준으로 고유 비율을 보존해 만든 신규 `ink-normalized` 마스터만 조합 슬롯 안에서 x/y를 같은 비율로 확대·축소한다. 두 좌표 모드를 구분하지 않고 기존 자모에 균일 스케일을 적용하면 세로중성의 높이가 가로폭에 종속되는 오류가 생긴다.
- 과거 `ㅏ·ㅗ·ㅜ` 자모 데이터에 있던 위치용 padding은 레이아웃 계산의 조합 배치 프로필로 이관했다. 화면 렌더링, 편집 선택선, 폰트 출력은 동일한 좌표 모드와 배치 변환을 사용한다.
- 초성이 `ㄷ·ㅁ·ㅂ` 계열처럼 닫힌 몸체형 하단면을 가진 경우 위쪽 가로중성 `ㅗ·ㅛ`의 세로획이 초성 하단 획을 관통하지 않는다. 초성과 중성의 기존 가로폭은 바꾸지 않으며, `ㄱ·ㄴ·ㄹ`처럼 열린 구조에는 이 세로 제한을 적용하지 않는다. 이 형태 규칙은 화면과 폰트 출력이 공유하는 레이아웃 계산 단계에 적용한다.
- 신규 보정 화면에서 레이아웃 슬롯은 배치 안내선이며 획 편집의 클리핑 경계가 아니다. 점·획·베지어 핸들은 슬롯 밖으로 이동할 수 있고, 기존 editor-v2의 명시적 `0–1` 편집 경계는 변경하지 않는다.
