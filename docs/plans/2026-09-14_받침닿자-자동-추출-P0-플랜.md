# 받침닿자 자동 추출 P0 플랜

## 현재 단계

D0 역할·용어·응답 계약 완료. G2 시각 표본에서 비필수 홀자 구조획이 받침군에 섞인 오류를 발견해 `final-component-matcher-v1`의 관련 family와 기존 G0·G1 verification 승계를 무효화했다. 사용자 승인 기준으로 `v2`로 G0·G1·G2·G3를 재계산하고 별도 검증(`.verification.v1.json`)을 만들었다. G0~G3는 각 게이트의 화면 검토 승인을 기록했지만, 이 기록만으로 전체 자동화의 완료·정확·지원은 선언하지 않는다.

## 확인한 기존 근거

- 레거시 문서와 조율값은 `finalTop`·`finalBottom`만 받침 잉크 전체의 위·아래 바깥 경계로 정의한다.
- 기존 Noto·IBM Plex 조율 fixture도 받침 있는 문맥에 `finalTop`·`finalBottom`만 저장한다. 받침은 모두 `ㄱ` 통제 사례다.
- `finalLeft`·`finalRight`는 Font Guide Lab 기본 UI 필드로만 있고 `LEGACY_GUIDE_IDS`에 포함되지 않는다. 기본 숫자 `150`·`750`은 승인된 받침 좌우 의미나 정답값이 아니다.
- 낱자 기준선 명칭 도판은 받침왼선·받침오른선을 받침 전체 양옆에 놓는다.
- 첫닿의 좌·우를 첫 구조획 양끝으로 정한 계약은 첫닿 P0에서 별도 승인된 규칙이다. 이를 받침에 복사할 근거는 없다.

## 좌·우 의미 — 승인

받침왼단면·받침오른단면은 **역할 판정이 끝난 받침 전체 그룹의 실제 왼쪽·오른쪽 외곽**으로 정한다. 2026-09-14 사용자 승인.

이유:

- 역할선 명칭과 도판이 받침 전체 배치 폭을 가리킨다.
- 겹받침에는 하나의 공통 첫 구조획이 없다. 지정 구조획을 택하면 왼·오른 구성원 중 하나나 돌출 구조가 선택 영역 밖으로 빠질 수 있다.
- `selectionArea`는 받침 역할 전체를 선택하는 색면이다. 전체 외곽을 써야 단일·된·겹받침에서 의미가 같다.
- 구조획 정보는 버리지 않는다. 선택 전 `axisFaces`와 구성원별 provenance로 별도 보존하면 배치 외곽과 내부 구조를 섞지 않는다.

이 안에서 좌표가 원시 `inkBounds.left/right`와 같을 수는 있다. 둘의 의미는 다르다. `inkBounds`는 그룹화 직후 계산한 원시 극값이고, `roleFaces`는 구성원·순서·이웃 자소 배제·실제 윤곽 접촉을 통과한 뒤 같은 극값을 역할 단면으로 채택한 결과다. 역할 판정이 불확실하면 같은 숫자가 보여도 자동 포기한다.

대안인 **지정 구조획 양끝**은 첫닿과 용어를 맞추기 쉽지만, 겹받침의 공통 구조획 정의가 없고 받침 전체 선택 폭을 나타내지 못한다. 권장하지 않는다.

## 네 역할 단면 계약

공통 좌표계는 Font Guide Lab의 `shared-baseline`이다. 위·왼쪽은 작은 좌표, 아래·오른쪽은 큰 좌표다.

| 역할 | 권장 선택 규칙 | 필수 근거 |
| --- | --- | --- |
| `top` 받침윗단면 | 받침 전체 그룹의 실제 Bézier 최소 y | 지지 구성원, contour·segment·곡선 구간 |
| `bottom` 받침밑단면 | 받침 전체 그룹의 실제 Bézier 최대 y | 지지 구성원, contour·segment·곡선 구간 |
| `left` 받침왼단면 | 받침 전체 그룹의 실제 Bézier 최소 x | 지지 구성원, contour·segment·곡선 구간 |
| `right` 받침오른단면 | 받침 전체 그룹의 실제 Bézier 최대 x | 지지 구성원, contour·segment·곡선 구간 |

평평한 면이 없더라도 실제 곡선 극점이 유일하고 provenance가 있으면 `roleFaces` 후보가 될 수 있다. `axisFaces`는 선택 전 실제로 보이는 축평행 유한 면 후보만 저장한다. 곡선을 직선 면으로 만들지 않는다.

## 응답 계약

```ts
interface FinalComponentCandidateCase {
  identity: {
    fontSha256: string
    axes: Readonly<Record<string, number>>
    character: string
    codepoint: number
    glyphName: string
    pathSha256: string
    initialJamo: string
    medialJamo: 'ㅏ' | 'ㅗ' | 'ㅘ'
    finalJamo: string
    contextId: 'right-final' | 'bottom-final' | 'mixed-final'
    schemaVersion: string
    extractorVersion: string
    roleDefinitionVersion: string
  }
  state: 'candidate' | 'abstained'
  structureKind: 'single' | 'doubled' | 'compound'
  members: readonly FinalMemberObservation[]
  componentGroup: Observation<FinalGroupEvidence>
  inkBounds: Record<'top' | 'bottom' | 'left' | 'right', Observation<BoundEvidence>>
  axisFaces: Record<'top' | 'bottom' | 'left' | 'right', Observation<readonly AxisFaceEvidence[]>>
  roleFaces: Record<'top' | 'bottom' | 'left' | 'right', Observation<RoleFaceEvidence>>
  selectionArea: Observation<DerivedArea>
}
```

각 `FinalMemberObservation`은 `memberId`, `jamo`, `memberRole`, `boundaryFragments`, `inkBounds`, `axisFaces`를 가진다. `boundaryFragments`는 `contourId`, `segmentIds`, 필요하면 segment 내부 `tRange`를 보존한다. contour 번호는 응답 provenance일 뿐 matcher 규칙이나 예외 조건으로 쓰지 않는다.

`selectionArea`는 네 `roleFaces`가 모두 `candidate`일 때만 다음처럼 파생한다.

```text
x = left
y = top
width = right - left
height = bottom - top
derivedFrom = [top, bottom, left, right]
```

원시 `inkBounds`, `axisFaces`, `roleFaces`, `selectionArea`는 서로 복사한 한 객체로 저장하지 않는다.

## 구성원 결속과 구조 불변식

- 요청 글자와 `initialJamo + medialJamo + finalJamo` 재조합 결과가 같아야 한다.
- 단일은 구성원 1개, 된·겹받침은 정확히 2개여야 한다.
- 두 구성원의 `left → right` 의미 순서를 contour 순서와 독립적으로 증명한다.
- 실제 관계를 `disjoint | touching | overlapping | merged-boundary`로 기록한다. bbox가 겹친다는 이유로 `touching`을 만들지 않는다.
- `touching`은 실제 segment 교점 또는 허용 오차 안의 최근접 segment 쌍, `overlapping`은 실제 내부 교차, `merged-boundary`는 구성원별 경계 fragment 분할 근거를 가져야 한다.
- 첫닿·홀자 provenance가 받침 구성원이나 받침 역할 단면에 들어가면 실패다.
- 각 역할 단면 좌표는 기록한 contour·segment·곡선 구간에 실제로 접촉해야 한다.
- 그룹 극값은 구성원 경계 fragment 합집합의 극값이어야 한다. counter·내부 접합·숨은 끝을 외곽 단면으로 채택하지 않는다.
- 역할·구조군·문맥 하나에서 오염이 발견되면 같은 matcher 버전의 해당 조합 전체 후보를 무효화하고 전수 재계산한다.
- 글자·폰트·contour 번호·절대 좌표 예외를 금지한다.

## 후보와 검증 상태

추출기 응답은 `candidate | abstained`만 만든다. `verified`는 별도 검증 기록이 후보 artifact SHA와 정확한 identity를 참조하고 사용자 화면 확인을 받은 뒤에만 만든다. 후보 fixture를 검증본처럼 이름 짓지 않는다.

레거시 받침값은 별도 평가기에서 비교할 수 있지만 계약·추출기 요청·응답·색면에는 들어가지 않는다.

주요 자동 포기 사유는 `glyph-missing`, `medial-anchor-unavailable`, `ambiguous-final-group`, `foreign-role-contamination`, `member-count-mismatch`, `ambiguous-member-order`, `merged-boundary-unresolved`, `invalid-component-bounds`, `provenance-missing`, `role-face-unavailable`로 둔다. `no-axis-face`는 해당 축면 관측만 포기하며 곡선 극점 기반 역할 단면까지 자동으로 버리지 않는다.

2026-09-14 v1 사용자 화면 승인 뒤 **v2 사용자 승인 완료**:

- 81개 모두 `candidate`다. 이는 후보 생성 현황일 뿐 정확도 근거가 아니다.

- Python 계약·추출기 테스트 11개, TypeScript 계약·fixture 테스트 9개가 통과했다. 신규 TypeScript ESLint와 production build도 통과했다.

자동 검사 중 기존 첫닿 v3 선택의 보완집합을 그대로 받침으로 쓰면 `single × right-final` 한 사례에서 받침 `ㅎ` 일부가 첫닿으로 섞이는 오류를 발견했다. 지침대로 해당 역할·구조군·문맥의 기존 결과 전체를 폐기했다. 글자·contour·좌표 예외를 추가하지 않고, 홀자군을 제외한 실제 외곽 contour를 상·하 역할군으로 재분할한 뒤 전 81자를 다시 계산했다.

또한 구성원 접촉을 Bezier segment 양끝 chord로 판정하면 곡선 자체가 닿지 않는 경우를 접촉으로 오판할 수 있어 기존 접촉 결과를 전부 폐기했다. 원곡선을 segment별 polyline으로 분해해 실제 경계 교차를 `touching`과 `overlapping`으로 나누고 39개 두 구성원 사례를 다시 계산했다.

## G1 나눔고딕 holdout

2026-09-14 v1 사용자 화면 승인 뒤 **v2 사용자 승인 완료**:

- 고정 SHA의 나눔고딕에서 G0와 같은 `ㄱ × ㅏ·ㅗ·ㅘ × 27받침` 81글자를 독립 holdout으로 계산했다.
- 후보 75개, 안전 자동 포기 6개다. 후보율은 정확도 판정에 쓰지 않는다.
- 자동 포기 6개는 `merged-boundary-unresolved` 3개와 `medial-anchor-unavailable` 3개다.
- 나눔고딕 `ㅆ`은 세 문맥 모두 두 구성원이 하나의 contour에 결합되어 있다. 구성원별 segment 경계 분할을 증명하지 못해 후보로 만들지 않았다.
- 섞임 문맥의 `ㄺ·ㄽ·ㄾ`은 홀자 필수 `baseStem` anchor가 불확실해 후보로 만들지 않았다.

## P1 Font Guide Lab 연결 — 사용자 화면 확인 완료

2026-09-15 구현·자동 검증:

- Noto Sans KR·나눔고딕·돋움의 별도 verification SHA에만 결속한 소형 display index를 만들었다. 원본 후보 artifact의 contour·segment provenance는 원본에 남기고, 화면에는 구성원 contour 소유권·분리된 `inkBounds`·`axisFaces`·`roleFaces`·`selectionArea`만 투영한다.
