# Noto 기준선 기반 프리셋 폰트 개발 플랜

## 목표와 출발점

정확한 Noto 기준선으로 편집 가능한 프리셋 폰트를 만들고, 문맥별 차이를 분석해 사용자의 편집에 활용한다. 전수 직접 측정과 대표 문맥·변화량 분석을 함께 진행한다. 글자마다 LLM을 호출하지 않는다.

가·고·과의 사용자 확인 결과와 가·고·과·곽·곿 등 이미 확보한 기준선은 출발점이다. 이미 된 생성 작업을 처음부터 반복하거나 전체 추출이 끝날 때까지 가능한 생성을 막지 않는다. 원본 contour를 붙여 보여 주는 실험과 기준선으로 획을 생성하는 경로는 구분한다. 전체 자모 생성·편집·OTF 연결의 완료 여부는 별도로 확인한다.

## 지켜야 할 원칙

- Noto 파일 SHA와 굵기 등 가변축을 고정한다.
- 실측값, 생성 규칙, 문맥 적용, 검수 상태를 따로 보존한다.
- 직접 측정·대표 문맥 투영·미측정을 구분한다. 자동 후보는 승인값이 아니다.
- 해당 실제 글자의 모든 자모 입력이 확인된 경우만 확실하다고 표시한다.
- 필요한 데이터나 생성 규칙이 없으면 누락 이유를 표시한다. 레거시 좌표로 채우지 않는다.
- 원본 윤곽은 추출·검증 근거다. 기준선에 결속된 생성 형태와 혼동하지 않는다.
- 화면과 OTF는 같은 최종 면 데이터를 사용한다.

## 1. 전수 작업 목록과 재개 가능한 배치

현대 한글 11,172자 목록을 만들고, Python 추출 함수를 직접 호출한다. 웹 API의 12자 제한과 분리한다. 기본 실행은 무받침 399자이며 대표 표본·지정 글자·전체 범위를 선택할 수 있게 한다.

글자별 원본 윤곽과 contour/segment 출처, 역할 관측, 정규화 측정값을 남긴다. 폰트와 알고리즘·역할 계약 버전으로 캐시를 구분한다. 중단 후 재개하고 실패·모호함은 별도 기록한다. 폰트는 한 번 열고 같은 글자의 홀자 분석을 닿자 추출에서 재사용한다.

현재 첫닿자 계약은 ㅏ·ㅗ·ㅘ × 받침 없음·ㄱ, 끝닿자는 대표 홀자 3종에 제한된다. 1차 배치가 이 문맥 밖을 미지원으로 보고하는 것은 전체 추출 완성이 아니다. 홀자 21종 역할 정의와 기존 평가·추출기를 재사용한다.

완료 기준: 전체 작업 목록, 중단·재개, 버전별 캐시, 글자·역할별 추출 상태와 실패 이유가 추적된다. 실제 실행 시간·성공률은 실행 뒤 기록한다.

## 2. 추출 계약과 탐색을 전체 문맥으로 확장

무받침 399자부터 같은 실제 글자의 첫닿자·홀자를 함께 추출한다. 다음으로 받침 포함 10,773자를 확장한다. 기존 관측은 재사용하며, 받침 대표 문맥 확장과 생성 작업을 함께 진행한다.

입력 제한만 풀지 않는다. 위·아래 방향의 홀자, 반복 기둥·줄기, 혼합 구조와 합쳐진 contour에서 다른 자모의 획을 고르지 않는지 검사한다. 분리 근거가 부족하면 자동 포기한다. 글자별 임의 좌표나 다른 글자 투영으로 직접 추출 성공을 만들지 않는다.

완료 기준: 실제 처리율, 필수 역할 확보율, 실패 이유, 구조 검증과 시각 검수 범위를 각각 보고한다. 후보 개수만으로 정확성을 주장하지 않는다.

## 3. 대표 문맥과 변화량 분석

원본 측정은 덮어쓰지 않고 분석 결과를 별도로 만든다. 같은 홀자·같은 실제 받침을 두고 첫닿자를 바꾸는 비교부터 시작한다. 첫닿자 고정 후 홀자 변경, 받침 추가·변경에 따른 차이로 넓힌다.

대응하는 역할끼리 위치·몸체 비율·기둥 관계·가로줄기 길이·접합·내부 공간·자모 간격을 비교한다. 획 구성이 다른 경우 별도 형태 유형으로 구분한다.

분석 가설은 `대표값 + 첫닿자 효과 + 홀자 효과 + 받침 효과 + 상호작용·예외`다. 단순 합으로 설명되지 않는 실측 차이는 보존한다. 관측된 상관관계를 곧바로 편집 제약으로 확정하지 않는다.

완료 기준: 각 변화량에서 기준 글자와 원본 관측까지 추적할 수 있고, 모델에 사용하지 않은 조합에서도 재현 오차를 확인한다.

## 4. 확보된 데이터부터 생성·편집 연결

기존 생성 결과를 유지하면서 데이터와 형태 규칙이 있는 조합을 새 경로로 확대한다. 닿자 박스 네 변 외에 필요한 곡률·접합·획 끝·두께는 명시적인 생성 매개변수로 둔다. 미측정 끝을 임의로 만든 경우 실측 구간과 구분한다.

편집 후 기준선은 `해당 글자의 실측 기준선 + 분석 모델이 계산한 편집 변화량`을 목표로 한다. 편집량 0이면 실측 기준선 그대로다. 추출 원본과 사용자 편집을 별도 저장하고 초기화·Undo·변경 비교를 제공한다.

연결된 획은 접합을 유지하고, 떨어져야 할 자모의 충돌은 따로 검사한다. 안전 처리가 실측 기준선을 몰래 바꾸지 않게 한다.

완료 기준: 기준선을 움직이면 관련 획과 공간이 예측 가능하게 바뀌고, 원본 복원이 정확히 된다.

## 5. 랩과 폰트 출력 검증

랩에서 실제 윤곽·추출 기준선·생성 결과를 같은 좌표계로 비교한다. 역할 누락, 다른 자모 침범, 큰 오차와 모호한 사례를 우선 보여 준다. 입력 확인과 생성 결과 승인은 다른 상태다.

이미 생성 가능한 글자부터 부분 OTF를 연결한다. 화면·출력의 위치·두께·접합·내부 공간을 비교하고 지원 범위를 명시한다. 미지원 글자를 레거시로 채워 완성 폰트처럼 내보내지 않는다.

## 이번 착수 범위

1단계 배치와 기존 추출기 재사용, 같은 홀자의 첫닿자별 변화량 수집부터 구현한다. 이후 2단계의 문맥 제한 해소와 4단계 생성 확장을 함께 진행한다. 범용 폰트 업로드·임의 폰트 일반화는 후속 범위다.

실행 명령은 `yarn reference:noto --scope no-final`. 전체는 `--scope all`, 지정 표본은 `--characters 가고과곽곿`, 중간 중단은 `--stop-after 25`, 목록만 작성할 때는 `--manifest-only`를 사용한다. 동일 명령을 다시 실행하면 캐시를 재사용한다. 기본 산출물은 프로젝트의 `.reference-fonts/guide-corpus/` 아래에 둔다.

검증 시 배치 캐시·재개·identity·미지원 상태 단위 테스트와 실제 무받침 399자 실행을 구분해 기록한다. 이 문서는 승인한 실행 방향이며 전수 추출·폰트 완성 또는 시각 검증 완료 보고서가 아니다.

## 1차 배치 상세 기록

전수 작업 목록·단계별 캐시·중단 후 재개·원시 곡선 보존·정규화 측정·같은 홀자의 첫닿자별 변화량 수집을 구현했다. 기존 승인 데이터와 생성 화면·OTF는 변경하지 않았다.

- 전체 작업 목록: 11,172자. 실제 배치 실행: 무받침 399자.
- 원본 윤곽: 399자 확보.
- 홀자: 필수 역할 후보 398자, 부분 후보 1자. `너`의 `primaryBeam`은 `no-role-match`로 자동 포기했다.
- 첫닿자: 기존 계약 범위 57자에서 필수 역할 후보 확보. 나머지 342자는 `context-contract-not-expanded`로 남겼다. 투영값으로 채우지 않았다.
- 같은 홀자·같은 실제 받침을 기준으로 첫닿자가 달라질 때의 역할면 위치·가시 길이 변화량: 1,114건. 아직 편집 규칙이 아닌 분석 후보다.
- 새 배치 단위·실제 Noto 공유 관측 회귀 15개와 기존 첫닿자·끝닿자 추출 회귀 16개, 총 31개 통과.

## 전체 그림 확인과 두 가지 결정

작업 범위를 다시 확인했다. 지금 추출기는 범용 자동 추출이 아니라 Noto 한 폰트, 계약된 문맥에서만 기준선을 뽑는다. 무받침 399 + 대표 받침 1,539 다음에 나머지 18홀자 받침 문맥 9,234자가 남고, 그걸 끝내야 11,172자 기준선이 모인다. 자동 포기 사례는 끝까지 소수 남을 수 있다. 기준선은 Noto 재현만이 아니라 `대표값 + 첫닿자·홀자·받침 효과` 분해로 새 프리셋 제작에 쓰는 것이 목표다.

## 자동 포기 146자 회복 (최신)

포기 148자를 원인별로 나눠 공통 규칙로 146자를 회복했다. 글자별 좌표 예외는 없다.

- **분리 증명 부족 120자** (갛·갓·칺 등, right가족 × 위로 솟는 받침): 첫닿자 다리와 받침 위 획은 세로 구간이 겹칠 뿐 실제 잉크 접촉이 없었다. bbox 겹침 병합 대신 윤곽 edge 교차 기반 접촉 성분으로 분리하는 fallback을 추가했다. 접촉으로 이어진 획은 절단하지 않고, 유효 분할이 이미 있던 글자는 건드리지 않는다. 기둥 하단 여유는 ㅋ·ㅌ 다리의 실측 하강(최대 57unit)을 근거로 60으로 정했다. 위장 클러스터(초과 127 이상)는 계속 차단된다.
- **ㅠ·ㅜ 계열 26자 중 24자** (귤·휸·훅 등): 납작한 초성 위로 올라간 ㅠ 보(y377)와 줄기가 점 판정 ROI(390~650) 밖이라 후보에서 잘렸다. 받침 문맥의 쌍줄기 경로에서만 ROI 하한을 해제했다. 위장은 줄기 잉크 증명·구조 점수가 계속 막는다. ㅜ는 받침이 있으면 항상 하향 접합을 증명한다(P0 집합에 ㅜ가 없어 보존 무관).
- **넖·덢 2자 포기 유지**: ㅓ 팔(y211)이 탐색 영역 밖이고 받침 ㄿ의 획이 유일한 후보다. 이 완화는 승인된 P0 경로와 공유되는 일반 탐색을 건드려야 해서, 모호로 정직하게 남긴다.
