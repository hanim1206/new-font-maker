# 모바일 트랙패드 편집

레이아웃·자소 편집기의 두 번째 개발은 모바일을 우선한다. PC 편집기를 그대로 축소하지 않고, 모바일에서 먼저 `화면에서 선택 → 하단 트랙패드에서 조작`하는 구조를 완성한 뒤 PC 확장을 검토한다.

PC는 화면에서 획과 레이아웃을 자유롭게 드래그하고, 모바일은 선택과 이동을 분리하는 방식을 기본으로 한다.

상단 글자 화면에서 획이나 조절점을 선택하면 활성 상태를 표시한다. 하단 전용 트랙패드는 선택된 대상만 상대적으로 움직여 손가락이 글자를 가리지 않게 한다.

자소를 아직 선택하지 않은 탐색 단계에서는 조작 대상이 없으므로 트랙패드를 노출하지 않는다. 자소 전체·획·꼭짓점 중 하나를 선택해 편집 단계로 들어간 뒤에만 트랙패드가 나타난다.

- 글자 화면에서는 파트, 획, 조절점만 선택
- 선택된 획과 조절점의 정밀 이동은 트랙패드를 우선 사용
- 자유 포인터 탐색 없이 선택된 대상에 집중
- 이동 속도에 따른 감도, 축 잠금, 스냅, 실행 취소 제공

큰 이동과 미세 이동은 입력 위치를 나누지 않고 트랙패드의 이동 속도에 따른 가속으로 구분한다. 빠르게 밀면 크게, 천천히 밀면 정밀하게 이동한다.

하단 드로어의 기본 내용은 트랙패드다. 상단의 `획 스타일`을 누르면 화면을 이동하지 않고 같은 드로어가 폰트 전체 획 스타일 조절로 전환된다.

- 획 스타일 드로어를 닫으면 선택했던 파트·획·조절점과 트랙패드 상태를 복원
- 획 스타일 조절 중에도 상단 캐러셀을 그대로 보며 결과 확인
- 변경 전 비교와 편집 히스토리는 전체 화면 유지
- 압력·끝맺음·세리프 등 옵션이 늘어나기 전까지 별도 획 스타일 전체 화면은 만들지 않음

## 확정한 모바일 편집 모델

트랙패드는 자유 포인터가 아니라 현재 선택된 대상을 상대적으로 조절하는 하나의 공통 입력기다. 선택 대상에 따라 허용되는 움직임만 달라진다.

- 레이아웃 분할선: 해당 가로축 또는 세로축으로만 이동
- 패딩 경계: 안쪽·바깥쪽 한 축 조절
- 획 본체: 획 전체를 2차원 이동
- 획의 끝점·경계 핸들: 길이·두께·크기 변경
- 곡선 조절점: 선택한 점만 2차원 이동

레이아웃 편집에서는 박스를 임의의 좌표로 옮기지 않는다. 기존 `분할선 + 패딩` 구조를 유지하고, 자소 형태 변경은 획이나 조절점을 선택하는 자소 편집 범위에서 수행한다.

선택은 중앙 활성 글자에서 `자소 전체 → 획 → 점`으로 단계적으로 좁힌다.

1. 자소를 처음 탭하면 해당 자소 전체 선택
2. 선택된 자소의 특정 획을 다시 탭하면 해당 획 선택
3. 획이 선택되면 모든 앵커를 표시하고 시작점·끝점은 구별
4. 원하는 앵커를 탭하면 해당 점 선택
5. 정밀 이동과 형태 조절은 하단 트랙패드에서 수행

선택을 상위 단계로 되돌리는 경로도 같은 화면에서 명시한다. 트랙패드 상단의 대상 이름을 `ㅁ 전체 › 1번 획 › 시작 꼭짓점` 형태의 선택 경로로 표시하고, 앞 단계를 누르면 해당 단계로 바로 돌아간다.

- 꼭짓점 선택: `ㅁ 전체`, `1번 획`을 눌러 원하는 상위 단계로 이동
- 획 선택: `ㅁ 전체`를 눌러 자소 전체 선택으로 이동
- 선택된 꼭짓점을 다시 탭하면 해당 획 선택으로 한 단계 이동
- 선택된 획을 다시 탭하면 자소 전체 선택으로 한 단계 이동
- 빈 공간 탭은 빗맞힘으로 선택이 풀릴 위험이 있어 상위 이동 동작으로 사용하지 않음
- 앱 상단 뒤로가기는 편집 화면을 나가는 기능으로 유지하고 선택 단계 이동에 재사용하지 않음

선택 경로는 앱 바 안이 아니라 앱 바 바로 아래의 기존 `자소 편집 · 초성 / 곰 · ㅁ` 한 줄을 대체한다. 앱 바의 `곰 편집`은 현재 화면 위치를, 그 아래 선택 경로는 편집 대상의 깊이를 나타낸다. 트랙패드에는 경로를 중복 표시하지 않아 조작 영역의 정보 밀도를 낮춘다.

각 상위 항목은 최소 터치 영역을 확보하되 문구가 길어지면 현재 단계보다 상위 단계의 표현을 먼저 줄인다. 재탭 단축 동작은 그대로 유지하고 편집 제스처 중에는 경로 버튼을 비활성화한다. 기존 상단 안내 줄을 교체하므로 전체 화면 높이는 늘어나지 않는다.

현재 `자소 편집 · 초성`과 `곰 · ㅁ` 문구를 제거하고 그 자리에 선택 경로를 옮겼다. 트랙패드 위의 중복 경로는 제거했으며 테스트와 빌드가 통과했다.

자소 전체 선택에서의 이동은 현재 레이아웃의 파트 위치에 귀속한다. 획·점 이동은 해당 자소 기본형에 귀속한다. 현재 선택 경로와 적용 범위를 트랙패드 위에 계속 표시한다.

## 현재 판단: 트랙패드 우선

`화면에서 선택 → 트랙패드에서 조작`하는 분리는 손가락이 작은 획과 조절점을 가리는 문제를 줄이고, 축 제한과 감도 조절을 예측 가능하게 만든다. 특히 끝점·곡선점과 미세한 획 위치 조절에 적합하다.

다만 모든 대상을 트랙패드로만 조작하는 방식이 최선이라고 확정하지 않는다.

- 선택과 조작 위치가 분리되어 손과 눈의 대응을 익혀야 함
- 큰 이동은 직접 드래그보다 느릴 수 있음
- 하단 드로어가 글자 미리보기 공간을 줄일 수 있음
- 입력 반응이 늦으면 간접 조작의 불편이 커짐

따라서 모바일 MVP는 `트랙패드 우선`으로 설계하되 `트랙패드 전용`으로 고정하지 않는다. 획과 조절점의 정밀 편집은 트랙패드를 기본으로 하고, 분할선·패딩처럼 크고 단순한 대상의 큰 이동은 직접 드래그와 비교 검증한다. 직접 조작을 도입하더라도 미세 보정은 같은 트랙패드로 이어지게 한다.

트랙패드 조작 중에는 중앙 글자를 최대한 크게 유지하고 양옆 캐러셀은 약하게 처리한다. 선택 대상의 이름과 강조색은 글자 화면과 트랙패드 헤더에 반복해 손과 눈의 연결을 유지한다.

초성 적용 문맥의 첫 카드는 `단독 사용`으로 둔다. 초성 기본형 자체를 먼저 확인한 뒤 세로모음, 세로모음+받침, 가로모음, 가로모음+받침 순서로 비교한다. 단독 카드를 선택하면 자소 단독 화면과 자소 캐러셀도 해당 초성을 유지한다.

## 트랙패드 MVP 기능

- 현재 대상 표시: 예) `중성 ㅗ · 2번 획 · 끝점`
- 이동 속도에 따른 감도 변화
- 별도 `정밀` 토글 없이 이동 속도에 따라 이어지는 단일 감도
- 획·조절점의 `가로 잠금`과 `세로 잠금`
- 분할선과 패딩의 이동 방향 자동 제한
- 중심선과 기준선에 붙는 스냅
- 현재 이동량 표시
- 허용된 이동 방향을 트랙패드 안에서 활성 축 그라디언트와 터치점 화살표로 표시
- 움직일 수 없는 축은 흐리게 처리하고 잠금 아이콘과 문구를 함께 표시
- 손가락을 움직이는 동안 실시간 미리보기
- 손을 뗐을 때 한 번의 변경으로 자동 저장
- 직전 조작 실행 취소
- 손을 떼는 순간 멈추며 관성 이동은 사용하지 않음

획 선택 상태에서도 `이동 | 비율` 탭을 따로 두지 않고 큰 트랙패드 하나를 유지한다. 한 손가락은 이동, 두 손가락은 비율 조절로 구분한다. 적용 범위와 현재 입력 방식은 트랙패드 안의 짧은 안내로 전달한다.

두 손가락 비율 조절은 두 터치점 사이의 가로·세로 간격 변화에서 의도를 판별한다. 두 손가락이 같은 방향으로 함께 움직여 간격이 변하지 않으면 비율을 바꾸지 않는다. 판별된 한 축만 제스처가 끝날 때까지 잠그고, 트랙패드에서 그 방향의 길을 밝게 보여준다.

- 손가락이 짧은 판별 거리를 넘은 시점에 가로·세로 중 더 가까운 축을 선택
- 가로로 판단하면 좌우 통로를 밝히고 위아래 영역은 어둡게 처리
- 세로로 판단하면 위아래 통로를 밝히고 좌우 영역은 어둡게 처리
- 축이 정해진 뒤 대각선으로 흔들려도 제스처가 끝날 때까지 바꾸지 않음
- 판별 전에는 두 축을 약하게 보이고, 판별 후 터치점도 선택된 축 위로 투영
- 획 바운딩 박스의 중심을 고정점으로 사용
- 굵기·회전은 바꾸지 않고 앵커와 베지어 핸들만 같은 비율로 변환
- 별도 정밀 모드 없이 하나의 스냅 단위를 사용하되, 0.5%·1% 중 실제 조작감으로 결정
- 두 손가락 사용이 어려운 경우의 단계 버튼은 패드를 줄이지 않는 보조 UI로 후속 검토
- 손을 떼면 변경 1건으로 자동 저장하고, 취소 시 시작 상태로 복귀

축 판별은 단순히 `|dx| > |dy|`만 쓰지 않고 시작 데드존과 방향 우세 기준을 함께 둔다. 거의 대각선인 입력은 성급히 확정하지 않고 조금 더 움직일 때까지 기다린다. 사용자가 방향을 잘못 잡았다면 손을 떼고 다시 시작하게 하되, 아직 축이 정해지지 않은 상태에서는 아무 변화도 저장하지 않는다.

두 손가락 비율은 획을 선택했을 때만 동작한다. 자소 전체나 점을 선택한 상태에서는 두 번째 손가락이 들어와도 비율을 바꾸지 않는다. 한 손가락 이동이 이미 데드존을 넘어 시작된 뒤 두 번째 손가락이 들어오면 도중에 비율로 바꾸지 않는다. 반대로 두 손가락 비율 중 하나를 먼저 떼면 그 시점에 비율 변경을 확정하고, 나머지 손가락을 모두 뗄 때까지 이동으로 전환하지 않는다.

두 축 동시 조절·두 손가락 회전·획 굵기 조절·자유 포인터는 모바일 MVP에서 제외하는 방향으로 검토한다. 별도 페이더와 로터리 노브는 통합 패드가 불편할 때 비교할 후속 후보로 둔다.

축 제한은 색만으로 전달하지 않는다.

- 자유 이동: 가로·세로 축을 모두 활성화하고 터치점에 `↕↔` 표시
- 가로 이동만: 가로 띠만 활성화하고 터치점에 `↔`, 세로축에 잠금 표시
- 세로 이동만: 세로 띠만 활성화하고 터치점에 `↕`, 가로축에 잠금 표시
- 손가락을 대각선으로 움직여도 화면의 터치점은 허용된 축으로만 이동

기준선의 생김새가 아니라 실제 이동 방향을 표시한다. 예를 들어 세로 분할선이 좌우로 움직이면 `가로 이동만`으로 보여준다.

## 꼭짓점 방향 잠금 검토

꼭짓점을 미세하게 옮길 때 의도하지 않은 대각선 이동을 막기 위해 트랙패드 하단 좌측에 `방향 잠금` 버튼을 구현했다.

2026-08-18 방향 잠금은 한 번의 이동 뒤 자동으로 풀지 않고 사용자가 `방향 잠금 해제`를 누를 때까지 유지하도록 바꿨다. 잠근 상태에서 다른 꼭짓점이나 획을 선택해도 유지하며, 상세 편집 화면을 나가면 종료한다. 모바일 브라우저 자동화에서 대상 변경 뒤 유지와 수동 해제를 확인했다.

## 캔버스와 트랙패드 분리 유지 판단

손가락이 획과 꼭짓점을 가리는 문제가 정밀 편집의 핵심 불편이므로 `화면에서 확인 → 분리된 조작면에서 이동`하는 구조는 유지할 가치가 있다. 특히 작은 꼭짓점, 곡선 손잡이, 축 잠금처럼 결과를 계속 보면서 미세하게 움직이는 작업에서는 직접 드래그보다 안정적이다.

현재 공간 낭비의 주원인은 트랙패드 분리 자체보다 남은 세로 공간의 배분이다. 390×844 화면에서 단독 자소 캔버스는 약 281px, 트랙패드는 176px이며 둘 사이에 약 128px의 빈 구간이 생긴다. 트랙패드를 없애기보다 다음 순서로 밀도를 조정한다.

- 짧은 화면에서 트랙패드 높이를 140~152px 정도로 줄여 실제 조작감을 비교
- 캔버스를 가능한 범위에서 더 크게 사용하고 캔버스와 트랙패드 사이의 빈 높이를 축소
- 트랙패드를 접을 수 있게 하되 정밀 편집 중에는 분리된 조작면을 기본으로 유지
- 큰 이동은 화면 직접 드래그를 보조 입력으로 검증하되 꼭짓점·곡선점 미세 편집은 트랙패드 우선 유지

따라서 현재 판단은 `분리 유지, 높이와 빈 공간 최적화`다. 트랙패드 통합이나 제거는 실제 기기에서 조작 성공률과 편집 속도를 비교하기 전에는 진행하지 않는다.

## 트랙패드 도구 레일

캔버스의 선택 영역을 가리지 않으면서 획 편집 기능에 빠르게 접근하도록 트랙패드 왼쪽에 세로 도구 레일을 배치했다. `추가 · 곡선/직선 · 연결 · 끊기 · 삭제`를 모두 고정 노출하지 않고 현재 선택에서 실행 가능한 기능만 보여준다.

- 곡선/직선: 꼭짓점이나 곡선 손잡이를 선택했을 때 표시
- 연결: 가까운 열린 선의 끝점이 있을 때 표시
- 끊기: 열린 선의 중간점이나 닫힌 선의 꼭짓점을 선택했을 때 표시
- 삭제: 최소 획·꼭짓점 수를 지킬 수 있을 때 표시
- 추가: 새 획을 만들 수 있는 상세 편집 단계에서 표시

선 연결과 끊기는 각각 한 번의 변경으로 저장한다. 끊은 두 획은 연결점 좌표와 곡선 손잡이를 공유하지 않는 독립 데이터로 만든다. 한 획을 이동해도 다른 획의 끝점이 따라 움직이지 않아야 한다.

곡선 편집의 선택 구조는 `자소 전체 → 획 → 꼭짓점 → 곡선 손잡이`까지 확장했다. 손잡이는 캔버스에서 선택하고 실제 이동은 트랙패드에서 수행한다. 선택 경로에도 들어오는 손잡이와 나가는 손잡이를 구분해 표시한다.

## 다음 와이어프레임 범위

`레이아웃 분할선 → 패딩 → 획 → 조절점` 네 선택 상태에서 상단 선택 표시와 하단 트랙패드가 어떻게 바뀌는지 순서대로 그린다.

## 와이어프레임

[모바일 트랙패드 편집 HTML 와이어프레임](./assets/모바일-트랙패드-편집-v2.html)

다음 네 상태의 화면 구조를 확정했다.

1. 초성·중성 분할선을 선택하고 가로축으로만 조절
2. 초성 패딩 경계를 선택하고 안팎으로 조절
3. 획 본체를 선택하고 트랙패드에서 2차원 이동
4. 끝점·곡선점을 선택하고 낮은 감도로 정밀 조절

와이어프레임은 기능이 완성된 프로토타입이 아니라 선택 상태, 정보 우선순위, 트랙패드 전환 규칙을 확인하는 용도다.

현재 v2 와이어프레임의 `정밀 누르기` 표시는 제거한다. 트랙패드는 느린 움직임을 미세 조절로, 빠른 움직임을 큰 조절로 해석하는 단일 감도를 사용한다. 가속이 갑자기 바뀌어 결과를 예측하기 어려워지지 않도록 연속적인 감도 곡선을 쓰고, 비율 스냅 단위는 0.5%와 1%를 실제 기기에서 비교한다. 큰 레이아웃 이동의 직접 드래그는 확정 기능이 아니라 트랙패드 방식과 비교할 검증 가설이다.
