# 스타일가이드 라이브러리

> 10-03 **뒤집힘**: 처음 계약(검토판 — 화면에서 OK · 요청을 받아 파일에 기록)은 G0을 만들어 본 뒤 사용자가 접었다. 지금 계약은 아래 `계약(D0′)`.

- **이번에 비교하는 것**: 지금 스타일가이드(견본만 나열) vs Storybook식 보기 전용 라이브러리(목록 · 실물 · 폰 미리보기).
- **이번 승인으로 바뀌는 것**: 스타일 소통 방식. 사용자는 라이브러리에서 보고, 항목 번호를 복사해 채팅으로 요청한다. 화면은 입력을 받지 않는다.
- **바뀌지 않는 것**: 토큰 · 공용 부품 생김새, 제품 화면, 스타일 가드, 실험실 주소(`/style-guide` · 관리자 `실험실`).

## 왜

사용자(10-03): 스타일가이드를 만든 이유는 "모든 스타일을 한눈에 보고 AI에게 명확히 요청하려고". 그리고 OK한 것은 화면에서 티가 나야 한다. 다른 팀들은 Storybook(실물 카탈로그) + 시각 검토(장면마다 승인)로 이걸 한다 — 같은 생각을 앱 안 실험실로 한다(사용자 결정: 실험실을 키운다 · 요청은 화면 안에 적는다).

## 계약(D0′, 10-03 뒤집힌 뒤)

- **보기 전용**: OK · 요청 · 기록 파일 없음. 의견은 번호(`button.size.sheet` 등)를 복사해 채팅으로.
- **세 칸**: 왼쪽 부품 목록(색 · 글자 · 모양 · 단추 강조 / 크기 · 탭 · 고르기 · 막대 · 체크 · 알림), 가운데 고른 부품 하나의 실물(상태별) · 설명 · 번호 복사 · 쓰는 화면, 오른쪽 폰 미리보기(390).
- **쓰는 화면 → 미리보기**: 누르면 미리보기가 그 화면으로 가고 그 부품을 깜빡인다. 공용 부품이 `data-slot` · `data-variant` · `data-size`(체크는 `data-tone`)를 단다 — 생김새와 무관. 시트 안처럼 주소만으로 안 보이면 안내 한 줄, 알림은 미리보기에 직접 띄운다.

## 처음 계약(D0, 접음)

**항목 번호**: `부류.이름.변형` 영문 점 표기 + 한글 이름. 예 `button.sheet.default`(단추 · 시트 큰 단추 · 검정), `color.primary`(색 · 주색), `notice.bar`(알림 · 어두운 막대). 사용자는 번호로 말할 수 있고, 화면은 번호 복사 단추를 둔다.

**한 항목 = 카드 하나**: 실물(실제 부품 코드로 그림) · 상태별 모습(기본 · 누름 · 비활성 · 고름) · 값 한 줄(높이 · 글자 · 모서리 · 색 토큰) · 쓰는 곳(화면 주소 · 몇 곳).

**상태 셋**:
- ✔ 확정 — 초록 테두리 · 날짜
- ✎ 요청 있음 — 노랑 · 요청 한 줄
- · 안 봄 — 회색(새 항목 · 고친 항목)

**지문**: 확정할 때 그 항목의 값(토큰 값 · 부품 클래스)을 지문으로 함께 저장한다. 코드가 바뀌어 지문이 달라지면 자동으로 "안 봄"으로 돌아간다 — AI가 고친 것도, 다른 작업이 건드린 것도 다시 보게 된다.

**저장**: `reference-data/`가 아니라 레포의 `src-next/style-review.json`(커밋한다). 화면의 OK · 요청은 개발 서버 플러그인이 이 파일에 쓴다(관리자 `프리셋`과 같은 방식, 개발 서버 전용). AI는 같은 파일을 읽고, 요청을 처리하면 요청 칸을 비우고 진행 기록에 한 줄 남긴다.

**머리**: "안 봄 N · 요청 N · 확정 N"과 거르기(안 봄만 보기). 위의 주색 · 테마 손잡이는 그대로 둔다.
