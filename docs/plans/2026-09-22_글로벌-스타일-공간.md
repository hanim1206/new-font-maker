# 글로벌 스타일 공간

- **이번에 비교하는 것**: 글로벌 스타일을 획 편집 화면 하단의 작은 패널로 둘지, 어느 모드에서든 여는 전용 공간으로 둘지.
- **이번 승인으로 바뀌는 것**: 입구가 셸 머리에 늘 보인다(레이아웃 모드에서도 열린다). 연 동안 캔버스가 비키고 문장 줄이 한 줄 그대로 크게 자라 미리보기를 맡는다. 패널은 문장 아래를 다 쓰고 탭은 넷(글자 네모꼴 · 획 스타일 · 굵기 · 부리). 기울기는 숨기고, 네모형 붓촉 · 레거시 스냅 획은 고르기에서 뺀다. 부리가 패널로 들어온다.
- **바뀌지 않는 것**: 저장 형식(`globalStyleStore`), 미리보기 → 손 떼면 적용 → 되돌리기 흐름, 옛 단독 화면(`/calibration`)의 선택지와 동작, 네모꼴 · 붓 · 절단 끝 · 부리의 계산.

앞 플랜 `2026-09-21_전역-스타일에-굵기와-기울기.md`의 하단 패널 탭을 이 공간이 대체한다. 그 플랜의 기반(읽는 길 하나, fit 잉크 굵기, OTF 기울기)은 그대로 쓴다.

## 이 뒤에 오는 것 (이번 플랜 아님)

1. 네모꼴을 줄이면 글자도 같이 줄게(지금은 모델 상자 글자가 안 따라온다).
2. 절단 끝을 홀자 줄기에도.
3. 붓촉 모양을 직접 그리기.
4. 자리별 부리(닿자 · 가로홀자 · 세로홀자).
5. shadcn `ui/`를 죽은 폴더(`src/components/`) 밖 공용 자리로 옮기기 — 사용자 결정 "다 가져와". 이번엔 기존 패턴(CSS Modules + 토큰)으로만 만들었다.
6. 셸 전체의 색 · 분위기. 이번에 패널 안에서만 파랑을 빼고 검정 · 회색으로 갔다.

### 2026-09-22 획 스타일 고르기 이름
- **사실 — 사용자 보고**: 획 스타일에서 `원형`이 골라져 있는데 글자 끝은 각지게 나온다.
- **사실 — 원인**: 버그가 아니라 이름표가 틀렸다. `원형`은 붓촉 모양이고 끝이 각진 것은 따로 저장된 끝 모양(`linecap: butt` · `linejoin: miter`, 커밋 `501f2ee`에서 기본을 Noto 고딕처럼 바꿈) 때문인데, 새 화면에 끝 모양을 바꾸는 UI가 없었다.
- **사실 — 고침**: 제품 화면의 고르기를 글자에 나오는 결과로 부른다 — `각진 끝`(둥근 붓촉 + butt/miter, 기본) · `둥근 끝`(둥근 붓촉 + round/round) · `납작 붓`. 끝 모양은 붓촉과 같은 되돌리기 기록에 실어 한 번에 돌아온다. 옛 단독 화면의 `원형 · 납작형 · 네모형`은 그대로.
- **사실**: 끝 모양이 바뀌면 상자 다듬기(`contextPlacementOf`의 `ends`)도 같이 바뀐다 — 둥근 끝은 끝에서 두께 절반만큼 더 나가므로.

### 2026-09-22 각도판 터치
- **사실 — 사용자 보고**: 납작 붓 각도 돌리기가 터치로 잘 안 먹는다.
- **사실 — 재현(CDP 실제 터치 이벤트)**: 터치는 들어오는데 각도판이 **가로 이동만** 읽었다. 세로로 끌면 0° 변화, 막대 끝을 잡고 +60° 돌리면 53 → 33으로 엉뚱하게 움직였다. 사람은 돌리려 한다.
- **사실 — 고침**: 잡은 자리에 따라 둘로 나눴다. 가운데에서 24px 밖(막대 끝 · 바깥)을 잡으면 `돌리기` — 손가락이 가운데를 중심으로 돈 만큼 돈다(한 걸음씩 쌓아 ±180° 경계에서 안 튀고, 납작 붓은 −90~90으로 접는다). 안쪽(막대 가운데)을 잡으면 `밀기` — 오른쪽 · 아래로 끈 만큼 시계 방향. 기존 가로 끌기는 그대로 되고 세로도 먹는다.
- **확인**: 실제 터치 다섯 동작(가운데 → 오른쪽 +35°, 가운데 → 아래 +26°, 끝 잡고 세로 +48°, 끝 잡고 +60° 돌리기 → +60°, 가운데를 가로질러 끝에서 끝 → 그대로) · e2e 13개 통과. 폰 실기는 아직.

### 2026-09-22 채움 막대 터치
- **사실 — 사용자 보고**: 굵기 슬라이더가 모바일에서 드래그가 잘 안 먹는다.
- **사실 — 재현 안 됨**: 크롬 터치 에뮬레이션(CDP 실제 터치)에서는 손잡이 · 빈 자리 · 비스듬히 · 톡 네 동작이 다 먹는다.
- **가설**: iOS 사파리의 기본 range는 손잡이를 정확히 잡아야만 끌린다. 채움 막대는 손잡이가 막대 끝 22px(보이는 건 3px 흰 줄)뿐이라 거의 못 잡고, 세로로 조금만 흘러도 패널 스크롤이 제스처를 가져간다(`touch-action: pan-y`였다).
- **사실 — 고침**: `rangeDrag.ts` — 막대 어디를 눌러도 그 자리 값으로 가고 누른 채 끌면 따라오게 직접 계산한다(포인터 캡처, `touch-action: none`). `<input type="range">`는 그대로 둬서 키보드 · 접근성 · 테스트의 `fill()`은 전과 같다. 굵기 · 네모꼴 가로 세로 · 부리 크기 각도 · 납작함 · 모서리 곡률 전부에 걸었다.
- **확인**: 터치로 끈 한 번이 되돌리기 한 줄(네 번 끌고 네 번 되돌리면 400, 버튼 꺼짐). e2e 15개 통과. **폰 실기 확인은 사용자 몫** — 가설이 맞는지는 거기서 갈린다.

### 2026-09-22 느림 — 문장 글자 자리 다시 계산
- **사실 — 사용자 보고**: 굵기 · 네모꼴을 끌 때 버벅인다. "SVG 렌더가 느린 건가?"
- **사실 — 원인(CPU 4배 느리게 놓고 프로파일)**: 렌더가 아니라 계산. `useContextPlacement`의 메모가 매 렌더마다 깨졌다 — 부르는 쪽이 `syllable` · `schema`를 매번 새 객체로 넘겨서. 그래서 문장 11글자 전부가 끌 때마다 무거운 fit(잉크 합치기)을 다시 했다.
- **사실 — 고침**: 메모 열쇠를 내용(글자 · 자모 · 레이아웃 · 패딩 값 · 끝 모양)으로 바꾸고, 무거운 기준 네모꼴 fit(`resolveReferenceBoxes`)과 가벼운 사용자 네모꼴 옮기기(`resolvePlacementBoxes`)를 나눴다. 굵기를 끌 때 잉크 합치기 약 1.0초 → 0, 네모꼴은 약 990ms → 155ms(둘 다 4배 느린 CPU 기준).
- **확인**: 전체 vitest 1046 통과 · 3 실패 — 셋 다 이 변경 전부터 깨져 있던 것(`preset-candidate-source` · `vertical-vowel-gap-reference` · `screen-spec`).

### 2026-09-22 네모꼴 막대 하나
- **사실 (결정, 사용자)**: 네모꼴은 결국 가로 · 세로 비율 조절이니 막대는 하나면 된다.
- **사실 — 구현**: 제품 화면의 네모꼴 탭은 막대 하나다 — `길쭉 ↔ 정네모 ↔ 납작`(−100 ~ 0 ~ 100, 정네모가 한가운데). 왼쪽은 세로를 둔 채 가로를 500까지 줄이고, 오른쪽은 가로를 글자 칸 끝(1000)까지 늘린 뒤 세로를 500까지 줄인다. 정네모 ±4 안에서는 정네모로 걸린다. 값은 `가로 × 세로`로만 보여 준다. 범위(`폰트 전체` / `현재 레이아웃`) 고르기는 제품 화면에서 뺐고 폰트 전체에만 쓴다.
- **사실**: 옛 단독 화면(`/calibration`)은 가로 · 세로 두 막대와 범위 고르기 그대로. 저장 형식도 그대로(패딩).
- **미결정**: 옛 화면에서 가로 · 세로를 따로 맞춘 값(예: 700 × 600)은 비율만 읽어 막대 자리로 보여 주고, 막대를 움직이기 전에는 안 건드린다 — 움직이면 그 비율의 표준 크기로 바뀐다. 레이아웃별로 저장된 네모꼴 값은 제품 화면에서 안 보인다.
