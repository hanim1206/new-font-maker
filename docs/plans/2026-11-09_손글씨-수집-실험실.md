# 손글씨 수집 실험실 — 시안을 제품 엔진 위로 옮긴다

- **이번에 비교하는 것**: 아티팩트 시안에서 정한 수집 흐름(배치 6종 먼저 → 자모 → 확인 카드 → 글자표)을 제품 획 모델과 렌더러 위에 올렸을 때, 내 손글씨가 같은 모양으로 보이고 전체 속성(굵기 · 꺾임 굴림)이 먹는가.
- **이번 승인으로 바뀌는 것**: 실험실 하나(`/admin/labs/handwriting`)와 순수 함수 몇 개(칸 안 획을 자리로 묶기, 배치 역추론, 2,350자 계획). 제품 화면 · 프리셋 · 저장 데이터는 그대로다.
- **바뀌지 않는 것**: 획 모델(`StrokeDataV2` 중심선 + 앵커 + 두께 고정), Split + Padding 배치, 펜 실험실의 맞춤 `ε`와 역할 문턱 `τ`, 1차 배포본(main · dev).

출처: 11-09 사용자 "일단 실험실로 가져가보자". 시안은 `구간별 보선 결속 시안`(공개 아티팩트, 복사본 `/mnt/project-files/2차-기획/글자꼴-해부/구간별-보선-결속-시안.html`).

## 왜

시안은 흐름을 정하는 데는 빨랐지만 그리는 쪽을 전부 따로 흉내 냈다. 쓰는 화면과 결과가 제품과 따로 놀아 덜 직관적이고, 지금부터 궁금한 것 — 내 글씨가 진짜 엔진에서 어떻게 보이나, 보선에 어떻게 묶이나 — 은 거기서 답이 안 나온다. 레포에는 이미 펜 입력(`penStrokeFit` · `penJamo` · `strokeRoleMatch`), 자모 캔버스, 레이아웃 에디터, 기준선이 있다.

## 시안에서 가져가는 것 · 버리는 것

| 가져간다 | 레포 것으로 바꾼다 | 버린다 |
|---|---|---|
| 문장 → 칸 쓰기, 칸마다 지우개, 한 손가락만 받기 | 획 단순화: 내 꺾임 찾기 → `fitPenStroke`(ε). 둥근 ㅇ은 `closed: true` | 가짜 보선(rail) 끌기 |
| 정답을 알 때 자리로 묶기(기둥 · 보 먼저, 왼쪽 · 위가 첫닿자, 아래가 받침) | 역할 이름: 내 틀 맞추기 → `matchStrokeRoles`(τ), 프리셋 획 id 승계 | 빈 문장 추측 모드, 틀(TPL) 편집거리 |
| 배치 역추론(글자 잉크 상자 기준 세 상자 + 칸 대비 틀) | 상자: `BoxConfig` / Split + Padding 값으로 환산해 저장 | 시안의 DEFBOX · vbox |
| 수집 흐름: 배치 6종 씨앗 문장 → 자모 주사위 → 확인 카드(변주 7자리 · 두기/바꾸기 · 배치 섞기/두기) → ㅇㅋ | 그리기: 내 SVG · 캔버스 → 제품 렌더러(`AppGlyph` 계열) | 시안 저장소(localStorage) |
| 내 글자표 2,350(다 찬 · 반쯤 찬 · 빈 글자, 누르면 문장 제안) | 자모 저장: 견본 → `JamoData`의 `StrokeDataV2[]`, 첫닿자 6자리 꼴은 벌(가른 벌)로 | — |

자리로 묶기와 배치 역추론은 좌표만 쓰는 순수 로직이라 그대로 옮긴다(`src/services/handwriting*.ts`, 단위 테스트 같이). 확인 카드 · 글자표는 실험실 화면이다.

## 하려는 것

**A. 입력** — 펜 실험실의 포인터 처리(펜만 받기, 손바닥 거부)를 가져와 15칸 문장 판을 만든다. 칸마다 ✕.

**B. 읽기** — 칸 안 획을 `fitPenStroke`로 앵커 획으로 만들고, 정답 글자로 자리를 묶은 뒤 `matchStrokeRoles`로 프리셋 역할을 승계한다. 시안의 "칸 안 획 분배" 수치(가로 · 세로 비율 1.4, 짧은기둥 붙음 보너스 등)는 그대로 시작값.

**C. 배치** — 음절마다 세 상자를 잉크 상자 기준으로 재고, 6종(홀자 자리 × 받침 유무)으로 평균한다. 저장은 레이아웃 에디터가 읽는 값으로.

**D. 확인 카드와 글자표** — 시안 그대로. 글자표만 제품 렌더러로 그린다(2,350 × 음절 그리기 비용이 문제면 보이는 줄만).

**E. 전체 속성 한 번** — 굵기 슬라이더와 "꺾임 모두 굴리기"를 글자표에 걸어 내 글씨가 따라오는지 본다. 이게 시안에서는 못 보던 것이다.

- 사실: "자모 하나 고치기" — 세 컬럼 격자에서 자모를 고르면(첫닿자는 6자리 중 하나도) 본보기 글자 한 칸만 쓰게 하고, 카드는 1단계에서 바로 반영(레이아웃 단계 없음). 예전 카드의 "다른 자리에 놓으면 · 이 자리 다시 쓰기" 줄은 이걸로 대신한다.
- 사실: `applyChoices`가 자리(첫닿자 · 홀자 · 받침)를 따로 본다(`hasSlot`) — 첫닿자 꼴만 있던 ㄱ에 받침 ㄱ이 오면 두기여도 받침 자리는 채운다. 배치 섞기는 배치마다(`mix`). 단위 테스트는 안 돌렸다(실험실 규칙).
- 확인 안 함: 합성 획 "헌"이 못 읽혔다(합성 상자 탓인지 읽기 탓인지 안 가림). 사파리 엔진으로는 안 봤다.
- 사실: 쓰기 칸 — 펜을 떼면 그 획을 바로 `fitPenStroke`(읽기와 같은 허용오차 · 굵기)로 맞춰 칸 위에 그리고, 날 선은 연한 회색으로 밑에 깐다. 앵커는 작은 점(사용자 고름: 날 선 남기기).
- 확인 안 함: 떨리는 ㅇ은 칸에선 앵커가 많은 울퉁불퉁한 고리로 보인다 — 읽기 뒤 은행에 들어가는 꼴(둥근 획)과 다를 수 있다.
- 사실: 1단계 아래 전 → 후는 누른 자모만 끈 것 → 켠 것(다른 자모는 고른 대로)이고, 지금 고른 쪽에 파란 테두리 · "반영해요 / 그대로 둬요". 격자에서 토글하면 같이 옮겨 간다.
- 사실: 확인 카드 토글이 느렸던 까닭 — 카드를 만질 때마다 글자표(보이는 줄 ~200자) · 쓰기 칸 · 흉내 줄을 통째로 다시 만들었다(React 개발 모드라 더 무거움). 글자표를 `ChartRows`(memo)로, 쓰기 칸 · 흉내 줄을 useMemo로 떼자 크롬에서 토글 한 번 CPU가 약 96ms → 22ms(프로파일, 6번 평균). 긋는 중에도 칸을 다시 만들지 않는다. 렌더러(`SvgRenderer`) 자체는 토글당 1ms 안쪽이라 문제 아님.
- 사실: 2단계에서 처음 들어오는 배치는 전이 없으니 글자 하나만("새") 보이고, 머리말도 "처음 잡는 배치예요"로 바뀐다. 이미 있는 배치만 전 → 후 + 섞기 토글.
- 사실(방향 바꿈): "프리셋 문장에서 한 군데 고치고 범위를 묻기" 시안은 사용자가 안 직관적이라 접음. 대신 **전역 스타일에 부위별 변형을 더해 실험실 전역 설정 상자에서 일괄 적용**해 보기로. 첫 축은 둥글기(사용자 선택 1).
- 사실: 둥글기 슬라이더(0~100%, 제품 `strokeStyle.roundness`) — 글자표 · 쓰기 칸 벡터 · 카드가 같은 값을 받는다. 쓰기 칸 벡터는 이제 렌더러와 같은 채운 윤곽(`strokeToRenderInkGroups`)으로 그린다. 글자표는 `useDeferredValue`로 슬라이더 뒤에 따라온다(한 칸 611ms → 173ms). 제품에 이미 있던 축: 둥글기 · 안쪽 둥글기 · 굵기 대비(`contrast`) · 뾰족 한계 — 다음 슬라이더 후보.
- 이상한 것: 손글씨로 그린 ㅇ(점 많은 닫힌 고리)은 둥글기 50%에서 윤곽이 톱니처럼 깨진다(0 · 100%는 멀쩡). 점이 적은 프리셋에선 안 보이던 것. 렌더러 `strokeToFlatInkGroups`의 부분 둥글기 쪽이거나 고리 점을 줄여야 함 — 확인 안 함.
- 사실: 은행이 비어 스타일 변화가 안 보인다는 지적 → 전역 설정 상자에 "프리셋으로 보기" 스위치. 켜면 글자표 2,350자와 흉내 줄을 제품 프리셋(자모 저장소 + 배치 + Noto 모델 자리, AppGlyph와 같은 길)으로 그리되 전역 스타일만 실험실 슬라이더 값을 받는다. 보이는 칸 전부 잉크 있음(빈 칸 0). 슬라이더 한 칸 61ms.

- 미결정: 홀자 섞임 · 겹받침에서 번호가 많아질 때 묶어 보일지. 프리셋 ㅎ 꼭지가 짧아 번호가 겹치는 자리는 마디를 따라 옮겨 피했다.
- 사실: 같은 이름 줄기가 한 자모에 둘 이상이면 자리말(홀자 = 보선 역할 표의 안 · 바깥 · 위 · 아래 · 왼 · 오른, 닿자 = 놓인 자리). 이름 자체는 공유한다.
- 사실(사용자와 정함): 부위 묶음은 기능 층과 형태 층 두 높이. 줄을 누르면 기능 층(짧은기둥의 머리 · 첫닿자 세로줄기)에서 시작하고, "세로줄기의 머리로 넓히기"는 따로 누른다. 닿자 줄기는 이름이 없어 자리 + 모양(첫닿자 가로줄기 · 받침 세로줄기)을 기능 이름으로 쓴다. 고른 묶음이 든 글자를 글자표에 칠하고 글자 수를 센다(예: 짧은기둥의 머리 473자 → 세로줄기의 머리 2,112자).
- 가설: 글자표 묶음은 기본 자모 획으로 읽어 가른 벌(홀자별 첫닿자) 꼴 차이는 안 든다. 큰 글자는 그려지는 획으로 읽어 둘이 드물게 갈릴 수 있다.

### 11-09 부위 속성 (사실)
- 닿자 줄기 묶음 이름에서 자리를 뺐다("닿자 가로줄기의 머리"). 첫닿자·받침은 묶음 상자에서 자리별로 나눠 센다.
- 묶음 상자는 큰 글자 아래로 옮기고, 묶인 자모를 같은 크기 글자 네모 안에 본보기 글자(○+ㅏ, ㅇ+○, 가+○) 속 자리대로 그려 묶인 부위만 칠한다.
- 부위마다 속성을 단다: 자리(첫닿자 · 받침) 또는 홀자 꼴(세로 · 가로 · 섞임), 자리말(위 · 아래 · 안 · 바깥 · 왼 · 오른), 곁줄기 · 걸침 방향(가까운 기둥 기준 오른쪽 · 왼쪽으로 뻗음), 짧은기둥 방향(보 위 · 보 아래).
- 사용자 결정: 획을 바꾸면 묶음 전체로 퍼지는 게 기본이고, 그 안에서 속성으로 세부 그룹을 고른다. 거름 칩은 그 화면을 만들 때 꺼낸다.
- 목록 번호는 줄기 · 꺾임 1, 2, 3…, 딸린 머리 · 맺음은 1-1 · 1-2(사용자). 머리 · 맺음은 자기 줄기 아래에 들여 쓴다.
- 글자표 위에 탭(글자 · 첫닿자 · 홀자 · 받침). 자모 탭은 앱 대시보드 자소 카드(`JamoGlyph`)를 쓰고, 누르면 본보기 글자(○+ㅏ, ㅇ+○, 가+○)를 크게 띄워 그 자리를 펼친다. 고른 묶음에 든 카드는 초록 바탕.
- 꺾임 속성: 귀 자리(두 팔 방향의 반대 — ㄱ 오른 위, ㄴ 왼 아래), 열린 꼴 · 닫힌 꼴(획 끝이 다 막혔나), 곧은 · 벌어진 · 좁은 꺾임. 두 획 끝이 맞닿아 귀를 이루면 '만난 꺾임'으로 넣는다(같은 꺾임 묶음). 프리셋에는 만난 꺾임이 없다(ㅁ이 한 닫힌 획, 나머지 만남은 T자 이음).
- 11-10 줄기 층(사용자): 닿자 가로줄기는 맨 위 · 가운데 · 맨 아래, 세로줄기는 맨 왼 · 가운데 · 맨 오른을 속성으로 단다. 쓴 차례가 아니라 자모 안 자리 비율(0.35 · 0.65)로 정해서 꼴을 바꿔도 따라간다. 줄기 개수로 세면 ㅋ 덧줄기가 맨 아래가 돼서 버렸다. 꼭지에는 안 단다. 같은 축 자리말(ㅍ 위 · 아래)은 층이 대신한다.

### 11-10 부위 스타일 규칙 (사실)
- 규칙 하나 = 무엇에(부위 묶음) · 어디까지(속성 칩 + 뺀 자모) · 무엇을(스타일). 첫 스타일은 제품의 세로줄기 부리 — `SvgRenderer`의 획별 부리(`groupBeakOf`)로 그릴 때만 입힌다. 프리셋 획은 안 고친다.
- 세로줄기의 머리를 고르면 묶음 상자에 [스타일 추가하기]. 팝업(`HandwritingPartRules.tsx`)에서 부리 모양 · 크기, 줄기 이름 칩(기둥 · 짧은기둥 · 꼭지 · 닿자 세로줄기)과 자리 칩으로 좁히고, 범위 카드가 부리 얹힌 꼴로 바로 그려진다. 카드를 누르면 그 자모만 뺀다.
- 걸린 규칙은 왼쪽 아래 목록(누르면 고치기). 넓은 규칙 먼저, 겹치면 좁은 규칙이 이긴다. `부리 없음` 규칙으로 좁은 범위만 뺄 수 있다. 저장은 localStorage `handwriting-lab-part-rules-v1`.
- 미결정: 부리는 획 단위로 걸려 한 획에 세로줄기 머리가 둘이면(ㅂ) 같이 얹힌다. 다음 스타일(맺음 · 꺾임 · 줄기)을 무엇으로 할지.

### 11-10 맺음 비스듬히 자르기

- 사실: 부위 스타일 규칙이 두 종류가 됐다. 맺음을 고르면 스타일 추가하기가 뜨고, 각도(−45°~45°) 하나로 끝 면을 기울인다. 범위 칩은 맺음이 달린 줄기 이름 아홉 가지와 자리 셋. 기본 20° 전체로 걸면 첫닿자 15 · 홀자 21 · 받침 23에 먹는다.
- 사실: 엔진에 맺음 꼴을 바꾸는 길이 없어 획 끝에 쐐기를 덧그린다(`HandwritingTailCut`). 그래서 기울인 쪽이 굵기 × tan(각)만큼 길어진다. 꺾임 모두 굴리기를 켜면 둥근 끝과 안 맞는다.
- 미결정: 깎는 방식(길이 유지)으로 갈지, 제품으로 갈 때 엔진의 끝 모양으로 넣을지.
- 사실(11-11): ㅞ의 안 기둥 맺음이 빠져 있었다. 획 문법이 끝에서 0.1 안에 다른 획이 있으면 닿은 끝으로 읽는데, 안 기둥 끝이 곁줄기에서 딱 0.1 아래다. 실험실의 맺음만 0.05로 좁혀 읽는다(`tailIsOpen`, 획 문법은 그대로). 같이 열린 것: 첫닿자 ㅃ, 받침 하나, 걸침 하나 — 전체 규칙이 첫닿자 16 · 홀자 21 · 받침 24로 늘었다.
- 사실(11-11): 맺음 자르기를 덧붙이기에서 깎기로 바꿨다(사용자 선택 1: 긴 귀를 원래 끝에). 파트 잉크에 SVG 가림판을 걸어 짧은 쪽 귀만 굵기 × tan(각)만큼 깎는다 — 줄기 길이와 보선이 그대로다. 렌더러 `PartStyle`에 `mask` 하나를 더했다(쓰지 않으면 아무 일 없음).
- 사실: 스모크는 이 컨테이너에서 바꾸기 전후 똑같이 8 실패 · 4 통과 · 2 건너뜀이다(따로 돌리면 통과하는 스펙이 묶음에서만 실패 — 환경 문제로 본다). 사파리 엔진(WebKit)은 컨테이너에 없어 못 봤다.
