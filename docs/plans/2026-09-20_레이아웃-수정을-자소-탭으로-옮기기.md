# 레이아웃 수정을 자소 탭으로 옮기기

- **이번에 비교하는 것**: 기준선으로 배치를 고치는 편집기를 검수 글자 화면에 둘지, 자소 탭(문장 → 글자 편집) 안에 둘지.
- **이번 승인으로 바뀌는 것**: 자소 탭에 `레이아웃` 모드가 생기고 검수의 기준선 편집기가 그 자리로 온다. 검수는 격자(표)로 전체를 훑는 화면만 남는다.
- **바뀌지 않는 것**: 칸 해석 함수, Δ 저장 방식(`layoutDeltaStore`, Δ만 저장), 전파 범위 규칙(기본 이 레이아웃), 획 편집, 뼈대 탭, production 값.

출처: 주간 노트 2026-W39 일요일 `순서 질문`. 9/16 Y-3 조건 3("편집 영역 이동은 Y-3 뒤")과 9/17 결정("검수 레이아웃 편집이 뼈대 페이지 자리를 대체")의 후속.

## 지금 상태

**사실** (코드 읽기로 확인, 화면 재현은 아직)
- `/workspace/jamo`는 `CalibrationSentenceEditor chrome="workspace"`다. 여기서 자소를 통째로 잡아 옮기면 `userPartOverrides`(split/padding 스키마)에 저장된다.
- 렌더는 `useContextPlacement`가 모델 상자를 풀면 상자만 쓴다(`placement.kind === 'boxes'`). Noto 배치가 기본 on이라 **자소 탭의 레이아웃 수정은 글자에 닿지 않는다.** 9/17에 뼈대 페이지에서 본 것과 같은 문제.
- 실제로 글자에 닿는 배치 편집은 검수 글자 화면 `GlyphView`(`ReviewWorkspacePage.tsx:344`)뿐이다. 기준선 캔버스(`GhostCanvas`) + 부품 탭 + 전파 카드 + Δ 적용. 같은 `MobileWorkspaceShell`을 쓰고 셸 말고는 검수에 묶인 게 없다.
- 검수 글자 화면엔 이미 `이 글자 획 편집 ›` 링크가 있어 두 화면이 서로를 가리킨다. 편집 세계가 둘.

**알려진 구멍**: 앱 렌더러는 홀자를 slot 상자에 스케일해 그린다. 홀자 안쪽 rail Δ(ㅐ 안기둥 등)는 편집 캔버스에선 움직이지만 문장 줄의 글자엔 안 닿는다. 자소 탭은 문장이 바로 위에 있어서 이게 그대로 드러난다.

## 하려는 것

1. `GlyphView`에서 셸과 제목을 뺀 편집부를 `GlyphLayoutEditor`로 떼어낸다. 입력은 글자 하나, 출력은 없음(Δ는 스토어로).
2. 자소 탭 편집 영역에 `획 · 레이아웃` 전환을 둔다. `레이아웃`이면 그 자리에 `GlyphLayoutEditor`가 뜬다. 문장 줄·글자 선택은 그대로.
3. 옛 경로(자소 통째 이동 → `userPartOverrides`)는 모델 상자로 그려지는 글자에선 끈다. 모델이 못 푸는 글자만 옛 경로로 남는다.
4. Δ 적용·지우기를 자소 탭 Undo/Redo에 넣는다.
5. 검수 `R-02 글자` 화면은 없애고, 격자에서 글자를 열면 `/workspace/jamo?char=…&mode=layout`으로 간다.
