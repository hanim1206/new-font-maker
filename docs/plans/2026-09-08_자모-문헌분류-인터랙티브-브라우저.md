# 자모 문헌분류 문맥별 시각화

별도 자모 선택 대시보드가 아니라 각 자모 노트를 상세 페이지로 만든다. 사용자가 `ㄱ.md`를 열면 ㄱ을 다시 선택하지 않아도 현재 Properties를 읽어 ㄱ의 모든 문맥을 바로 보여 준다.

현재 `/reference-group-lab`은 `그룹 선택 → 네 문맥 → 그룹에 속한 여러 자모의 실제 폰트 SVG` 순서다. 원하는 화면은 이를 `현재 자모 → 자모가 속한 문맥별 그룹 → 해당 자모의 실제 폰트 SVG` 순서로 뒤집는다.

`ㄱ.md`에서는 다음 사례가 한 화면에 나온다.

- 위치 관계: `가`의 나란히, `고`의 위, `각`의 아래
- 최종 조합 그룹: `감`의 첫닿자, `곰`의 첫닿자, `막`의 받침닿자, `극`의 받침닿자
- 각 사례의 문헌 필드명, 그룹 번호, 원문 대조 상태
- `/reference-group-lab`과 같은 원본 폰트 SVG, UPM, advance, bounds, 공통 기준선과 Design Body

`문헌_위치_나란히·위·아래`와 `문헌_최종_*` 네 필드는 화면에서 두 구역으로 나눈다. 같은 숫자도 필드가 다르면 같은 그룹으로 합치지 않는다.

구현은 자모 파일마다 코드를 복사하지 않는다. 각 파일 본문에는 현재 노트를 넘기는 짧은 공용 뷰 호출만 두고, 공유 renderer가 `dv.current()`의 자모와 Properties를 읽는다. 자모별 문맥 음절 조합과 그룹값은 현재 메타데이터에서 파생한다.

실제 폰트 SVG 생성은 Obsidian이 직접 맡지 않는다. `/reference-group-lab`의 outline 파이프라인으로 문맥별 SVG와 측정 manifest를 생성해 Vault에 저장하고, 공용 뷰가 이를 표시하는 방식이 우선 후보다. 그러면 `ㄱ.md`는 서버가 꺼져 있어도 열린다. 실시간 폰트 전환이 필요할 때만 로컬 reference 서버 연결을 추가한다.

실제 폰트의 완성 글리프는 자모별 contour가 분리되어 있지 않다. 현재 `/reference-group-lab`도 첫 문맥 초성만 고정 사각형 clip으로 강조한다. 첫 버전에서는 선택한 닿자의 실제 윤곽이라고 주장하지 않고, 문맥 템플릿이 정한 `역할 영역`을 SVG 위에 강조한다. 실제 자모 윤곽 분리는 수동 주석이나 별도 segmentation 근거가 생긴 뒤 다룬다.

초기 화면은 읽기 전용이다. 시각화와 측정값은 문헌 Properties를 덮어쓰지 않는다. 현재 좌표가 실제 Font Maker PartFrame 채택값이라는 오해를 막기 위해 원본 폰트 관찰값과 프로젝트 채택값을 구분해 표시한다.

## 기존 랩 검토

2026-09-08 화면 검토 결과, 현재 `/reference-group-lab`이 핵심 경험을 이미 제공한다. 닿자 선택, 네 최종 조합 문맥, 실제 폰트 SVG, 역할 영역 강조, 그룹 번호와 전체 그룹표, 폰트 전환이 한 화면에 있다. 같은 기능을 각 Obsidian 노트 안에 다시 만드는 우선순위는 낮다.

남은 차이는 시각화보다 데이터 연결이다. 현재 랩의 문헌 그룹은 React 코드에 별도로 정의되어 있어 Obsidian Properties와 달라질 수 있다. Obsidian 자모 데이터를 기준 원본으로 삼아 검증된 JSON snapshot을 만들고 랩이 이를 읽도록 해야 한다. 랩 URL에는 `?jamo=ㄱ`처럼 선택 자모를 보존하고, 각 자모 노트에는 해당 화면으로 가는 링크만 두는 구성이 우선 후보다.

높이·속공간·원문 대조 상태까지 랩 상단에 표시하면 Obsidian에서 별도 상세 뷰를 만들 필요가 더 줄어든다. 서버 없이 결과를 보존해야 할 때만 랩의 SVG 또는 스크린샷을 자모 노트에 snapshot으로 첨부한다.
