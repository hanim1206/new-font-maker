# e2e 전체 시간 줄이기

- **이번에 비교하는 것**: e2e 전체(`npm run test:e2e`)를 지금 설정(파일 단위 병렬, 워커 기본값)으로 돌린 시간과, 테스트 단위로 쪼개 동시에 돌린 시간.
- **이번 승인으로 바뀌는 것**: `playwright.config.ts`의 병렬 설정과 무거운 스펙 묶음.
- **바뀌지 않는 것**: 스펙 내용 · 단언, 스모크 목록, 푸시 훅(자동화는 다음 단계), 다른 워크트리와의 잠금(`.git/e2e.lock`).

## 왜

dev → main 직전 ④(단위 전체 + e2e 전체)가 약 8분이라, 푸시 훅에 붙이면 건너뛰게 된다. 먼저 줄이고 다음 단계에서 훅에 붙인다.

## 방법

- 가벼운 스펙은 테스트 단위로 동시에(`fullyParallel`), 워커 상한을 둔다.
- 무거운 스펙(OTF 추출 · 노토 코퍼스)은 따로 묶어 차례로 돈다. 동시에 돌리면 시간 초과가 날 수 있어서다.
- 테스트마다 새 브라우저 환경이라 저장 공간은 겹치지 않는다. 파일을 쓰는 건 OTF 기준 두 스펙(갱신할 때만, 서로 다른 파일)뿐.

## 진행 기록

### 10-05

- 사실: 지금 설정 e2e 전체 3.7~4.2분(8분 아님). 같은 조건 연달아 잰 것 — 옛 설정 4.2분 · 새 설정(테스트 단위 병렬 4 + 무거운 묶음 앞) 4.5분. 워커 6 · 무거운 묶음 뒤는 4.3~4.7분. 새 설정이 안 빠르다.
- 사실: 테스트 도는 동안 load 35 안팎(8코어). 컴퓨터가 이미 꽉 차 있어 동시 실행을 늘려도 줄지 않는다.
- 사실: dev에서 늘 깨짐 — `design-body-internal-spacing` 에의 ㅔ(0.275 기대, 0.196 · 6번 중 6번), `announcement` 새 공지 카드(시간 초과 · 6번 중 4번). 바쁠 때만 깨짐 — `font-export-experience` 대시보드 카드(99%에서 멈춰 120초 기다림), `area-stroke-style`, `model-otf-baseline`, `shape-rule-panel`, `workspace-jamo-editor` 복사.
- 가설: 시간은 병렬보다 깨지는 테스트가 기다리는 시간(120초 · 30초)에서 더 줄일 수 있다.
- 미결정: 설정 되돌릴지(G1 실패).
- 결정(나, 10-05): 병렬 설정 되돌림. 4분 그대로 푸시 훅에 붙인다.
- 사실: `.githooks/pre-push` — main 푸시는 `npm test && npm run test:e2e`, dev · claude/main은 스모크 그대로. 한 번에 둘 올리면 main 쪽. npm이 PATH에 없으면(Fork) nvm을 불러 찾는다. 가짜 실행(검사 명령만 echo)으로 main · dev · 둘 같이 · 피처 네 경우 확인, 진짜 푸시는 안 함.
- 미결정: `design-body-internal-spacing`이 늘 깨져 지금은 main 푸시가 막힌다. 먼저 고치거나 `--no-verify`.

### 10-06

- 사실: `design-body-internal-spacing` ㅔ는 앱 버그가 아니라 잣대 차이. 기본 네모꼴은 획을 선으로, 바꾼 네모꼴은 면으로 그리는데 Playwright `boundingBox`는 선 두께를 사방에 더한다(기본 .275 · 600은 .196, 기하 경계로는 .199 · .196). `6a5b572`부터 깨짐 — 그 전엔 첫 값을 그리는 중간(.12대)에 재서 우연히 맞았다. 기하 경계로 재고, 첫 값은 .15를 넘고 두 번 같을 때 잡게 고침. 혼자 5번 통과.
- 사실: `announcement` 관리자 공지와 들쭉날쭉한 실패 대부분은 Vite 묶음 캐시 공유 탓. 워크트리가 node_modules를 심링크로 같이 써 `node_modules/.vite`도 같이 쓰고, 다른 워크트리 서버가 다시 묶으면 테스트 서버 묶음이 덮여 React 두 벌(Invalid hook call, "문제가 생겼어요") — 한 번은 26개 실패 중 21개가 이것. `cacheDir`를 체크아웃마다(`.vite-cache`) 두게 고침. 다른 워크트리가 공유 캐시를 다시 쓰는 중에 announcement 4번 연속 통과, 전체 1번 140 통과 · 1 실패(`font-export` 대시보드 카드, 부하 탓).
- 미결정: `font-export-experience` 대시보드 카드가 부하 때 99%에서 멈춤 — main 푸시를 가끔 막을 수 있다.
