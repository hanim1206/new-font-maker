# 홈을 자소 탭으로

- **이번에 비교하는 것**: 앱을 열었을 때(`/`) 옛 단독 문장 보정을 보여 줄지, 셸의 자소 탭을 보여 줄지.
- **이번 승인으로 바뀌는 것**: `/`는 `/workspace/jamo`로 넘어간다(`?char=` 등 쿼리 유지). 옛 단독 문장 보정은 `/calibration`으로 옮긴다. 셸 왼쪽 위 `문장 보정` 링크와 PWA 시작 주소도 같이.
- **바뀌지 않는 것**: 편집기 자체, 모르는 주소가 문장 보정으로 떨어지는 것, 랩의 `보정 화면으로` 링크(`/` → 자소 탭으로 가게 됨), 하단 내비 구성.

배포본을 열면 옛 화면이 먼저 나와서. 옛 단독 모드를 아예 지우는 건 e2e 14개를 셸 기준으로 다시 써야 해 범위 밖.

## 게이트

| G0 대표 | `/`와 `/?char=간`이 자소 탭으로 넘어가고 레이아웃 편집이 뜬다. Playwright. |
| G1 홀드아웃 | `/calibration`은 셸 없이 뜨고, 셸의 `문장 보정` 링크가 그리로 간다. |
| G2 전수 | `tsc -b` · eslint · `screen-spec` 테스트(주소 ↔ 명세 1:1) · `/`를 열던 e2e 14개를 `/calibration`으로 옮겨 돌림. 기존 실패는 늘지 않음. |
| G3 사용자 검증 | 배포 주소를 열어 자소 탭이 먼저 뜨는지. |

## 진행 기록

### 2026-09-21
- **사실**: `App.tsx`에 `HomeRedirect`, `WorkspaceChrome` 뒤로가기 링크 → `/calibration`, `screenRoutes`(제품 `/calibration`, 넘김 `/`), `vite.config` `start_url`, 명세 `문장보정` · `자소편집` · `_트리`, e2e 14개 주소 + 새 `home-redirect.spec.ts`.
- **사실 (검증)**: `tsc -b` 0, eslint 0, `screen-spec` 15/15, e2e 12개 파일 중 19 통과 · 3 실패. 실패 셋은 이 변경이 없는 HEAD를 따로 띄워 돌려도 똑같이 실패한다 — `dev-screen-spec:9`(명세 `6.14`가 두 줄에 걸림), `calibration-layout-persistence:36`(저장 횟수 0 기대, 1), `area-stroke-style`의 레거시 스냅 획 전체 OTF(240초 안에 안 끝남). 기본 스타일 OTF 추출은 HEAD에서 4초에 받아진다(`opentype.js` 2.0.0 머지 뒤에도 정상). OTF 기준선 스펙 둘(`otf-legacy-baseline` · `nonround-otf-baseline`)은 오래 걸려 안 돌렸다.
- **사실**: 같은 워크트리에서 다른 세션이 `App.tsx` · `WorkspaceChrome.tsx` · e2e 5개를 고치는 중이라 같은 파일에 두 작업이 섞여 있다. 그쪽 미커밋 변경은 하단 `홈` 탭을 `/`로 보내고 `홈을 누르면 주소가 /`임을 단언한다. `/`가 넘어가게 됐으니 그 탭은 자소 탭과 같은 곳으로 가고 그 단언은 깨진다. 그쪽 줄은 건드리지 않았다.
- **결정 (구현 전)**: 하단 내비는 없애고 `검수`는 머리 `…` 메뉴로 옮긴다(사용자). 다른 세션이 그 내비의 `홈` · `출력`을 고치는 중이라 그 작업이 정리된 뒤 새 플랜으로 한다. 아래는 판단 근거.
- **근거**: 하단 내비를 없애면 `검수`로 가는 길이 하나도 안 남는다 — `홈`은 중복, `출력`은 `…` 메뉴의 `OTF 추출`과 중복, `자소`는 자기 자신.
