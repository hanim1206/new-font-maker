# 자모 구조 메타데이터 수집 플랜

## 목표

기준선·PartFrame 좌표와 별개로, 자모가 어떤 의미 있는 부분으로 이루어졌는지 `JamoMaster`에 저장한다. 이 데이터가 있어야 편집기가 `모든 세로줄기 상단`, `꺾이는 부분`, `부리 있는 끝`처럼 형태 역할을 대상으로 일괄 편집할 수 있다.

획 수는 원본 필드가 아니다. 획·이음·끝점 구조에서 계산하는 파생값이다.

## 기존 데이터와 책임 분리

| 층 | 책임 | 이 플랜과 관계 |
| --- | --- | --- |
| `자모-문헌분류-v1` | 논문에서 전사한 높이·속공간·조합 문맥 소속 | 유지. 구조 태그나 좌표를 넣지 않는다. |
| `JamoMaster` | 자모 기본 스켈레톤과 의미론적 구조 | 이번 수집 대상. 자모마다 한 번 정의한다. |
| `LayoutProfile` / PartFrame / Guide | 문맥에서 자모가 차지할 영역·기준선·좌표 | [2026-09-11_기준선-첫닿자-검증-플랜](./2026-09-11_기준선-첫닿자-검증-플랜.md)에서 검증한다. 구조 태그와 혼합 금지. |
| `ContextPreset` | 역할형·레이아웃형 변형과 예외 | 같은 자모라도 문맥에서 구조가 달라질 때만 차이를 저장한다. |
| 파생 측정값 | 획 수, 줄기 수, 꺾임 수, 끝점 수, 현재 윤곽의 bounds | 원본 구조 또는 실제 윤곽에서 계산한다. |

관계는 아래 순서다.

```text
JamoMaster 구조 태그
  → ContextPreset 구조 차이 또는 좌표 보정
  → LayoutProfile / PartFrame 배치
  → 실제 조합 윤곽
  → 파생 측정값·충돌 검사
```

`자모 × 6문맥` 관찰은 배치·비율·여백 검증 단위다. 기본 획 구조를 여섯 번 복제 저장하는 단위가 아니다.

## 홀자 자동 추출 P0와의 경계

[2026-09-13_홀자-기준선-자동-추출-P0-플랜](./2026-09-13_홀자-기준선-자동-추출-P0-플랜.md)은 외부 폰트 완성 글자에서 기둥·보의 **윤곽 바깥 면**을 찾는 분석 작업이다. 이번 플랜은 생성 자모 내부의 **구조축·획·이음·끝점**을 정의하는 작업이다. 둘은 역할 어휘를 공유하되 좌표와 저장소를 공유하지 않는다.

P0가 시작되기 전에 현대 자모 전체의 `strokes`, `joints`, `terminals`, 공유 부분 구조를 채우지 않는다. P0가 요구하는 최소 입력은 홀자별 관측 역할 목록과 `not-applicable` 판정이다. 이 최소 목록도 `ㅗ·ㅜ`의 짧은 세로줄기 1개와 `ㅛ·ㅠ`의 좌우 세로줄기 2개를 보선과 별도 역할로 포함한다. 분석 ROI는 생산 `JamoMaster`·`LayoutProfile`에서 가져오지 않는다.

P0 G1·G2 뒤에는 승인된 `ExternalObservation`과 자동 포기 사례를 구조 어휘 검토 근거로 사용한다. 다음 항목은 사용자 검토 없이 자동 생성하지 않는다.

- `outerPillarFace`를 `pillarAxis` 좌표로 변환
- 관측 contour를 JamoMaster 획으로 복사
- 반복된 외형만 보고 공유 부분 구조·결합부 처리 확정
- 한 폰트의 문맥 차이를 ContextPreset으로 승격

## JamoMaster 최소 구조 스키마

각 자모는 `strokes`, `joints`, `terminals`, 선택적으로 `features`를 가진다. 숫자만 적지 않고 각 요소의 역할과 연결 관계를 남긴다.

```yaml
jamo: ㄷ
structure_version: 0.1

strokes:
  - id: top-horizontal
    role: topHorizontal
    direction: horizontal
  - id: left-vertical
    role: leftVertical
    direction: vertical
  - id: bottom-horizontal
    role: bottomHorizontal
    direction: horizontal

joints:
  - type: corner
    position: topLeft
    connects: [top-horizontal, left-vertical]
  - type: corner
    position: bottomLeft
    connects: [left-vertical, bottom-horizontal]

terminals:
  - stroke: top-horizontal
    end: end
    position: topRight
  - stroke: bottom-horizontal
    end: end
    position: bottomRight

features: []
```

### 가로 홀자 필수 구조

가로 홀자를 `보만 있는 자모`로 기록하지 않는다. 좌표와 획 수를 원본 필드로 중복 저장하지 않되, 아래 획·연결 역할은 JamoMaster에서 식별 가능해야 한다.

| 홀자 | 구조 요소 | 연결 |
| --- | --- | --- |
| `ㅗ` | `primaryHorizontal` + `baseShortVertical(up)` | 짧은 세로줄기 아래쪽이 주 가로보에 붙음 |
| `ㅜ` | `primaryHorizontal` + `baseShortVertical(down)` | 짧은 세로줄기 위쪽이 주 가로보에 붙음 |
| `ㅛ` | `primaryHorizontal` + `leftShortVertical(up)` + `rightShortVertical(up)` | 두 줄기를 별도 인스턴스로 연결 |
| `ㅠ` | `primaryHorizontal` + `leftShortVertical(down)` + `rightShortVertical(down)` | 두 줄기를 별도 인스턴스로 연결 |
| `ㅡ` | `primaryHorizontal` | 짧은 세로줄기 없음 |

혼합홀자 `ㅘ·ㅙ·ㅚ`는 `ㅗ` 계열 바탕 줄기를, `ㅝ·ㅞ·ㅟ`는 `ㅜ` 계열 바탕 줄기를 가진다. `ㅢ`의 바탕 `ㅡ`에는 짧은 세로줄기가 없다. 외부 폰트 P0의 `basePillarFace`는 현재 저장 호환 ID지만 구조 용어는 `baseShortVertical`이다. P0의 오른면 X·끝면 Y는 외부 윤곽 관측값이고, JamoMaster의 획 중심선·시작·끝 좌표와 같은 값으로 저장하지 않는다.

완성 글자에서 짧은 세로줄기 끝이 이웃 자소 잉크에 묻혀도 JamoMaster 구조를 잘라 저장하지 않는다. 원래 줄기 끝은 자모 구조, 첫 접촉면과 겹침 깊이는 조합 결과의 `DerivedMetrics`다. 외부 폰트의 숨은 component 끝은 provenance가 확인될 때 분석 증거로만 남기며 보이는 바깥면 기준선으로 승격하지 않는다.

### 저장할 의미 태그

- **획과 줄기**: `horizontal`, `vertical`, `diagonal`, 역할명(`topHorizontal`, `leftVertical` 등), 시작·끝·연결 대상.
- **꺾임과 이음**: `corner`, `curveJoin`, `crossing`, `attachment` 등 유형, 위치, 연결한 획.
- **끝과 부가 형태**: `terminal`, `serif`, `beak`, `spur`, `protrusion` 등. 어느 획의 어느 끝인지 연결한다.
- **속공간·열린 면**: 필요할 때만 `enclosedSpace`, `openSide`처럼 구조적 관계를 기록한다. 현재 윤곽 면적·여백 수치는 별도 파생 측정값이다.

태그 이름은 첫 수집 전에 작은 어휘표로 확정한다. 같은 뜻을 `부리`, `삐침`, `beak`처럼 섞어 쓰지 않는다. 화면 표기는 한국어, 안정 ID는 코드형 이름으로 유지할 수 있다.

## 저장하지 않는 것

- `가로획: 2`, `꺾임: 1` 같은 count 원본값
- 첫닿윗선·첫닿밑선·기둥선, PartFrame 좌표, optical offset
- 특정 폰트 윤곽의 ink bounds·무게중심·충돌값
- 논문 분류 그룹 번호
- 문맥마다 달라진 완성 자모 복사본

예:

```text
horizontalStrokeCount = strokes 중 direction: horizontal 수
cornerCount = joints 중 type: corner 수
terminalCount = terminals 수
```

구조 변경 뒤 count가 자동 갱신되므로 중복값 불일치를 막는다.

## 문맥 차이 처리

기본 구조는 `JamoMaster`에 둔다. 문맥별 `ContextPreset`에는 기본 구조에서 달라진 사실만 둔다.

```text
기본 ㄱ
  → 초성·세로모임: 위치·비율 보정
  → 초성·가로모임: 위치·비율 보정
  → 받침: 위치·비율 보정
  → 특정 문맥에서 부리 생략: 구조 override
```

구조가 유지되면 좌표·비율 보정만 저장한다. 획 추가·삭제, 이음 종류 변경, 특정 끝의 부리 생성·삭제처럼 구조가 달라질 때만 `structureOverride`를 만든다. 기본 구조 변경은 관련 ContextPreset을 `검토 필요`로 표시한다. 자세한 상속 원칙은 `옵시디언 2026-08-16_자소별-문맥-프리셋`을 따른다.

## 구조 기반 추천과 일괄 반영

사용자가 한 자소에 적용한 편집은 자소 이름이 아니라 **편집 종류와 부착된 구조 역할**로 해석한다.

```text
사용자 편집
  → 편집 의도와 부착점 판정
  → 같은 구조 역할을 가진 자소 조회
  → 실제 조합 문맥에서 충돌·방향 검사
  → 후보 미리보기와 사용자 선택
  → 하나의 일괄 명령으로 반영
```

예를 들어 세로 홀자 상단에 부리를 붙였다면 편집을 `addFeature: beak`, 부착점을 `verticalStem.topTerminal`로 기록한다. 편집기는 같은 상단 끝점을 가진 세로 홀자와 혼합 홀자의 세로부를 후보로 찾는다. 자소 목록을 고정해서 외우지 않고 구조 호환성으로 찾으므로, 이후 전체 홀자로 확장해도 같은 규칙을 쓸 수 있다. 부리 방향이 반대이거나 조합 안에서 공간이 부족한 후보는 별도 경고 또는 제외 대상으로 둔다.

`ㅅ`에 적용한 성질도 `ㅅ` 전체가 아니라 공유 구조에 붙인다. 두 빗금과 아래 이음으로 이뤄진 공통 몸체를 가칭 `sBody`로 정의하면, 이를 포함하는 `ㅆ·ㅈ·ㅉ·ㅊ`을 추천할 수 있다. `ㅆ·ㅉ`처럼 공통 몸체가 반복되면 각 인스턴스에 반영한다. 반대로 `ㅈ·ㅊ`에만 있는 가로획에 붙은 성질은 공유 구조가 아니므로 `ㅅ` 계열 전체에 전파하지 않는다.

이를 위해 스키마 v0.2에서 다음 두 연결을 검토한다.

- **공유 부분 구조**: `sBody`, `verticalStem`처럼 여러 자소 안에서 같은 역할을 하는 획·이음 묶음. 실제 획 데이터는 복제하지 않고 각 자소의 요소를 역할에 연결한다.
- **형태 부착점**: `terminal`, `joint`, 특정 획의 시작·끝처럼 부리·돌기·꺾임이 붙을 수 있는 위치. 형태는 부착점과 방향·크기 파라미터를 가진다.

### 결합부 처리와 반복 부품

공유 관계는 자소 사이뿐 아니라 한 자소 내부에도 둔다.

- **결합부 처리**: 고운돋음 `ㄱ`처럼 가로획이 세로획으로 꺾이는 부분을 `joint`로 식별하고 `jointTreatmentRef`를 연결한다. 곡률, 진입·이탈 길이, 굵기 변화, 안팎 모서리 처리를 전역 베지어 좌표가 아닌 국소 방향과 획 굵기에 대한 상대값으로 정의한다. 크기와 비율이 다른 `ㄱ·ㄲ·ㅋ` 및 받침 속 `ㄱ` 구조에도 같은 조형 문법을 투영할 수 있다.
- **반복 부품**: `ㅉ`은 같은 `jieutBody`를 참조하는 왼쪽·오른쪽 인스턴스로 표현할 수 있다. 두 인스턴스는 위치·크기 변환은 따로 가지되 획 구성, 결합부, 끝처리 같은 기본 형태는 함께 바뀐다.
- **획 굵기 프로필**: `ㅉ`의 두 상단 가로획처럼 진행 방향에 따른 굵기 변화가 반복되면 `strokeProfileRef`를 공유한다. 시작부터 끝까지의 진행률 `0–1`에 대한 굵기 변화와 끝처리를 저장하므로 길이가 달라도 같은 리듬을 유지한다.

적용 순서는 `공유 부품 → 결합부·획 프로필 → 인스턴스 변환 → 문맥 안전 보정 → 명시적 예외`로 고정한다. 공유값을 수정하면 연결된 인스턴스를 함께 미리 본다. 한쪽만 달라야 할 때는 원본 연결을 끊지 않고 해당 인스턴스에 sparse override를 둔다.

앱 내부에서 만든 자소는 이 연결을 명시하므로 판정이 결정적이다. 외부 폰트 윤곽에서는 반복 곡선과 굵기 프로필을 비교해 연결 후보를 제안할 수 있지만, 완성 윤곽만으로 제작자가 사용한 원래 부품 관계까지 확정할 수는 없다. 자동 분석 결과는 구조 가설로 표시하고 사용자가 승인한 관계만 규칙으로 저장한다.

초기 동작은 자동 확정이 아니라 추천이다. 후보를 `동일 구조`, `반복 구조`, `문맥 예외`, `호환 안 됨`으로 나누고 실제 낱자·단어 미리보기를 보여준다. 사용자가 범위를 승인하면 하나의 되돌릴 수 있는 명령으로 반영한다. 문맥 검사에서 충돌한 경우 해당 ContextPreset만 제외하거나 `structureOverride` 후보로 남긴다.

기준선 자동 추출은 이 대상 관계를 직접 만들어 주지 않는다. 외부 폰트에서 부착 위치와 문맥별 공간을 측정해 추천값과 예외 판단을 보조한다. “어디에 같은 편집을 적용할 수 있는가”는 `JamoMaster` 구조 메타데이터가, “그 문맥에서 안전하게 들어가는가”는 PartFrame·Guide·실제 윤곽 검사가 맡는다.

## 단계별 실행

### 1. 어휘와 스키마 v0.1 확정

- 획 방향, 역할명, 이음, 끝점, 부가 형태의 허용값을 작은 목록으로 만든다.
- `id`, `role`, `direction`, `connects` 필수 여부와 빈값 규칙을 정한다.
- 이 단계에서는 좌표, count, 폰트별 관찰값을 넣지 않는다.

완료 기준: ㄱ·ㄷ·ㅁ·ㅇ·ㅅ 같은 서로 다른 구조를 같은 필드만으로 기록할 수 있다.

### 2. 대표 닿자 파일럿

- `ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅅ ㅇ ㅈ ㅌ ㅍ ㅎ`에 기본 구조를 입력한다.
- 된소리·겹받침은 독립 구조인지 구성 자모 조합인지 판단 근거를 남긴다.
- 각 태그가 편집 명령이나 비교 화면에서 실제 선택 단위가 되는지 확인한다.

완료 기준: 예시 자모에서 `세로줄기 상단`, `특정 꺾임`, `오른쪽 끝`을 모호함 없이 선택할 수 있다.

### 3. 파생값 계산과 검증

- 스키마에서 가로·세로·빗금 획 수, 꺾임 수, 끝점 수를 계산한다.
- 수동으로 적어 둔 기대값과 비교해 연결 누락·중복 태그를 고친다.
- 현재 윤곽에서 측정하는 bounds·centroid·여백은 구조 count와 분리한다.

완료 기준: count를 직접 수정하지 않아도 구조 편집 뒤 결과가 일관되게 바뀐다.

### 4. 6문맥과 예외 검증

- 19개 초성 × 6 레이아웃 문맥에서 기본 구조가 유지되는지 본다.
- 차이를 `배치·비율`, `시각 보정`, `구조 override`로 나눈다.
- 같은 차이가 반복될 때만 ContextPreset 또는 LayoutProfile 규칙으로 승격한다.

완료 기준: 문맥 차이를 이유로 JamoMaster 구조를 복제하지 않으며, 실제 구조 차이는 예외로 추적된다.

### 5. 전체 확장과 편집 기능 연결

- 파일럿 결과로 어휘를 고정한 뒤 현대 닿자 전체로 확장한다.
- 일괄 선택·부리 추가·꺾임 수정 같은 편집 기능이 구조 태그와 형태 부착점을 입력으로 쓰게 한다.
- 세로 홀자 상단 부리와 `ㅅ` 공통 몸체 편집을 파일럿 규칙으로 연결한다.
- `ㄱ` 결합부 처리 공유와 `ㅉ` 반복 부품·획 굵기 프로필 공유를 파일럿 규칙으로 연결한다.
- 후보 추천 → 문맥 검사 → 미리보기 → 승인 → 일괄 반영을 하나의 되돌릴 수 있는 명령으로 검증한다.
- 새 구조 태그는 실제 편집·검색·검증 중 하나에 쓰일 때만 추가한다.
