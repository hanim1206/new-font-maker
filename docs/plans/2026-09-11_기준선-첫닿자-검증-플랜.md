# 기준선 · 첫닿자 검증 플랜

## 현재 상태

- 2026-09-14부터 자동 추출 구현은 [2026-09-14_닿자-구조면-자동-추출-P0-플랜](./2026-09-14_닿자-구조면-자동-추출-P0-플랜.md)이 이어받는다. 이 문서의 수동 `폰트 × 넓은 조합 문맥 기준값` 방식은 역사 기록으로만 유지하고 새 후보 생성에는 쓰지 않는다.
- 기준선 조율 랩: `/font-guide-lab`
- 저장 구조: `폰트 × 조합 문맥 기준값` + `첫닿자 × 조합 문맥 오버라이드`
- 기준값 적용은 다른 첫닿자의 직접 조율값을 덮어쓰지 않는다.
- 분석값은 production 레이아웃·자모 마스터·OTF 기본값으로 자동 반영하지 않는다.
- 노토 산스 KR의 ㄱ 6문맥 조율값은 저장되어 있다.

## 확인된 것

- 첫닿윗선·첫닿밑선은 첫닿자, 가로·세로·섞임 구조, 받침 유무에 따라 달라진다. 전역값으로 고정 불가.
- 받침밑선은 노토 산스에서 952·961·960으로 차이가 작다. 전역 후보로 관찰한다.
- 기둥선은 오른쪽 세로 홀자가 있는 사례에서 703으로 일치했다. 아래 홀자에는 적용하지 않는다.
- 무받침 첫닿밑선은 기준선 880까지 이동할 수 있다.

## 현재 사례와 문제

현재 사례:

```text
가 / 각
과 / 광
고 / 곡
```

`광`만 종성 ㅇ이고 `각·곡`은 종성 ㄱ이다. 첫닿자·홀자 영향과 종성 영향이 섞여 있어 통제 비교로는 부족하다.

## 다음 결정

통제용 받침 사례를 다음처럼 둘지 결정한다.

```text
첫닿자 X

Xㅏ / Xㅏㄱ
Xㅗ / Xㅗㄱ
Xㅘ / Xㅘㄱ
```

ㄱ의 경우:

```text
가 / 각
고 / 곡
과 / 곽
```

`광`은 실제 조합 확인용 자연 사례로 별도 유지할 수 있다.

## 다음 실험 순서

1. 통제 사례에 `곽`을 추가할지 결정한다.
2. 노토 산스 KR과 ㄱ 기준값을 고정한다.
3. 19개 첫닿자의 실제 완성 글자 path에서 문맥별 component·잉크 경계 후보를 만든다.
4. 첫닿자 버튼으로 하나씩 넘기며 후보를 육안 검토한다.
5. 차이를 숫자 오버라이드로 복사하지 않고 정확한 글자 identity의 분석 관측으로 남긴다.
6. 첫닿자 검토 뒤 홀자군을 확장한다.
   - 오른쪽: ㅏ·ㅑ·ㅓ·ㅕ…
   - 아래: ㅗ·ㅛ·ㅜ·ㅠ·ㅡ…
   - 섞임: ㅘ·ㅙ…

## 주의

완성형 글리프 윤곽에는 첫닿자·홀자·받침 경계가 따로 없다. 자동 윤곽 측정은 후보만 만들 수 있고, 기준선 확정은 실제 조합 윤곽의 시각 검토가 필요하다.

첫닿 영역의 상·하·좌·우 잉크 극값과 평평한 구조면도 분리한다. ㅇ처럼 곡선인 첫닿은 영역 경계가 있어도 축 평행 구조면은 없을 수 있다. 선택 영역 색면은 네 잉크 경계 후보가 모두 있을 때만 파생한다.
