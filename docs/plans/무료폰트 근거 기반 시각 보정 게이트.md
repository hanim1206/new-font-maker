- [ ] 입력한 한글을 10개 조합 레이아웃으로 자동 분류한다.
- [ ] 글자마다 폭, 좌우 여백, 잉크의 위·아래·왼쪽·오른쪽 끝을 자동 계산한다.
- [ ] baseline 아래로 내려간 잉크가 있으면 초과 방향과 거리를 그대로 표시한다.
- [ ] `가·고·각·곡`의 실제 윤곽 위에 baseline과 잉크 윗끝·밑끝을 겹쳐 보여준다.
- [ ] 수치를 얻지 못한 경우 `0`으로 속이지 않고 이유와 함께 `측정 불가`로 표시한다.
- [ ] 같은 입력과 같은 폰트 파일에서는 언제나 같은 결과가 나오는지 자동 검사한다.

R1에서 사용자가 확인할 것은 하나다. **표시된 선과 숫자가 실제 윤곽의 위·아래 관계를 제대로 재는가.** 아직 평균값이나 프리셋 후보를 고르지 않는다.

### 그다음 확인 단위 · R2 레이아웃 비교

- [ ] 세로중성은 좌우 방향, 가로중성은 상하 방향에서 자소 사이의 빈 통로 후보를 찾는다.
- [ ] 받침 글자는 윗몸과 받침 사이의 빈 통로, 받침 밑끝과 baseline 사이 거리를 찾는다.
- [ ] 자소가 붙었거나 경계가 여러 개면 신뢰도가 낮다고 표시하고 자동 집계에서 뺀다.
- [ ] 글자별 결과를 레이아웃별 중앙값과 범위로 묶어 실제 대표 글자와 함께 보여준다.
- [ ] Noto Sans KR·IBM Plex Sans KR·Nanum Gothic·Dotum은 중립 비교군으로 묶는다.
- [ ] Gowun Dodum·Black Han Sans는 중립 평균에 섞지 않고 별도 스타일 참고값으로 보여준다.

R2에서 사용자가 확인할 것은 **자동으로 잡은 자소 사이 경계가 눈으로 본 구조와 맞는가**다. 통과한 측정만 이후 다섯 선과 우리 프리셋 후보의 근거로 사용한다.

### 기록 규칙

- 완료한 기능은 이 체크에서 먼저 `[x]`로 바꾼다.
- 진행 중 기능은 어느 화면에서 무엇을 확인하면 되는지 함께 적는다.
- 내부 함수명보다 사용자가 화면에서 보게 되는 결과를 먼저 적는다.
- 영어 기술어가 필요하면 쉬운 한국어 설명 뒤 괄호로 붙인다.
- 측정 완료, 후보 승인, 프리셋 반영을 서로 다른 단계로 기록한다.

기존 코드의 배치값은 동작을 재현하는 기술 기준일 뿐, 새 서체의 시각 기본값으로 바로 채택하지 않는다.

간격·배치·두께를 보정할 때는 질문을 하나로 좁히고 대상 자모와 문맥, 고정 변수, 판단 제외 범위를 먼저 정한다. 보유한 무료폰트의 실제 윤곽을 같은 좌표로 추출해 출처·라이선스·파일 해시와 측정 한계를 남긴다. 중립 기준 서체와 스타일 경계 서체는 수치 집계에서 구분한다.

사용자 확인물은 실제 reference 글자, 현재값, 복수 후보, 후보 도출 근거, 남은 미결정, 마지막 판정 질문 하나를 함께 보여준다. 사용자가 고른 단위만 fixture와 후속 구현 입력으로 승격하며, 승인 전에는 production 값이나 전체 자모 규칙에 반영하지 않는다.

첫 검증 단위는 `가`의 초성–중성 X 간격이다. 무료폰트 6종의 10개 무받침 세로모음 문맥과 우리 Shape `가`의 Current/A/B/C를 비교했다.

## 폰트 레퍼런스 랩

일회성 HTML 생성은 글자를 직접 입력해 여러 무료폰트와 우리 프리셋을 같은 원점·UPM으로 비교하는 내부 도구로 발전시킨다. 새 폰트는 등록부에 파일 해시·인스턴스·출처·라이선스를 추가하면 화면 코드를 고치지 않고 나타나야 한다.

확대 캔버스에서 사용자가 사각 영역을 드래그하면 그 사각형은 `gap` 자체가 아니라 분석 범위가 된다. P0는 범위 안의 벡터 잉크를 X축 또는 Y축에 투영해 완전히 빈 띠를 측정한다. 윤곽이 겹치거나 두 잉크 경계를 찾지 못하면 0으로 기록하지 않고 측정 불가로 남긴다. 광학 최단거리와 자동 자소 분리는 별도 후속 기능이다.

화면은 하나지만 원본은 다음처럼 분리한다.

- 폰트 코퍼스 등록부: 파일·인스턴스·출처·라이선스·해시
- 글리프 캐시: 재생성 가능한 윤곽·advance·bounds
- 분석 세션: 질문·글자·폰트 역할·드래그 영역·측정법·결과
- 프리셋 결정 사전: 후보·적용 문맥·근거·승인 상태
- 제품 binding: 승인된 결정을 실제 프리셋에 적용하는 별도 단계

사용자와 Codex는 같은 세션 URL과 versioned JSON을 본다. Codex는 큰 SVG 전체 대신 작은 분석 세션과 결정 JSON만 읽고 후보를 제안한다. AI가 관찰과 후보 초안을 만들 수는 있지만 사용자 승인과 production 적용은 분리한다.

권장 구현은 React 비교 화면과 로컬 Python FontTools 엔진의 조합이다. 가변 폰트 인스턴스와 정확한 윤곽 추출은 FontTools를 기준으로 하고, 쓰기 가능한 로컬 서비스는 `127.0.0.1` 전용으로 제품 스토어·마이그레이션과 격리한다. 현재 S0b HTML과 manifest는 첫 legacy evidence로 보존한다.

첫 구현 단위는 `글자 입력 → 현재 등록된 6종 원본 윤곽 비교`다. 다음 단위에서 한 셀 확대와 ROI 측정을 붙이고, 그 뒤에 세션 JSON 저장·재열기와 프리셋 사전 후보 생성을 연결한다.

### R0 구현 기록 · 2026-08-28

`/reference-lab`에 첫 단위를 구현했다. 글자를 최대 12자까지 입력하면 로컬 FontTools 엔진이 등록된 폰트의 실제 SVG 윤곽을 뽑아 공통 UPM 1000·baseline 880에 표시한다. 각 폰트의 원점·advance·잉크 크기는 유지하고 Design Body 75…925는 보조선으로만 보여준다.

현재 6종은 기존 `vertical-vowel-gap` 근거의 파일·인스턴스·출처·라이선스·해시를 그대로 이어받는다. 폰트 등록부는 항목 수를 코드에 고정하지 않으므로, 검증 가능한 새 항목과 로컬 파일을 추가하면 화면 코드 변경 없이 행이 늘어난다. 파일 누락이나 해시 불일치는 대체 폰트로 숨기지 않고 오류로 막는다.

R0는 메모리 캐시만 쓰며 localStorage·프로젝트·프리셋·production 값을 수정하지 않는다. 측정, 후보 생성, 세션 저장, 프리셋 적용은 아직 없다. 실제 6종의 `가` 윤곽 해시가 기존 frozen evidence와 모두 일치했고, 데스크톱·390px 비교와 무저장을 자동 검증했다.

## 측정 인터랙션

일상적인 비교는 미리 정의한 측정 레시피와 영역을 글자 위에 표시하고, 사용자가 그 영역을 눌러 값과 경계를 확인하는 방식이 기본이다. 같은 관계를 매번 새로 드래그하면 결과가 달라지고 근거를 다시 설명해야 하므로 자유 드래그를 기본 조작으로 삼지 않는다.

드래그는 새 측정 레시피를 만들거나 특정 폰트·글자에서 기존 영역이 맞지 않을 때만 여는 `영역 수정` 모드로 둔다. 수정본은 기존 레시피를 덮지 않고 candidate revision이나 font-specific override로 저장한다.

무료폰트에서는 자소 슬롯과 padding 원본을 알 수 없으므로 `padding`이라는 이름을 직접 붙이지 않는다. 대신 advance 경계에서 잉크까지의 side bearing, EM 위·아래 여유, 두 잉크 군집 사이 gap처럼 실제 윤곽에서 관측 가능한 metric을 표시한다. 우리 프리셋은 source padding과 같은 화면에서 비교할 수 있지만 `설계값`과 `관측된 잉크 거리`를 분리해서 보여준다.

## 윤곽 자동화와 토큰 절약

사용자가 입력한 글자는 모델이 SVG를 작성하지 않는다. 로컬 FontTools 엔진이 NFC 글자를 폰트의 cmap glyph로 찾고, 가변축 인스턴스를 고정한 뒤 윤곽·advance·bounds를 추출한다. 결과는 `font file hash + axes + codepoint + extractor version`을 키로 한 글리프 캐시에 저장하고 React 화면은 캐시의 path만 SVG로 그린다.

분석 세션과 Codex용 digest에는 SVG path를 복사하지 않는다. `sampleId/path hash`, 측정 레시피, 결과값, 유효성, 집계, 후보와 질문만 기록한다. 새 글자나 새 폰트에서 캐시가 없을 때만 윤곽을 추출하며 11,172자를 미리 생성하지 않는다. 같은 엔진을 화면과 CLI가 공유하면 Codex는 작은 digest JSON만 읽고 같은 세션 URL을 사용자와 함께 확인할 수 있다.

도구의 기본 실행은 AI와 네트워크를 전혀 호출하지 않는 완전 로컬 모드다. 글자 입력, SVG 윤곽 생성, 측정, 통계, 세션 저장·재열기, 프리셋 사전 후보와 사용자 승인까지 로컬 코드와 JSON만으로 처리한다. Codex 연결은 사용자가 해석이나 구현을 요청할 때만 compact digest를 읽는 선택 기능으로 둔다.

권장 실행 단위는 `npm run reference:lab` 하나다. 이 명령이 `127.0.0.1` 전용 FontTools 서비스와 빌드된 React 화면을 함께 열고, 폰트와 세션은 로컬 폴더에 저장한다. 최초 의존성 준비 뒤에는 인터넷 연결 없이 동작해야 한다.

## 무료폰트 집계 기반 자동 후보

무료폰트 측정값으로 프리셋 후보를 로컬에서 자동 생성하는 것은 토큰을 크게 줄일 수 있다. 다만 `전체 평균 = 정답`으로 승격시키지 않고, 측정 레시피와 스타일 목표가 명확한 연속형 수치의 초기 후보로만 쓴다.

현재 `가`의 전폭 X 빈 띠는 중립 4종 평균이 약 188 unit, 중앙값이 약 192 unit이다. Gowun Dodum과 Black Han Sans까지 동일 비중으로 섞으면 전체 평균은 약 160 unit으로 내려간다. Black Han Sans의 85 unit은 오류가 아니라 고밀도 디스플레이 스타일이므로, 중립 모집단의 한 표로 섞지 않고 명시적 `스타일 target`으로 다룬다.

자동 집계는 같은 문맥과 목적의 폰트만 고른 뒤 `폰트별 문자 중앙값 → 폰트 간 중앙값`으로 구한다. 평균·중앙값 차이, IQR, 유효 표본 수, 폰트 하나를 뺀을 때의 변화를 함께 계산한다. 굵기가 많이 다른 폰트의 gap은 raw em 값 대신 `gap / 대표 획 굵기`처럼 비교 가능한 관계를 우리 Shape에 투영한다.

화면의 기본 후보는 네 장으로 제한한다.

- `Current`: 현재 프리셋
- `Neutral`: 중립 기준군 중앙값
- `Style`: 사용자가 명시하게 고른 스타일 target의 정규화된 관계
- `Hybrid`: Current와 Style 사이의 명시적 보간 후보

간격·ink bounds·side bearing처럼 완성 윤곽에서 반복 측정할 수 있는 값은 자동 후보로 만든다. 5선, 자소 분리, 굵기·곡률·각도는 별도 주석과 정규화가 있을 때만 반자동 후보로 다룬다. 면·선 구성 문법, topology, 광학 예외와 스타일 목표는 평균으로 정하지 않는다.

자동화의 상한은 `추천 후보 생성`이다. 스타일 target, 정규화 방식, 적용 문맥을 명시하고 최소 간격·충돌 등 우리의 hard constraint를 통과한 후보만 보여준다. 사용자 승인과 production 적용은 계속 분리한다. 매번 Codex에게 평균을 계산시키지 않고 이 규칙을 로컬 엔진으로 고정하면, 일상적인 후보 생성과 승인은 AI 토큰 없이 반복할 수 있다.

## 현재 비교 보드를 세션 템플릿으로 사용

`vertical-vowel-gap.html`은 일회성 숫자를 일반 기본값으로 쓰지 않고, 동적 폰트 레퍼런스 랩의 첫 frozen session과 회귀 fixture로 보존한다. 다음 시각 계약은 그대로 유지한다.

- UPM 1000 공통 Font Space, 공통 baseline과 고정 viewBox
- 폰트별 원래 원점·advance·ink 크기 유지
- 개별 ink-fit·가운데 정렬·autofit 금지
- 실제 문자 윤곽, 폰트 인스턴스·해시·출처 표시
- 한 번에 판정 하나, 고정·변경·제외 변수와 `production 0%` 표시
- reference 원본과 동일한 Shape에서 허용한 변수 하나만 바꾼 우리 후보를 나란히 표시

동적 화면은 현재 보드의 구조를 `세션 계약 → active reference 1 → 통제 후보 → 판정 → 접힌 지원 근거`로 재배치한다. 최종 질문과 이번 승인·미승인 범위는 첫 화면에서 바로 보여준다. 10문맥×6종 윤곽, 측정표, provenance는 `이번 승인 아님`이라고 표시한 접힌 패널로 내린다.

현재 보드의 Noto 원본은 후보가 아니라 관측 기준이다. `같은 조건`은 무료폰트 원본과 우리 글자의 획 굵기·크기까지 강제로 같게 만든다는 뜻이 아니다. reference는 원래 설계를 유지하고, 우리 후보 끼리만 같은 Shape·굵기·문맥·고정 좌표를 공유한 채 active variable 하나를 바꾼다.

현재 Current/A/B/C는 `Current + 중립 기준 P25/중앙값/P75`이므로 의미를 바꾸지 않고 그대로 legacy session에서 가져온다. Black Han Sans를 style anchor로 고른 `Style`과 `Hybrid`는 새 session revision에서만 생성한다. 비교 조건·폰트 역할·측정 영역이 바뀌면 기존 후보를 조용히 재사용하지 않고 `stale`로 표시한 뒤 세션 revision을 올린다.

## 5선·획 근거에서 프리셋 출력까지

원도의 `밑선`은 typography baseline이다. 현 출력 좌표에서 baseline은 `fontY=0`, 화면 Y-down 좌표로는 880이다. 이 값은 무료폰트 평균으로 추정하지 않고 모든 관측과 출력이 공유하는 고정 anchor로 삼는다.

다섯 선은 `상단 기준선 · 배치윗선 · 중심선 · 배치밑선 · baseline`으로 다룬다. Canonical Design Body 아래 경계는 필요하면 여섯 번째 보조선으로 표시할 수 있지만 5선 role에 포함하지 않는다. 무료폰트에서는 baseline 자체가 아니라 baseline에 대한 잉크 상·하단, 받침과 무받침의 거리, overshoot 분포를 측정한다.

완성 폰트 윤곽에는 원래 자모의 필순·획 중심선·면 점유·Rail 구조가 남아 있지 않다. 따라서 자모 획 정보는 가로·세로 대표 굵기, 각도, 곡률, 내부 공간, 끝처리, 대칭과 같은 `최종 잉크 관측값`으로 저장한다. 이 관측값을 우리의 선·면·형태 그리드 문법에 제한적으로 맞춘 후보를 만들지, 무료폰트의 중심선이나 생성 구조를 복원했다고 간주하지 않는다.

전체 흐름은 다음으로 단계화한다.

```text
무료폰트 윤곽·baseline 관측
→ 5선 landmark·획 probe 의미 확인
→ 스타일군별 중앙값·분포 시각화
→ 우리 renderer에서 제한 변수 후보 생성
→ Current / Neutral / Style / Hybrid 실제 글자 비교
→ 사용자 승인과 versioned preset diff
→ 대표 글자 prototype OTF
→ 전체 Shape master·문맥 커버리 완료 후 11,172자 OTF
```

첫 출력은 프리셋 후보 JSON과 대표 글자 prototype OTF다. 현재 Shape 출력은 단일 `FinalGlyphInk` prototype 경로만 있으므로, 도구가 완성된다고 바로 전체 11,172자 Shape 폰트가 생성되는 것은 아니다. 67개 역할 master, 문맥 선택·fallback, 전체 glyph collector와 출력 검증을 별도 gate로 통과해야 한다.

## 자동 추출 속성의 귀속

자동 측정값을 `폰트 전체`와 `레이아웃` 두 종류로만 나누지 않는다. 같은 자소가 초성·종성에서 달라지고 같은 레이아웃 안에서도 중성과 받침에 따라 보정되므로 다음 다섯 귀속을 사용한다.

- `global`: UPM, baseline, advance 경향, 전체 잉크 점유율, 대표 가로·세로 굵기
- `layout`: 10개 조합별 외곽, X·Y 분할 후보, 자소 사이 빈 공간, 상하·좌우 점유 비율
- `jamo-role`: `ㄱ@CH`, `ㄱ@JO`처럼 역할별 크기·비율·위치
- `context`: 세로·가로·혼합중성, 받침 유무, 열린·닫힌 자소에 따른 차이
- `glyph-exception`: 위 규칙으로 설명되지 않는 정확한 음절 보정

모든 값에는 출처 성격도 함께 표시한다.

- `direct`: 폰트 테이블이나 윤곽에서 그대로 읽는 값. UPM, baseline, advance, side bearing, ink bounds, coverage가 해당한다.
- `derived`: 고정 알고리즘으로 계산한 값. 잉크 면적·중심·밀도, projection, 빈 띠, 대표 획 굵기, overshoot가 해당한다.
- `hypothesis`: 자소 경계와 의미를 추론한 값. 첫닿윗선·중심선·받침밑선, 조합 속 자소 envelope가 해당한다. 사용자 검수 없이 프리셋 후보로 승격하지 않는다.

완성 윤곽에서는 원래 padding, slot, 자소 중심선, 필순, Rail, 선·면 생성법을 복원할 수 없다. 호환 자모의 단독 glyph도 조합 속 같은 자소와 다른 디자인일 수 있으므로 조합 레이아웃 근거로 자동 재사용하지 않는다.

## 다음 자동 측정 범위

첫 개발은 의미 추론보다 재현 가능한 직접값과 계산값을 먼저 닫는다.

1. 입력 글자를 Unicode 분해로 10개 레이아웃에 자동 분류한다.
2. 폰트 테이블의 UPM, 상하 메트릭, 축, coverage와 글리프의 advance, side bearing, ink bounds를 추출한다.
3. baseline 대비 잉크 top·bottom·overshoot, 좌우 여백, 폭·높이·중심·점유율을 실제 윤곽 위에 표시한다.
4. 레이아웃별 행·열 투영에서 지속적인 빈 통로를 찾아 X·Y separator 후보와 신뢰도를 표시한다. 붙은 자소나 후보 동률은 0으로 만들지 않고 `측정 불가`로 제외한다.
5. 검수된 값만 폰트별 중앙값·IQR로 요약하고, 다시 중립 폰트 사이 중앙값을 낸다. 레이아웃별 표본 수가 전체값을 왜곡하지 않게 각 레이아웃을 동일 가중한다.

P0의 균형 표본은 `ㄱ·ㅁ·ㅇ × ㅏ·ㅗ·ㅘ × 무받침·ㄴ받침`으로 시작한다. 첫 화면은 `가·고·각·곡`에 baseline과 전체 잉크 top·bottom만 표시하며, 사용자는 측정선이 윤곽과 부호를 올바르게 잡는지만 판정한다. 그 다음 separator, 5선 후보 band, 중립 4종 중앙값·IQR 순서로 연다. 획 굵기·곡률·각도·면 문법은 이 골격 측정이 통과한 뒤 다룬다.

11,172자를 계산에 사용할 수는 있지만 한꺼번에 평균내지 않는다. `글자 측정 → 자소·문맥 요약 → 레이아웃 요약 → 레이아웃 동일 가중 전역 요약` 순서를 지킨다. Black Han Sans와 Gowun Dodum은 중립 집계에 섞지 않고 별도 스타일 범위로 표시한다.

## R0 좌표 계약 보완 · 2026-09-07

Reference Lab의 Design Body `75…925`를 넘는 무료폰트 윤곽은 오류가 아니다. 이 선은 우리 프로젝트의 Canonical Design Body를 읽기 쉽게 겹쳐 둔 보조선일 뿐, 외부 폰트의 설계 body나 clipping·적합 판정선이 아니다. 원본 비교에서 그 밖의 overshoot와 여백은 숨기지 않는다.

폰트를 비교할 때는 아래 두 부류를 섞지 않는다.

- **공통으로 고정할 값**: 비교 UPM과 변환식, 화면 x 원점, 공통 baseline, 고정 viewBox, 비교할 글자·문맥·폰트 인스턴스, 원본 윤곽 확대·중앙 정렬·autofit 금지, 측정 영역과 이번에 판단할 변수 하나.
- **폰트·글리프마다 보존할 값**: 원본 UPM과 변환 비율, advance, left/right side bearing, ink bounds, baseline 대비 top·bottom·overshoot, 실제 윤곽, ascender·descender·line gap, 가변축 인스턴스와 파일 버전·해시.

Baseline은 글자별 바닥선이 아니라 한 줄이 공유하는 anchor다. 각 원본 폰트의 `y=0`을 공통 비교 baseline으로 투영한다. 폰트별 차이는 baseline 자체가 아니라 baseline 위·아래 metric, 실제 잉크 위치와 line metric에 남긴다.

따라서 화면은 두 보기로 구분한다. `원본 좌표 비교`는 공통 UPM·원점·baseline에서 윤곽·advance·side bearing·overshoot를 그대로 본다. `우리 글자 투영 비교`는 같은 원본 보기와 나란히 우리 Canonical Design Body와 5선 후보를 겹쳐, 우리 설계값을 판단한다. 후자의 Design Body 밖 윤곽도 자동 실패로 처리하지 않으며, target style과 명시한 허용 범위를 가진 별도 판단에서만 다룬다.
