# 스타일 공통화

- **이번에 비교하는 것**: 리팩터 전후의 같은 화면. 색과 배치는 같아야 하고, 글자 크기 · 모서리 · 굵기는 가까운 단계로 모여 1~2px 안에서만 달라진다(스크린샷 전후 나란히).
- **이번 승인으로 바뀌는 것**: 스타일이 나오는 곳. 화면마다 따로 쓴 CSS → 토큰 한 파일 + 공용 부품(Tailwind + shadcn). 실험실에 `스타일가이드` 화면이 생긴다. CLAUDE.md의 `스타일은 CSS Modules` 한 줄.
- **바뀌지 않는 것**: 지금 색과 화면 배치, 실험실 13개의 CSS, 캔버스(SVG) 안 동작과 이벤트 순서, Tailwind 3.4(4로 안 올린다), 죽은 `src/components/`.

## 왜

디자인은 아직 안 끝났다. 지금 필요한 건 새 디자인이 아니라, 디자인이 정해졌을 때 **한 곳만 고치면 앱 전체가 바뀌는 손잡이**다. 지금은 토큰이 있어도(`src/index.css`) 제품 화면이 그걸 일부만 쓰고, 부품은 화면마다 따로 만들었다.

지금 상태(제품 화면만, 실험실 · 관리자 제외):

- CSS Modules 30개 · 142KB. 토큰을 안 거친 색이 CSS에 52가지(투명도 차이 빼고), TSX에 16가지.
- 글자 크기 27가지 · 모서리 25가지 · 글자 굵기 6가지(650 · 750 포함). 단계가 없다.
- 날 `<button>` 112개(문장 편집기 35개), 날 `<input>` 21개(그중 막대 12개). shadcn 부품은 관리자 화면에서만 쓴다.
- Tailwind는 `src-next/admin`과 `components/ui`만 훑는다. 제품 화면에서는 Tailwind 클래스가 안 먹는다.
- 테마 전환 장치(다크 등)는 없다.

## 방향(사용자 확정 10-03)

1. 범위는 제품 화면만. 실험실은 그대로 둔다.
2. 공용 부품은 최대한 shadcn으로. 화면 고유 배치는 CSS Modules에 남기되 색 · 간격 · 모서리 · 그림자는 토큰만 쓴다.
3. 컬러 베리에이션 = 테마 통째 교체(주색 바꾸기, 다크 포함).

## 단계

1. **기반** — 토큰을 세 층으로 나눈다: 원색 팔레트 → 의미 색(바탕 · 글자 · 테두리 · 주색 · 위험) → 편집 색(선택 주황 · 영역 색 · 보선 · 고스트). 화면은 의미 색과 편집 색만 쓴다. Tailwind가 `src-next` 전체를 훑게 한다. 테마는 `data-theme`으로 의미 색만 갈아 끼운다.
2. **스타일가이드 화면** — 실험실 `/admin/labs/style-guide`. 색 판 · 글자 크기 · 간격 · 모서리 · 그림자, 그리고 부품 × 변형 표. 실제 부품을 그린다(그림이 아니다). 테마 스위치가 있다.
3. **부품 통일** — 많이 쓰는 순서로 하나씩: 버튼 → 시트 · 대화상자 → 탭 · 묶음 단추 → 카드 → 칩 · 토글 → 막대 → 입력 → 토스트 · 알림. 부품마다 `지금 생김새 조사 → 변형 축 정하기(강조 · 크기 · 상태) → 화면별 교체 → 스크린샷 비교`.
4. **색 정리** — 제품 CSS · TSX의 날 색 68가지를 의미 색이나 편집 색으로 옮긴다.
5. **테마** — 다크와 주색 교체를 스타일가이드에서 켜 보고, 깨지는 화면을 고친다.
6. **가드** — 제품 CSS의 날 색과 제품 화면의 날 `<button>`을 막는 검사 하나. CLAUDE.md · AGENTS.md 컨벤션을 고친다.

화면 순서는 한가한 곳부터: 계정 · 로그인 · 추출 완료 → 셸(헤더 · 토스트 · 알림) → 글로벌 스타일 → 레이아웃 편집 → 문장 편집기(마지막, 다른 세션이 계속 고치는 파일).

## D0 계약 (승인 10-03)

- **한 변수**: 스타일의 출처. 생김새는 변수가 아니다 — 색 · 배치가 달라지거나 크기가 단계 모으기(1~2px)보다 크게 달라지면 실패다.
- **캔버스는 색만**: SVG 안 손잡이 · 보선 · 띠는 부품 통일 대상이 아니다. 색만 편집 색 토큰으로 옮긴다.
- **부품이 안 맞으면**: shadcn 부품에 변형을 더한다. 화면에서 `className`으로 덮어 생김새를 바꾸지 않는다(배치용 여백 · 너비만 허용).
- **토큰 이름**: shadcn 표준 이름을 지금 이름 옆에 같이 둔다. shadcn 부품을 받아 온 그대로 쓴다.
- **값 바꾸는 법**: 스타일가이드 화면 안 손잡이로 미리 보고(이 브라우저에만 저장), 정해지면 토큰 파일에 굳힌다. 굳히는 건 `구현` 요청으로 한다.
- **크기 단계**: 글자 크기 · 모서리 · 굵기를 가까운 단계로 모은다. 1~2px 달라지는 곳은 G0에서 전후를 나란히 보여 준다.

이름표:

| 층 | 이름 |
|---|---|
| 의미 색(shadcn 이름) | `background` `foreground` `card` `popover` `primary` `secondary` `muted` `accent` `destructive` `border` `input` `ring` + 각각의 `-foreground` |
| 의미 색(우리 것) | `surface-2~4` `text-dim-1~6` `success` `warning` `info`(주색과 따로) + 각각의 `-soft`, `destructive-dark` |
| 편집 색 | `edit-select`(선택 주황) `edit-rail`(보선 · 띠) `edit-slot-ch/ju/jo`(영역) `edit-ghost` `edit-guide` |
| 단계 | 글자 10 · 11 · 12 · 13 · 14 · 16 · 18 · 20 · 머리글 24 · 28 / 모서리 4 · 6 · 10 · 14 · 18 · 둥근 끝 / 굵기 500 · 600 · 700 · 800 |

부품과 변형 축: 버튼(강조 5 · 크기 4, 지금 shadcn 것 그대로) · 시트 · 대화상자 · 탭 · 묶음 단추 · 카드 · 칩 · 토글 · 막대 · 입력 · 토스트. 부품별 변형은 3단계에서 조사한 뒤 그 부품을 시작할 때 확인받는다.
