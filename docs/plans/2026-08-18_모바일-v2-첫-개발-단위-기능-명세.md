# 모바일 v2 첫 개발 단위 기능 명세

관련 문서: [2026-08-18_모바일-우선-2차-개발-방향](./2026-08-18_모바일-우선-2차-개발-방향.md), [2026-08-18_모바일-통합-편집-v3-디자인-핸드오프](./2026-08-18_모바일-통합-편집-v3-디자인-핸드오프.md), [2026-08-17_모바일-트랙패드-편집](./2026-08-17_모바일-트랙패드-편집.md), `옵시디언 2026-08-17_자동-저장과-편집-히스토리`

## 해결할 문제

기존 편집기는 화면에서 획을 직접 드래그하는 PC 중심 구조다. 모바일 v2의 핵심 가설인 `화면에서 선택 → 하단 트랙패드에서 조작`이 실제 자모 데이터, 렌더링, 자동 저장, 복원까지 이어지는지는 아직 검증되지 않았다.

첫 개발 단위는 많은 화면을 만드는 대신 다음 한 흐름을 끝까지 연결한다.

`곰 열기 → 초성 ㄱ 선택 → 획 선택 → 트랙패드 이동 → 손 떼기 → 한 건 저장 → 히스토리 비교·복원`

## 목표

- 손가락이 글자를 가리지 않은 채 선택한 획을 이동할 수 있다.
- 조작 중에는 결과가 즉시 보이고, 손을 뗄 때만 확정된다.
- 한 번의 연속 조작이 정확히 히스토리 한 건으로 남는다.
- 새로고침 뒤에도 확정된 위치가 유지된다.
- 과거 상태를 비교하고 비파괴적으로 복원할 수 있다.

## 이번 범위에서 제외

- 자소 캐러셀과 길게 누르는 빠른 탐색
- 조절점과 베지어 핸들 편집
- 레이아웃 분할선·패딩 편집
- 획 스타일과 납작 붓촉
- 계보 인스펙터
- 어니언 스킨
- PC 화면 개편

## 화면 흐름

1. `/editor-v2`에서 `곰` 편집 화면을 연다.
2. 중앙 글자에서 초성 `ㄱ`을 탭한다.
3. `ㄱ`의 획을 탭하면 선택 표시와 대상 이름이 나타난다.
4. 하단 트랙패드가 활성화된다.
5. 트랙패드를 움직이는 동안 선택한 획만 실시간으로 이동한다.
6. 손을 떼면 변경 한 건을 자동 저장한다.
7. 우측 상단 히스토리에서 변경 전·현재를 확인한다.
8. 과거 상태를 복원하면 복원 자체가 새 기록으로 추가된다.

## 필수 상태

- 편집 화면: `자소 편집`
- 현재 음절: `곰`
- 선택: 없음, 파트, 획 가운데 하나
- 트랙패드: 비활성, 조작 중, 저장 중, 저장 완료, 실패
- 임시 편집: 조작 시작 데이터와 현재 이동량
- 전체 화면: 없음, 히스토리 목록, 과거·현재 비교

여러 불리언을 조합하지 않고 서로 배타적인 상태로 정의한다. 선택이 없으면 트랙패드는 데이터를 바꾸지 않는다.

## 편집 명령

첫 명령은 `획 이동` 하나만 제공한다.

- 대상: 자모 종류, 자모 문자, 획 ID
- 문맥: 현재 음절과 레이아웃 유형
- 범위: 현재 편집 단계
- 변경: 모든 앵커 포인트에 적용할 정규화된 x·y 이동량
- 기록: 변경 전·후 좌표와 타임스탬프

획 전체가 자모 박스 밖으로 빠져나가지 않도록 이동량을 획 단위로 제한한다. 각 점을 따로 잘라 형태가 찌그러지게 하지 않는다.

## 저장 규칙

- 조작 중에는 확정 자모 스토어를 변경하지 않는다.
- 임시 좌표를 SVG 렌더러에 넘겨 미리보기만 갱신한다.
- 손을 뗐을 때 값이 달라진 경우에만 확정 자모 데이터와 행동 기록을 함께 갱신한다.
- 이동량이 0이면 저장하지 않는다.
- `pointer cancel`, 앱 전환, 터치 중단은 조작 시작 상태로 복귀한다.
- 저장에 실패하면 마지막 확정 상태로 돌아가고 실패 기록은 남기지 않는다.
- 복원은 과거 값을 새 편집 명령으로 적용하며 기존 기록을 삭제하지 않는다.

## 파일과 책임

- `src/features/mobile-editor/MobileEditorV2Page.tsx`: 독립 진입 화면
- `src/features/mobile-editor/components/GlyphSelectionCanvas.tsx`: 파트·획 선택과 실제 SVG 미리보기
- `src/features/mobile-editor/components/TrackpadDrawer.tsx`: 상대 이동 입력과 상태 표시
- `src/features/mobile-editor/components/EditorHistoryPage.tsx`: 목록, 비교, 복원
- `src/stores/mobileEditorStore.ts`: 선택, 화면 모드, 임시 편집 상태
- `src/stores/editorHistoryStore.ts`: 행동 단위 기록과 비파괴 복원
- `src/services/editorCommands.ts`: 획 이동 검증과 확정
- `src/utils/appRoutes.ts`: v2 경로 추가

공유 타입은 기존 `src/types/index.ts`에 추가한다. 기존 `MobileLayout`과 `historyStore`는 수정 범위를 최소화하고 v2에서 직접 사용하지 않는다.

## 검증

- 단위 테스트: 이동량 제한, 0 이동 무시, 명령 전·후 좌표, 복원 명령
- 모바일 브라우저 자동화: 선택 전 트랙패드 비활성, 드래그 중 미리보기, release 한 건 저장, cancel 복귀, 새로고침 유지
- 실제 기기: iOS Safari와 Android Chrome에서 한 손가락 조작, 스크롤 충돌, 화면 가림 확인

## 인수 조건

- [ ] `곰`에서 초성 `ㄱ`과 그 획을 탭해 선택할 수 있다.
- [ ] 선택되지 않은 자소와 획은 이동하지 않는다.
- [ ] 트랙패드 이동이 정규화 좌표로 실시간 미리보기에 반영된다.
- [ ] 손을 떼기 전에는 영속 데이터와 히스토리가 바뀌지 않는다.
- [ ] 손을 떼면 실제 변경이 있을 때만 히스토리 한 건이 추가된다.
- [ ] 연속 20회 조작에서 기록 수가 실제 조작 수와 일치한다.
- [ ] 터치 취소 뒤 좌표와 기록 수가 조작 전과 같다.
- [ ] 새로고침 뒤 마지막 확정 위치가 유지된다.
- [ ] 과거 복원 뒤에도 복원 전 기록을 다시 확인할 수 있다.
- [ ] 테스트 기기에서 포인터 입력부터 미리보기까지의 p95 지연이 50ms 이하다.

## 구현 중 결정할 사항

- `@use-gesture/react`가 pointer cancel과 브라우저 스크롤 충돌을 충분히 제어하는지 작은 실험으로 확인한다.
- 행동 기록을 패치로 저장할지 명령의 전·후 값으로 저장할지 첫 명령 구현 뒤 비교한다.
- v2 행동 기록의 영속 저장소는 현재 프로젝트 저장 방식과 연결하되, 전체 상태 스냅샷은 사용하지 않는다.

## 구현 결과

첫 개발 단위의 획 선택, 트랙패드 이동, 실시간 미리보기, 손을 뗄 때 한 건 저장, 히스토리 비교·복원 흐름을 구현했다. 이후 같은 구조를 자소 전체, 꼭짓점, 곡선 손잡이와 획 비율 조절까지 확장했다.

초기 제외 범위였던 자소 캐러셀과 레이아웃 편집도 후속 개발에서 연결했다. 하단 초성·중성·종성 선택기는 캐러셀 기준만 바꾸고, 중앙 글자의 자소를 누르면 기본형 상세 편집으로 들어간다. 현재 글자 보정 트랙패드는 메인 화면 최하단 편집 버튼으로 분리했다.

상세 편집에는 트랙패드 왼쪽 도구 레일을 추가했다. 현재 선택에서 실행 가능한 새 획 추가, 곡선화·직선화, 선 연결·끊기, 삭제만 표시한다. 방향 잠금은 사용자가 해제할 때까지 유지하며 다른 꼭짓점을 선택해도 풀리지 않는다.

구현 파일은 초기 예상처럼 여러 화면 컴포넌트로 바로 분리하지 않고 `MobileEditorV2Page.tsx`에서 흐름을 먼저 완성했다. 입력 수명주기는 `useUnifiedTrackpad.ts`, 좌표 변경과 범위별 편집은 `editorCommands.ts`와 각 서비스로 분리했다. 단위 테스트, 모바일 브라우저 자동화와 프로덕션 빌드로 주요 흐름을 검증했다. 실제 iOS Safari와 Android Chrome에서의 장시간 조작감과 입력 지연 측정은 남아 있다.
