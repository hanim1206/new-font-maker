# 제품 철학

이 문서는 한글 폰트 메이커의 장기적인 제품 방향과 판단 기준을 프로젝트에 남기는 메모리다. 대화에서 나온 아이디어나 결정이 숨은 맥락에만 머물지 않도록 계속 갱신한다.

## 지향점

한글 폰트 메이커는 결과 폰트의 형태만 조절하는 도구에 머물지 않는다. 붓, 압력, 도구의 성격을 벡터 획 스타일로 번역하여 사용자가 글자를 만드는 행위와 재료의 느낌까지 설계할 수 있게 하는 도구를 지향한다.

## 제품 판단 원칙

사용자가 제안한 아이디어에 무조건 동의하거나 곧바로 확정안으로 취급하지 않는다. 다음 관점에서 비판적으로 검토하고, 판단 근거와 남은 불확실성을 함께 기록한다.

- 프로젝트 철학과 핵심 사용 흐름에 맞는가
- 사용자가 이해하고 다뤄야 할 복잡도를 감당할 수 있는가
- 구현과 유지보수의 기술 비용이 가치에 비례하는가
- 같은 입력에서 결과를 예측할 수 있는가
- 적용한 변경을 쉽게 되돌리거나 비교할 수 있는가
- MVP에 필요한 범위와 후속 단계로 미룰 범위는 무엇인가

## 현재 브러시 모델

아래 항목은 1차 제품 범위에 관해 합의한 결정이다. 구현 가능성이나 출력 품질까지 검증된 사실을 뜻하지는 않는다.

- MVP의 붓촉 모양은 `원형`, `납작형`, `네모형`이다.
- 납작형 붓촉은 모서리가 없는 타원형으로 정의한다. aspect ratio로 납작한 정도를 조절하고, 좌·우 방향을 포함한 각도를 조절한다.
- 네모형 붓촉은 모서리가 살아 있는 직사각형으로 정의한다. 납작형과 같은 aspect ratio와 각도를 사용하며, 대각선을 기존 획 굵기와 같게 두어 원형보다 바깥으로 더 돌출되지 않게 한다.
- MVP의 방향 모드는 `고정 방향`만 제공한다.
- 브러시 스타일은 폰트 전체에 일괄 적용한다.
- 기존 자모 중심 편집 흐름에서는 자소 캐러셀과 하단 드로어를 사용한다. 신규 샘플 문장 기반 역추론형 흐름에는 자모 교체 스와이퍼를 가져오지 않고, 보정 문장과 선택한 완성 글자를 계속 문맥으로 유지한다. 글자 네모꼴과 획 스타일은 하나의 `글로벌 스타일` 진입점 아래에서 하단 조절판 탭으로 전환한다.
- 원형 붓촉에서는 의미가 없는 aspect ratio와 각도 조절을 노출하지 않는다.
- 납작형과 네모형의 각도는 가로축을 `0°`로 삼아 `-90°`부터 `+90°`까지 조절하며 기본값은 `0°`다.
- 납작함과 각도 수치는 조작 중에만 표시하고, 원형으로 전환해도 마지막 비원형 설정은 기억한다.
- 별도의 브러시 크기는 두지 않는다. 전체 획 굵기와 붓촉의 납작한 정도를 서로 다른 역할로 유지한다.
- 사용자는 대표 글자 미리보기와 변경 전·현재 비교를 통해 전체 적용 결과를 확인하고, 저장 이력으로 되돌릴 수 있어야 한다. 조절 중에는 결과를 즉시 미리보되 손을 떼는 시점에 한 번의 변경으로 저장한다.
- 편집 히스토리와 변경 전·현재 비교는 기존 전체 화면 흐름을 유지한다. 압력, 끝맺음, 세리프처럼 조절 항목이 늘어날 때만 별도 전체 화면 편집기를 다시 검토한다.

아래 항목은 후속 가설로 남긴다.

- `획 따라가기`는 급커브와 교차부의 품질을 먼저 기술 실험한 뒤 도입 여부를 판단한다.
- 개별 획 오버라이드는 필요성과 UX 비용을 확인한 뒤 검토한다.
- 압력, 속도, 끝맺음, 세리프는 시간에 따른 입력과 획 방향의 의미를 정의한 뒤 별도 단계에서 다룬다.

## 알려진 위험과 미결정 사항

- 고정각 납작형·네모형은 SVG 기본 `stroke`가 아니라 중심선을 세분화한 뒤 고정된 붓촉 다각형을 각 구간에 sweep하는 공통 윤곽 엔진으로 표현한다. 화면은 이 윤곽을 채우고 OTF는 같은 정규화 윤곽을 폰트 좌표로 투영한 뒤 Boolean union한다. 브라우저 미리보기와 전체 OTF 생성·다운로드까지 검증했으며, 설치한 OTF의 여러 렌더러별 세부 품질 비교는 남아 있다.
- 후속 후보인 `획 따라가기`는 급커브와 획 교차부에서 윤곽이 뒤틀리거나 불안정해질 수 있다.
- 브러시 옵션을 한꺼번에 노출하면 사용자가 결과를 예측하기 어렵고 편집 UI가 복잡해질 수 있다. 단계적 노출, 프리셋, 고급 설정 분리가 필요한지는 검증해야 한다.
- 현재 원형 중심선 모델은 SVG와 OTF가 같은 배치·두께·linecap·linejoin·문맥 안전 계산을 사용한다. CFF 1 출력 직전에는 닫힌 경로의 중복 시작점을 제거하고 획 컨투어를 Boolean union하여 교차부의 흰 구멍을 없앤다. 이 처리로 `ㅁ·ㅂ·ㅙ`의 꼭짓점과 교차부, `ㅇ·ㅁ·ㅎ`의 의도된 내부 공간을 브라우저와 macOS CoreText의 실제 OTF 렌더링에서 검증했다. 납작형·네모형은 화면과 OTF가 동일한 custom sweep 윤곽을 공유한다.
- Shape 마스터의 새 선·면 혼합 경로는 중심선과 점유 면을 글리프 좌표의 한 `FinalGlyphInk`로 합친 뒤, 화면은 그 면을 직렬화하고 OTF는 같은 면에 원점·기울기·UPM 투영만 적용한다. 첫 검증 범위는 명시적으로 선택한 초성 마스터와 곡률·사선 처리가 없는 원형 끝모양이며, `ㄱ`의 선·면 교차, `ㅇ`의 내부 공간, 내부 공간을 지나는 선을 확인했다. 지원하지 않는 boundary treatment나 non-round cap/join은 비슷한 결과로 대체하지 않고 차단한다. 전체 글자 자동 선택과 전체 폰트 출력 전환은 문맥 프리셋·레이아웃 투영 계약이 연결된 뒤 진행한다.
- 공통 레이아웃 그리드는 자소 형태의 part grid와 다른 좌표·ID 체계로 둔다. 기존 Split 저장값에는 안정 ID를 덧붙이지 않고, 공통 그리드의 Rail ID와 레이아웃 binding을 해석할 때만 의미 기반 split 주소를 파생한다. 숫자 위치가 우연히 같다는 이유로 여러 레이아웃 경계를 자동 공유하지 않으며, 공유 관계는 명시적 binding으로만 만든다. 저장 원본은 `absolute/between` Rail 위치식과 정확히 7개인 binding만 가지며, 해석된 좌표·안정 split·박스는 저장하지 않는다. 저장 파서는 깨진 Rail, 순환·축 교차, split과 part edge의 의미 불일치, ID 충돌을 전체 차단한 뒤에만 원본을 승인한다. Design Body가 있는 배치는 기존 850×850 canonical body에서 해석한 뒤 최종 배치 계산에서 한 번만 Font Space로 투영한다. 이 원본은 Shape System V2의 선택적 `layoutGridSystem`으로 저장하며 FontData 1.4에서만 내보낸다.
- 문맥 형태 규칙은 `자소 마스터 → 역할 기본값 → 조합 문맥 프리셋 → 자소별 예외` 순서로 상속한다. 같은 기본 문맥에서는 정의된 특징 태그가 많은 규칙을 우선하고, 태그 수가 같으면 `medialClass → finalWidthClass → initialClass` 순서로 fallback을 고정한다. 배열 순서나 ID 문자열로 승자를 정하지 않으며, 자소 variant가 명시한 실제 preset ID는 role과 요청 문맥이 맞을 때만 자동 선택을 대신한다.
- 역할 part grid는 0–1 로컬 좌표로 유지하고, 최종 레이아웃 slot으로의 affine 투영은 `projectPartGridToSlot()` 한 곳에서만 수행한다. 비정방 slot에서는 x/y 축 비율이 다르므로 투영 결과를 편집용 `ResolvedRailGrid`로 재사용하지 않고 `SlotProjectedPartGrid`로 구분한다. 화면·OTF용 Shape primitive는 이미 glyph 좌표가 된 Rail과 identity box를 소비하며 slot을 다시 곱하지 않는다. Rail·master·provenance 원본은 투영 과정에서 바꾸거나 저장하지 않는다.
- 자소 형태 그리드는 결과 뒤에 겹쳐 보이는 안내선이 아니라 글자의 선과 면을 만드는 생성 문법이다. 하나의 면 요소가 현재 part grid의 여러 원자 셀 점유 집합을 소유하며, 면 채우기는 셀 하나를 독립 도형처럼 이동하는 기능이 아니라 이 집합을 연속해서 채우고 비우는 기능이다. 신규 중심선의 앵커와 꺾임은 Rail 교점에 고정하고 Rail이 움직이면 같은 참조로 다시 계산한다. 기존 legacy 선은 자동으로 스냅하지 않고 사용자가 명시적으로 `그리드에 연결`할 때만 이 문법으로 변환한다.

## 샘플 문장 기반 편집 원칙

- 제품의 기준 흐름은 `보정 문장 → 완성 글자 직접 편집 → 편집 의도 분류 → 관련 글자 자동 전파`다.
- 사용자는 초성·중성·종성 카드나 레이아웃 편집 화면에서 적용 범위를 선택하지 않는다.
- 완성 글자의 자모 전체 이동·크기 변경은 레이아웃 패턴 변화로, 점·획 변경은 자모 형태 변화로 기록한다.
- 기존 모바일 편집기의 트랙패드, 포인트·베지어 조작, 스냅, SVG 렌더러, 히스토리는 독립 부품으로만 차용한다. 기존 페이지 라우팅과 자모 교체 스와이퍼는 신규 흐름에 포함하지 않는다.

## 결정 기록 방식

논의와 구현 결과는 다음 상태를 구분해 기록한다.

- **사실**: 코드, 사용자 검증, 기술 실험 등으로 확인된 내용
- **가설**: 가치나 구현 가능성을 검증해야 하는 제안
- **미결정**: 대안과 위험이 남아 선택하지 않은 사항

현재 이 문서에서 사실로 볼 수 있는 것은 프로젝트가 정규화된 벡터 획 데이터를 사용하며, OTF 출력 과정에서 중심선 획을 채워진 윤곽선으로 변환한다는 점이다. 원형 획의 화면·OTF 공통 좌표, 교차 획의 CFF 겹침 제거, 닫힌 경로 꼭짓점, 폰트 전체 적용은 실제 생성 파일과 브라우저·macOS CoreText 렌더링으로 검증했다. 고정각 납작형·네모형은 공통 sweep 윤곽 엔진, 브라우저 미리보기, 전체 OTF 생성·다운로드까지 검증했으며 설치 환경별 세부 렌더링 비교는 남아 있다. `획 따라가기`와 개별 획 오버라이드는 후속 가설이며, 그 구현 방식은 미결정이다.

제품 결정, 프로토타입 결과, 사용자 검증 또는 기술 제약이 새로 확인되면 관련 항목의 상태와 근거를 갱신한다. 오래된 가설을 확정 사실처럼 남겨두지 않는다.
