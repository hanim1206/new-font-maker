# 레이아웃 적용 범위에 `이 자모만` 층 더하기

- **이번에 비교하는 것**: 레이아웃 Δ를 `이 레이아웃 전체`에만 줄 수 있는 지금과, 잡은 부품의 자모(ㄱ만, ㄱ·ㅋ만)로 좁힐 수 있는 것.
- **이번 승인으로 바뀌는 것**: 범위 칩이 `이 레이아웃 · 이 자모만 · 전체` 셋이 되고, 저장소에 레이아웃×자모 층이 하나 생긴다. 카드 표본이 범위를 따라간다.
- **바뀌지 않는 것**: Δ만 저장, 더하기 모델, `layoutDeltaStore`가 사용자 전용이라는 것, 프리셋 모델·승인 입력, 캔버스·rail 편집, production 값. `직접 선택`·`범위 전체보기` 팝업·우선순위 드래그는 이 플랜에 없다.

출처: 주간 노트 2026-W39 일요일 `레이아웃 수정 적용범위` + 9/21 결정(결정과 뒤집힘 09-21, 8/20 "범위 선택 안 함" 뒤집음). 원칙: 기본은 자동, 좁히기만 사용자가. 프리셋 자동 오버라이드와 사용자 오버라이드는 키는 같게 저장은 따로.

## 지금 상태

**사실** (코드 읽기)
- `layoutDeltaStore`는 `all` + `layers[contextId]`(6칸) 두 층. 글자의 유효 Δ = 둘의 합(`effectiveLayoutDelta`). 저장은 localStorage `noto-layout-delta-v1`, 사용자 Δ만 든다. 프리셋 쪽 값(모델 예측·승인 입력 `notoApprovedIndex`)은 여기 없다. **경계는 이미 깨끗하다.**
- 유효 Δ를 읽는 곳 셋(`notoModel.ts` 칸 해석, `GlyphLayoutEditor`, `ReviewPropagationCards`)이 모두 `identity`(초성·홀자·받침 자모 포함)를 손에 쥐고 `contextId`만 넘긴다.
- 전파 카드의 범위 칩은 `이 레이아웃 · 전체`. 카드 표본(`propagationCandidates`)에는 `jamo` 묶음이 이미 있지만 형태 Δ 카드 전용이고 레이아웃 제한이 없다.
- 잡은 부품(`focus`: CH/JU/JO)과 그 자모(`focusJamoOf`)는 이미 안다.
- 9/21 커밋으로 홀자 상자 네 변이 rail이 됐다(`faces.JU`). 그래서 홀자도 자모 층으로 좁힐 실제 대상이 있다.

**알려진 구멍**: 닿자 네 변을 자모 하나에만 주는 길이 없다(9/16 남은 구멍). 이 플랜이 그 구멍을 메운다.

## 하려는 것

1. 저장 층 하나 추가: `jamo[contextId][`${part}:${jamo}`]`(예 `right-open/CH:ㄱ`). 유효 Δ = `all` + `layers[ctx]` + `jamo[ctx][CH:초성]` + `jamo[ctx][JU:홀자]` + `jamo[ctx][JO:받침]`. 더하기라 순서는 뜻이 없고, 좁은 층이 위에 얹힌다는 말은 이 합에서 나온다. `useLayoutDelta`는 `identity`를 받는다. 스냅샷(Undo/Redo)에 `jamo` 포함.
2. 범위 칩 `이 자모만` 추가. 누르면 잡은 부품과 같은 종류의 자모 목록이 뜨고 기본은 잡은 자모 하나. 다중 선택(ㄱ·ㅋ)은 같은 Δ를 자모별 키에 각각 쓴다(나중에 하나만 지울 수 있게). 힌트: `이 레이아웃에서 [초성이 ㄱ]인 글자`.
3. 카드 표본: `layer × jamo` 묶음. `저장된 Δ 지우기`는 이 층도 받는다.
4. 편집기 캔버스는 이미 유효 Δ를 original로 쓰므로 자모 층이 생기면 자동으로 보인다.

## 미결정

1. 칩 순서·기본값 — `이 레이아웃`(기본) · `이 자모만` · `전체`(추천) vs `이 자모만`을 잡은 부품이 닿자일 때만 보이기.
2. 홀자 자모 층의 키 — 혼합중성(ㅘ)은 홀자 하나로 볼지(`JU:ㅘ`, 추천) 가로부·세로부로 나눌지.
3. `저장된 Δ` 표시 — 층마다 따로(추천) vs 합쳐서 하나.

## 진행 기록

**2026-09-21** 플랜 작성. 구현 없음.
- 사실: 위 `지금 상태` 다섯 줄. 작업 트리에 화면 명세 트리(`docs/specs/화면/`, `ScreenSpecButton`)와 `skeletonFit`·`baseJamos` 미커밋 변경이 있으나 이 플랜과 무관.
- 가설: 읽는 곳 셋이 모두 `identity`를 가져서 합산식 바꾸는 일은 작다. UI 쪽은 자모 목록 팝업이 새 부품이라 그쪽이 더 크다.
- 미결정: 위 셋.

**2026-09-21 승인·구현** 사용자: 미결정 셋 다 추천안 ✔(칩 셋 항상 · 혼합중성은 `JU:ㅘ` 하나 · 저장된 Δ는 층마다 따로), `구현해`.

사실
- 저장소 `layoutDeltaStore`: `jamo[contextId][part:자모]` 층 추가. `apply/clear`는 `LayoutDeltaTarget`(`{scope:'all'} | {scope:'layer',contextId} | {scope:'jamo',contextId,jamos}`)을 받고, 자모 범위는 고른 키마다 같은 Δ를 따로 쓴다. 유효 Δ = `all` + `layers[ctx]` + `jamo[ctx][CH:초성]` + `jamo[ctx][JU:홀자]` + `jamo[ctx][JO:받침]`. `useLayoutDelta(identity)`로 바뀌어 읽는 곳 셋(`notoModel` 칸 해석, `GlyphLayoutEditor`, 카드) 모두 자모 층을 받는다. 스냅샷(Undo/Redo)에 `jamo` 포함. 옛 저장분(`jamo` 없음)은 persist `merge`가 빈 층으로 채운다. 주석에 "사용자 전용, 프리셋 자동 오버라이드는 여기 안 옴"을 박았다.
- `PropagationScope`는 저장소로 옮겨 `'layer' | 'jamo' | 'all'`. 형태 카드용 표본 묶음은 `'sameJamo'`로 이름 바꿈.
- 카드: 칩 `이 레이아웃 · 이 자모만 · 전체`. `이 자모만`을 누르면 잡은 부품 자리의 자모 전부(초성 19·홀자 21·받침 27)가 줄로 뜨고 잡은 자모는 켜진 채 고정, 나머지를 눌러 더한다. 힌트 `이 레이아웃에서 첫닿자가 ㄱ·ㅋ인 글자`. 카드 표본은 같은 문맥 × 고른 자모(표본 목록 밖 자모도 고르면 들어옴). `저장된 Δ 지우기`는 지금 칩의 층만 본다.
- G0(가, Playwright): 첫닿자 ㄱ 오른변 +20u → `이 자모만`(ㄱ + ㅋ) 적용 → 저장소 `jamo.right['CH:ㄱ']`·`['CH:ㅋ']`에 각각, `layers`·`all`은 빔. 문장 줄 가는 바뀌고 마(ㅁ+ㅏ, 같은 레이아웃)는 그대로. `이 레이아웃` 칩엔 저장된 Δ 없음, `이 자모만`엔 있음(층 분리). Undo → 가 복원·`jamo` 빔, Redo → 다시. 지우기는 고른 키(ㄱ)만 지우고 ㅋ은 남는다.
- G1: 받침 ㄱ 윗변(각, right-final) → `jamo['right-final']['JO:ㄱ']`만. 옛 저장 형식(`layers`만) 읽고 그 위에 자모 층 더하기. 단위 테스트: 층 합산, 부품별 분리(받침 ㄱ 층은 첫닿자 ㄱ에 안 감), 층별 지우기, 스냅샷 하위 호환.
- G2: `tsc -b` 통과, 바뀐 파일 eslint 0. `npm test` 910 통과 · 2 실패(기존: `preset-candidate-source` digest, `vertical-vowel-gap-reference` 해시 — 이 변경 밖). e2e `workspace-jamo-layout` 16개 + `workspace-jamo-editor` 3개 통과. `calibration-layout-persistence`는 병렬 실행에서 한 번 실패, 단독 실행 통과(flaky, 이 변경 밖). 11,172자 전수 스윕은 안 돌렸다 — 칸 해석 함수는 안 바뀌고 Δ 합산만 늘어서.
- Undo/Redo 뒤 편집부가 새로 뜨면 활성 부품은 홀자, 칩은 `이 레이아웃`, 고른 자모는 잡은 것뿐으로 돌아간다(세션 상태). 의도한 동작이고 e2e에 적어 둠.

가설
- 자모 줄이 받침 27개일 때 폰 너비에서 세 줄쯤. 길지만 팝업보다 한 번에 보인다. G3에서 사용자가 판단.

미결정
- 이 자모만 층이 쌓인 글자에서 `이 레이아웃` Δ를 지우면 자모 층은 남는다. 층 전부를 한 번에 지우는 버튼이 필요한지.
- 프리셋 자동 오버라이드 층(`layoutIs`, 곡선 질문)은 이 저장소 밖. 어디에 둘지는 그 플랜에서.
