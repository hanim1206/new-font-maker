# 모바일 우선 2차 개발 방향

2차 개발은 기존 프로젝트 안에서 진행한다. 기존의 자모·레이아웃 데이터, 정규화 좌표계, SVG 렌더링, 저장, 폰트 출력 코드를 재사용하기 위한 선택이다.

기존 PC 중심 화면은 새 제품 화면의 디자인 기준으로 삼지 않는다. 새 모바일 편집기는 독립된 v2 진입점으로 만들고, 안정화 전까지 기존 편집기와 나란히 유지한다. 모바일 v2가 핵심 흐름을 대체하면 기존 화면을 레거시 경로로 옮긴 뒤 제거 여부를 판단한다.

## 확정한 기술 방향

- 같은 React·TypeScript·Vite 프로젝트 안에 모바일 편집기 v2를 만든다.
- Next로 이전하거나 별도 네이티브 프로젝트를 만들지 않는다.
- 웹 PWA를 먼저 완성하고, 앱스토어 배포나 네이티브 파일 공유가 필요해질 때만 Capacitor 포장을 검토한다.
- 기존 UI 컴포넌트와 화면 구조는 재사용하지 않는다. 자모·레이아웃 데이터, 계산 유틸리티, 렌더러, 저장·출력 기반만 공유한다.
- 새 화면은 화이트 톤 디자인 토큰과 Tailwind 의미 클래스를 사용한다. 기존 다크 하드코딩을 새 코드로 가져오지 않는다.
- Zustand와 Immer는 유지하되, v2의 선택·모드·드로어 상태는 기존 UI 상태와 분리한다.
- SVG 렌더링을 유지한다. 윤곽 계산이 실제 병목으로 확인되면 Web Worker를 먼저 적용하고, 그래도 부족할 때만 Rust·WASM을 검토한다.

## v2 코드 경계

새 화면은 `src/features/mobile-editor/` 아래에 독립적으로 둔다. 라우팅에서는 `/editor-v2` 계열 경로로 구분하고, 개발 중에는 데스크톱에서도 모바일 폭으로 확인할 수 있게 한다.

공유 영역은 다음으로 제한한다.

- `src/types`: 정규화 좌표와 자모·레이아웃 타입
- `src/data`, `src/utils`: 한글 분해, 레이아웃 계산, 스냅과 패스 계산
- `src/stores`: 확정된 자모·레이아웃 데이터와 프로젝트 정보
- `src/renderers/SvgRenderer`: 실제 글자 미리보기
- `src/services`: 프로젝트 저장과 폰트 출력

기존 `MobileLayout`, PC 패널, 기존 드로어 조합은 v2에서 가져오지 않는다.

## 편집 명령과 미리보기

화면이 자모 스토어를 직접 계속 바꾸지 않게 한다.

`조작 시작 → 임시 미리보기 → 손을 뗌 → 편집 명령 한 건 확정 → 자동 저장·히스토리`

- 조작 중에는 비영속 임시 데이터만 갱신해 SVG 렌더러에 전달한다.
- 손을 떼면 실제 값이 달라진 경우에만 확정 데이터에 반영한다.
- 터치가 취소되거나 앱이 중단되면 임시 데이터를 버리고 조작 시작 상태로 돌아간다.
- 한 번의 연속 조작은 히스토리 한 건이다.
- 편집 명령에는 대상, 적용 범위, 문맥, 변경 전·후 값, 시간이 들어간다.
- 과거 상태 복원은 기존 기록을 지우지 않고 새 복원 기록을 추가한다.

현재 히스토리는 자모와 레이아웃 전체를 복제해 저장하므로 v2의 기본 기록 방식으로 사용하지 않는다. 변경된 대상만 저장하는 행동 기록을 별도로 만들고, 기존 히스토리는 레거시 화면용으로 유지한다.

## 라이브러리 원칙

- 트랙패드 제스처는 `@use-gesture/react`를 우선 검증한다.
- 자소 캐러셀은 `embla-carousel-react`를 우선 검증한다.
- 하단 드로어는 현재 Radix 기반을 유지한다.
- 대량 글자 목록은 `@tanstack/react-virtual`로 별도 최적화하되, 모바일 v2의 첫 세로 흐름을 막는 선행 작업으로 두지 않는다.
- Canvas 편집기로 전면 교체하지 않는다.

## 개발 순서

첫 개발 단위는 다음 한 줄을 실제 데이터로 완성하는 것이다.

`곰 열기 → ㄱ의 획 선택 → 트랙패드 이동 → 손 떼기 → 한 건 자동 저장 → 히스토리에서 비교·복원`

이후 `자소 캐러셀 → 글자 배치 → 전역 획 스타일` 순서로 확장한다. 전역 획 스타일은 UI와 별도로 고정각 납작 붓촉의 윤곽 생성 기술 실험을 통과해야 구현 완료로 본다.
