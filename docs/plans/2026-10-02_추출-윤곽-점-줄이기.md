# 추출 윤곽 점 줄이기

- **이번에 비교하는 것**: 지금 추출(윤곽 점 그대로) 대 합친 뒤 윤곽을 단순화한 추출. 같은 폰트 데이터에서 모양 차이와 걸린 시간을 잰다.
- **이번 승인으로 바뀌는 것**: OTF 추출의 윤곽 변환 끝에 한 번 더 넣는 단순화 단계 하나, 그 허용오차 한 값. 아직 승인 전이라 production은 그대로다.
- **바뀌지 않는 것**: 화면 미리보기·편집기 윤곽, 저장 데이터, 획 모델, 파일 검사 규칙, 진행 표시(10-02 경과 초 이미 반영)

## 왜

하니무스 손글씨체(`0528b0d8…`)를 받는 데 이 맥에서 93초가 걸린다. 기본 폰트는 19초. 세 단계가 고르게 느리다(수집 28초 · 윤곽 변환 35초 · 서브루틴 약 30초). 이유는 점이다.

- 받은 파일(4.9MB)을 재 보니 글리프당 윤곽 명령이 평균 360(최대 623). 기본 폰트는 평균 96(최대 262).
- 윤곽은 전부 `lineTo`다. 곡선이 아니라 점을 촘촘히 찍은 다각형이다(`한` 374, `글` 218).
- 이 폰트의 스타일은 붓(brush) 모드 · 둥글기 0.55 · 안쪽 둥글기 2.25. 둥근 곳을 다각형으로 근사해서 점이 는다.
- 획 단계에서 Douglas-Peucker 허용오차 0.5(1000단위 기준)가 이미 한 번 돈다(`strokeToOutline.ts`). 합치고 난 뒤에는 단순화가 없다.

## D0 계약 초안

- **한 값**: 합친 뒤 윤곽의 허용오차 `ε`(1000단위). 후보 0.5 · 1 · 2. 모양은 `ε`를 넘게 벗어나지 않는다.
- **자리**: 추출 경로에서 윤곽 → CharString으로 굳히기 직전. 화면용 윤곽은 안 건드린다.
- **지키는 것**: 닫힌 윤곽 · 방향(채움/구멍) · 잉크 상자(`inkBox`). 윤곽 개수는 안 바뀐다.
- **곡선 맞추기(다각형 → 3차 곡선)**는 이번에 안 한다. 점은 더 줄지만 모양 위험이 커서 이 플랜 결과를 보고 다음 후보로 둔다.
- **미결정**: `ε`의 기본값(G0에서 정한다). 서브루틴은 점이 줄면 같이 빨라질 것이라 가정한다. G0에서 재서 확인한다.

## 게이트

| 게이트 | 무엇을 | 통과 기준 |
|---|---|---|
| D0 | 위 계약 승인 | 사용자 승인 |
| G0 대표 | 하니무스 + 기본 폰트, 글자 약 20개(`한 글 손 씨 체`와 둥근 자모 · 겹침 많은 글자 · 홀자). `ε` 셋을 단계별 ms · 점 수 · 파일 크기로 표 | 점 수 감소율과 시간 감소가 `ε`마다 보인다. 윤곽 겹쳐 그림에서 눈에 띄는 차이 없음 |
| G1 홀드아웃 | G0에서 안 본 글자 100자(무작위, 시드 고정)로 원본 윤곽과의 최대 거리 | 최대 거리 ≤ `ε`. 방향·개수 동일 |
| G2 전수 | 11,172자 전수로 하니무스 · 기본 폰트 추출 | 검사 오류 0 · 빈 글자 0 · 시간 목표 안 · 파일 줄어듦. 기본 폰트는 모양 차이 `ε` 안 |
| G3 사용자 | 사용자가 실제 기기에서 받아 설치 · 문장 · 큰 글자 확대 | 사용자 확인 |

시간 목표는 G0 결과를 보고 사용자가 정한다(지금은 93초 → 절반 이하를 가늠으로 둔다).

## 진행 기록

**2026-10-02**
- 사실: 하니무스 폰트 추출 93초 재현(수집 28 · 윤곽 35 · 서브루틴 ≈30 · 묶기 0.4). 기본 폰트 19초. 계측은 `fontGenerator.ts`가 `[OTF 추출 시간 누적 ms]`로 콘솔에 찍고, 재현은 `exportSampleOtf.ts --font-data <font_projects 행 JSON>`.
- 사실: 받은 OTF 윤곽 점이 글리프당 평균 360(기본 96), 전부 `lineTo`.
- 사실: 파일로 묶는 단계에 경과 초를 보이게 함(`fontExportStore.ts`). 시간은 그대로.
- 가설: 점 수가 시간의 주원인이다. 단순화로 세 단계가 같이 준다. 서브루틴 시간은 Node 인라인 실행에서 뺀 값이라 브라우저(Worker)에서 다를 수 있다.
- 미결정: `ε` 기본값, 시간 목표, 곡선 맞추기를 다음 후보로 둘지.
- 결정: D0 승인(사용자, 10-02). `ε` 후보 0.5 · 1 · 2, 시간 목표는 93초의 절반 이하를 가늠으로.
