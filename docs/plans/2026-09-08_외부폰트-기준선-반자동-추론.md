# 외부 폰트 기준선 반자동 추론

외부 폰트 윤곽에서 첫닿윗선·첫닿밑선·가운뎃선·끝닿윗선 같은 기준선을 사용자가 직접 윤곽 끝에 드래그해 지정하는 실험실을 만든다.

수동 지정은 버릴 입력이 아니다. 알고리즘이 윤곽만으로 유일하게 복원할 수 없는 자소 경계의 사용자 판단이며, 추론 규칙의 정답·검증 데이터가 된다.

초기에는 대표 글자와 대비 쌍만 수동으로 지정한다. 예: 가·각, 고·곡, 과·곽. 세 쌍의 받침을 모두 ㄱ으로 맞춰 홀자 구조와 받침 모양 효과를 분리한다. 같은 폰트 안에서 지정값을 바탕으로 글리프 윤곽 통계, 조합 차이, 자소·문맥 일관성을 사용해 나머지 글자의 기준선 후보와 신뢰도를 제안한다.

사용자는 자동값을 승인·미세조정·거절할 수 있어야 하며, 낮은 신뢰도 글자만 수동 지정 대상으로 남긴다. 결과는 완성된 자소 마스터가 아니라 외부 폰트 분석용 Rail 후보로 저장한다.

우선 검증: 수동 지정 10~30개만으로 같은 레이아웃군의 미지정 글자 기준선이 충분히 쓸 만하게 제안되는지 측정한다. 자동 추론이 수동 작업량을 줄이지 못하면 실험실 기본 흐름으로 승격하지 않는다.

## 기준선의 의미와 결속

기준선은 단순한 윤곽의 x/y 끝값이 아니다. 전역 외곽선, 초닿·끝닿 역할선, 구조 요소선, 광학선으로 나눈다.

- 전역 외곽선: 윗선·밑선·왼선·오른선. 전체 글자의 잉크 범위 후보.
- 역할선: 첫닿왼선·첫닿오른선·첫닿윗선·첫닿밑선, 받침왼선·받침오른선·받침윗선·받침밑선. Unicode 조합의 초성·종성 역할을 범위로 삼는다.
- 구조 요소선: 기둥선. 가장 우측의 구조상 `기둥`에 결속한다. 곁줄기·이음줄기 끝이나 우연한 붓끝 돌출을 보고 x 최댓값으로 정하지 않는다. 겹기둥이면 바깥기둥을 선택한다.
- 광학선: 무게중심선. 기하학적 ink bounds의 중심과 다를 수 있다.

한 Rail은 역할을 여러 개 가질 수 있다. 이미지의 첫닿밑선과 무게중심선처럼 같은 위치가 요구되는 경우, Rail을 두 개 만들지 않고 `coincident roles`로 결속한다. 다만 이 일치를 모든 폰트·모든 문맥의 불변 규칙으로 가정하지 않고, 폰트별 승인값으로 둔다.

각 선에는 축, 역할 범위, 결속 대상, 위치 방식, 신뢰도를 저장한다. 위치 방식은 `outline-extreme`, `structural-pillar`, `optical`, `manual`처럼 구분한다. 해당 구조가 없는 글자에는 억지 값을 넣지 않고 `not-applicable`을 저장한다.

실험실은 기둥선 드래그 전에 세로 구조 후보를 보여 주고, 사용자가 `바깥기둥`을 선택하면 그 기둥의 정의된 면 또는 축에 Rail을 snap한다. 이 선택은 윤곽 알고리즘의 학습 데이터가 된다.

### 가로선
- 윗선
- 첫닿윗선
- 첫닿밑선
- 무게중심선
- 받침위선
- 보선
- 받침밑선
도판은 기준선을 전체 글자 외곽선과 첫닿·홀자·받침의 역할선으로 함께 읽어야 함을 보여 준다. 현재 기준선 조율 랩의 필드도 이 명칭으로 해석한다.

- `initialTop` → 첫닿윗선. 첫닿자 윤곽의 최고점에 정확히 둔다. 안전 여백을 더하지 않는다.
- `initialBottom` → 첫닿밑선. 첫닿자 윤곽의 최저점에 정확히 둔다. 무받침 문맥에서도 기준선과의 관계는 검토하되, 선값 자체는 윤곽 끝에서 물러나지 않는다.
- `pillarX` → 기둥선. 오른쪽 홀자의 구조상 바깥기둥에 결속하고, 현재 랩에서는 그 바깥 면 윤곽 끝에 맞춘다. 세로획의 축을 통과하지 않는다. 축 선택은 후속 데이터 모델에서 명시적으로 지원할 때만 별도 위치 방식으로 둔다.
- `finalTop`·`finalBottom` → 받침윗선·받침밑선. 받침 잉크의 위·아래 바깥 경계다.

도판의 `윗선·왼선·오른선`은 전체 글자의 외곽 역할선이다. 첫닿 역할선과 같은 숫자라고 가정하지 않는다. `첫닿왼선`도 이후 역할선 후보로 남긴다.

`보선`은 도판에 표시되지만 현재 랩의 고정 baseline이나 기존 필드와 자동으로 같은 역할이라고 단정하지 않는다. 어떤 글자·문맥에서 무엇을 가르는 선인지 대표 사례로 먼저 검증한 뒤 필드 추가 여부를 결정한다.

## 조율 순서 보정

ㄱ 기준 여섯 문맥은 기존 저장 숫자나 다른 첫닿자의 값부터 상속하지 않는다. `가 → 각 → 과 → 곽 → 고 → 곡` 순으로 각 역할선을 수동 배치한다. 원본 폰트 파일 좌표를 따로 옮겨 추정하지 않고, 랩이 실제 그린 같은 SVG 좌표계에서 대상 자소 path의 끝값을 읽는다. 첫닿·받침의 윗·밑선은 대상 윤곽의 최외곽 좌표에 정확히 맞추며, 안전 여백·강제 최소 간격을 넣지 않는다. 보이는 선은 글리프 뒤에 두고 드래그 판정선만 글리프 앞에 둔다. 기둥선은 구조상 바깥기둥의 바깥 면 윤곽 끝에 맞추며 축을 쓰지 않는다. 사용자 확인을 마친 여섯 값만 기준값으로 승격한다.

## 분석 Rail과 생산 PartFrame의 분리

외부 폰트에서 읽은 왼선·오른선과 첫닿·받침 역할선은 분석 관측값이다. 이 값을 생산용 자모 마스터의 절대 좌표나 고정 inset으로 바로 저장하지 않는다.

생산 흐름은 `Layout → 역할별 PartFrame → 자모 마스터 → 최종 잉크`로 둔다. 레이아웃은 PartFrame을 소유하고, 자모 마스터는 그 안에서의 형태를 소유한다. 최종 잉크와 PartFrame의 차이인 left/right/top/bottom inset은 검증·비교를 위해 계산할 수 있지만, 자모 원본의 별도 진실값으로 중복 저장하지 않는다. 획을 편집하면 이 값은 자연히 다시 계산되어야 한다.

문맥별로 의도한 배치 차이가 필요하면 자모 원본 inset이 아니라 `문맥 레이아웃 preset`의 위치·크기 보정으로 둔다. 가로·세로·섞임 문맥은 같은 원리를 쓰되 같은 숫자를 공유한다고 가정하지 않는다.

ㄱ의 아래 삐침 같은 잉크 돌출은 구조 위치를 잡는 anchor가 아니다. 구조 anchor는 PartFrame과 역할 Rail로 잡고, 돌출은 최종 잉크 overflow로 남긴다. 다만 overflow는 충돌 검사·글리프 전체 bounds·출력에서 빼지 않는다.

Y축도 같은 방식이나, typography baseline은 자모 inset으로 대체하지 않는 전역 메트릭이다. PartFrame 안의 top/bottom inset과 baseline 관계를 함께 검증한다.
