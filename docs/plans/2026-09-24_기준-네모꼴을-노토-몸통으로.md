# 기준 네모꼴을 노토 몸통으로

- **이번에 비교하는 것**: 지금 기준 틀(850 정네모, 사방 여백 75)과 노토 여섯 레이아웃 잉크의 합집합(840 × 910, 여백 위 50 · 아래 40 · 왼 50 · 오른 110).
- **이번 승인으로 바뀌는 것**: 기준 틀 상수와 여백 기본값, 네모꼴 막대의 0점과 라벨, `보선 층 쌓기` 페이지의 ⓪. 글자 좌표는 기본값에서 하나도 안 바뀐다(선형 변환이 항등).
- **바뀌지 않는 것**: 모델 값(`model.json`), 획, 굵기, 레이아웃 여섯 개, 사용자가 이미 옮긴 여백의 뜻.

## 왜

노토 관측 잉크는 위 53 · 아래 960 · 왼 43 · 오른 893까지 간다. 850 틀(75~925)을 위 22 · 아래 35 넘고, 가로는 오른쪽이 30~55 남는다. 그래서 사용자가 `정네모 850`을 고르면 실제 글자는 세로 907 · 가로 824의 세로 긴 글자다. 틀은 이름표일 뿐이라 결과는 안 깨지지만, 사용자에게 보이는 말과 수치가 어긋난다. 09-24 사용자 결정: 일치시킨다.

## 새 값

| | 지금 | 새 값 |
|---|---|---|
| 위 여백 | 0.075 | 0.05 |
| 아래 여백 | 0.075 | 0.04 |
| 왼 여백 | 0.075 | 0.05 |
| 오른 여백 | 0.075 | 0.11 |
| 몸통 | 850 × 850 | 840 × 910 |

오른쪽이 넓은 건 노토 한글이 왼쪽으로 치우쳐 앉아서다. 데이터 그대로 둔다.

- `보선 층 쌓기` 페이지 ⓪ — 기준 틀 점선과 `bodyMap`.

## 주의 (구현 전에 풀 것)

- **저장된 프로젝트**: 지금은 여백 0.075가 `isReferenceBody`로 "기준 틀"을 뜻한다. 값을 바꾸면 옛 저장값 0.075가 "사용자가 고른 더 작은 틀"로 읽혀 글자가 줄어든다. 옛 0.075 사방을 새 기준으로 읽는 이관이 필요하다. 사용자가 실제로 0.075 사방을 골랐을 가능성은 낮지만 0은 아니다.
- **막대 두 방향**: 지금 막대는 정네모를 가운데 두고 양쪽을 따로 편다. 0점이 노토 비율이 되면 `길쭉` 쪽은 세로 고정 · 가로 줄이기, `납작` 쪽은 가로 늘리다 세로 줄이기 규칙을 새 0점 기준으로 다시 편다. 정네모가 막대 어디에 오는지 표시한다.
