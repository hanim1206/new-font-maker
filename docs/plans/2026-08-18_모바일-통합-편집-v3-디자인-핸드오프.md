# 모바일 통합 편집 v3 디자인 핸드오프

관련 문서: [2026-08-18_모바일-v2-첫-개발-단위-기능-명세](./2026-08-18_모바일-v2-첫-개발-단위-기능-명세.md), [2026-08-18_모바일-우선-2차-개발-방향](./2026-08-18_모바일-우선-2차-개발-방향.md), [2026-08-17_모바일-트랙패드-편집](./2026-08-17_모바일-트랙패드-편집.md), [2026-08-17_모바일-전역-획-스타일-드로어-기능-명세](./2026-08-17_모바일-전역-획-스타일-드로어-기능-명세.md)

와이어프레임: [모바일 통합 편집 v3](./assets/모바일-통합-편집-v3.html)

이 문서는 통합 v3 와이어프레임을 구현 가능한 화면·상태·동작 규칙으로 옮긴다. 전체 구조를 설명하되 첫 개발 단위는 `P0`, 이후 단계는 `P1·P2`로 구분한다.

## 화면 구조

모바일 편집기는 세 영역을 유지한다.

1. 상단 앱 바: 뒤로 가기, 현재 화면 제목, 히스토리
2. 중앙 작업 영역: 현재 글자, 활성 파트, 캐러셀 또는 레이아웃
3. 하단 편집 드로어: 트랙패드 또는 전역 획 스타일

`획 스타일`은 글자 제목 아래에 두고, `레이아웃`은 트랙패드가 나오기 전 초기 글자 선택 상태에 둔다. 히스토리와 과거·현재 비교는 드로어가 아니라 전체 화면으로 연다.

## 구현 우선순위

### P0 · 첫 세로 흐름

- 독립된 모바일 v2 화면
- `곰`의 초성 `ㄱ`과 획 선택
- 선택 전·후 상태가 분명한 실제 SVG 미리보기
- 자유 2축 트랙패드 이동과 정밀 토글
- 조작 중 임시 미리보기, release 시 한 건 저장
- 히스토리 목록, 과거·현재 비교, 비파괴 복원
- 저장·실패·터치 취소 상태

### P1 · 핵심 모바일 편집 확장

- 활성 파트 기반 자소 캐러셀
- 길게 누르는 동안만 보이는 빠른 자소 탐색 팝업
- 조절점 선택과 축 잠금
- 레이아웃 편집 상태와 축 제한 조절 UI
- 영향을 받는 대표 글자

### P2 · 전역 스타일과 계보

- 원형·납작형 획 스타일 드로어
- 납작함과 고정 각도
- 현재 형태 계보 인스펙터
- 대표 글자와 전역 스타일 비교

## 공통 디자인 토큰

새 화면은 `src/index.css`와 Tailwind에 정의한 의미 토큰만 사용한다. 레거시 다크 색상과 임의의 회색·파란색을 새 컴포넌트에 직접 쓰지 않는다.

| 역할 | 토큰 |
|---|---|
| 앱 배경 | `background` |
| 카드·앱 바·드로어 | `surface` |
| 비활성 컨트롤·트랙패드 | `surface-2`, `surface-3` |
| 본문 | `foreground` |
| 보조 문구 | `text-dim-3`~`text-dim-5` |
| 기본·약한 경계 | `border`, `border-subtle` |
| 선택·포커스 | `primary`, `primary-light`, `ring` |
| 위험·실패 | `danger` |
| 간격 | `--space-1`~`--space-6` |
| 모서리 | `--radius-sm`~`--radius-xl` |
| 표면·오버레이 그림자 | `--shadow-sm`, `--shadow-md`, `--shadow-overlay` |
| 동작 | `--motion-fast`, `--motion-normal`, `--motion-slow`, `--ease-standard` |
| 최소 터치 영역 | `--touch-target` |

파트 색은 초성·중성·종성의 의미를 설명할 때만 기존 `slot` 색을 쓴다. 일반 선택 상태는 항상 `primary`를 사용한다.

## 크기와 반응형

- 실제 제품은 화면 전체 폭을 사용한다. 390px 고정 폭은 와이어프레임 표현에만 사용한다.
- 개발 중 데스크톱 미리보기에서는 편집 화면을 최대 430px로 제한할 수 있다.
- 앱 전체 높이는 `100dvh`, 하단에는 `safe-area-inset-bottom`을 더한다.
- 앱 바 높이는 54px, 좌우 아이콘 터치 영역은 최소 44px다.
- 기본 좌우 여백은 `--space-4`, 좁은 320px 화면에서는 `--space-3`까지 줄인다.
- 중앙 글자 영역은 최소 200px를 확보하고 드로어가 바뀌어도 글자 중심이 크게 튀지 않게 한다.
- 트랙패드 높이는 `clamp(124px, 18dvh, 160px)`로 잡는다.
- 드로어는 콘텐츠가 늘어나도 화면 높이의 48%를 넘지 않는다. 넘으면 드로어 안에서 조절 영역만 세로 스크롤한다.
- 320px에서도 모드 버튼 두 개는 같은 행을 유지한다. 텍스트를 줄이지 않고 버튼 사이 간격만 축소한다.
- 가로 화면에서는 중앙 작업 영역과 드로어 높이를 함께 줄이되 트랙패드의 최소 높이는 유지한다.

## 컴포넌트 책임

### `MobileEditorV2Page`

- 현재 전체 화면과 드로어 모드를 조합한다.
- 레거시 `MobileLayout`을 감싸거나 가져오지 않는다.
- 뒤로 가기와 전체 화면 복귀 시 직전 글자·파트·획 선택을 복원한다.

### `EditorAppBar`

- 가운데 제목, 왼쪽 뒤로 가기, 오른쪽 히스토리를 표시한다.
- 히스토리·비교 화면에서는 오른쪽 액션을 숨기고 제목을 해당 화면명으로 바꾼다.

### `EditorModeRow`

- `획 스타일` 진입점을 두고, 레이아웃 편집은 트랙패드가 나오기 전 초기 글자 선택 상태에서 진입한다.
- 현재 모드는 색과 `aria-pressed`를 함께 사용한다.
- P0에서는 버튼을 보이되 구현 전 기능은 비활성 처리하거나 개발 플래그 뒤에 둔다.

### `GlyphSelectionCanvas`

- 확정 데이터와 조작 중 임시 데이터를 받아 같은 SVG 렌더러로 그린다.
- 파트 탭 → 획 탭 → 같은 획 재탭 시 조절점 표시 순서를 지원한다.
- P0는 파트와 획 선택까지만 구현한다.
- 선택하지 않은 파트는 형태 확인이 가능할 정도로 유지하고, 현재 대상은 색과 외곽 표시를 함께 쓴다.

### `TrackpadDrawer`

- 선택 대상, 허용 축, 이동량, 정밀 상태, 저장 상태를 표시한다.
- 선택 전에는 입력을 받지 않고 `대상을 선택하세요`를 표시한다.
- 자유 이동은 가로·세로 그라디언트와 `↕↔`, 한 축 이동은 해당 축 띠와 화살표를 표시한다.
- 잠긴 축은 흐린 축, 잠금 아이콘, `가로 잠금` 또는 `세로 잠금` 문구를 함께 쓴다.
- 관성 이동은 사용하지 않는다.

### `QuickJamoPicker` · P1

- 캐러셀을 길게 누르는 동안만 작업 영역 위에 떠 있는 팝업으로 표시한다.
- 기존 화면 공간을 밀어내지 않는다.
- 활성 파트의 후보만 보여주고 손을 떼면 현재 후보를 확정한다.
- 종성 후보에는 `없음`을 항상 포함한다.

### `StrokeStyleDrawer` · P2

- 헤더에 `획 스타일`, 범위에 `폰트 전체에 적용`을 고정한다.
- 원형에서는 추가 제어를 숨기고, 납작형에서만 납작함과 각도를 보인다.
- 완료 시 이전 파트·획·조절점과 트랙패드 상태로 돌아간다.

### `LayoutEditorView` · P1

- 사용자 화면에서는 `글자 배치` 대신 `레이아웃`으로 표시한다.
- 트랙패드가 나오기 전 초기 글자 선택 상태의 `레이아웃` 표시로 진입한다.
- 자소 캐러셀 대신 파트 영역, 분할선, 패딩을 표시한다.
- 분할선이나 패딩을 선택한 뒤에만 레이아웃 전용 조절 UI를 표시한다.
- 범위 문구와 영향을 받는 대표 글자를 상시 표시한다.

### `EditorHistoryPage`와 `HistoryComparePage`

- 히스토리는 최신순 목록이며 시간, 대상, 변경 요약, 범위를 표시한다.
- 비교 화면은 선택한 시점과 현재를 나란히 보여준다.
- 복원 버튼은 기존 기록을 삭제하지 않고 새 복원 기록을 만든다.

## 상태 모델

다음 상태들은 서로 배타적인 구별된 유니온으로 정의한다.

- 화면: `editor | layout | history | compare`
- 드로어: `trackpad | stroke-style | lineage`
- 선택: `none | part | stroke | point | layout-boundary | padding`
- 조작: `idle | active | committing | saved | error`
- 캐러셀: `idle | swiping | quick-picking`

P0에서는 `editor`, `history`, `compare`, `trackpad`, `none | part | stroke`, `idle | active | committing | saved | error`만 구현한다.

전체 화면을 닫으면 편집 화면의 선택과 드로어 상태를 복원한다. 획 스타일 드로어를 닫으면 열기 전 선택 상태를 복원한다. 레이아웃 편집에서 초기 글자 상태로 돌아갈 때도 직전 자소 선택을 복원한다.

## 트랙패드 동작

- 한 손가락 이동만 편집 입력으로 사용한다.
- 조작 시작 시 확정 좌표를 기준값으로 고정한다.
- 이동 중에는 임시 좌표만 갱신한다.
- release 시 실제 이동량이 있을 때만 한 건 확정한다.
- `pointercancel`, 전화·앱 전환, 터치 이탈은 시작값으로 되돌린다.
- 정밀 토글은 누르는 동안이 아니라 켜고 끄는 상태다.
- 정밀 모드에서는 기본 감도의 25%를 초기값으로 사용한다.
- 일반 모드의 속도 가속은 저속·중속·고속 세 구간으로 시작하되 정확한 경계값은 실제 기기 테스트에서 조정한다.
- 화면에 표시하는 이동량은 소수 셋째 자리까지다.
- 조작 중 프리뷰 갱신과 release 이후 전체 저장 처리를 분리한다.

속도 구간의 수치 조정은 비차단 검증 사항이다. `빠르면 크게, 느리면 정밀하게`와 `정밀 토글 25%`가 사용자에게 예측 가능하게 느껴지는지를 우선 본다.

## 콘텐츠와 피드백

| 상태 | 문구 |
|---|---|
| 선택 없음 | `획이나 조절점을 선택하세요` |
| 획 선택 | `초성 ㄱ · 1번 획` |
| 조절점 선택 | `초성 ㄱ · 1번 획 · 끝점` |
| 조작 중 | `조정 중 · 손을 떼면 자동 저장` |
| 확정 처리 | `저장 중…` |
| 성공 | `저장됨` |
| 로컬 저장 실패 | `저장하지 못했어요. 이전 상태로 돌아갔습니다` |
| 범위 | `가로모음 + 받침 전체에 적용`, `폰트 전체에 적용` |

`저장됨`은 1.2초 뒤 사라지고, 오류는 사용자가 확인하거나 다시 조작할 때까지 유지한다. 대상 이름이 한 줄을 넘으면 말줄임표를 사용하고 전체 이름은 접근성 레이블로 제공한다.

로컬 확정과 클라우드 동기화는 구분한다. 로컬 확정 실패만 좌표를 되돌린다. 클라우드 동기화 실패는 로컬 결과를 유지하고 후속 동기화 상태로 다룬다.

## 동작과 전환

- 버튼·선택 강조: `--motion-fast`
- 드로어 내용 전환: `--motion-normal`
- 전체 화면 전환: `--motion-slow`
- 모든 전환은 `--ease-standard`를 사용한다.
- 원형에서 납작형 제어가 나타날 때 중앙 글자 위치를 움직이지 않는다.
- 히스토리와 비교 화면은 편집기 위에 전체 화면으로 들어온다.
- `prefers-reduced-motion`에서는 위치 이동 애니메이션을 제거한다.

## 접근성

- 모든 조작 가능한 요소는 최소 44×44px 터치 영역을 갖는다.
- 파트와 획은 색만 바꾸지 않고 외곽선·선택 핸들·대상명으로도 상태를 표시한다.
- SVG 파트와 획은 포커스를 받을 수 있고 `초성 ㄱ`, `초성 ㄱ의 1번 획`처럼 읽힌다.
- Enter·Space로 선택하고, 트랙패드에 포커스한 상태에서는 방향키로 이동한다. Shift+방향키는 일반 이동, 방향키는 정밀 이동으로 제공한다.
- 선택 변경, 저장 완료, 오류는 `aria-live="polite"`로 알린다.
- 축 제한은 색과 그라디언트만으로 전달하지 않고 아이콘과 문구를 함께 쓴다.
- 포커스가 전체 화면을 벗어나지 않게 하고 닫을 때 진입 버튼으로 돌려보낸다.

## 반응형 검증 크기

- 320×568: 최소 지원 폭과 짧은 화면
- 360×800: 소형 Android
- 390×844: 기준 iPhone 폭
- 430×932: 큰 모바일
- 가로 화면 844×390

각 크기에서 앱 바, 모드 버튼, 중앙 글자, 드로어 헤더, 트랙패드, 세 개의 보조 버튼이 잘리거나 겹치지 않아야 한다.

## 디자인 인수 조건

- [ ] 새 화면에서 레거시 다크 색상과 기존 PC 패널이 보이지 않는다.
- [ ] 선택 전과 획 선택 후의 차이를 색 없이도 구분할 수 있다.
- [ ] 손가락이 중앙 글자를 가리지 않은 채 획을 이동할 수 있다.
- [ ] 트랙패드가 자유 이동인지 한 축 이동인지 즉시 구분된다.
- [ ] 조작 중과 저장 완료가 별도 상태로 보인다.
- [ ] 히스토리 전체 화면을 닫으면 직전 획 선택과 트랙패드 상태가 복원된다.
- [ ] 320px 폭에서도 주요 조작이 가로로 잘리지 않는다.

## 검증이 남은 값
