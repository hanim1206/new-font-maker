# 추출 윤곽 꼬임

- **이번에 비교하는 것**: 획을 급하게 휘게 고친 폰트도 OTF가 끝까지 나오는지, 실패하면 바로 알 수 있는지.
- **이번 승인으로 바뀌는 것**: 추출에서 스스로 겹친 획 윤곽을 멈추지 않고 풀어서(NonZero) 합친다. 그래도 안 되는 글자는 빼고 폰트는 만들고, 몇 자를 뺐는지 알린다. 추출 실패 · 뺀 글자는 편집 화면 토스트로 바로 알린다.
- **바뀌지 않는 것**: 화면 그림, 면(`part-grid` 영역) 입력의 fail-closed(finalGlyphInk), 윤곽을 만드는 방식.

## 지금 상태 (사실)

- 사용자 test1 새 폰트의 ㄱ: 끝점을 (0, 1)로 옮기고 handleIn을 줘 크게 휜 획. 스타일은 둥근 붓 · 둥글기 0 → `strokeToContours`(옛 윤곽) → `mergeStrokeContourGroupsForCff` → `inkBoolean.assertSimpleRing`이 던진다. 곡선이 두께보다 급해 안쪽 윤곽이 제 몸을 지난다.
- Boolean은 9/24부터 Clipper2(`polygonBoolean.ts`)라 겹친 링을 채우기 규칙으로 풀 수 있다. 검사는 `polygon-clipping` 시절 그대로다.
- 추출 실패는 `☰` 점과 다음 추출 창의 `지난 추출 실패`에만 보인다.

## 계약

- `InkBooleanOptions.resolveSelfIntersections`(기본 false). OTF 합치기(`contourBoolean` CFF 옵션)만 true. true면 겹친 링을 던지지 않고 Clipper2 union(NonZero)로 푼다. 획 윤곽(스트로커 결과)은 NonZero가 맞는 채우기다.
- 그래도 한 글자가 실패하면 그 글자만 빼고(.notdef) 계속. 결과에 뺀 글자 목록. 폰트 전체를 버리지 않는다.
- 토스트: 추출 실패 → 에러 토스트(닫을 때까지). 뺀 글자 있음 → "빽 등 N자는 모양을 만들지 못해 빠졌어요" 에러 토스트. 셸(`WorkspaceChrome`)에 둔다.
