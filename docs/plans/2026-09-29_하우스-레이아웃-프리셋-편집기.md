# 하우스 레이아웃 프리셋 편집기

- **이번에 비교하는 것**: 프리셋 v1(노토 레이아웃 모델) 대 v2(사용자가 손으로 고친 대푯값 모델)
- **이번 승인으로 바뀌는 것**: 폰트마다 프리셋 버전을 박고 그 버전 모델을 읽는 구조, 관리자 `프리셋` 메뉴(편집 · v1 대 v2 비교 · 버전별 폰트 수), 계정 폰트 카드의 버전 표시, v2 초안 파일
- **바뀌지 않는 것**: 기존 폰트(계속 v1), 새 폰트의 기본(v2 출시 커밋 전까지 v1), 자소별 효과 · 짝 칸(다음 플랜), 기본 자소 획, 홀자 두께

## 왜

프리셋의 레이아웃은 노토 11,172자에서 잰 모델을 그대로 쓴다. 대푯값 168개 · 자소별 효과 6,052개 · 짝 칸 525개. 노토와 똑같이 맞춘 뒤 오차를 남기는 방식은 파생 관계를 더 굳히므로 쓰지 않는다(09-29 논의). 노토는 고스트로만 두고, 사용자가 대푯값부터 직접 정한다. 효과 · 짝 칸을 사용자 규칙으로 바꾸는 건 다음 플랜.

## D0 계약 초안

- **버전 박기**: 폰트 데이터의 `preset` 칸(이미 있음, 지금 값은 `basic-gothic` 하나)을 버전으로 쓴다. `basic-gothic` = v1 = 노토 모델. 새 id `basic-gothic-v2`를 더한다.
- **덮어쓰기 막기**: 지금은 저장할 때마다 `preset`을 기본값으로 덮는다(`collectAccountFontData`). 이대로면 기본을 v2로 바꾸는 순간 기존 폰트가 다음 저장에서 v2로 넘어간다. 새 폰트를 만들 때만 기본값을 박고, 저장은 연 폰트의 값을 그대로 둔다. 이게 첫 작업이다.
- **새 폰트 기본**: `DEFAULT_FONT_PRESET` 한 줄. v2 출시 = 이 줄을 v2로 바꾸는 커밋(사용자 말이 있어야 함). 그 뒤 새로 만드는 폰트만 v2.
- **모델 고르기**: 모델 입구(`notoModel.ts`의 모델 공유 함수)가 연 폰트의 버전을 보고 그 모델을 준다. 버전별로 한 번씩만 읽는다. 문장 · 편집기 · 검수 · OTF가 모두 이 입구를 지나므로 다른 곳은 안 고친다. 관리자 계정 미리보기는 그 폰트의 버전을 쓴다.
- **v2 파일**: `public/house-preset/layout-model-v2.json`. `targets` 모양은 노토 모델과 같아서 예측기를 그대로 쓴다. 시작값은 노토 복사. 손댄 대푯값은 `authored` 목록(`타깃 · 레이아웃 · 노토값 · 우리값 · 날짜`), 효과 · 짝 칸은 `source: noto-measured`로 표시한다. 두께는 노토 그대로. v1은 지금 파일 그대로 동결.
- **편집기**: 관리자 사이드바 `프리셋` 메뉴, v2 초안만 고친다. 레이아웃 6칸 중 하나를 고르면 대표 글자 8자가 v2 잉크 + 노토 고스트로 뜬다. 상자 변을 끌면 그 레이아웃 대푯값이 바뀐다. 기존 레이아웃 편집기(`GlyphLayoutEditor`)를 쓰고 저장만 v2 파일로 돌린다. 숫자는 끄는 중에만, 옆에 노토와의 차이(u).
- **관리자에서 보기**: 
  - 계정 폰트 카드 이름 옆에 `v1 노토` · `v2` 표시. 미리보기는 그 폰트의 버전 모델로 그린다. 카드마다 `v2로 보기` 토글로 같은 폰트를 v2 모델로 그려 본다(저장 안 함, 옮기기 판단용).
  - `프리셋` 메뉴 머리에 새 폰트 기본 버전과 버전별 폰트 수(`v1 n개 · v2 m개`).
  - `프리셋` 메뉴에 비교 줄: 같은 문장을 v1 · v2 두 줄로 위아래, 또는 겹쳐 보기(v2 잉크 + v1 고스트). 문장은 대시보드 예시 문장을 같이 쓴다.
  - 손댄 대푯값 목록: 레이아웃 · 자리 · 노토값 · 우리값 · 차이. 줄을 누르면 편집 캔버스가 그 레이아웃으로 간다.
- **저장**: 개발 서버 전용 `/api/house-preset`이 레포 파일에 쓴다. 문지기는 의견 API와 같다(이 맥 · 전용 헤더 · 같은 출처). 배포본에는 쓰기가 없다.
- **기존 폰트를 v2로 옮기기**: 이번엔 없다. 열린 질문으로 둔다.
- **미확인**: 홀자 rail Δ가 대푯값(`face · spanFrom · spanTo · visibleLength`)에 1:1로 옮겨지는지. 닿자 변은 1:1이다. 그래서 편집기 G0은 닿자 변만.

## 진행 기록

- 2026-09-29 · 플랜 작성. **사실**: 모델은 대푯값 168 · 효과 6,052 · 짝 칸 525, 모든 소비처가 모델 공유 입구 하나를 지난다. 관리자 화면은 개발 서버 전용. **가설**: 대푯값만 바꿔도 인상이 크게 달라진다. **미결정**: 홀자 rail ↔ 대푯값 대응, 대표 글자 8자 고르기.
- 2026-09-29 · **뒤집힘** 전역 스위치 대신 폰트마다 프리셋 버전을 박는다. 기존 폰트는 v1, v2 출시 뒤 새 폰트만 v2 · 사용자 결정. **사실**: `preset` 칸이 이미 있고, 저장마다 기본값으로 덮는다.
- 2026-09-29 · 관리자에서 버전을 매끄럽게 보기 추가(계정 카드 표시 · `v2로 보기`, 프리셋 메뉴 비교 줄 · 버전별 수 · 손댄 값 목록) · 사용자 요청.
- 2026-09-29 · 구현. D0 · G0 · G2 닫힘, G1 조건부, G3 대기.
  - **사실**: 저장이 연 폰트의 `preset`을 덮지 않는다(테스트 2개). 새 폰트만 기본(v1)을 받는다. 모델 입구가 버전별로 모델을 주고, 확인용 서버에서 v2로 저장된 폰트를 열면 첫닿자 오른변을 줄인 v2 모델로 `가 · 다`가 좁아졌다. 자동 저장 뒤에도 v2로 남았다.
  - **사실**: 관리자 `프리셋` 메뉴에서 여섯 레이아웃 모두 선이 뜨고(그 홀자에 있는 줄기만), 첫닿자 · 받침 변 · 홀자 가로줄기를 끌면 대푯값이 바뀐다. 저장 → 새로고침 뒤 유지. 계정 카드 `v1 노토` 표시 · `v2로 보기` 동작, 버전별 수(v1 28 · v2 0) 읽힘. 콘솔 오류 없음.
  - **사실**: v2 = 노토 복사일 때 11,172자 × 모든 타깃 예측이 v1과 같다(테스트). `npm test`의 이 레포 실패 3개(`preset-candidate-source` · `screen-spec` · `vertical-vowel-gap-reference`)는 변경 전 커밋에서도 같은 메시지로 실패한다.
  - **D0에서 달라진 것**: v2 파일은 노토 모델 전체 복사가 아니라 대푯값 168개만 절대값으로 적는다(6KB). 효과 · 짝 칸은 노토 파일에서 읽고 `effectsSource: noto-measured`로 표시.
  - **미확인 풀림**: 홀자는 rail Δ를 거치지 않고 대푯값(`medial.*.face`)을 바로 고친다. fit이 예측값으로 줄기를 놓아 선을 따라온다(곡 주 가로줄기 +39u 확인).
  - **G1 조건부**: OTF 추출은 같은 입구(`loadNotoModel`, 기본 = 연 폰트 버전)를 지나지만 v2 폰트로 실제 추출은 안 해 봤다. Playwright e2e 묶음은 안 돌렸다.
  - **미결정**: v2 출시(`DEFAULT_FONT_PRESET` 한 줄), 기존 폰트 옮기기.
