# 공지 팝업 — 관리자에서 만들고, 자리마다 한 번 띄운다

- **이번에 비교하는 것**: 공지가 없는 지금과, 관리자 `공지` 메뉴에서 장 카드로 조립해 게시하면 정해진 자리에 처음 들어온 사람한테 한 번 뜨는 흐름.
- **이번 승인으로 바뀌는 것**: `announcements` 테이블 · 이미지 버킷 마이그레이션, 관리자 `공지` 메뉴, 앱 곳곳의 자리 훅, 팝업 컴포넌트.
- **바뀌지 않는 것**: 처음 들어온 사람의 둘러보기(`BetaGuideSheet`) 내용과 뜨는 조건, 의견 · 계정 메뉴, 편집 동작.

출처: 9/29 논의. 버전이 오르거나 기능이 바뀌면 "이거 좋아졌다"를 알리고 싶다. 이미지는 AI가 만들고, 올리기 전에 한 번 검토한다.

## 결정된 것

- **본문 = 장 카드.** 한 장 = 이미지 한 장 + 제목 + 짧은 본문(줄바꿈만). 에디터 라이브러리 안 붙임. 좌우로 넘김은 `BetaGuideSheet`와 같은 방식.
- **읽음 = 브라우저.** `localStorage`의 `announcement-read:<id>`. 닫으면 읽음(끝까지 안 넘겨도). 기기를 바꾸면 한 번 더 뜨는 건 받아들인다.
- **옛 공지 건너뛰기 = 계정 가입일.** `published_at < 가입일`인 공지는 안 띄운다(새 사람은 둘러보기를 본다). 가입일은 `betaAuth`의 `createdAt`.
- **자리 = 코드에 정한 이름.** 페이지와 패널 둘 다. 관리자는 공지마다 자리 하나를 고른다.

| 자리 키 | 뜨는 때 |
|---|---|
| `global` | 어느 화면이든 첫 진입 |
| `dashboard` | `/dashboard` |
| `style` | 글로벌 스타일 공간 열 때 |
| `style.brush` | 붓 트랙패드 열 때 |
| `jamo-editor` | 획 편집기 진입 |
| `layout-editor` | 레이아웃 편집기 진입 |
| `review` | `/workspace/review` |
| `export` | 추출 완료 화면 |

## 계약 (D0에서 정할 것)

- **저장**: `announcements(id, title, place, slides jsonb, status 'draft'|'published'|'archived', published_at, created_at)`. `slides = [{ image, title, body }]`. RLS: 로그인한 사람은 `published`만 읽는다. 쓰기는 로컬 관리자 API(`scripts/announcementAdminApi.ts`, service_role)만 — `feedbackAdminApi`와 같은 방식.
- **이미지**: Storage 버킷 `announcements`(공개 읽기). 관리자 API가 올린다. 배포 없이 게시된다.
- **관리자 화면**: 목록(상태 · 자리 · 게시일) → 편집(장 카드 추가 · 끌어서 순서 · 이미지 올리기 · 자리 고르기) + 오른쪽에 **실제 팝업 컴포넌트로 미리보기**. 버튼은 `게시` · `내리기` 둘.
- **뜨는 규칙**: 한 번에 하나. 같은 자리에 여럿이면 오래된 것부터 차례로. 둘러보기가 떠 있으면 미룬다. `global`이 자리별 공지보다 먼저. 공지는 앱이 뜰 때 한 번 받아 둔다(자리 훅마다 부르지 않는다).
- **팝업**: `BetaGuideSheet`의 판 · 넘김 · 키보드를 공용 컴포넌트로 빼서 둘이 같이 쓴다. 닫기는 마지막 장 `확인`, 어느 장이든 `닫기`, Esc.

## 열린 것

- 공지 이미지 크기 · 비율(둘러보기 캡처는 390×520). AI가 만들 때 맞출 규격.
- 공지를 다시 띄우고 싶을 때(고친 뒤 재게시) — 새 id로 복제하는 걸로 충분한지.
