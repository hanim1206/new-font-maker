# 배치 규칙 역추론 실험 — 노토를 원본이 아니라 시험지로

- **이번에 비교하는 것**: 지금 엔진(노토 변화량 모델 — 레이아웃 대표값 + 자모별 효과 + 짝 보정, 숫자 수천 개)과, 우리가 쓴 규칙(배치 패턴 + 자동 보정 서너 개)으로 놓은 상자가 노토와 얼마나 가까운가.
- **이번 승인으로 바뀌는 것**: 아무것도 안 바뀐다. 실험실 화면과 측정 스크립트만 생긴다. 결과가 좋으면 다음 플랜에서 v2 엔진의 배치 단계를 규칙으로 바꾸는 것을 논의한다.
- **바뀌지 않는 것**: 1차 배포본(main · dev), 노토 변화량 모델 파일, `baseJamos.json`, 획 우선 모델과 두께 고정 원칙, Split + Padding 레이아웃 스키마.

출처: 11-08 스레드 "2차 v2 브랜치 시작하기". 사용자 제안 — 폰트는 ①자소 디자인 → ②세 케이스 배치 → ③레이아웃별 미세보정 순서로 만드는데, 우리는 노토의 최종 형태에서 ②③을 통째로 빌려 왔다. ②를 패턴으로 정형화하고(사용자에게 투명) ③을 우리 자동 보정 규칙으로 만든 뒤, 그 결과를 노토와 비교해 규칙을 채점하자.

## 왜

**사실**
- 지금 모델의 "첫닿자 ㄱ 효과"는 노토 ㄱ의 생김새가 들어 있는 숫자다. 사용자가 ㄱ을 다르게 그리면 남의 글자에서 빌린 값이 되고, 왜 맞고 틀리는지 설명할 수 없다. 11-08 해설 아티팩트 세 개로 확인했다(`ㄱ은 어디에 담겨 있나` · `글자 한 자가 만들어지는 순서` · `자모마다 얼마나 미는가`).
- 모델은 목표 40개 × 레이아웃 6개 = 156칸, 칸마다 자모별 효과 수십 개. 짝 보정은 27칸에만 있고 첫닿자 × 받침 쌍은 없다. 세 상자는 서로 보지 않고 따로 예측된다.
- 홀자 안쪽 줄기(안 기둥 등)의 가로 위치는 모델 예측을 따르지 않고 우리 자모 원형 비율을 따른다(`fitPartStrokes`는 줄기 높이만 보선에 다시 맞춘다).
- 사용자가 레이아웃 편집에서 혼란을 느끼는 원인이 여기 있다(11-08 사용자). 상자를 만지는데 그 상자가 왜 그 자리인지 어디에도 안 보인다.
- 쓸 수 있는 재료가 이미 있다. ② 배치 패턴 = `DEFAULT_LAYOUT_SCHEMAS`(Split + Padding). 채점 = `glyphXorAgainstNoto` · `public/noto-preset/xor.json`. 틈 규칙 하나는 10-02 플랜에서 이미 역추론했다(실제 틈 = max(예측, 0.25 × 양쪽 줄기 두께 평균)).

**가설**
- 노토 ③의 대부분은 "획 사이 최소 틈" · "홀자 기둥 높이 고정" · "받침 윗면 여백" 정도의 규칙으로 설명되고, 남는 차이는 취향이라 규칙으로 쫓지 않아도 된다.
- 규칙 열 몇 개가 숫자 수천 개보다 사용자 글자에 더 잘 맞는다. 규칙은 우리 자모의 실제 잉크를 보고 움직이기 때문이다.

## 하려는 것

**A. 채점판 (실험실 `/admin/labs/layout-rules`)**
1. 오른홀자 + 받침 레이아웃의 588자(첫닿자 ㄱ 고정이 아니라 첫닿자 19 × 홀자 9 × 받침 27 중 표본 588)를 격자로 놓고, 글자마다 노토 대비 xor를 색으로 칠한다. 지금 모델의 xor를 기준선으로 같이 둔다.
2. 규칙을 켜고 끄는 스위치와 규칙 변수(최소 틈 비율 등) 슬라이더. 바꾸면 588자가 다시 계산된다.
3. 차이가 큰 글자 상위 20개를 따로 보여 준다. 이게 "아직 못 찾은 규칙" 목록이다.

**B. 규칙 (`src/services/layoutRules.ts`, 순수 함수 · 단위 테스트)**
1. 출발 = Split + Padding 스키마 상자. 자모 효과 없음.
2. 규칙 1 · 획 사이 최소 틈: 첫닿자–홀자, 첫닿자–받침, 홀자–받침 잉크 사이 틈이 두께 × k 아래면 양쪽을 반반 밀어 벌린다. 10-02의 0.25에서 출발.
3. 규칙 2 · 홀자 기둥 높이 고정: 기둥은 글자 몸 위아래에 닿는다. 받침이 있으면 받침 윗면 여백만큼 올린다.
4. 규칙 3 · 받침 윗면 여백: 받침 상자 위 변 = 첫닿자 아래 변 + 두께 × m.
5. 규칙은 순서가 있고(2 → 3 → 1) 글자 몸 안에서만 움직인다. 한계에 닿으면 멈추고 표시한다.

**C. 안 하는 것** — 모델 파일 수정, 제품 화면 변경, 사용자 Δ 저장소 변경, 아래홀자 · 섞임홀자(결과를 보고 다음 플랜).
