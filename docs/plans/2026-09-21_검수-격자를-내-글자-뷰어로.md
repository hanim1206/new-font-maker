# 검수 격자를 내 글자 뷰어로

- **이번에 비교하는 것**: 검수 격자가 Noto와 얼마나 닮았는지 보여 주는 지금과, 내가 만든 글자를 한눈에 훑는 뷰어.
- **이번 승인으로 바뀌는 것**: 격자 칸이 시스템 글꼴 대신 내 획으로 그려진다. xor 색·범례·`추출 상태` 토글·파란 테두리·Noto 미리보기가 검수 탭에서 빠진다. 칸에 색은 없다. 격자가 `/api/noto-corpus` 없이 뜬다.
- **바뀌지 않는 것**: 표 구조(시트·축 배치·행열 묶음), 칸 탭 = 선택 · 다시 탭 = 자소 탭으로 이동, 저장소(`layoutDeltaStore`·`jamoStore`)와 production 값, 랩 페이지(`/noto-corpus-lab`)의 Noto 검수 기능.

출처: 주간 노트 W39 월 `검수탭 기능 변경` + 9/21 논의. 9/20 "검수는 격자만 남긴다"의 다음 걸음. [Noto 프리셋 정적 배포](./2026-09-21_Noto-프리셋-정적-배포.md)의 G1이 "검수 격자가 다른 API에 막힘"으로 열려 있는데, 이 플랜이 그 막힘을 없앤다.

## 지금 상태

**사실** (코드 읽기)
- 칸 글자는 `<strong>{character}</strong>` 시스템 글꼴 텍스트다(`NotoCorpusMatrix.tsx:131`). 아래 선택 카드 미리보기(`GlyphMini`)는 Noto 윤곽이다.
- 격자는 `/api/noto-corpus` 응답이 와야 뜬다(`ReviewWorkspacePage.tsx:80`, `rows.length > 0`). 글자 목록 11,172자는 앱이 직접 만든다(`allCorpusRows`). 응답은 추출 상태 색에만 쓰인다.
- 한 번에 보이는 칸은 시트 하나다. 가장 큰 배치(행 홀자 21 × 열 받침 28)가 588칸. 11,172칸을 한꺼번에 그리지 않는다.
- 내 획으로 글자 하나를 그리는 길은 이미 있다: `GlyphPreview`(`ShapeWorkspacePage.tsx:113`) = 자모 획 + `useContextPlacement`(모델 상자 + 저장된 Δ) + `SvgRenderer`. 글자별 Noto 윤곽을 받지 않는다.
- 글자 하나만 고치는 저장은 없다. 배치 Δ(`layoutDeltaStore`)도 자모 획(`jamoStore`)도 범위로 퍼진다.
- `NotoCorpusMatrix`는 랩(`/noto-corpus-lab`)과 같이 쓴다. `tierOf`·`toneOf`는 검수 탭만 넘기는 선택 prop이다.

**가설**
- 588칸 × (`useContextPlacement` + `SvgRenderer`)가 폰에서 버벅일 수 있다. G0에서 잰다. 느리면 보이는 칸만 그린다.

## 하려는 것

1. 칸 내용을 prop으로 받게 한다(`renderCell`). 검수 탭은 내 획 글자를, 랩은 지금처럼 텍스트를 넘긴다. `GlyphPreview`는 공용 파일로 뺀다.
2. 검수 탭에서 xor 색·범례·토글·파란 테두리와 설명 줄·`GlyphMini`·제목 옆 `Noto 고스트 · N자 추출`을 뺀다. 선택 카드 미리보기도 내 획으로. `useNotoXorMap`과 `/api/noto-corpus` 호출을 검수 탭에서 없앤다. 추출 상태가 없으니 칸 상태색·머리줄 막대·범례도 검수 탭에서는 안 보인다.

판단 변수 하나 = **격자가 내 글자 뷰어로 쓸 만한가**. 홈의 폰트 목록, 출력 화면, 글자별 Δ(직접 선택), OTF에 배치 Δ 반영은 이 플랜 밖이다. 손댄 곳 색 표시도 밖이다 — 글자별 Δ가 생기면 그 플랜에서 "이 글자만 따로 고침" 표시로 넣는다.
