# 대시보드 폰트 캐러셀 — `/fonts`를 없애고 넘기면 그 폰트로

- **이번에 비교하는 것**: 폰트 바꾸기를 지금처럼 새로 고침(`/fonts` → 고르기 → 다시 열기)으로 할지, 대시보드 캐러셀에서 넘겨 멈추면 그 자리에서 바꿔 끼울지.
- **이번 승인으로 바뀌는 것**: 대시보드 캐러셀이 진짜 내 폰트 목록(최대 3장 + `새 폰트`)이 된다. 멈춘 카드의 폰트가 새로 고침 없이 열린다. 카드 `…`의 이름 바꾸기 · 지우기가 동작한다. 로그인 뒤 첫 화면과 `/fonts`는 대시보드로 간다. 폰트마다 카드 문장 그림(미리보기)을 저장한다.
- **바뀌지 않는 것**: 계정당 3개 한도(DB 트리거), 소프트 삭제, 폰트 데이터 형식(`FontData`), 서버 저장 규칙(멈추면 10초 뒤 · `updatedAt` 충돌 검사), 탭 하나만 편집(편집 잠금).

배경: `/fonts`(`FontHomePage`)가 목록 · 만들기 · 이름 · 지우기 · 바꿔 열기를 다 하고, 대시보드 캐러셀은 지금 폰트 한 장 + `/fonts`로 가는 버튼뿐인 시안이다. 사용자는 한 화면을 원한다(2026-09-26). 바꿔 열기는 B(넘겨 멈추면 전환) + 미리보기 a(저장된 그림)로 정했다.

## 결정 (2026-09-26, 사용자)

| 무엇 | 결정 | 왜 |
|---|---|---|
| 전환 시점 | **넘겨서 멈추면** 그 폰트로 | 대시보드가 한 화면처럼 느껴진다. 탭 전환(A)보다 한 동작 적다. |
| 옆 카드 글자 | **저장해 둔 문장 그림** | 카드 문장은 지금 열린 폰트로만 그릴 수 있다. 저장할 때 같이 남긴 그림을 옆 카드에 쓴다. 안 연 새 폰트는 프리셋 그림. |

## 어떻게 (AI 안)

1. **미리 받기.** 대시보드가 열리면 `listFonts` + 각 폰트 `fetchFont`를 한 번에 받아 메모리에 둔다(폰트당 작은 JSON).
2. **멈추면 끼우기.** 스냅이 멈추고 짧게 조용하면(`scrollend` + 여유) → 떠나는 폰트 내용을 먼저 떼어 두고(`collectAccountFontData`) → 받아 둔 데이터로 `applyFontData` → 세션 · 이름표 · 편집 잠금을 새 폰트로 → 되돌리기 기록 비움. 서버에 올리는 건 뒤에서, **떼어 둔 순간의 폰트 id로 고정**.
3. **아래 섹션 전환.** 스타일 · 레이아웃 · 자소 섹션이 잠깐 흐려졌다가 새 폰트로 선명해진다.
4. **미리보기 저장.** 서버에 올릴 때 카드 문장 SVG를 같이 올린다. 저장 칸은 `font_projects.preview_svg`(새 열, 마이그레이션 하나 — 운영 Supabase에는 사용자가 적용).
5. **`/fonts` 걷기.** `FontHomePage`의 만들기 · 이름 · 지우기를 카드 · `새 폰트` 카드로 옮기고, `/fonts`는 `/dashboard`로 보낸다. 계정 칸 `1 / 1개` → `n / 3개`.

## 미결정

- **미리보기 저장 칸.** 새 열 `preview_svg`(AI 추천 — 목록 받을 때 데이터 전체를 안 받아도 된다) vs `FontData` 안 한 칸(마이그레이션 없음, 목록에서 쓰려면 데이터 전체를 받아야 한다).
- **전환 중 떠나는 폰트 저장 실패.** 가설: 사본에 `pending`으로 남기고 다시 올 때 먼저 올린다(지금 `uploadPendingCopy`와 같은 길). 다만 사본이 폰트 하나 분이라, 폰트별 대기 사본이 필요한지 D0에서 확인.
