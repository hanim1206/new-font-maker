# 글로벌 스타일 공간

- **이번에 비교하는 것**: 글로벌 스타일을 획 편집 화면 하단의 작은 패널로 둘지, 어느 모드에서든 여는 전용 공간으로 둘지.
- **이번 승인으로 바뀌는 것**: 입구가 셸 머리에 늘 보인다(레이아웃 모드에서도 열린다). 연 동안 캔버스가 비키고 문장 줄이 한 줄 그대로 크게 자라 미리보기를 맡는다. 패널은 문장 아래를 다 쓰고 탭은 넷(글자 네모꼴 · 획 스타일 · 굵기 · 부리). 기울기는 숨기고, 네모형 붓촉 · 레거시 스냅 획은 고르기에서 뺀다. 부리가 패널로 들어온다.
- **바뀌지 않는 것**: 저장 형식(`globalStyleStore`), 미리보기 → 손 떼면 적용 → 되돌리기 흐름, 옛 단독 화면(`/calibration`)의 선택지와 동작, 네모꼴 · 붓 · 절단 끝 · 부리의 계산.

앞 플랜 `2026-09-21_전역-스타일에-굵기와-기울기.md`의 하단 패널 탭을 이 공간이 대체한다. 그 플랜의 기반(읽는 길 하나, fit 잉크 굵기, OTF 기울기)은 그대로 쓴다.

## 게이트

| 게이트 | 닫는 조건 |
|---|---|
| D0 계약 | 입구는 `MobileWorkspaceShell`의 `tools` 자리(되돌리기 앞). 연 동안은 어느 모드에서 왔든 같은 화면이고 닫으면 있던 모드 그대로. 캔버스는 렌더하지 않는다. 문장 글자는 em을 따라 자란다(평소 24px → 140px). 제품 선택지 제한은 `BrushStyleTrackpad productOptions`로만 하고 저장된 값(네모형 · 레거시)은 그대로 그려진다. 부리는 `StemBeakControls`가 맡고 랩과 같은 그림(`BeakShapeThumb`)을 쓴다. 패널 안 생김새는 `GlobalStyleMode.module.css`의 `.panel` 아래에서만 다룬다. |
| G0 대표 | `한`을 레이아웃 모드로 열고 → 입구 → 네 탭을 돌며 굵기 700 · 납작형 · 각진 부리를 준다 → 닫으면 레이아웃 모드. 스크린샷. |
| G1 홀드아웃 | 획 고치기에서 열어도 같다. 옛 단독 화면의 붓촉 · 절단 · 레거시 · 네모꼴 e2e가 그대로 통과한다. |
| G2 전수 | `tsc -b` · eslint · vitest · 셸 e2e 전부. 폰 실기에서 문장 자라는 움직임과 채움 막대 조작. |
| G3 사용자 검증 | 사용자가 직접 돌려 보고 판정. |

## 이 뒤에 오는 것 (이번 플랜 아님)

1. 네모꼴을 줄이면 글자도 같이 줄게(지금은 모델 상자 글자가 안 따라온다).
2. 절단 끝을 홀자 줄기에도.
3. 붓촉 모양을 직접 그리기.
4. 자리별 부리(닿자 · 가로홀자 · 세로홀자).
5. shadcn `ui/`를 죽은 폴더(`src/components/`) 밖 공용 자리로 옮기기 — 사용자 결정 "다 가져와". 이번엔 기존 패턴(CSS Modules + 토큰)으로만 만들었다.
6. 셸 전체의 색 · 분위기. 이번에 패널 안에서만 파랑을 빼고 검정 · 회색으로 갔다.

## 진행 기록

### 2026-09-22
- **사실 — 경위**: 밤새 캔버스 아티팩트와 로컬 시제품으로 시안을 여럿 만들었으나(카드 허브 · 계기판 · 격자판 · 색 잔상 · 다이얼 원판 · 호 · 유리) 전부 퇴짜. 사용자 결정: 새 디자인을 접고 "지금 구현된 UI 느낌대로 기능 중심으로" 만든다. GPT 세션의 `/global-style-preview` 시안도 "AI 같고 개성 없다"로 보류.
- **사실 — 구현**: 머리의 입구(`tools`), 스타일 공간(캔버스 비킴 + 문장 줄 140px 한 줄 가로 스크롤, 260ms 전환, 동작 줄이기 대응), 탭 넷, 굵기 100 단위 눈금, 기울기 UI 숨김, 제품 선택지에서 네모형 · 레거시 뺌, 부리 탭(모양 고르면 바로 적용, 크기 · 각도는 손 떼면 적용, 되돌리기 `beak` 기록), 패널 생김새(밑줄 탭, 테두리 상자 없음, 회색 길 위 흰 알약, 파랑 없음), 슬라이더는 손잡이 없는 채움 막대(웹킷은 긴 그림자로 채움, 파이어폭스는 `::-moz-range-progress`).
- **사실 (결정, 사용자)**: 슬라이더는 셋 중 채움 막대. 글로벌 편집에서는 캔버스를 치우고 문장을 한 줄 · 가로 스크롤 · 아주 크게. 결과를 보고 "이거다".
- **G0 · G1**: 실제 앱에서 열고 닫기 · 네 탭 · 굵기 700 · 납작형 · 절단 끝 · 부리를 눌러 보며 스크린샷 확인. `global-style-tone.spec.ts` 5개 통과. 격리 워크트리(HEAD + 내 변경만)에서 붓촉 · 절단 · 레거시 · 네모꼴 간격 e2e 14개 통과(패널 생김새와 문장 줄 변경 전 시점).
- **사실 — 남의 실패**: 작업 트리에서 `design-body-internal-spacing`(에의 ㅔ 가로점)이 깨지는데 격리 상태에서는 통과한다 — 다른 세션의 미커밋 변경 탓. `design-body.spec`의 `폰트 전체와 현재 레이아웃…`은 HEAD에서 이미 깨져 있다.
- **미결정**: 문장 글자 크기 140px(한 화면에 두 글자 반)이 맞는지, 패널 아래 빈자리를 어떻게 쓸지. 절단 끝 각도판과 붓촉 그림 버튼의 생김새가 아직 어색하다.
- **안 한 것**: G2 전수(전체 vitest · 셸 e2e 전부 · 폰 실기). `docs/specs/화면/자소편집.md` 8번 절 갱신은 다른 세션이 그 파일을 고치는 중이라 미뤘다. 커밋 전.
