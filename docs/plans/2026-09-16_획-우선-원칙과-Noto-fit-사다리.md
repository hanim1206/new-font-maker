# 획 우선 원칙과 Noto fit 사다리

[2026-09-15_Noto-기준선-기반-프리셋-폰트-개발-플랜](./2026-09-15_Noto-기준선-기반-프리셋-폰트-개발-플랜.md)의 다음 단계. 코퍼스 측정을 앱에 어떻게 들여올지 오늘 확정한 원칙과, 그 위에 하루 만에 올린 것.

## 원칙 (확정)

- 이 앱은 모든 자소를 **획(centerline)으로 직접 그리고 편집**하는 앱이다.
- **Noto 윤곽은 편집 대상이 아니다.** 측정 원천 · 고스트(비교 오버레이) · 룩(렌더 스타일) 세 역할만. 잉크 union에 Noto 윤곽이 들어가면 안 된다.
- 자소 하나를 그리면 문맥별 기준선 공식으로 위치·크기·비율만 변형되고 **두께는 고정**된다. 앵커는 좌표가 아니라 rail 참조로 저장한다. 문맥별 두께·곡률 보정은 변화량 모델 효과항 전파로 얹되 기본 0.
- 폐기: 윤곽 stretch 편집(`notoBoundMaster` 결속은 랩 전용), 닿자 윤곽을 잉크에 섞는 안, 오프셋 결속 같은 윤곽 편집 투자.

왜: 윤곽 통짜를 고무줄처럼 늘리면 두께가 부산물로 따라 변한다. 획 모델이어야 두께와 위치가 분리된다.

## 사다리

1. 홀자 → centerline 마스터. Noto 측정(기준선·두께)이 초기값.
2. 닿자 → centerline 마스터. 곡선은 핸들·곡률 측정으로 fit.
3. Noto 고스트를 반투명으로 깔고 내 획이 얼마나 벗어났는지 수치로 본다. 고스트는 표시 전용.
4. `StrokeRenderStyle`에 Noto Sans 룩 추가(끝맺음·꺾임·굵기 대비).

리스크: 닿자 fit이 Noto 디테일(ㅇ 원형, ㅅ 테이퍼, 꺾임 곡률)을 못 잡는 부분 → 룩으로 갈지 획 모델 확장(면·테이퍼)으로 갈지는 그때 결정. 면 조형은 별도 트랙([2026-08-22_그리드-점유-기반-면-생성](./2026-08-22_그리드-점유-기반-면-생성.md)).

## 오늘 올린 것

**입력** — 58MB 글자별 윤곽 export는 dev API로 글자 하나씩(~5KB) 받고 IndexedDB에 둔다. 캐시 키에 추출 stageKey를 넣어 버전이 바뀌면 자동으로 다시 받는다. 변화량 모델도 예측 필드만 추려(928KB) 같은 캐시.

**생성 엔진**
- Noto 윤곽 → 폴리곤 (`notoOutlineInk`). 잉크가 아니라 고스트·측정용. union 안 탐.
- 홀자 fit (`notoMedialMasterFit`): 역할면·가시 구간·두께에서 줄기·보 중심선을 읽어 part-local RailGrid + centerline element로 다시 그린다. slot = 홀자 잉크 박스, 두께는 element에만. 직교 획 끝은 상대 중심선에 붙인다(보는 기둥 중심에서 시작).
- 매핑: 축별 필요값(중심선·끝)을 core rail 5개에 순서 배정. 양끝 outer, 안쪽 1개면 center, 2개면 inner, 3개면 inner+center.
- slot·rail 값은 변화량 모델 예측에서(11,172자). 승인 57자는 검증셋. 모델에 `spanFrom/spanTo` 타깃 추가.
- 닿자 fit (`notoComponentFit`): Noto는 닿자 네 변만 재므로 **앱 현재 획을 seed**로 모델 박스에 축별로 맞춘다. 중심선 상자 = 잉크면 − 두께/2.
- 예측 수식(대표값+효과+셀보정)은 `notoVariationModel` 한 곳. 홀자별 역할 구성표는 corpus 전수 예외 0.

**편집** — 검수 탭 글자 화면(`/workspace/review/glyph?char=가`). 회색 고스트 위에 파랑(홀자 획)·초록(닿자 획). 홀자 rail 5개 + 닿자 네 변을 캔버스 드래그·자(RulerStrip)·칩으로 옮긴다. 두께 고정, 순서 위반은 마지막 유효값. 세션 임시, 저장 없음. 다이얼은 뺐다 — 기준선은 자, 다이얼은 굵기·각도용.

**검증 리포트** (게이트 아님, corpus `analysis/`)
- 홀자 직접 fit xor: ㅏ·ㅗ·ㅘ세로부 9%. 남은 9%는 round cap 삐짐 + Noto 끝맺음 = 룩 영역.
- 모델 rail fit: rail 오차 중앙 0.4~3.4u, p95 4~26u. 꼬리가 문맥 예외 = 자소 오버라이드 후보.
- ㅘ 가로부는 65%였다가 30%. 원인은 Noto 섞임홀자 보의 윗변이 기울어져 추출기 `visibleSpans`가 스텁만 잡은 것. 재추출·재승인 없이 `measure_role_extents.py`(contour 투영 extent, 9초)로 보정하고 모델이 그걸 쓴다. 남은 30%는 기울어진 윗변 자체.
- 닿자 박스 fit: 모델 박스 네 변 오차 중앙 0.8u. 앱 기본 획 xor — ㄴㄷㄹㅁㅇㅌ 8~11%, ㄱ 19%, ㅂ 28%, ㄸ 29%, ㅃ 41%, ㅉ 42%, ㅍ 44%, ㅈ 57%, ㅆ 67%, ㄲ 73%, ㅊ 74%, ㅎ 97%, ㅅ 102%. 이 순서가 2단계-b(획 다듬기) 우선순위.
