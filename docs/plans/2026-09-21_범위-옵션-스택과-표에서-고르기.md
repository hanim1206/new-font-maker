# 적용 범위: 옵션 스택과 표에서 고르기

- **이번에 비교하는 것**: 범위를 칩 한 줄(`이 레이아웃 · 이 자모만` + 찬 칩)로 고르고 하단에 표본 8장이 붙는 지금과, 범위가 **옵션 박스로 쌓이고** 닿는 글자는 **상단 한 줄**로 올라가며 좁히기는 **검수 표를 그대로 쓴 풀스크린**에서 하는 것.
- **이번 승인으로 바뀌는 것**: 범위 띠 → 옵션 스택, 표본 카드 줄의 자리(하단 → 상단), `이 자모만` 시트 → 범위 고르기 화면(추천 칩 + `NotoCorpusMatrix`), 배치 Δ의 저장 키, 이용제 구조군의 출처(코드 상수 → 옵시디언 `자모 데이터/`).
- **바뀌지 않는 것**: Δ의 뜻과 단위(em, 변 고정 `{ at }` 포함), 프리셋 오버라이드와 사용자 Δ의 분리, 획 편집·문장 보정(`/`) 화면, 적용 전 세션 편집 모델(복원·Undo).

출처: 9/21 논의. 앞선 결정 둘을 이어받는다 — `전체`는 고르는 범위가 아니다(오늘 구현, 아래 사실), 범위는 더해지는 층이고 좁은 층이 위다(`2026-09-21_레이아웃-적용-범위-이-자모만.md`). 목업: 세션 scratchpad `scope-stack-mockup-2.html`(표본 자리 네 안) · `scope-picker-mockup.html`(추천 칩 + 표).

## 지금 상태

**사실**
- `전체`는 오늘 고를 수 없게 됐다. 저장된 옛 Δ가 있을 때만 읽기 전용 칩으로 서고 ×로만 지운다(`layoutOverrides.ts` `scopeChipsOf`, `LayoutScopeStrip`). 스토어의 `all` 층과 `effectiveLayoutDelta`는 그대로다.
- 저장 키는 세 층이다: `all` · `layers[contextId]` · `jamo[contextId][부품:자모]`. 층 이름이 곧 넓이 순서다.
- `NotoCorpusMatrix`에 **`renderCell`**(검수 탭이 프로젝트 획으로 그린 글자를 넘긴다)과 **`variant: 'viewer'`**(상태 표시 없이 격자가 부모 높이를 다 씀)가 이미 있다. 축 배치 3종·시트 탭·방향키·`크게` 토글도 있다.
- 그 표의 홀자 축은 `세로 9 / 가로 5 / 혼합 7`, 받침 축은 `없음 / 홑·쌍 16 / 겹 11`로 **묶여 있고 그룹 머리를 그린다**. 즉 `이 레이아웃`(홀자 계열 × 받침 유무)은 표에서 연속 블록 하나다.
- e2e `workspace-jamo-layout`이 "첫 화면 390×844에서 범위 띠와 표본 다섯 장이 스크롤 없이 보인다"를 잰다. 표본이 상단으로 가면 이 조건을 고쳐 써야 한다.
- 표본 카드는 `propagationCandidates`가 만든다. 범위가 `layer`면 같은 문맥, `jamo`면 잡은 부품의 자모가 같은 글자.
- 이용제 구조군은 **두 벌로 산다**. 옵시디언 `자모 데이터/<자모>.md` 머리말(`문헌_최종_가로_첫닿자` 등 넷, `문헌_높이`, `문헌_속공간_그룹`)과 `ReferenceGroupLabPage.tsx`의 상수 배열. 오늘 대조한 다섯 자모(ㄱ·ㅅ·ㅋ·ㄹ·ㅎ)는 값이 같다. 필드 뜻은 옵시디언 `2026-09-08_자모-문헌분류-필드-설명.md`.

**가설**
- Δ가 10~20u(0.01~0.02em)라 표의 작은 칸에서는 차이가 안 보인다. 칸이 답하는 질문은 "이 범위에 어떤 글자가 들었나"고, "Δ가 어떻게 먹었나"는 상단 한 줄과 칸 하나를 크게 보는 걸로 답한다.

## 하려는 것

**A. 결과는 위로** (`GlyphLayoutEditor`)
1. 상단 두 줄: `내 문장`(안 바뀜, 지금 글자 강조) + `닿는 글자`(지금 켠 옵션의 표본, 범위 따라 갈림). 두 줄은 **글자 크기가 같고** 줄 높이는 고정한다(화면이 안 출렁이게). `닿는 글자`는 다섯 장을 보이고 옆으로 밀어 더 본다.
2. 하단 표본 카드 줄을 없앤다. 카드를 눌러 그 글자를 여는 동작은 상단 줄이 물려받는다.
3. 적용 직후에는 문장 줄에서 방금 범위에 든 글자를 잠깐 표시한다(적용의 신호).

**B. 옵션 스택** (`LayoutScopeStrip` → `LayoutOptionStack`)
1. 박스 하나 = 저장 항목 하나. 머리에 그 레이아웃 몬드리안(자모 범위면 그 부품만 진하게), 이름은 고른 범위에서 자동 생성, 옆에 닿는 글자 수와 Δ 한 줄, `더 보기 ▸`와 `×`.
2. 맨 위는 `전체`(읽기 전용 기본값). 그 아래 넓은 것 → 좁은 것. 순서는 **닿는 글자 수**로 정한다(층 이름이 아니라).
3. 박스는 **범위를 고르는 순간** 생긴다(점선 = 적용 전). Δ 0인 박스는 범위가 바뀌거나 글자를 떠나면 사라진다.
4. 넷 이상이면 접기가 기본.

**C. 범위 고르기 화면** (`NotoCorpusMatrix` 재사용, `variant: 'picker'`)
1. 옵션의 `더 보기`가 풀스크린으로 연다. 머리에 몬드리안·이름·닿는 글자 수·Δ.
2. **추천 칩**: 지금 고친 것에서 나온다 — 잡은 rail 역할(`바깥기둥 있는 홀자`), 잡은 부품의 자모(`ㄱ·ㅋ 첫닿자`), 받침 묶음(`홑받침만`), 그리고 아래 **E의 구조군·속공간·높이**. 칩은 **표를 켜 줄 뿐** 범위를 확정하지 않는다. 칩 둘을 누르면 합치지 않고 **갈아치운다**(같은 칩을 다시 누르면 꺼진다).
3. 표: 행·열 **머리와 그룹 머리**를 눌러 범위를 토글한다(칸 개별 선택은 범위가 아니다 — 아래 D의 규칙과 맞춘다). 켜진 칸은 Δ를 얹어 그린다.
4. 칸 하나를 누르면 그 글자를 크게 본다(범위는 안 바뀐다). Δ가 10~20u라 칸 크기로는 차이가 안 보여서 필요한 길이다.
5. 세 번째 축은 시트 탭 그대로 쓴다.
6. 발에 `취소` · `이 범위로`. 확정하면 옵션 박스의 범위와 이름이 바뀐다.

**D. 저장 키 일반화** (`layoutDeltaStore`)
1. 세 층 대신 **자모 집합의 곱** 하나로: `{ 홀자계열?, 받침?, CH?: [...], JU?: [...], JO?: [...] }`. `전체`는 조건 없음, `이 레이아웃`은 계열+받침, `이 자모만`은 거기에 자모 목록이 붙은 것.
2. 겹칠 때는 **닿는 글자가 적은 쪽이 위**. 변 고정(`{ at }`)이 값을 교체하는 규칙은 그대로.
3. 옛 저장분(`all` · `layers` · `jamo`)은 읽을 때 새 규칙식으로 옮긴다.

**E. 추천 조합의 출처는 레포 JSON, 옵시디언은 거울** (`src/data/` + 새 스크립트)
1. 원본은 `src/data/jamoLiteratureGroups.json`. 자모 19개 × 기준 넷 + 높이 + 속공간. 필드는 영문으로 쓰고 볼트 이름과 짝은 스크립트가 들고 있는다 — `initialHorizontal` `initialVertical` `finalHorizontalMixed` `finalVertical` `height` `inkSpaceGroup` ↔ `문헌_최종_가로_첫닿자` `문헌_최종_세로_첫닿자` `문헌_최종_가로섞임_받침닿자` `문헌_최종_세로_받침닿자` `문헌_높이` `문헌_속공간_그룹`. 첫 값은 지금 옵시디언 노트와 `ReferenceGroupLabPage.tsx` 상수에서 옮겨 온다(오늘 다섯 자모 대조 결과 둘이 같다).
2. 이 JSON으로 만드는 추천 칩 셋: **구조군**(문맥에 맞는 기준을 자동으로 고른다 — 세로모임+받침 첫닿자면 `세로_첫닿자`), **속공간**(`S4`), **높이**(`3줄`).
3. `ReferenceGroupLabPage.tsx`의 상수 배열은 같은 JSON을 읽게 바꾼다. 두 벌을 한 벌로.
4. 거울: `npm run jamo:groups:docs`가 JSON → 옵시디언 `자모 데이터/자모 구조군 표.md` **한 장**을 다시 쓴다(19행 × 기준 넷 + 높이 + 속공간). 자모별 노트 19개는 **안 건드린다** — 사용자가 쓴 글과 `근거` 링크가 있는 곳이고, 그 머리말은 이제 출처가 아니라 옛 기록이다(표 맨 위에 그 사실을 한 줄 적는다). **사용자가 `문서화해`라고 할 때만 돌린다**(자동 아님).

## 진행 기록

### 2026-09-21

**사실**
- `전체` 칩 제거 구현·테스트 통과(`layoutOverrides.ts`, `LayoutScopeStrip.tsx`, `reviewPropagation.ts` 주석, `layout-overrides.test.ts`, e2e 3곳). 저장 층은 그대로 두고 칩만 읽기 전용으로. e2e는 옛 전체 Δ를 `addInitScript`로 심어 연다(이동마다 다시 돌므로 비어 있을 때만 쓴다).
- 목업 두 개로 표본 자리(네 안)와 범위 고르기(추천 칩 + 표)를 비교했다. 사용자 선택: 표본은 상단, 좁히기는 풀스크린 표, 칸에 글자.

**결정**
- 표 칸 누르기 = 그 글자 크게 보기. 추천 칩은 갈아치움(토글). 상단 `닿는 글자`는 다섯 장 + 옆으로 밀기, 글자 크기는 문장 줄과 같게.
- 구조군의 원본은 **레포 JSON**, 옵시디언 `자모 데이터/`는 거울이고 표 한 장(`자모 구조군 표.md`)으로 받는다. 자모별 노트 19개는 안 건드린다. JSON 필드는 영문, 볼트 이름과의 짝은 거울 스크립트가 들고 있는다. 사용자는 볼트를 읽기만 한다.
- **뒤집힘**: 볼트 `자모 데이터/` 노트가 구조군의 출처였는데 이제 생성물이 된다. `문서화해` 때 `결정과 뒤집힘.md`에 한 줄 올린다.
- **D 구현됨** — `scopeRule.ts`(판정·정규화·키·글자 수·넓이 비교·이름·옛 자리 이전) + `layoutDeltaStore`를 규칙식 한 층(`rules`)으로 교체. 소비처 다섯(`LayoutContextCards` · `LayoutScopeStrip` · `layoutOverrides` · `ReviewPropagationCards` · `GlyphLayoutEditor`)은 화면 동작을 그대로 두고 자리만 옮겼다. 옛 저장분은 읽을 때 `rulesOfPersisted`가 옮긴다(호환 아님). `PropagationScope`는 저장 개념이 아니라 표본 묶음을 고르는 말이라 `reviewPropagation`으로 옮겼다.
  - 유효 Δ 누산은 `undefined`에서 시작해야 한다 — `{}`부터 더하면 `addContextBoxDelta`가 안 쓰는 `medial: {}`를 붙인다.
  - 계약에 한 줄 더함: 자모를 여럿 고르면 **자모마다 규칙 하나씩** 저장한다(칩 ×가 하나만 지워야 해서). 합치기는 B에서.
  - 검증: `tsc -b` · `npm test`(965 passed, 기존 실패 둘은 내 파일 아님 — digest·artifact 동결) · e2e `workspace-jamo-layout` 27/28(나머지 하나는 다른 세션 영역의 flaky, 단독 재실행 2회 통과).
- **B 구현됨** — `LayoutOptionStack`이 가로 범위 띠(`LayoutScopeStrip`, 지움)를 대신한다. 범위 고르기 버튼 두 개(`이 레이아웃` · `이 자모만`) 아래 옵션 박스가 세로로 쌓인다. 박스 = 저장 규칙 하나 + 지금 고른 범위(점선, `아직 고친 것 없음`). 순서는 닿는 글자 수 내림차순이라 `전체`가 맨 위. 이름은 `ruleName`에서 짓되 이 레이아웃 앞머리는 떼고 꼬리만 남긴다. 박스를 누르면 그게 범위가 되고 자모 조건이 있으면 그 부품이 켜진다.
