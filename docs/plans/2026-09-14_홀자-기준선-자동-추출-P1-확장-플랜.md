# 홀자 기준선 자동 추출 P1 확장 플랜

## 목적

P0에서 검증한 유한 구조면 추출을 남은 현대 홀자 14자로 확장한다. 사용자는 계속 `/font-guide-lab?font=...` 한 화면에서 폰트·첫닿자·홀자·받침을 고르고, 현재 완성 글자의 실제 윤곽에서 계산된 후보와 자동 포기를 본다.

P1 결과도 `ExternalObservation` 분석 후보다. 생산 `JamoMaster`, `LayoutProfile`, `ContextPreset`, OTF 값으로 자동 승격하지 않는다.

상태: D1·G0·G1·G2·G3·G4 완료. v9는 혼합 바탕 줄기가 선택 보 양끝에서 보 폭의 8% 이상 안쪽에 결속되는지 검증한다. 두 폰트 전체 batch, 변경 구조군 자체 화면검증, API·parser·cache·프리셋 입력 교체, `풔·풕` 사용자 확인까지 통과했다.

## 시작 조건

- P0 G0~G4 완료.
- 정확한 SHA의 Noto Sans KR·나눔고딕에서 7홀자, 첫닿자 19자, 받침 없음/ㄱ을 검증했다.
- 사용자가 나눔고딕 G4 위험 표본 24카드를 확인했다.
- runtime은 글자별 contour 번호가 아니라 contour·가시 선분군의 구조 특징을 읽는다.

## 범위

추가 홀자는 `ㅐ·ㅑ·ㅒ·ㅔ·ㅕ·ㅖ·ㅙ·ㅚ·ㅛ·ㅝ·ㅞ·ㅟ·ㅠ·ㅢ` 14자다.

- 폰트: 고정 Noto Sans KR·나눔고딕만.
- 첫닿자: 현대 첫닿자 19자.
- 받침: 없음과 ㄱ만.
- 추가 batch: 폰트당 `19 × 14 × 2 = 532`글자.
- 화면: 기존 Font Guide Lab 유지. 별도 랩을 만들지 않는다.
- 캐시: 파일 SHA·축·codepoint·path SHA·추출기·역할 버전 identity 유지.

P1에서 제외:

- ㄱ 외 받침 26자
- 임의 폰트 업로드
- variable font 축 선택
- 생산 설계값 자동 생성·일괄 반영

## 먼저 고칠 역할 계약

현재 화면 모델은 21홀자 버튼과 다중 역할 ID를 이미 갖지만 backend 추출기는 P0 7홀자만 지원한다. 확장 전 아래 불일치를 먼저 닫는다.

- `ㅐ·ㅔ`는 긴 기둥 둘과 보 하나다. `innerPillar`·`outerPillar`·`primaryBeam`을 각각 둔다.
- `ㅒ·ㅖ`는 긴 기둥 둘과 보 둘이다. `innerPillar`·`outerPillar`·`upperBeam`·`lowerBeam`을 각각 둔다.
- `ㅑ·ㅕ`는 긴 기둥 하나와 보 둘이다.
- `ㅛ·ㅠ`는 왼쪽·오른쪽 짧은 세로줄기 각각의 면·진행 방향 끝과 주 보를 둔다.
- `ㅙ·ㅞ`는 바탕 줄기, 안쪽·바깥쪽 긴 기둥, 공간상 위·아랫보를 분리한다.
- `ㅚ·ㅟ`는 바탕 줄기, 바깥 긴 기둥, 주 보를 둔다.
- `ㅝ`는 바탕 줄기, 바깥 긴 기둥, 위·아랫보를 둔다.
- `ㅢ`는 바탕 줄기 없이 바깥 긴 기둥과 주 보만 둔다.

각 구조 요소는 `면 위치 + 실제 보이는 복수 구간`을 독립 후보로 낸다. 합쳐진 윤곽의 숨은 접합점은 복원하지 않는다. 휜 면의 시작쪽 국소 접선은 홀자 구조와 두 폰트 증거가 맞는 경우만 명시적으로 추가한다.

## 실행 게이트

### D1 — 역할 정의 정합화

TypeScript 역할표·Python 역할표·응답 parser·UI 라벨을 같은 계약으로 맞춘다. 특히 `ㅐ·ㅔ·ㅒ·ㅖ`의 누락된 안쪽기둥을 먼저 보강한다. 역할 존재 여부와 방향을 단위 테스트로 고정한다.

완료 조건: 21홀자 전부가 구조 요소 수·방향·면 방향을 결정적으로 반환한다. 없는 요소에 0을 넣지 않는다.

완료: 2026-09-14. TypeScript·Python 역할표를 21홀자로 맞췄다. `ㅐ·ㅔ`에 안쪽·바깥쪽 기둥과 주 보, `ㅒ·ㅖ`에 두 기둥과 두 보를 명시했다. `ㅛ·ㅠ`의 좌우 짧은 세로줄기와 끝 역할, 혼합 홀자의 바탕 줄기·안쪽·바깥쪽 기둥을 보존한다. candidate parser와 UI 라벨도 새 요소 ID를 지원한다. `ㅘ lowerBeam`에 승인된 국소 접선 provenance는 다른 `lowerBeam`에 자동 적용되지 않는다. Python 13개·관련 TypeScript 6개·targeted lint·build가 통과했다.

### G0 — 14홀자 구조 대표

첫닿 ㄱ, 받침 없음/ㄱ, 두 폰트에서 14홀자 56글자를 계산한다. 에이전트가 모든 후보선을 화면에서 먼저 확인하고 잘못된 역할 가설·과도한 포기·곡면 정책 후보를 분류한다.

완료 조건: crash·NaN·중복 역할·근거 누락 0건. 잘못된 역할은 threshold 조정 전에 구조 가설 원인으로 기록한다.

완료: 2026-09-14. Noto·나눔고딕에서 각각 28글자·96요소, 합계 56글자·192요소를 계산했다. v3 usable은 Noto 40, 나눔고딕 39로 합계 79/192이며 단순 구조 `31.73%`, 혼합 구조 `52.27%`다. 두 전체 contact sheet에서 후보 79개와 자동 포기 113개를 전수 확인했고 잘못된 역할 선택은 0건이다. 포기는 v3에 `innerPillar`, `leftStem`, `rightStem` scorer가 없고 추가 겹보·혼합 바탕보를 구분하지 못해 발생했다. 새 홀자에 `ㅘ` 국소 접선 정책을 복제하지 않았으며 Noto의 곡면 6개는 `non-scalar-face`로 유지했다. 결과는 `medial-p1-g0-baseline.v1.json`의 agent-reviewed diagnostic baseline으로 기록했다.

### G1 — 추출기 v4

다중 기둥·다중 보·쌍줄기 역할 점수를 구현한다. P0 v3 좌표와 포기 결과는 회귀 고정한다. 의미나 threshold가 바뀌므로 추출기 버전을 v4로 올려 기존 browser cache와 분리한다.

완료 조건: 글자별 contour ID·수동 좌표표 없이 G0 구조 대표를 재현하고 P0 회귀를 깨뜨리지 않는다.

완료: 2026-09-14. `geometric-role-matcher-v4`가 긴 기둥의 상대 순서, 기둥에 붙은 겹보, 주 보에 붙은 좌우 쌍줄기, 바탕 줄기와 연결된 혼합 보를 구조군별로 고른다. 글자별 contour ID나 좌표표는 쓰지 않는다. Noto는 96/96, 나눔고딕은 84/96 후보를 냈고 contact sheet 전수검사에서 후보 180개의 역할 오선택은 0건이었다. 나눔고딕의 둥근 혼합 바탕보 12개는 평평한 국소 지지가 10 unit 미만이라 `non-scalar-face`로 유지했다. P0 승인 28요소 좌표·포기 상태는 exact 회귀를 통과했다. 결과는 `medial-p1-g1-v4.report.v1.json`에 기록했다.

### G2 — 두 폰트 전체 batch

두 폰트에서 추가 532글자씩 검사한다. 전체 생성률 하나로 뭉개지 않고 `겹기둥`, `겹보`, `쌍줄기`, `혼합` 구조군별 후보율과 confidence를 기록한다.

완료 조건:

- crash·NaN·역할 계약 위반·근거 누락 0건
- high-confidence 오선택 0건
- 구조군별 usable 후보율 80% 이상
- 기준 미달 구조군은 지원했다고 표시하지 않고 자동 포기 유지

완료: 2026-09-14. `geometric-role-matcher-v9`는 혼합 바탕 줄기가 선택 보 양끝에서 보 폭의 8% 이상 안쪽에 있어야 같은 홀자 구조로 인정한다. Noto의 오염 11문맥·22요소만 교정됐고 나눔고딕 결과는 변하지 않았다. 두 폰트 합계 1,064글자·3,648요소가 모두 usable이며 수치·역할 계약·근거·구조·방향·스캔 위반은 0건이다. 변경 영향권 `ㅙ·ㅚ·ㅝ·ㅞ·ㅟ` 10개 전수 시트의 380카드·1,520후보를 에이전트가 확인해 오선택 0건을 기록했다. 보고서는 `medial-p1-g2-v9.report.v1.json`이며 사용자 검토 전 상태다.

### G3 — 통합 화면·캐시

기존 21홀자 버튼에서 추가 14홀자 API 후보를 연다. Noto G0 gold는 기존 7홀자에만 표시하고, P1 후보를 gold처럼 보이지 않게 한다. 부분 cache miss·빠른 선택·새로고침을 확인한다.

완료: 2026-09-14. 기존 URL과 21홀자 화면을 유지하면서 API·parser·browser cache identity를 v9로 교체했다. v4·v6·v7·v8은 프리셋 입력에서 차단한다. Noto ㄱ의 자동 후보 28자는 좌표·reference mode·anchor·가시 구간 digest가 기존 사용자 확인값과 완전히 같을 때만 검토 상태를 승계한다. 실제 로컬 화면에서 `풔` 줄기 x380·바탕 보 y556, `풕` 줄기 x370·바탕 보 y437을 확인했다.

### G4 — 사용자 검증

에이전트 화면 전수검사 뒤 구조군별 위험 표본만 사용자에게 보여 준다. 사용자 확인 전 P1을 완료 처리하지 않는다.

완료: 2026-09-14. 앞선 `뚀·퓩·뫠·궥` 확인은 그 네 글자 범위로 보존한다. v9 변경 구조군 380카드·1,520후보 에이전트 전수검사 뒤 사용자가 실제 `Noto · 방향 스캔` 화면의 `풔·풕`을 확인했다. 두 글자 모두 초성 `ㅍ` 중간획이 아니라 홀자 바탕 보·줄기를 골랐다. 보고서는 `user-reviewed-diagnostic`, `userReviewed=true`로 닫되 생산값 승인은 아니다.

## 후속 작업

`닿자 구조면 자동 추출 P0`는 별도 세션에서 계속 진행한다. 홀자 v9 G4가 끝났으므로 공용 Font Guide Lab UI와 cache identity 병합 조건이 열렸다. 레거시 첫닿·받침 숫자는 복구하지 않으며 색면은 승인된 관측면에서만 파생한다.
