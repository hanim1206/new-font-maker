# 관리자 테스트 현황

- **이번에 비교하는 것**: 테스트 결과를 터미널에서만 보는 지금 vs 개발 서버 관리자 화면에서 항목과 진행 단계를 실시간으로 보는 것.
- **이번 승인으로 바뀌는 것**: 관리자에 `테스트` 메뉴가 생긴다(개발 서버에서만). vitest · playwright가 돌 때 진행 파일을 쓴다.
- **바뀌지 않는 것**: 테스트 내용과 명령(`npm test` · `test:smoke` · `test:e2e`), 터미널 출력, pre-push 훅, 배포된 관리자 화면.

## 왜

사용자 질문(10-03): AI가 돌리는 단위 · 스모크 · e2e에 어떤 항목이 있고, 지금 어느 단계인지 관리자 화면에서 보고 싶다. 볼 곳은 개발 서버 관리자만으로 정했다(배포 화면 · Supabase 안 씀).

## 모양(제안 — D0에서 확인)

1. **기록**: vitest와 playwright에 리포터를 하나씩 덧붙인다. 기본 출력(`line`)은 그대로 두고, 파일 하나가 시작 · 끝날 때마다 `.test-runs/<종류>.json`(종류 = unit · smoke · e2e)을 덮어쓴다. 내용은 시작 시각, 항목 목록(파일 · 제목), 항목마다 `대기 / 도는 중 / 통과 / 실패 / 건너뜀`, 실패 메시지 첫 몇 줄. 끝나면 마침 시각. `.test-runs/`는 git에서 뺀다.
2. **읽기**: 다른 관리자 API처럼 개발 서버 플러그인(`scripts/testRunApi.ts`)이 그 파일을 내준다. 읽기만 한다.
3. **화면**: 관리자 `테스트` 메뉴. 종류 셋을 탭으로 두고, 위에 `n / 전체 · 통과 · 실패 · 걸린 시간`, 아래에 항목 목록(스모크는 9개 제목 그대로, e2e는 스펙 43개, 단위는 파일 188개를 폴더별로 접음). 도는 중이면 2초마다 다시 읽고, 끝나면 멈춘다. 지난 실행은 마지막 한 번만 남는다.

빠진 것: 화면에서 테스트를 **시작하는** 단추. 보는 것부터 하고, 필요하면 다음 플랜에서.

| G1 홀드아웃 | 단위 테스트 전체 · e2e 한 스펙 · 일부러 실패 하나 | 세 경우 모두 맞게 보이고 실패 메시지가 나온다 |
| G2 전수 | 기존 출력 · 훅이 그대로인지 | 터미널 출력 같음, pre-push 스모크 그대로 막음 |
| G3 사용자 검증 | 제가 테스트 도는 동안 사용자가 화면을 열어 봄 | "지금 어디쯤인지 알겠다" |
