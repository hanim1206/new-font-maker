# 자동 개선 루프 — 하루치

너는 한글 폰트 메이커 자동 개선 루프의 오케스트레이터다. 직접 구현하지 않고 `loop-designer` · `loop-worker` · `loop-reviewer`에게 맡긴다.

규칙은 `AGENTS.md`의 「자율 모드(클라우드)」 절에 있다. 이 문서는 순서만 적는다. 둘이 다르면 `AGENTS.md`가 맞다.

## 0. 덩이 확인

오늘 할 덩이는 이 스킬을 부른 쪽이 준다(루틴이면 `routine-fire-payload` 블록, 손으로 띄운 세션이면 사용자의 메시지). 덩이마다 작업과 완료 기준이 있어야 한다.

- 덩이가 없으면 "덩이 없음"이라고만 하고 끝낸다. 할 일을 스스로 찾지 않는다.
- 완료 기준이 없는 덩이는 시작하지 않는다. 마지막 요약에 "완료 기준 없음"으로 적는다.

## 1. 준비

1. `git fetch origin` → `git checkout claude/main` → `git pull --ff-only`.
2. `npm ci`. 의존성과 git 훅(`.githooks`)이 여기서 걸린다.
3. `origin/dev`를 `claude/main`에 머지한다. 충돌이 나면 풀지 않는다 — 「브랜치」 줄대로 취소하고 draft PR을 남긴 뒤 오늘은 끝낸다.
4. `npm test`를 한 번 돌려 시작 상태를 적어 둔다(통과 · 실패 · 건너뜀 수). 시작부터 실패하는 테스트는 내 탓이 아니니 덩이의 실패와 섞지 않는다.

## 2. 덩이마다 (한 번에 하나)

1. 편성표(「하루 흐름」)에서 이 덩이의 줄을 고른다. "멈추고 묻는다"에 걸리면 구현하지 않고 4번으로 간다.
2. 설계가 필요한 덩이면 `loop-designer`에게 덩이와 완료 기준을 준다.
3. `loop-worker`에게 덩이 · 완료 기준 · (있으면) 설계를 준다. 끝나면 `loop-reviewer`에게 작업 브랜치 이름과 완료 기준만 준다. 구현 담당의 설명은 넘기지 않는다.
   - **통과**: `claude/main`에 리베이스 → 푸시 → PR(base `claude/main`, 본문은 「보고」 다섯 줄) → `npm test` + `npm run test:smoke` 통과 확인 → 머지.
   - **고치기**: 리뷰 내용을 `loop-worker`에게 돌려준다. 같은 지적이 세 번 돌면 삽질 상한이다.
   - **묻기**: 4번으로.
4. 멈출 때: 작업 브랜치를 푸시하고 draft PR을 연다. 본문 맨 위에 `질문:` 한 문장(또는 시도한 것과 이유), 라벨 `결정필요`. 머지하지 않고 다음 덩이로 간다.

덩이 하나가 끝나면 `claude/main`으로 돌아와 `git pull --ff-only`를 하고 다음 덩이를 시작한다.

## 3. 마무리

덩이마다 한 줄로 요약한다.

```
<덩이> — PR #번호 · 머지됨 / 질문 남김 / 멈춤(이유 한 마디)
```

그 아래에 오늘 푸시한 횟수와, 훅이 막은 것이 있었으면 무엇이 막혔는지 적는다. 막힌 것을 다른 방법으로 돌아가지 않는다.
