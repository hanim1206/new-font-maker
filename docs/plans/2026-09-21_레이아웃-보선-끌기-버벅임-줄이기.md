# 레이아웃 보선 끌기 버벅임 줄이기

- **이번에 비교하는 것**: 보선을 끄는 동안 글자 카드 8장이 매번 처음부터 다시 계산되는 지금과, 편집과 무관한 계산은 글자당 한 번만 하고 끄는 동안에는 Δ 얹기만 도는 것.
- **이번 승인으로 바뀌는 것**: 글자 카드 안의 계산 순서(`PropagationCard`). 화면에 보이는 것과 끄는 느낌은 그대로다.
- **바뀌지 않는 것**: 끄는 중 실시간 미리보기, 스냅 · 진동, 적용 범위 규칙, 저장 형식, 본 캔버스 그리기, 예시문장, production 값.

출처: 9/21 사용자 — 모바일에서 레이아웃 보선을 끌 때 버벅인다. "터치가 끝날 때만 그리면 나은가?"

## 지금 상태

**사실** (코드)
- 끌기 핸들러(`GlyphLayoutEditor.tsx`의 `moveDrag`)는 `pointermove`마다 제한 없이 상태를 바꾼다. 모바일은 초당 60~120번.
- 그때마다 `propagationEdit`이 새로 만들어지고, 글자 카드 8장(`CARD_COUNT`)의 계산 묶음이 전부 다시 돈다. 그 묶음 안에는 편집과 무관한 것이 같이 들어 있다: Noto 고스트 경로, 칸 해석(`resolveContextBoxes`), 홀자 · 닿자 fit, Δ 없는 기준 획 렌더.
- 편집 값에 따라 달라지는 것은 Δ를 얹어 다시 그리는 부분뿐이다.
- 본 캔버스는 움직일 때마다 두 번 그린다. 놓을 수 있는지 보는 검사(`tryPlace`)에서 한 번, 화면용으로 한 번.
- 1u 격자로 반올림한 값이 직전과 같아도 상태를 새 배열로 바꿔서 다시 그린다.
- 예시문장은 이 경로에 없다. 레이아웃 편집 상태는 편집기 안에만 있고, 문장은 `적용` 때만 다시 그려진다.

**가설**
- 버벅임의 대부분은 카드 8장의 헛계산이다. 프로파일링은 아직 안 했다.
- 카드 계산을 나누면 실시간 미리보기를 지키면서도 터치 끝 갱신에 가까운 부드러움이 나온다.

## 하려는 것

1. **재기(D0)**: 코드를 바꾸기 전에 끄는 동안의 프레임 시간을 잰다. Playwright + CPU 4배 감속, 모바일 뷰포트, 받친글자 하나(`각`)와 섞임모임 하나(`봐`)에서 보선을 200px 끈다. 카드 계산 · 본 캔버스 · 나머지로 나눠 적는다. 실기기 체감은 사용자가 G3에서 본다.
2. **카드 계산 나누기**: 카드 한 장의 계산을 둘로 가른다. 글자 · 모델 · 저장된 Δ에만 달린 부분(고스트, 칸 해석, fit, 기준 획)은 따로 기억해 두고, 편집 Δ에 달린 부분만 끄는 동안 돈다. 결과 경로는 지금과 글자 하나 안 다르게.
3. 2로 모자라면 다음 플랜으로 넘긴다(한 단계에 변수 하나). 후보 순서: 같은 값이면 다시 안 그리기 → move를 프레임당 한 번으로 묶기 → 카드만 한 박자 늦게 그리기(`useDeferredValue` + `memo`) → 터치가 끝날 때만 카드 갱신.

터치 끝 갱신을 맨 뒤에 둔 이유: 끄는 동안 다른 글자가 어떻게 바뀌는지가 이 화면의 쓸모다(원칙 `실제 글자를 먼저 보여 준다`). 앞의 것들로 안 될 때만 꺼낸다. 그때도 본 캔버스는 실시간으로 둔다.
